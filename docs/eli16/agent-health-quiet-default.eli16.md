# Agent Health is quiet until it needs you

The Agent Health topic was filling with descriptions of the agent's own machinery: a machine briefly unreachable, a conversation waiting on a machine, a session that appeared stuck, or a preference that had not settled yet. These reports were useful to the agent, but they did not give the person a decision to make. Several even repeated their heading as the whole body. The approved Quiet by Default design already said Agent Health belongs in the quiet category; the missing piece was the actual delivery decision.

This change makes that decision where an Agent Health observation enters the attention store. The observation is saved first and remains available to the agent and dashboard. A routine one also gets a hold record and causes no Telegram send or new topic. This applies to the first report, later refreshes, a report that reopens after recovery, and high-priority labels. If the producer explicitly says the person needs to act, the report still goes to the established Agent Health topic. If that need emerges later on an open report, the saved report can become a push then. A recent report that Justin dismissed as WONT_DO stays dismissed. Normal replies to the person's messages use another path and keep flowing.

The screenshot also showed literal bold tags on reports from standby machines. The relay was dropping the format choice passed by the caller and using the machine's default instead. The choice now reaches the Telegram holder. An Agent Health message that really must be sent keeps its formatting, and a heading repeated in the body is shown once.

This is the Agent Health slice of the larger approved selectivity spec. The other automated senders still need the spec's last-hop provenance gate, quiet store, opt-in controls, and rollout. Those remain tracked under #2738 <!-- tracked: 2738 --> (the existing spec also names CMT-1948). The agent's own repair actions for the individual stranded-topic, pin, and stale-session conditions also need source-specific follow-up; suppressing a Telegram push does not itself repair a condition.
