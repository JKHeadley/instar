This changes one test, not the product. The test walks a piece of feedback through its whole life: it arrives, gets judged ready, becomes a project, and is approved and queued for work. Two of those steps happen in the background, so after asking for them the test has to wait until they're done. It used to wait for at most about two seconds, by checking two hundred times, ten milliseconds apart. On a quiet machine the background work finishes in time. On a busy machine it can take longer, and then the test failed with no clear reason, which marked the whole main branch as broken this morning. Now the test keeps checking for up to thirty seconds. If the work still hasn't finished by then, it fails with a message saying which step stalled and what it saw last. Every check the test makes afterwards is exactly the same as before.
