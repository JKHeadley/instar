When someone asks to change how a conversation runs, for example its model or thinking level, Instar asks a clear question and waits for a yes. A few things can go wrong along the way. The yes might arrive, but the "got it" message fails to send. Instar might be unable to tell which machine owns the conversation. A small notice might fail to send. Or the question itself might fail to send. In every one of these cases Instar already did the safe thing. It kept the saved answer, refused to act when it could not check ownership, kept the settings, or told the caller the question failed. But it did so quietly, without writing down what went wrong. Instar has a rule that a quiet failure path must either report itself or explain in the code why being quiet is safe, and a counter that may never go up. This change made the counter go up by four, which blocked it. So each of those spots now writes one short line to the log saying what failed, plus a note explaining why it's safe. Nothing a person sees changes, and the counter is back where it was.
