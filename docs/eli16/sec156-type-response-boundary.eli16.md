A Secret Drop password meant for one website's sign-in page is never handed to the agent. Instead the agent's server gives it straight to a small browser driver, which types it into the page. The server then tells the agent how that went. Until now, that report included the last part of whatever the driver printed while it worked. The driver had just been given the password, so anything it printed could contain the password itself or text from the private sign-in page, and the report would carry it straight back to the agent. That undoes the whole point. Now the report says only one of three fixed things: it typed, it timed out, or the driver failed. The driver's own messages are thrown away. Only the outcome, the website and the exit code are written to this machine's log (plus the system's own error if the driver can't even start), so nothing the driver saw can leak there either. Two new tests use a fake driver that deliberately prints the password and some page text, and check that none of it ever reaches the agent.
