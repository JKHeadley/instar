This is a correction to one comment in the code, with no change to what the code does. When Instar asks the browser driver to type a Secret Drop password, it watches how the driver finishes. If the driver prints far too much text, Node stops it for going over an output limit. Instar counts that as the driver failing, not as the driver running out of time, because the two mean different things to whoever reads the result. The comment beside that check said Node marks an over-the-limit stop the same way it marks a timeout. An independent reviewer tested this on the version of Node we run and found that's not true: Node marks it with its own error code instead. The check was already right and stays exactly as it was. Only the explanation next to it was wrong, and leaving a wrong explanation in security code invites the next person to break the check while "fixing" it. So the comment now says what Node really does.
