Instar collects problem reports from agents running on many people's machines. It groups them, decides which are real, and lines them up as work to fix. When it picks what to work on next, it used to take whatever had been waiting longest. That sounds fair, but it meant the first batch Justin would approve held ten small items, each reported once, while problems reported hundreds or thousands of times by agents in the wild waited behind them. One was reported 1,768 times. Justin's whole point is to fix the most important problems first. Now the work is lined up by importance: the high-priority problems come first, then the ones reported most often, and only after that the oldest. The preview Justin sees when he approves is in exactly the same order, so the batch he approves is exactly what gets worked on.
