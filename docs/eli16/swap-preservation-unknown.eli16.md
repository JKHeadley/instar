When one subscription account runs low, Instar can move a working conversation onto another account and resume it there. Afterwards it writes a line in its log saying how the move went. Until now there were only two possible lines. If the move clearly lost the earlier conversation, the log said so. In every other case it said the conversation was preserved, even when the code doing the move never said either way. Some older parts of the code just answer "it worked" without saying whether the conversation came along, and those got logged as a confirmed success the code never actually reported. That's a small but real false claim: someone reading the log later, or a check that relies on it, would believe the conversation was kept when nobody knows. Now there's a third, honest line for that case, saying the move happened but whether the conversation carried over is unknown. Nothing about the move itself changes. Only what the log claims afterwards changes, so the record matches what's actually known.
