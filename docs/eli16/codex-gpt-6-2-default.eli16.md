# Codex moves to GPT-6.2 Sol and Astra

OpenAI released two new Codex models on 2026-11-17: GPT-6.2 Sol (the everyday, medium model) and GPT-6.2 Astra (the heavy, most capable model). Justin asked that all of our Codex work move to them as soon as possible. Before writing any code we checked that the models really work for us: all five Codex accounts list both models, and a real one-line request to each model answered "OK" on every account. There is no small GPT-6.2 model, so the light work Codex does (quick background checks) stays on GPT-6 Luna.

What already exists: Instar picks a Codex model by size. "Fast" means light work, "balanced" means everyday work, and "capable" means hard work and the main chat. Each size points at one model name. Instar also keeps a list of every Codex model name it trusts, and refuses names that are not on the list.

What changes: both new names join the trusted list. "Balanced" now points at GPT-6.2 Sol instead of GPT-6 Sol, and "capable" points at GPT-6.2 Astra instead of GPT-6 Astra. Echo's bug-report topics, which already defaulted to Codex, now default to GPT-6.2 Sol. The review checks that require a specific Codex model (the feedback reviewer and the feedback triage approval) now accept the GPT-6.2 model of the same size. They still refuse a model of the wrong size, and the previous GPT-6 model keeps passing so a review made by a machine that has not updated yet is not thrown away.

The safety net: older versions of the Codex program cannot use the new models. We tested several versions against the real service. Version 0.166.0 and newer can use them; 0.165.0 and older are refused. When a machine has an older Codex program, Instar quietly uses the previous model of the same size (GPT-6 Sol or GPT-6 Astra) instead of starting a session that fails. For a full session, if Instar cannot even read the Codex version, it also takes the older model, because a session that fails to start has no second try. For quick one-off internal questions, Instar keeps the new model when the version is unreadable, because those calls already retry on a known-working model if they are refused. A fallback is written into the session's own record and the system's logs rather than posted in the chat, since nobody needs to act on it. When someone is asked to approve which model the feedback system uses, the proposal also checks the Codex version on that machine, so it never asks them to approve a model that machine cannot run. The price of each new model is recorded too, so spending reports show real numbers from the first day.

What is not changed: if someone has chosen a Codex model for this agent on purpose (in its settings, or pinned on a topic), that choice is left exactly as it is. Instar never wrote a Codex model into agent settings itself, so any value found there was a person's choice. The safety floor model used after a refusal stays the same.

One bookkeeping note: Instar keeps a list of every file the carefully tested Codex message-delivery code can reach, and the small file that reads the Codex version is now reachable from it. It only picks a model, so it is recorded on that list as outside the tested delivery path, and the tested files themselves are unchanged.

What you need to decide: nothing. This follows Justin's directive. If the new models misbehave, undoing this one change puts every size back on the GPT-6 models.
