Every few seconds Instar checks a log of which machine owns which conversation, so it knows where to send messages. To do that, it reads the newest entries from the end of that log. The problem was how it read them. It grabbed up to four megabytes from the end of the file all at once, split all of it into lines, and only then took the few hundred newest entries it actually needed. It did this several times per check, on the same thread that answers every request. On a busy laptop one of these reads froze the server for more than eleven seconds. Now it reads backwards from the end in small pieces and stops as soon as it has enough entries. The answer is exactly the same as before, which a new test checks against the old code on hundreds of different files. It just reads a tiny fraction of the data, so the server isn't stuck waiting.
