# ELI16 — Let Cartographer read the protected Instar checkout safely

Cartographer now knows how to choose and verify the right project checkout before it writes summaries. On the Instar development agent, that checkout is also protected by a safety guard created after an old test accidentally damaged the real source tree. The guard is correct, but Cartographer forgot to declare that its three Git operations are read-only. As a result, the new root authority said “this is the verified checkout,” while the detector immediately treated that same checkout as if Git were unavailable. The map stayed structural-only and the authoring path could never start on the real dogfooding project.

This fix does not weaken the guard or add a general escape hatch. It marks only Cartographer’s existing `rev-parse` and `ls-tree` calls as approved source-tree reads. Those verbs are already in the safety layer’s closed read-only allowlist; a destructive Git command still cannot use this permission. A regression test runs against the protected checkout itself, and a wiring test requires every Cartographer detector Git read to carry the narrow option. The recurring paid sweep remains off, the 200-node navigation ceiling is unchanged, and no new setting or operator action is introduced.

After release, a topic-bound verified checkout can produce a real Git-backed snapshot and a bounded one-node authoring pass. The acceptance proof remains operational rather than synthetic: the same live health query must show zero authored summaries before the pass and a positive count after it.
