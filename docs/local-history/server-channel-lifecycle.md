# Local History: Server Channel Lifetime

`LocalHistoryChannelRegistry` owns the in-memory lifetime of target-authenticated local-history channels. It wraps the existing handshake and record crypto with current owner/device/issuer checks, capacity admission, expiry, revocation, replacement and exchange disposal. This is a component checkpoint for the active selected-history import work in topic 143810. It exposes no endpoint and grants no upload, preview, copy or library authority. <!-- tracked: topic-143810 -->

The production adapter must provide actual current unique native-owner resolution, stable owner profile, authenticated enrolled device and key hash, the current agent/machine/boot identity and actual signing-key fingerprint, and the machine signer. No owner role or identity comes from a request body. The registry does not verify the native request signature: full existing device authentication remains mandatory before private dispatch. Likewise, the shared importer exchange lease must be acquired before allocating request bodies and retained through response drainage; this registry does not replace that admission layer.

Capacity is charged before cryptographic handshake creation. An idle channel can be replaced atomically; a still-held exchange keeps its slot even after expiry or supersession. Refused refresh at full capacity leaves a valid existing exchange usable and invokes no signer. Synchronous issuance is fenced against reentrant abort/signing callbacks. The registry keeps one current channel per device and checks that current mapping before decryption or response publication.

Every accepted request returns an owned exchange with plaintext, an abort signal, one response-sealing action and idempotent close. Response plaintext passed to `sealResponse` transfers ownership and is cleared immediately after sealing or refusal. Request plaintext, ciphertext and sealed-response buffers remain accounted for until the adapter has disposed the actual transport and calls close. An aborted request that never sealed a response invalidates its channel. The adapter must close on disconnect, timeout and dispatch failure; an in-flight exchange is never reclaimed merely because its timer expired.

The existing 60-second channel lifetime is absolute from grant creation. Signing and abort callbacks cannot extend it: the clock and issuer are rechecked before publication, expired or rolled-back creation refuses, and the timer uses only the remaining lifetime. Idle expiry needs no further request. In-flight expiry aborts work and denies new private publication while retaining its resources until close. Owner, enrolled device key, agent, machine, boot and server signing-key changes invalidate old authority. Timers and Buffer clearing are lifecycle controls, not forensic memory erasure or a hard operating-system scheduling guarantee.

Focused verification uses real Ed25519/P256/HKDF/AES-GCM handshakes and records. The registry tests cover successful exchanges and clearing, expiry with and without timer callbacks, live profile/device/server-key changes, foreign identity refusal, capacity-preserving refresh, abandoned/tampered requests, reentrant replacement and stop, and elapsed/rolled-back time during signing. Existing handshake and channel checks run alongside them. These are component checks; signed HTTP ingress, actual pairing hooks, AgentServer construction/shutdown and installed native upload acceptance remain required before the complete feature is available.

This component persists no state and makes no network or filesystem call. It adds no plaintext or bearer fallback. The server upload operation service, durable operation recovery, resource accounting, sealed endpoints, copy permits and owner-filtered library connection remain active implementation work in the parent contract, `docs/specs/local-history-native-contract.md`.
