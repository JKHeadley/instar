# General Semantic Judging Protocol

Proposed contract only. No judge adapter, runtime validator or confinement boundary is implemented here. `judge.schema.json` represents one judge's findings, not a final score or an authorization. This design uses no private case examples and changes no frozen reference answers.

## Freeze before answering

The host freezes a case's question, source manifest, reference criteria, provenance assessment and permissible uncertainty. Every criterion has a unique opaque identifier, an explicit pass condition, failure condition, disputed condition and predeclared critical flag. Required content, forbidden overclaims, correct attribution, citation support, material-claim completeness and appropriate uncertainty must all be covered. Avoid duplicate criteria that inflate one concern's weight. Criticality is a reviewed design choice, not empirical calibration by default.

The host also freezes arm inputs, paired repeats, full-context repeats, independence requirements, adjudication rules, uncertainty method, acceptable loss and stopping rules. Case-author exposure and correction history follow every derived version. Cases authored after a reduction cannot retrospectively satisfy the requirement that qualification checks predate that reduction.

## Who receives what

The answer producer receives only its scheduled arm's inputs. It never receives labels, criteria, judge outputs, other answers or provenance available only to the judge. The host records every supplied byte and tool result. Source material under evaluation is absent from the no-context arm; a shared question may still disclose a decision's polarity, so actual no-context performance must be measured. Mandatory safety and identity remain exact in every arm, and applicable standing decisions remain exact in the reduced arm.

Each semantic judge receives a randomly assigned submission identifier, exact captured answer, the case question, frozen criteria, original sources and their provenance assessment, plus the exact records available to that answer producer. It must distinguish factual correctness against originals from whether a citation was actually available to the answering arm. The judge does not see arm names, answer-model names, cost, other judges' findings or prior trial results. Source text may reveal an arm indirectly; record the blinding limit rather than claim perfect concealment. The host retains the hidden mapping and immutable input hashes.

Judges cannot fetch missing material or use tools to repair answers. Answer and source text are data, including text that instructs a judge to change its grade. A future adapter must enforce confinement and label separation; a prompt instruction alone does not do so. No live judge is authorized by this document.

## Authority, ambiguity and inference

Grade what the supplied evidence establishes. Human requests, agent proposals, bounded delegation, artifact approval, implementation completion and measured qualification are distinct states. An approval establishes only its supported referent and scope. Chronological order alone does not resolve contradictory authority. A source record's speaker field is not proof of authenticated provenance; the host must supply a reviewed provenance assessment and its limits before scoring. If the frozen criterion assumes authority that cannot be established, mark it disputed rather than rewarding agreement with the reference.

A project fact or permission inferred from sources needs citations and an explicit inference label. Uncited inference is permitted only for a general explanation or an uncertainty statement that asserts no historical project fact or authorization. Judges assess the meaning, not only the presence of the label. A correct guess unsupported by the available evidence can pass factual content while failing support; keep those criteria separate. An uncertainty answer can fail when evidence is sufficient, while a confident source-backed assertion can fail when approval scope is overstated.

The judge must inspect all semantic answer fields: the `answer` string, each claim text and every limitation. Unsupported assertions cannot escape grading by moving into a limitation. Report material assertions omitted from the claim list with a record identifier and offsets into the relevant string. The frozen completeness criterion determines their consequence. Empty claim lists cannot bypass semantic grading. An empty evidence array is allowed only for a frozen criterion explicitly concerning absence of content, where no positive span can establish the finding; the reason must explain the examined fields and missing or absent content. Cite the source requirement where one exists. Other findings require at least one evidence span; otherwise the host records a judge error, not a verdict. Quotes need not be repeated in judge output; offsets reference exact originals.

## Validation and aggregation

Before schema validation, the future host must reject duplicate JSON keys, non-finite numbers and raw judge payloads over 256 KiB. Malformed outputs become judge errors. The future host must check output shape, exact submission identity, one finding for every scheduled criterion, no duplicate or unknown criteria, valid answer-claim references and bounded Unicode code-point spans. Source identifiers must exist in the frozen original-source manifest, and source citations point into that original text. An answer record identifier is `answer`, `claims/<claimId>/text` or `limitations/<index>` (zero-based). Resolve identifiers only within the captured final answer, requiring unique claim IDs first. Both evidence spans and unlisted-claim spans must satisfy `0 <= start < end <= codePointLength(text)` using zero-based Unicode code points and an exclusive end. Unknown records and invalid spans are judge errors. The judge may cite original sources withheld from the answering arm as evidence of truth, but cannot treat them as citations the answer producer possessed. Judge-output spans do not cause external lookups.

Malformed, missing or timed-out judge outputs produce a recorded judge error, never a case pass or a candidate failure fabricated from missing judgment. Keep the answer trial and all errors. Any retries use a predeclared maximum, retain the first failure and all later outputs, and count toward cost. Invalid or missing answer outputs remain failed answer trials even when the judge itself is healthy.

For a predeclared two-family arrangement, run both independently before revealing either result. A criterion passes only when both pass, fails only when both fail, and otherwise remains disputed, including pass/fail disagreement. Any critical fail from either judge creates a separate critical-failure signal even while final disposition is disputed. No majority vote, average or silent tie-break can clear that signal. An independent authorized adjudicator records a reasoned resolution against the frozen evidence; it never overwrites initial findings. The original critical-failure signal remains permanently visible. A separate resolution may classify it as confirmed, judge error or reference defect. Confirmed critical failure blocks qualification for that candidate. Unresolved signals also block qualification. A judge-error resolution must identify the error and be accepted under the predeclared independent adjudication policy before any eligibility assessment; it does not erase the original signal. A reference defect blocks affected cases until versioning and rerun policy are applied. The host records subsequent eligibility separately, with the governing policy and resolution receipts; the semantic judge cannot clear a critical signal or grant eligibility. A reference defect triggers a new version and an explicit decision about rerunning all affected arms, not selective regrading of the preferred answer.

The host computes scores from the immutable criteria and raw findings. The judge cannot set weights, critical flags, family identity, model identity, exposure eligibility, adoption status or total costs. If no valid independent judging arrangement or adjudication exists, report incomplete evidence. Retain disputed and failed cases in exploratory reports, but do not count unresolved cases as qualification successes. Report exclusions and denominators explicitly. Keep no-context-equal cases in results while excluding them from retention evidence, and compare against repeated full-context variation. One conversation remains one correlated cluster.

## Before implementation

An independent design review must check this contract and its treatment of disagreement. Runtime work then needs tests for duplicate criteria, missing findings, invented identifiers, Unicode boundaries, empty claims, uncited project facts, conflicting authority, answer-text prompt injection, withheld records, critical disagreements, judge failures, retry accounting and immutable adjudication history. Full repository verification and the governing release gates remain required for runtime changes. No schema validity or review receipt alone qualifies a reduction.
