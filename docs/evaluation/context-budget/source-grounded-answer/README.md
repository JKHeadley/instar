# General Source-Grounded Answer Contract

This is a proposed data contract, not an implemented evaluator or a live model route. It extends beyond relationship arithmetic without encoding any private holdout answers. The relationship runner remains unchanged and cannot consume this contract yet. No qualification, savings or activation follows from a schema-valid answer.

The corresponding proposed judge output is in `judge.schema.json`. `judging-protocol.md` defines its inputs, criterion completeness, authority checks, judge-error handling and preserved disagreement. These files specify future implementation requirements; they do not implement a judge or score the private cases.

`answer.schema.json` defines the final answer only. The answering process receives a case identifier, question, only the immutable source records assigned to that arm and its selected context. It never receives reference labels, grading criteria, expected decision codes or other arms' outputs. The host supplies trial identity, model and route, source and context hashes, repeat number, cost and timing outside the answer. A model cannot self-assert those facts or grant authority through an answer field.

Each source record has a host-assigned identifier, original text, text SHA-256, original timestamp, speaker identity and independently established provenance. An agent's proposal is not operator approval. A later message supersedes an earlier one only where its authority and scope support that interpretation. The future host must define and review an evidence standard for provenance; copied speaker metadata alone is not authentication. Those judgments belong to the reviewer; a timestamp alone cannot decide them.

Answers separate their conclusion from atomic claims, evidence and limitations. `supported` means the answer claims sufficient evidence; it is not a passing grade. `partial`, `insufficient-evidence` and `conflicting-evidence` require an explicit limitation. A missing source must not be replaced with a guessed decision. Inferences must be labelled, and uncertainty must remain visible. An inference with no source citation is permitted only as an explicitly general explanation or statement of uncertainty; it cannot assert a historical project fact or an authorization. The future judge contract must define and test this distinction. No confidence percentage is accepted as evidence.

## Validation and grading boundaries

JSON Schema checks field shapes and basic bounds only. Before accepting an answer, a future host must reject duplicate JSON keys, non-finite values and payloads over 128 KiB; check that case identity matches the scheduled trial; require unique claim identifiers; and verify citation identifiers against only the sources actually supplied to that arm. Citation offsets are zero-based Unicode code-point indices into the exact source text, with an exclusive end. The host must enforce `0 <= start < end <= len(text)`. It must not resolve an unknown citation by fetching a source or a label. Schema validation cannot check these relationships.

An independent semantic judge receives the frozen rubric, original sources and captured answer, with arm and model identity hidden where possible. It checks whether citations actually support each claim, whether every material assertion in the prose is represented, whether authority and chronology are interpreted correctly, whether required content is present, and whether prohibited overclaims occur. Citing an operator's question does not make the agent's proposed answer approved. Unsupported or uncited inferences cannot establish authority. A schema-valid refusal can still be a semantic failure when sufficient evidence was available.

Record rubric results individually as pass, fail or disputed, with source citations and a reason. Keep critical failures separate from aggregate scores. Preserve disputed cases, reviewer disagreements and any adjudication; never silently revise the frozen reference. Invalid or missing final answers remain failed trial records. Unresolved reference ambiguity excludes a case from qualification until adjudicated and refrozen with its history, while retaining it in exploratory results.

## Trial and exposure requirements

The same final-answer contract applies to no task-context, reduced-context and full-context arms, with paired repeats and full-context variation measured. Define precisely which source records are the context under evaluation: giving those same records to the no-context arm would defeat the control. Keep mandatory safety and identity in every arm and applicable standing decisions exact in the reduced arm. Preserve all trial outcomes; no-context-equal cases do not demonstrate retention.

Record exposure separately for author, reducer, reviewer, answer producer and semantic judge, including session identity, first access, file hashes and materials seen. A separate session can provide a second interpretation while sharing a model family; it is not cross-model agreement or proof of hidden-label isolation. Reviewers who see labels cannot later produce blind answers. Schema designers must not use private questions or labels as examples or tune a reduction against them.

Before implementation or trials, independently review this contract, the judge contract, label isolation and the confinement boundary. This document adds no network client, model adapter, tools, automatic grading or authorization. Required future tests include invalid identities, Unicode offsets, invented citations, authority laundering, ambiguous references, withheld context, invalid outputs retained as failures, forbidden effects and labels inaccessible to the answer producer. Full repository verification remains necessary for runtime implementation.
