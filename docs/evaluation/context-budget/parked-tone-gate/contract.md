# Tone-gate input capture at the Codex CLI

## Problem statement

The tone gate assesses draft outbound messages. Its existing ledger can identify a disposition but cannot reconstruct the rendered request or tie it to the attempted route. The benchmark needs byte-level evidence at the adapter handoff. This serves Groundedness Before Confidence and Signal vs. Authority. Collection can influence research evidence only. It cannot choose a route, change a verdict or impede ordinary delivery.

## Proposed design

The deliverable is a synthetic integration pilot only. Build the receipt mechanics in an isolated harness, invoking a local fake binary through the actual JSON transport seam, with synthetic fixtures defined by the harness. There is no live opt-in flag, persistent product store, automated notice, migration or production capture path in this revision. The fixture at 5c2d92f9 provides a byte-preservation and scoring control. A later production specification must establish real-source authority and positive custody evidence before installing any production collector.

### Submission receipt

At `src/providers/adapters/openai-codex/transport/codexSpawn.ts`, the JSON transport currently calls `child.stdin.end(options.prompt)`. The production transport stays byte-for-byte unchanged. The harness supplies the existing `spawnImpl` seam with a wrapper around a real local child launched by pinned absolute Node executable and an authored script inside the verified scratch directory. Use only an allowlisted fixture environment with scratch-local HOME and no account settings, route discovery or inherited credentials. Assert the spawn command and environment before launching the child, and assert that a real-Codex canary was never invoked. The wrapper intercepts its writable `end` call only in test code. The wrapper attaches its observers, then forwards the original receiver and arguments unchanged before capture work. It accepts for research only the existing single-string UTF-8 end call. It checks string length, reserves capacity, and then derives the bytes, using the fake reader’s output as the independent ground truth. An unexpected argument or encoding makes the probe inconclusive, with the original write still forwarded. No hashing or scanning runs before forwarding. Only the test wrapper registers capture observers. The authored fixture has no ledger-derived or real message text. Capture failures must leave dispatch and its errors behaving as before. Local orchestration never waits on scanning, receipt serialization or persistence. The source classification and immutable manifest originate in the renderer or its synthetic stand-in. The manifest is bound to the exact buffer by SHA-256 and checked off the transport path. Drop only the receipt on missing, mismatched or unexpected sources, including an unclassified source added to a retry. Any capture limit, scan failure or scanner timeout drops only the receipt and increments a fixed reason counter. No manifest, scanner or storage check can prevent forwarding the original write. Compare dispatch bytes and ordinary result with the wrapper disabled and with each rejection, including a lone surrogate encoding case. Identity and source classification come from typed fixture code and cannot be asserted by prompt contents. A clean scanner result does not establish absence of secrets.

The adapter-neutral receipt names a version, opaque run namespace, issued-at fixture wall time, disposition correlation ID, unique attempt ID and ordinal, route, transport, requested model, observable boundary, relative event order, and request bytes, byte length and SHA-256. A bounded application-visible verdict can be included with a separate format, length and digest. Stdout, stderr, raw arguments and environment are excluded. Only Codex JSON stdin is implemented in the pilot. Other adapters and fallback attempts are uncaptured unless their own boundary is implemented. A disposition fixture written by the component that selects the verdict names the chosen attempt explicitly. Never infer selection from matching text or success. A repeated identical selection is idempotent. A conflicting selection marks the correlation unusable. Missing selection remains unknown. A selection naming an uncaptured attempt is explicitly unusable. The harness collects attempts, selection events and commit completions until a fixture-owned seal. Replay receives a finalized snapshot only after every producer and worker has drained, and only from the sealed run index. Individually committed files are private staging input and unavailable to replay before the seal. A pre-seal conflict invalidates the correlation even if its first file already committed. Reject writes after seal. An incomplete run never produces a replay index. The harness allocates a unique dispatch token before each spawn and closes registration before draining all registered children, selection events and worker operations. Repeated identical events for the same dispatch token are idempotent. Two different dispatch tokens with the same attempt ID invalidate the correlation even if the bytes match. The sealed index binds run, correlation, selected attempt and SHA-256 of the entire serialized receipt. On reopen verify those fields and the full digest against the independently held sealed index. Repeated seal requests return the same finalized index. No post-seal events alter it.

Record independently whether spawn failed, the adapter called `end`, the writable reported completion, the adapter settled, and the receipt became readable. Attach listeners before `end`. At adapter settlement snapshot the first successful finish only if no earlier or intervening write error or premature close invalidated it. If settlement wins the race, record unknown unless a failure was observed. Receipt publication can occur after process exit. A write error observed after the settlement snapshot and before child drain makes replay ineligible. The capture observer has no consumer in the tone gate, router or dispatcher. Successful writable completion establishes acceptance by the writable, while reader consumption, CLI-added context, upstream serving identity and provider delivery remain unknown. Only a sealed, digest-verified, selected receipt with writable completion can enter replay. A stored failure or unknown write can be inspected only as a diagnostic fixture. The scorer assertion uses the canned passing verdict and pins the existing scorer pass outcome. No replay qualifies exact model input.

### Synthetic custody and limits

Use an OS-created temporary directory under the test runner’s canonical scratch root, outside project, agent state, dashboard and effective backup include roots, mode 0700 with 0600 regular files. The harness parent owns the scratch directory and retains its nonce, inode, UID, mode and canonical path in memory. Teardown verifies them against the directory and refuses links or decoys. Reopen and crash checks restart only the child writer while the owning harness parent remains alive. There is no automatic cross-run discovery or deletion. If the parent is killed, a synthetic scratch directory may remain for manual cleanup. Keep synthetic markers out of general logs and API surfaces. There is no state backup, replication, fallback to other machines or replay API. Temporary synthetic output is a disposable test artifact with no deployed multi-machine state surface. Losing it yields an unavailable receipt and the test can rerun.

All numbers below are synthetic fixture parameters selected to exercise the specified pass and drop cases on a finite test run. They have no production policy effect. The fixture is 36,583 request bytes. A 128 KiB combined request and verdict ceiling gives the fixture over 3x headroom while allowing deliberate rejection above the ceiling. Apply byte counts to raw UTF-8 before storage encoding. Envelope overhead is at most 4 KiB of bounded metadata and framing. The two base64 payload strings total at most 174,768 bytes at the raw cap, leaving over 17 KiB inside a 192 KiB serialized ceiling. An eight-slot, 1 MiB raw reservation covers eight maximum-size records. Reserve one slot and exactly 128 KiB total per attempt before any custody copy, covering unresolved attempts, request plus verdict together, and queue handoff. A combined payload exceeding the reservation drops the whole receipt. Count a dropped individual attempt and, if it was selected, its correlation as unusable. A dropped unrelated attempt preserves a valid selected receipt. A child worker with asynchronous filesystem I/O accepts one record at a time. Its capture-owned binary buffers are capped at 1 MiB. Preallocate a 128 KiB input region, a 192 KiB output region and at most 704 KiB of scanner and handoff scratch, including temporary encoding copies. Use a bounded synthetic marker scan with no arbitrary regex or helper allocation. Language runtime and original transport buffers are outside this capture budget. Release a reservation after durable write or discard, or during teardown after worker termination. Force release when a registered attempt settles without an eligible verdict or its correlation is invalidated, unless its writer still owns the slot. A late result after discard cannot revive a reservation. Drop the newest candidate on exhaustion and count a fixed reason. No waiting for a slot. An eventually selected dropped attempt is expected to be unusable under overload.

Use a single scratch writer and reserve file count and maximum serialized bytes before creating a temp file. Cap receipt entries at 80 including the writer’s at most one partial, to bound directory enumeration and teardown, and receipt bytes at 15 MiB. Account for the nonce file, fake script, framing and filesystem allocation separately within the 16 MiB total cap. Keep the sealed index in the harness parent, outside scratch. This comes from 80 times 192 KiB and leaves 1 MiB of headroom within the 16 MiB scratch budget. Verify the selected filesystem allocation and include actual allocated file blocks when exercising the budget. Publish by same-directory atomic rename and sync file and directory. Keep readers unavailable after a suspected ambiguous commit until validated on next open. No links or unexpected files are followed. Use the runner’s hard deadline with a reserved teardown interval. An expired run closes admission and cannot seal. Stop and reap fixture children and the scratch writer before teardown. If reaping cannot be confirmed, leave the scratch directory for manual cleanup and mark the run inconclusive. Use a seeded wall clock for issued-at and expiry checks on reopen and every replay read, including rejection of missing timestamps or a clock earlier than issued-at. Use monotonic time only for process deadlines. Sweeps are explicit fixture calls. No polling or retry loop. No candidate survives pilot teardown by design, with crash leftovers limited to synthetic data. Exercise 24-hour read expiry as a fixture value and a one-minute simulated idle tick, without treating these values as deployed limits.

### Production carry-forward

Production remains outside the implementation scope. Before enabling it, require an operator-recorded source grant with expiry and revocation, an explicit policy for third-party material, real authorized workload size and rate evidence without content, and evidence of benefit after exclusions and expiry. The production review must justify retention and capacity within measured host and privacy floors and resolve multi-machine posture. Local-only production storage would require a valid taxonomy basis, such as a resolvable operator-ratified exception. Agreement to capture full benchmark inputs does not establish that exception. The production design must prove effective Git, dashboard, API, backup, OS sync and replication exclusions with synthetic markers and included positive controls, invalidate custody proof on relevant changes, and define bounded recovery and safe deletion-only behavior on revocation or custody failure.

## Synthetic acceptance checks

1. Send bytes containing multibyte characters, newlines, and a trailing blank line to a local fake CLI that reads stdin. Compare its bytes with the reopened receipt and an independently pinned digest. Reject one-byte corruption and receipt format mismatch before offline replay. Assert the pinned passing scorer result for reopened bytes and canned verdict.
2. Simulate synchronous throw, spawn failure, EPIPE, close before completion, callback and error races, successful write followed by invalid output, timeout and cancellation. Check that each fact reflects the observed boundary and provider delivery stays unknown. Compare normal and wrapped behavior in deterministic write-error cases, including settlement, error code and cleanup. Isolate any deliberately fatal test in a subprocess. Use the fixture-size and maximum-size payload with a slow reader, exited reader, and live child that does not read. Pin deterministic injected event order separately from platform-dependent OS pipe outcomes.
3. Exercise missing tone-gate provenance, retries, fallback to a different adapter, ambiguous selection, repeated IDs and crashes during publication. Verify attempt isolation and that incomplete records cannot become replay inputs. Swap two valid receipt files and require digest binding to reject them. Give two distinct dispatches identical bytes and the same attempt ID, with one failed and one finished write, and require rejection in either commit order. Include a conflict after the first file commits, a selected unrecorded fallback, and a complete receipt describing a failed write.
4. Test prompt content that mimics classification, selection and seal records and prove it has no control effect. Plant unique synthetic markers in credentials, maliciously shaped inputs, excluded fields and stdout or stderr. Inject classifier and scanner failures. Prove an excluded response echo, scanner failure, or unknown classification drops the whole receipt. Verify schema-listed out-of-scope fields are never retained. Search logs, API and dashboard projections, backup and replication inventories, and Git for the marker. Include a positive control proving each probe would detect an exposure.
5. Exercise wrong ownership, permissive modes, symlinks, caps under concurrency, queue overload, interrupted writes and idle and startup expiry. Verify that a storage failure preserves the normal tone-gate result and leaves only content-free telemetry.
6. Run replay through the fixture-only dispatcher with live discovery disabled. Prove that a receipt with unknown provider delivery is usable for local research and ineligible as evidence of exact model input.

7. Run eight serialized single-attempt supported correlations with one selected receipt each and require eight usable receipts before expiry. Run a separate overlapping retry workload with a deterministic barrier holding the first eight attempts while the ninth arrives, assert the deterministic capacity drop, and show a later attempt can reserve a slot after release. Include capacity and eligibility rejection controls with content-free accounting. This exercises capacity accounting and eligibility in the synthetic envelope. Production benefit is a separate measurement.


## Multi-machine posture

The pilot creates no deployed data or user interface. Its test artifacts are disposable and loss is handled by rerun. A production store has no approved locality or replication posture in this draft.

## Decision points touched

- **invariant** — Eligible route and known, authorized source classifications are required for collection. Uncertainty excludes capture.
- **invariant** — Local stream evidence alone determines whether a local write completed.
- **invariant** — Content restrictions, caps and expiry are enforced at admission and read.
- **invariant** — Qualification requires separate evidence of provider delivery.

## Frontloaded Decisions

Synthetic-only integration, trusted fixture manifest, explicit attempt selection, settlement-time snapshot, fixture limit arithmetic, and bounded one-shot custody are decided above. Production-source authorization, production caps and machine-local posture belong to a separate activation specification.
