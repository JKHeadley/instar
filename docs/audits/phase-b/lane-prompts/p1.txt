PROPOSED STANDARD UNDER EXAMINATION:
=== A check must say what it measures and what it certifies — and those must be argued equal ===
A test or check can quietly verify something NARROWER than the property it claims to prove. It passes; the pass is read as 'that property holds'; the gap between the two is invisible.
Concrete instance: a test named 'untrusted agents get no operations' whose only assertion is that the returned value is a list. If the code handed an unknown agent 'delete everything', the test would still pass, because a list containing 'delete everything' is still a list.
The proposed discipline: every check must state (a) what it measures and (b) what it certifies, and must argue those are the same set. The authoring-time question is: what input passes this check while failing the claim?
=== end proposal ===
