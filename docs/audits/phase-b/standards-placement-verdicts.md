# The five proposed standards — verdicts under Justin's placement rule

**Rule applied, verbatim:** complete overlap → discard · tight overlap → adjust existing · slight overlap (or a valuable explicit deep dive) → new tree node · no overlap → new root node.
**Second condition:** each must carry a real-world case study, attached explicitly rather than living in a ledger.

**Method.** The mechanical half — *for each proposal, every candidate overlapping standard in the registry* — went to 7 Codex lanes on the laptop with a return-step waiter (all landed in 330s). Each lane read **82 of 82** standards and was required to quote registry text rather than paraphrase. **The lanes were given the question and not the answer:** no lane was told the observer's priors, my expectations, or Justin's verdict categories. A control grep confirmed zero leading phrases in all 7 prompts. Verdicts and reasoning below are mine.

**Recall control.** An independent census lane enumerated all 82 standards, so a suspiciously small candidate set would have been visible. My priors were pre-registered on disk at 18:41:17Z **before** any lane output was read, so it is auditable which conclusions I formed and which I adopted.

## P1 — "A check must say what it measures and what it certifies" → **ADJUST, do not add**

**Overlap: TIGHT.** 29 of 82 standards touch it. Two already own the substance:

- **#29 Verify the State, Not Its Symbol** — *"never accept a **symbol** of that state (a string, label, marker, filename, or the mere presence/absence of a proxy signal) as proof the state holds."* The lane: the proposal's `is a list` assertion *"is the same shape as accepting a symbol/proxy for 'contains no operations.'"* Five of P1's seven instances are proxy-for-state failures.
- **#37 Testing Integrity** — already requires *"semantic-correctness tests for both sides of every decision boundary."* That is the two-sided rule, already ratified. The lane: it *"substantially covers"* the trust-boundary instance.

**What is genuinely new** is one clause, not a body of doctrine: that a check must **explicitly declare** its measured condition and its certified claim, and answer *"what input passes this check while failing the claim?"* Neither parent requires that declaration.

**The decisive evidence is the proposal's own enforcement section.** It states the `/spec-converge` gate *"already fires on this class — it raised it against this window's own spec five times **under Verify the State, Not Its Symbol**"* and that *"the change is scope, not machinery."* A proposal whose own enforcement plan describes widening an existing standard's scope is describing an amendment.

**Verdict: amend #29** — extend it from the detector's *subject* to the check's *own passing condition*, and add the pass-while-failing question as a fourth tooth, cross-referencing #37's both-sides clause. **This refutes the observer's prior** that measures-vs-certifies would survive as a genuine node. It survives as the sharpest amendment of the five.

## P2 — "Search by meaning, not word-matching" → **new tree node under #10, but BLOCKED**

**My own prior was that this was a discard. The lane refuted it.**

- **#10 Intelligence Infers, Keywords Only Guard** — *"A decision about what a human MEANT — their intent, their request... A keyword/phrase/regex list is NEVER the decision-maker for natural-language meaning."* Its object is **human-message meaning**. The lane: it *"does not police general repository, memory, document, or registry search."*
- **#11 Intelligent Prompts** governs LLM gate *prompts* only.

So the *principle* is ratified twice over; **P2's object — recall over our own stored material — is reached by neither.** That is a genuine application to an uncovered surface: a tree node under #10, not a discard.

**Condition 2 is not met, and it is answerable.** There is no proposal document. But the case study exists and is strong: on 2026-07-27 all **2,852** memory entries carried embeddings at 100% coverage while the recall path called keyword-only search — and the measured consequence was re-deriving a lesson I had written down **eight days earlier**. **Justin held this one "for lack of evidence"; the evidence exists and simply was never attached.**

## P3 — "Decisions written where no check can see them" → **new tree node under #7**

- **#7 Observation Needs Structure** — *"an observation without a required artifact is indistinguishable from no observation at all."* The lane: this covers the generic causal core — an inspection duty without unskippable proof *"can silently omit an entire population."*
- **Not covered:** source-language scope, decision placement, shims, parallel detector regimes. Enforcement verdict: **"No.** ... None enumerates source-language populations or checks blocking/refusal code."

**Verdict: a valuable explicit deep dive of #7 → new tree node under it.** I had guessed the parent was *A Dark Feature Guards Nothing*; the sweep did not even list it. **Condition 2 not met** — no proposal document; the case study (two guards sharing a defect because both are unwatched) exists in substance and must be written up, and it should carry the disclosed wobble that the count of twelve was right by accident.

## P4 — "Remove what demands attention" → **new tree node, but the family is wrong in both proposals**

Two standards own the *diagnosis*; **neither owns the remedy.**

- **#1 Structure beats Willpower** covers *"repeated drift despite knowledge/care, and the rejection of remembering or trying harder."* But: *"It does not say the architectural answer must be **deletion**; it permits gates, hooks, dispatch tables."*
- **#28 Distrust Temporary Success — A Recurrence Is a Root Cause** owns the trigger: *"the recurrence is the signal... Before declaring a thing fixed, verify the cause is gone."* But: *"It does not identify redundant copies or mandatory deletion as the root-cause remedy... **It permits any root fix.**"*

P4's three moves — count the copies, delete rather than synchronise, make the wrong state unrepresentable — are absent from both.

**Verdict: new tree node under #28, not #1.** #28 owns the trigger; P4 supplies the remedy for one class of cause. **And it cannot be a sibling to #1 at all** — the registry's own text says #1 is *"the founding lens... every other standard in this document is an instance of it."* A sibling to the founding lens is structurally impossible. **The proposal mis-placed itself and the observer's prior mis-placed it too**, in different directions.

**Anchor control.** P4's prompt carried the author's own filed objection, which primes toward finding a restatement. I ran a paired lane with that sentence stripped. **19 of 22 and 19 of 23 candidates agree, and both lanes independently surfaced both #1 and #28**; the seven differences are all peripheral. **The anchor did not move the core result.** Narrow claim only: this anchor named no specific standard. A stronger one might well have biased it.

## P5 — "Give the question, withhold the answer" → **new tree node under #29**

- **#29 Verify the State** — the lane, plainly: *"It does not say that the dispatcher's answer or hypothesis is itself forbidden input, nor that a checker should receive only the question. **A checker can receive the expected answer and still gather two apparently state-based signals.**"*
- **#37 Testing Integrity** — *"No requirement to conceal expected results, causal guesses, or locations from the testing agent; no question-only dispatch protocol."*

#29's tooth (B) isolates the sensor from its **subject**; P5 isolates it from the **requester**. Different contamination source, confirmed uncovered.

**Verdict: new tree node under #29.** **Not a child of P1** — the observer's prior. P1's failure is a *narrow passing condition*; in P5's crystallizing case the check was **correctly scoped** and still returned a wrong verdict, because the question was contaminated. Different axis, so P5 is P1's cousin under a shared parent, not its child.

## One honest note on my own instrument

My first run of the anchor comparison reported **"0 candidates in both"** — which reads as total divergence between the two lanes. It was a formatting artifact: one lane numbered its headings and the other did not, so every comparison was unequal. **The control could not have produced a match, and its failure looked exactly like a finding.** I caught it because zero-overlap was implausible, not because I checked. Normalising the headings produced the real answer, 19 in common. Recorded because it is this window's defect committed inside the control built to test for bias.
