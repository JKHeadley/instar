# Fake Codex Provider Fixtures Still Share Host Admission

Both internal-codex-account-room.test.ts and internal-codex-reset-first-lifecycle.test.ts create an owned temporary pool and fake shell binary, clear/restore CODEX_HOME, and reset the internal account-source callback. However, provider() calls the real buildIntelligenceProvider({framework: codex-cli, binaryPath: fakeCodex, ...}), then evaluates it. Neither fixture scopes os.homedir nor resets the host-spawn singleton. The factory wrapper therefore resolves the ordinary real-home host-spawn holders file before reaching the fake CLI. An owned pool stateDir and child login home do not scope host admission.

These are confirmed source-level coupling defects, not intentional native-provider smoke tests. The smallest fix is an owned scoped home before factory/singleton initialization, an explicit private holder-path assertion, and matching singleton/poller cleanup with spy restoration. Keep account routing, persistence, reset-deadline and actual fake-child assertions unchanged. Do not change real native-provider smoke admission. Do not broaden the already frozen three-file host-ledger test grant. No tests or live ledger probes were run for these findings.

A third member is tests/unit/intelligence-provider-factory-subscription-path.test.ts: its child_process mock and fake pool sit behind actual factory evaluate calls, while beforeEach only clears execFile. There is no home scope or host singleton reset. This provides a natural unit-tier companion to the two Codex integration/lifecycle findings, without changing the frozen running fixture group.
