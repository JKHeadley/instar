# Bounded-input derivation review — batch 2

One row per baselined site. "Converted" means the site now bounds through `src/core/boundedInput.ts` with its number derived beside it. "Exempt" means a `bounded-input-reviewed: <why>` reason on the line. Each row records the reading (who consumes the value and whether a cut can change their answer), not only the outcome.

## commands/server.ts, server/routes.ts, core (Resume, Seamless, Temporal), memory/TopicSummarizer — 11 baseline entries

| Site | Reading | Outcome |

| `commands/server.ts:text` | **Real defect, and a twin outside the lint.** A fresh session continues the conversation from this history, and the bootstrap's own rule is "inject the FULL context inline — no truncation". Each message was cut at 2000, but a Telegram message can be 4096, so a long operator instruction arrived half-cut with no sign. The primary path, `TopicMemory.formatContextForSession`, makes the same cut twice. That file does not build prompts, so the lint never saw it. Both paths now use `SESSION_HISTORY_MESSAGE_CHARS` (4096 + disclosure room). | converted (+2 unbaselined twins) |

| `commands/server.ts:snippet` | A dead helper's last message, typed into the parent session, which decides whether to retry. | `core/ResumeValidator.ts:text` | The 200-char per-message clamp is an input to the already-derived `COHERENCE_CONTEXT_MAX_CHARS` (4000). Ten in-line markers (~230 each) would overflow that bound and push out the newest messages. The header discloses the clamp, and a cut message carries a short ` …[cut]` tag (10 × 7 characters fits the bound), so an exactly-200 message is distinguishable from a cut one. The injected `getTopicHistory` path is not clamped per message; that block is tail-bounded and disclosed. | exempt (block-level disclosure + per-message tag) |
| `core/SeamlessOrchestratorEngine.ts:neutralize` | **Wrong direction for paths.** The preload ranker's candidate paths were cut from the head, dropping the file name, the part that identifies the artifact. Advisory ranker with a deterministic fallback, so it discloses rather than refuses. | converted |
| `core/TemporalCoherenceChecker.ts:truncated` | State documents the prompt calls the agent's CURRENT understanding, with BLOCK on contradiction. A cut later section was invisible, so its absence read as "nothing newer". **Direction matters here**: `reflections.md` is most likely an append-only log (no instar code writes it), and AGENT.md ends with its newest Identity History, so a head cut drops the newest understanding. The first version did exactly that, and the second pass caught it. It now uses a new helper, `boundedEnds`, which keeps the start AND the end with the disclosure in the middle. The configured bound is honoured, floored at that helper's minimum. | converted (new helper `boundedEnds`) |
| `core/TemporalCoherenceChecker.ts:summary` (2 decls) | (1) Timeline of up to 50 one-line entries cut to 120 with `...`.
