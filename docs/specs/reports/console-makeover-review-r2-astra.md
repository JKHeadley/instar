# Review round 2 — GPT-6 Astra (codex CLI), 2026-10-25

**Verdict: ready with changes.** A polished Home beside the unchanged default dashboard is a good 80/20 plan. The revised architecture is substantially simpler. The remaining problems are mostly specific data contracts and destinations, not reasons to redesign it again. This is a source review of the current spec and ELI16, not a live-phone acceptance test.

The round-1 security concerns are answered correctly. Ordinary links preserve `X-Frame-Options: DENY`; there is no longer a proposed relaxation to `SAMEORIGIN` or `frame-ancestors 'self'` (`src/server/middleware.ts:691`). The existing static mount covers the new directory (`src/server/AgentServer.ts:1243`). Reusing the existing same-origin bearer token does not newly share operator proof. Keeping that proof in memory is correct, and subscription repair really does request a fresh unlock when it is absent (`dashboard/subscriptions.js:1602`, `dashboard/index.html:10654`). I found no new security blocker in this revised approach. The full-query/hash adapter covering `tab`, `session`, and `path` also answers the earlier agent-link finding; implement its promised browser tests at cutover. The ELI16 accurately reflects these architectural changes.

1. **High — Two Home detail destinations do not contain the records being summarized.** The table at `docs/specs/console-makeover.md:97` sends attention items to Health, but Health fetches `/systems/status` and displays subsystem health, not `/attention` (`dashboard/index.html:10483`). With only three rows on Home, the rest of the queue would still have no readable destination. Likewise, Features reads `/features` and `/autonomy`, not the guard inventory (`dashboard/index.html:9088`). Guard details currently live under Machines' safety-checks tile (`dashboard/index.html:6514`), which is skipped when the pool is disabled (`:6505`). These links cannot fulfill the promise that each card opens its underlying detail.

   **Smallest fix:** add a simple read-only “See all” expansion for the attention records already fetched, with full text available on selecting a row. Do the same for guard records, or use the existing Machines drill where available with a single-machine fallback. Keep the three-row budget before expansion. Verify that every displayed count leads to its actual records; no new write workflow is needed.

2. **High — The chosen commitments query hides remote violations and does not establish complete, fresh mesh coverage.** At `docs/specs/console-makeover.md:99`, `/commitments?scope=mesh&status=active` looks suitable, but the server applies different filters: local active commitments include pending, verified, and violated (`src/monitoring/CommitmentTracker.ts:1203`), while remote replicas are filtered to pending only (`src/server/routes.ts:32802`). A violated promise on another machine therefore disappears from the very card meant to prioritize it. Also, the route can return `enabled:true` with only local records when replication is absent (`:32798`). Replica rows expose `viewSource`, `originMachineId`, and `stalenessMs` (`src/core/CommitmentsSync.ts:311`), none of which the contract lists. A successful poll does not make an old replica fresh or prove that every machine answered.

   **Smallest fix:** fetch `/commitments?scope=mesh` and apply the same active/expiry filter to all rows, or correct the server's inconsistent filter. Include replica age and origin in the view model with a stated freshness limit. Until completeness can be established, say “known promises; other-machine coverage unverified” rather than claiming an empty mesh or letting it justify “All quiet across 4 machines.” Test a remote violated promise, an old replica, and a known peer with no replica.

3. **High — The five-second client deadline races the APIs' five-second partial-result deadline.** The new independent rendering rule is good, but `docs/specs/console-makeover.md:91` still sets failure at five seconds. Both sessions and attention wait for peer calls with five-second timeouts before returning local successes plus failed-peer markers (`src/server/routes.ts:10980`, `:20288`, `:20402`). On a cold request with a hanging peer, the browser's clock starts first and includes network travel. Aborting at five seconds discards the useful partial answer. Repeating every 30 seconds can repeat that failure indefinitely.

   **Smallest fix:** give these two pool requests a longer transport deadline, such as eight seconds, while showing “Still checking other machines” at five seconds and retaining any previous data with its age. Keep the normal three-second target. Test a peer that hangs until the server timeout and assert that local results and the named peer failure eventually appear.

4. **Medium — The machine-state rules overlap, including for a known unreachable peer.** The mapping at `docs/specs/console-makeover.md:115` calls a recently heard-from, online machine “live,” but also calls it “unreachable” when `ropeCondition` is `peer-offline`. That combination is expected: the code explicitly preserves the conservative online flag after transport failure (`src/server/poolRopeCondition.ts:6`). A fresh overloaded machine likewise satisfies both live and struggling; an older overloaded machine can satisfy struggling and stale. Listing these predicates is not yet a deterministic mapping.

   **Smallest fix:** specify precedence and boundary cases. An explicit peer-offline signal must beat live; stale observations must not support a present-tense load diagnosis; healthy/live is the final case after adverse evidence is checked. Name the PR 2355 fields before accepting them as an override, or omit that speculative branch for MVP. Test the overlapping examples, absent timestamps, and exactly two/fifteen minutes.

5. **Medium — “Last tool use” is still the wrong label, and the activity source is local.** The revised wording at `docs/specs/console-makeover.md:111` fixes the initial-prompt problem but introduces a narrower factual claim than the data supports. `telemetry.lastActivity` is assigned `summary.lastEvent` (`src/server/routes.ts:10943`); that is the receipt time of the last hook event of any type, including Stop and SubagentStart, not necessarily a tool call (`src/monitoring/HookEventReceiver.ts:25`, `:205`). Also, the plain `/parallel-work/activities` in the pool-scoped card returns local topic activity; remote activity requires `?scope=pool` (`src/server/routes.ts:15164`).

   **Smallest fix:** label the timestamp “Last recorded activity.” For MVP, use local focus only for sessions on this machine and say when remote focus is unavailable. If using the existing pool activity route, preserve its replica/coverage information and join by machine as well as topic. Do not invent a latest action from either source.

6. **Medium — The phone navigation cannot meet its own two-tap criterion.** Nine tabs are under a collapsed section inside Settings (`docs/specs/console-makeover.md:133`). Reaching one takes Settings → expand Under the hood → tab: three taps, contradicting lines 139 and 189. This is a small fix, but a guaranteed acceptance failure as written.

   **Smallest fix:** make Under the hood a visible section heading with its tiles already shown on the Settings directory page. Scrolling is fine; an extra disclosure tap is unnecessary. Walk all 29 links at 360 and 390 px, including Back to the console and a legacy PIN unlock with the keyboard open.

7. **Low / optional cut — Defer the second theme if it delays the first useful screen.** A fully designed light theme is an additional MVP requirement at `docs/specs/console-makeover.md:69`, multiplying contrast and state checks across phone and desktop. It is not needed to deliver the stated dark Instar identity or the new operational answers. The earlier large sources of over-engineering—iframes, legacy reskinning, dynamic group summaries, and an unbounded critique loop—have already been removed correctly.

   **Smallest fix:** keep semantic CSS tokens and ship one polished dark theme first; add the light toggle after Justin accepts Home unless he specifically requires it for MVP. Keep the aesthetic acceptance bar, self-hosted fonts, and phone screenshots.
