## Findings

### F1: Quote admission must not prevent the intelligent emergency-stop arm from hearing the request

- **Classification / severity:** DESIGN / high.
- **Index reference:** P2 Signal vs Authority; P8 UX & Agent Agency; P20 Verify the State, Not Its Symbol; L11 External Operation Safety.
- **Source:** Current registry *Structure Decides Alone Only on an Exact Match* owns `stop = exact floor OR model`; *Intelligence Infers, Keywords Only Guard* permits the floor but forbids making it the only recognizer. *The User Experience Is the Product* protects the person's channel.
- **Spec trigger:** `Reservation, Recovery And Stop` gives only an **exact** authenticated stop priority before quote-source/signer admission. `Decision points touched` calls every decision an enumerable invariant. The boundary matrix tests only the exact-stop case.
- **Independent evidence:** In `mobileConversationRoutes.ts`, the exact fast path is handled separately from the later `deps.sentinel.decideInboundDisposition(...)` intelligent arm. The draft puts original visibility and signer checks before new quoted reservation and effects. A nonliteral genuine stop can therefore be refused for quote prerequisites before reaching the intelligent arm. Exact identity/ACL checks are enumerable; whether “halt everything you are doing right now” is a stop is not.
- **Contrasting cases:** Exact `stop` with no source/signer must still stop without a model. A contextually genuine paraphrase must reach the existing intelligent recognizer even when its selected source is unavailable. A quoted discussion of the word stop, or a scoped instruction about one build, must not be promoted to a global halt by a new keyword rule.
- **Required resolution:** Specify how the existing intelligent stop decision runs before quote-only admission can reject the request, while retaining the exact floor's unvetoable priority, current stop authority and idempotency. A recognized stop uses the existing stop action and adds no quoted append. Add both nonliteral-stop and ordinary-discussion HTTP boundaries, including missing source/signer. Do not invent another phrase list.
- **Deferral:** Not acceptable as a claim that the new reply action preserves stop priority. Resolve before implementation approval.

### F3: Inherited resource quotas remain judgment candidates, not proven exact safety floors

- **Classification / severity:** DESIGN / medium.
- **Index reference:** P8 UX & Agent Agency; P11 A Wall Is a Hypothesis; P25 A Safeguard Must Leave a Benefit; current *Judgment Within Floors*.
- **Spec trigger:** The draft inherits request/media/provider resource bounds, labels all decisions enumerable invariants, and specifically asks review to contest inherited limits. No resource-admission arbiter, evidence basis for exact values, or parent exception is identified.
- **Independent evidence:** `MobileChatRequests.ts` hard-refuses a device at 2,000 live request records, retaining each for its embedded time plus 24 hours 5 minutes. `mobileConversationRoutes.ts` separately hard-refuses the 21st send in a rolling minute. Neither observed source establishes that these exact numbers follow from an external provider constraint, enumerable identity domain, or irreversible-consequence floor. Finite resource protection is legitimate; the precise workload eligibility cut is not thereby proven.
- **Legitimate counterexample:** A permitted high-throughput app session on a healthy host can make its 2,001st distinct admitted operation while durable storage remains available; an ordinary permitted burst can contain a 21st short send. Neither is a changed actor, fabricated source or widened audience. The draft would inherit a refusal anyway.
- **Required resolution:** Document the actual governing parent authority/evidence if these are approved operational floors, or identify the resource decision's intelligent assessment within a deterministic safe envelope, conservative fallback and named owner. State the effect on quoted operations and how ordinary legitimate work recovers. Do not silently replace caps or launch a new resource subsystem; if this is an existing foundation defect, name and own that dependency and its disposition before representing every inherited decision as an invariant.
- **Deferral:** A reasoned explicit parent-floor/exception disposition is possible. “Existing” or “bounded by design” alone is not the required evidence.

## Benefit Survives The Walls

Same-conversation selection, the v3 proof, original ACL and private-proof redaction each protect different identity/disclosure failures. They do not duplicate one another: a valid signature does not grant source visibility, and current source visibility does not prove that a stored reference was originally selected. Their cost is unavailable quoting where source/proof cannot be established, while ordinary legacy sends remain available. That is a real benefit tradeoff, not zero utility.

Dedicated reply paths cost old-holder compatibility but prevent silent loss of selected-message intent. Reusing the App-link prerequisite costs a dependency wait but avoids a second conflicting source/navigation implementation. Fixed reservation/recovery prevents duplicate provider sends rather than requiring repeated human involvement. No new sandbox, practice-only allowlist or permanent user approval loop is added. The meaningful surviving benefit is one checked selected original per quoted send, with exact App navigation and current-reader preview; throughput and effort savings have not been measured. F2 prevents treating an indefinite unowned trial as completion.
