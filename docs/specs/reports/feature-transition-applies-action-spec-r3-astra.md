# spec review round 3 — GPT-6 Astra (codex CLI), 2026-10-25

**Verdict: ready with changes.** The action adapter, existing route validation, one stored result and separate operator proof are proportionate. Most earlier findings are resolved. Four remaining gaps concern what the operator sees, rather than requiring a different architecture.

Reviewed the current spec, ELI16, completed round-one and round-two reports, and working-tree code. References below are to the current working tree, including implementation edits. Validation was source inspection and isolated Node probes of the actual dashboard functions and state formatter; no full application or test-suite run.

1. **Medium — Threadline can still say plain “Off” when its environment override enables it.** With `threadline.relayEnabled: false` and `THREADLINE_RELAY_ENABLED=true` on an active machine, the relay bootstrap requests a connection (`src/threadline/ThreadlineBootstrap.ts:385`). The registry reads only the config key (`src/core/FeatureDefinitions.ts:25`), captures false at boot (`src/core/FeatureRegistry.ts:1001`), and formats the result as “Off.” (`:1410`). The isolated formatter probe confirmed this result. The revised reversibility note names the override, but there is no Threadline `honestyNote`, so the card's supposedly honest summary omits it. This is the unresolved part of the earlier consumer-alignment finding; correcting the action key alone does not fix the displayed claim. **Smallest fix:** make the plain off sentence explicitly about settings, with runtime unverified, and append a Threadline note that `THREADLINE_RELAY_ENABLED=true` can keep the relay enabled despite this switch. Name the literal value `true`; the current note's “if set” also incorrectly includes `false`. No connection-monitoring framework is needed.

2. **Medium — The consent dialog still contains false shutdown promises for other features.** Round two correctly fixed Threadline and Evolution System, but the same dialog now presents Publishing's “no new pages can be created” and Cloudflare's “Quick tunnels disappear immediately” (`src/core/FeatureDefinitions.ts:64`, `:97`; `dashboard/index.html:9225`). Publishing is constructed at startup (`src/commands/server.ts:12988`), and `/publish` checks the existing publisher, not the newly saved enabled flag (`src/server/routes.ts:24868`). The tunnel is likewise constructed from startup settings (`src/commands/server.ts:13020`). `PATCH /config` only replaces config fields and writes the file (`src/server/routes.ts:32233`); it does not stop either component. Thus the disclosure contradicts the spec's qualified restart wording. **Smallest fix:** qualify these undo notes with the restart requirement and check the remaining restart-dependent notes in the same pass. Keep the existing distinction between saved settings and actual shutdown; do not add lifecycle machinery just to preserve inaccurate copy.

3. **Medium — “Right now” stays stale after switching from the detail page.** Section 2.4 promises the same honest sentence on the card and detail panel. The detail panel renders `effective.summary` once (`dashboard/index.html:9310`). After a switch, `toggleFeature` calls `loadFeatures` (`:9268`), which refreshes only the autonomy card and catalog (`:9102`). The detail remains visible with its previous sentence, even after a successful change or a refusal. An isolated execution of these functions fetched the new summary while the visible detail HTML retained the old one. **Smallest fix:** remember the open feature ID and re-render that detail from the newly fetched feature after every completed or cancelled toggle. This also restores the checkbox after cancellation or rejection.

4. **Low — Evolution's read-only switch is still clickable in the detail view.** The catalog correctly disables it, but the detail checkbox has no `switchable === false` check (`dashboard/index.html:9319`) and derives its position from the old discovery fields rather than `effective.recorded` (`:9284`). Clicking it can prompt for a PIN before the server returns the intended 409 (`src/server/routes.ts:40136`). The server boundary works; the spec's promise of a read-only control is only partially implemented. **Smallest fix:** reuse `featIsOn`, `featToggleTitle` and the catalog's disabled condition in the detail view.

**Security assessment:** No new general Bearer privilege escalation found in the loopback client. The target address and port come from the accepted socket, and the action comes from the registered definition (`src/server/routes.ts:39979`). The four exact method/path pairs and refusal to follow redirects constrain where the server's token goes (`src/core/FeatureActionApplier.ts:49`, `:131`). Requests still pass the shared Bearer middleware (`src/server/AgentServer.ts:1397`), config allowlist and executable-selection fence (`src/server/routes.ts:2213`, `:32143`). The applier does not manufacture operator proof.

The operator bypass uses the real PIN-issued session and verifier (`src/server/AgentServer.ts:1299`, `:4601`); supplied invalid proof now gets an explicit renewal response (`src/server/routes.ts:40146`). The dashboard shows high-tier disclosures before submitting it and renews expired proof. Bearer-only callers retain the legacy graph, supplied consent record and challenge protocol; that protocol is not independent human proof, as the revised spec acknowledges. The documented file-viewer expansion is real: while disabled at boot, Bearer callers can now inspect settings, change allowed/editable paths and enable file access through the existing validated handlers (`src/server/fileRoutes.ts:518`, `:937`). The CSRF header is an intent check, not extra operator authorization. Caller-chosen `userId` remains a courtesy rule, not an identity boundary. These accepted limits do not need reopening as new findings.

**80/20 and Occam:** Keep the small HTTP adapter, per-feature queue and single nullable result column. The timeout qualification and telemetry's local-mutation reorder address the earlier ordering concern. Keep the removed retry endpoint and duplicate timestamp removed. The useful remaining simplification is to share the catalog/detail switch logic; none of these findings warrants a generic liveness service, dependency engine or durable retry worker.

DONE.
