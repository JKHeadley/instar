## ELI10 Overview

This test asks whether a project checklist decision that already made it to a second machine is still visible when the first machine is gone and the second starts fresh. It also checks that people who cannot see the test project still cannot see it. It uses two real test computers and a simulated owner device. A real-phone check and any change to who controls project records are separate.

## Original vs Converged

The procedure now matches one exact native event to the independent durable receive record and a fresh authorized Work view. It checks positive and negative access on the same restarted process. It treats an immediate stop as a separate observation and records the actual cutoff.

## Full Findings Catalog


### Round 1

**Verdict: SERIOUS ISSUES**

- **DESIGN — Witness protocol §4; Authorization during isolation.** The procedure opens B’s owner Work view before describing the restricted and revoked requests. It requires fresh requests and excludes client caches, yet explicitly says the server checks role before an **owner cache**. An empty restricted response therefore has two possible explanations unless the test establishes that the fixture was available to disclose. After B’s cold restart, capture a successful owner GET containing the exact checked item, immediately issue both negative requests against the same B process, and confirm the owner can still retrieve it afterward. Record the denial gate and metadata absence for each credential.

- **DESIGN — Maturation plan, graduation criterion.** The authorization section requires both a restricted credential and a formerly authorized phone. Graduation accepts a “restricted **or** revoked read outcome,” while the allowed outcomes include `unavailable`. A reviewer could graduate a run with only the restricted case, leaving revocation untested. Require a passing assertion for each credential, including evidence that B observed the former phone’s revocation. Record `unavailable` as a valid run result that leaves qualification pending.

- **DESIGN — Witness protocol §§2–3; Authoritative inputs and data handling.** The spec states that the tap ID is server-generated and instructs the reviewer to match the stream incarnation, sequence, binding revision and action fields across A and B. The inlined parent describes a binding HLC and an item digest, but provides no schema showing how to join the native action to a journal occurrence and its replica. The linked implementation is outside the supplied material, so whether that join exists remains unverified. Specify the read-only field mapping and uniqueness check, including which values come from the payload, journal envelope and receive frontier. If the installed version lacks a required identifier, identify that limitation in preflight.

- **PRECISION — Problem statement; Witness protocol §4.** The stated intervention stops and isolates A, then restarts B. Describe the measured condition as *origin unavailable during a cold survivor read*. That wording gives readers the precise failure boundary behind “real machine loss.”

- Conformance — Documents Stand on Their Own. The witness protocol requires the reviewer to distinguish an absent record from an unknown “receive frontier,” but it never defines the frontier or explains how it establishes which records B has received.

Disposition. Pinned cohort scope, exact occurrence semantics and both positive and negative read controls.

### Round 2

**Verdict: MINOR ISSUES**

- **DESIGN — Witness protocol, outcome labels.** The protocol allows `observed`, `unproven`, `unavailable` and `denied`. If a restricted phone receives the exact fixture between two successful owner reads, the test has observed a disclosure. `observed` alone leaves its meaning ambiguous, and `unproven` understates the result. Add a `failed` assertion outcome, record which credential and gate were tested using aliases, and make a forbidden disclosure explicitly fail qualification.
- **DESIGN — Authorization during isolation.** The owner reads bracketing the negative requests establish that B can serve the fixture. They do not establish that the *specific phone later revoked* could read it. The procedure calls that phone previously authorized and requires B to observe its revocation, but specifies no successful pre-revocation read by that phone. Require one signed GET returning the fixture from B before revocation. Bind that observation, B’s revocation record and the post-restart denial to the same device identity. This distinguishes loss of access from a phone that never had working access to B.
- **PRECISION — Witness protocol §5 and Maturation plan.** The development run requires both cases, while the graduation criterion enumerates only the positive-case evidence and access checks. Require the reviewed artifact to include the immediate-isolation probe’s outcome, even when its receive frontier is unknown. Its inclusion should be mandatory while its replication result remains observational.

The parent spec requires recoverable shared delivery before acknowledgment. The positive case here deliberately waits for B’s durable receipt before isolating A, so it answers the narrower survival question. That ordering fits the stated scope. This was a document review. The linked implementation was not inlined, and no runtime behavior was measured.

- Conformance — Judgment Within Floors. Independent recovery requires an isolated origin and a distinct durable survivor, but the exact two-machine roster rejects a valid three-member fixture whose third member is demonstrably unable to serve, repair or modify the item; a reviewer could admit that topology while keeping the isolation and evidence requirements fixed.
- Conformance — Verify the State, Not Its Symbol. The preflight can stop before the tap, yet `observed` is an allowed case outcome without an explicit rule binding it to the completed cold read and both access checks, so a consumer could mistake an observed intermediate fact for a successful qualification.
- Conformance — Documents Stand on Their Own. The witness protocol requires the reader to bind an `HLC` and verify a `contiguous applicable receive interval` without defining either term or explaining how to identify the interval for the action under review.

Disposition. Specified current authority, retirement boundaries, retained receive coverage, and exact event payload fields.

### Round 3

**Verdict: MINOR ISSUES**

- **DESIGN — Witness protocol §§2 and 5.** The positive case maps the phone tap to a server-generated `askId` in A’s journal because the HTTP response omits it. The immediate-isolation probe requires isolation before verification, then directs the reviewer to inspect B. It leaves out how to identify the exact tap if B has no matching row. Pin A’s pre-tap head, isolate A on success, then inspect A’s stopped home read-only while isolation holds. Use that occurrence as the comparison target on B. If A’s occurrence cannot be identified, record an unproven comparison even if B shows a checked item.
- **DESIGN — Authorization during isolation.** The spec requires a successful read from the phone later revoked. For the restricted credential, it requires a fresh signed request but permits an empty response as a passing result. The bracketing owner reads prove the fixture was visible. They do not establish that B recognized the restricted caller and evaluated its role. Require evidence that B authenticated that device as the intended restricted principal on the tested request before counting an empty result as a passing role control. If the installed route provides insufficient evidence, mark that assertion unproven.
- **PRECISION — Witness protocol §3.** “Missing or quarantined records … make this step unproven” leaves the scope of *records* ambiguous. The preceding sentence expressly allows an exact persisted event to establish historical custody despite incomplete surrounding history. Specify that a missing or quarantined **target occurrence** defeats the receipt assertion. An unrelated gap defeats a current-state or absence assertion only when it compromises the coverage that assertion requires.

The parent spec requires shared delivery proof before acknowledgment. This increment expressly leaves that gate open. Neither a new replication protocol nor an LLM judgment is needed to resolve these witness-procedure issues.

- Conformance — Judgment Within Floors. Independent storage and origin isolation justify requiring at least two physical hosts, but the preflight rejects a legitimate three-member installation even when the third member is verifiably isolated from the fixture, so a reviewer could judge topology equivalence within deterministic isolation and provenance checks.
- Conformance — Verify the State, Not Its Symbol. The procedure verifies current authority and source coverage but requires the owner GET before both negative probes without first proving that the ordinary reader’s bounded load admitted the exact item-check occurrence, so omission from all three responses can prevent testing either denial gate while leaving the cause of the missing owner result unknown.

Disposition. Verified actual loadUnion read path, observed revocation state, receipt frontier and immediate-case source mapping.

### Round 4

**Verdict: MINOR ISSUES**

- **DESIGN — Witness protocol §5.** The immediate-isolation probe stops A before inspecting its home, but gives B no observation cutoff. A signed batch already in flight could become durable on B during inspection. The parent’s *Cutover and recovery* test expressly excludes additional copying or repair after isolation. For this narrower probe, pin a read-only snapshot of B’s receive state at a recorded cutoff and compare the exact occurrence against that snapshot. Record the order of A’s success, isolation and B’s cutoff. If that order is uncertain, report only that B held the event by the observed cutoff. This preserves the probe’s value without attributing receipt to the instant of acknowledgment.

- **DESIGN — Authorization during isolation.** The spec correctly counts forbidden disclosure as `failed`, but its unknown-authority branch says to suppress collector output and report `unavailable`. If B’s ordinary GET already returned item data, redacting the artifact cannot establish that B withheld it. Check the authority prerequisites before issuing a content-bearing request. If a negative request runs, score its actual response first. Returned fixture metadata is `failed` for either negative credential. An empty restricted response without evidence of role evaluation remains `unproven`, as specified.

- **PRECISION — Witness protocol §3.** “An unreadable stream … makes exact receipt unproven” is broader than the same paragraph’s interval-specific gap rule. Specify which evidence must be readable to identify the target occurrence and its incarnation. A gap outside that evidence can leave historical receipt `observed` while defeating a separate claim about current state.

These findings concern the written procedure. The linked implementation files were not inlined, and no run artifact was supplied, so none establishes an observed runtime failure.

- Conformance — Judgment Within Floors. Preflight rejects every roster with a third enrolled writer, even when that writer is verifiably isolated from the fixture throughout the run; a reviewer could assess that topology while retaining hard requirements for independent storage, exact receipt on B, and exclusion of alternate serving and repair paths.
- Conformance — Documents Stand on Their Own. The opening relies on “Chief of Staff records” and an “item decision” before explaining the concrete action under test: an owner checks off a project item on one machine and opens it on another after the first goes offline.

Disposition. Added intended actor authentication, isolated target snapshot and no inferred global guarantee.

### Round 5

**Verdict: SERIOUS ISSUES**

- **DESIGN — Witness protocol §§3, 5.** The immediate-isolation probe allows a finding that the record was absent “under complete evidence,” but §3 requires complete head coverage to assert absence. If A’s tap is at sequence *n* and B has received only through *n−1*, the receiver frontier cannot cover the target. Yet an exhaustive inspection of B’s pinned, retained replica storage can establish that B lacked the exact record **at cutoff**. Define that local absence test separately. If retention or inspection is incomplete, report absence as unproven. Neither outcome establishes what B held when A acknowledged the tap.

- **DESIGN — Authorization during isolation.** The spec gives the restricted-device control an explicit pass condition. For the revoked device it requires “post-restart denial,” but only the restricted-device rule explicitly excludes project and item metadata from the response. An implementation could score a revoked request by its denial status while overlooking protected fields in its error body. Apply the same disclosure check to both complete responses, and require the revoked request’s denial to be attributable to the recorded revocation. A denial carrying protected metadata fails the qualification.

- **PRECISION — Witness protocol §4 and Authorization during isolation.** The revoked phone must first read the fixture successfully, while the cold B read must occur after isolation and revocation. The intended sequence is recoverable from several paragraphs. Put it in one ordered trace specifying which reads occur before B restarts and which owner request first exercises the cold process. This also makes the owner-cache negative controls reproducible.

The parent’s **Cutover and recovery** section requires immediate holder loss after shared acceptance and recovery of the exact mutation result. This increment explicitly leaves that stronger test open. Reusing the existing journal for the narrower observation is appropriate. The inlined material contains no run artifact or route implementation, so these findings concern the qualification procedure, not observed runtime behavior.

- Conformance — Judgment Within Floors. Independent durable storage and verified isolation justify requiring two physical hosts for this witness, but do not justify rejecting an equally isolated and authorized pair solely because it is not the named Studio and Mac Mini; a reviewer could select an eligible pair within the same deterministic preflight checks.
- Conformance — Self-Hosting. The fleet rung publishes the project's redacted result, while the qualification procedure remains restricted to project-owned fixtures, leaving users unable to run the same proof on their own agents.

Disposition. Adopted the approved two physical fixture hosts, simulator keys and separate real-phone acceptance.

### Round 6

**Verdict: MINOR ISSUES**

- **DESIGN — Witness protocol §5 and Maturation plan.** The immediate-isolation probe requires a pinned B snapshot, but gives no deadline for taking it after A is isolated. B could finish applying a batch already in flight before the snapshot. The spec correctly limits the result to what B held at the observed cutoff. The remaining issue is comparability: two runs can follow the procedure and sample B at materially different times. Define the cutoff as the first available consistent B snapshot after isolation, take it before inspecting A’s disconnected home, and record the elapsed time from isolation to capture. Keep receipt at acknowledgment unproven.

- **PRECISION — Authorization during isolation.** The ordered trace puts the soon-to-be-revoked phone’s successful GET before revocation and restart. Immediately after the instruction governing the first post-restart request, “First require a signed GET from that exact active fixture phone” can read as a direction to use that same phone after restart. Put the requests in one numbered sequence and name the credential at each step. The first cold GET belongs to the distinct, still-authorized owner.

The parent spec requires an accepted response followed by immediate holder loss and recovery of the exact mutation result. This increment explicitly leaves that gate open. Its positive case answers a narrower question: once B has independently persisted the exact occurrence, can an authorized owner see the checked item through B’s ordinary Work view after restart? The inlined material specifies that test but supplies no run artifact or implementation source, so it establishes no observed recovery result.

- Conformance — Judgment Within Floors. Independent storage and isolation justify requiring two physical hosts for this witness, but restricting qualification to the named Studio and Mac Mini rejects an equally isolated pair of enrolled test machines even when a reviewer can verify the same storage, authority, transport and isolation evidence.
- Conformance — Self-Hosting. The procedure is a tool for developing agents, yet its exclusive dependence on Instar’s approved test installations prevents users from qualifying their own agents on hardware they control.

Disposition. Bound both negative response bodies, holder isolation sequence and exact local absence. Cap accepts only the evidence procedure.
