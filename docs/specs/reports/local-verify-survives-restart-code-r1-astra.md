# code review round 1 — GPT-6 Astra (codex CLI), 2026-10-25

Verdict: not ready.

Reviewed `echo/local-verify-survives-restart`, including the uncommitted changes and new test file, against `docs/specs/local-verify-survives-restart.md`. Ran both requested diffs; `git diff origin/main...HEAD` was empty, so the implementation reviewed is in the working tree.

1. **P1 — A drift restart can swallow a stop request and leave the server unsupervised.** `src/lifeline/RestartOrchestrator.ts:86` and `src/lifeline/RestartOrchestrator.ts:140`. The first request wins regardless of its server policy. If drift enters first with `keepServer: true`, a subsequent watchdog, version-skew, or external-signal request is suppressed, and quiesce still only detaches. This changes the other restart paths despite the spec saying they retain their stop behavior. In particular, if SIGTERM comes from stopping/unloading the service, there is no successor to adopt the server: the lifeline exits and leaves it running unsupervised. A focused probe reproduced the external-signal request being suppressed while quiesce received only the drift request. **Smallest fix:** let any competing request requiring a server stop override `keepServer`; honor that override before exit even if detach has already happened. Test both arrival orders and a stop arriving during persistence.

2. **P1 — `detach()` does not stop supervisor work already in flight.** `src/lifeline/ServerSupervisor.ts:486`. Clearing the interval prevents future ticks, but an existing `runHealthTick()` awaiting `checkHealth()` continues afterward. It can still process restart requests or enter recovery, and an already scheduled recovery timeout at line 2248 can still kill the tmux session. Setting `isRunning = false` does not fence those paths. A probe paused a health check, detached, then resolved the check; both unhealthy-server evaluation and restart-request processing ran after detach. During quiesce/persistence, this can still kill the verify the change promises to preserve. **Smallest fix:** invalidate a supervisor lifecycle generation on detach, check it after awaits and before recovery mutations, and cancel outstanding recovery timers. Add a pending-health-check and pending-retry regression test.

3. **P2 — Normal boot ordering can bypass the interruption alarm indefinitely.** `src/localVerify/LocalVerifyService.ts:1053`. `checkStarved()` considers only queued entries and runs only from `tick()`. After boot, the status reconciler immediately observes main; `noteMainHead()` reaches `enqueueMain()` and `pump()`, which starts the interrupted PR before the first 30-second service tick. The PR has left the queue by the time starvation is checked. The same ordering can repeat after every restart. A probe restoring `interruptions: 2, resumeFirst: true`, then calling `noteMainHead()` before `tick()`, produced an active PR and zero signals. **Smallest fix:** evaluate restored entries for starvation before any can start, such as at the end of restoration before releasing the restore guard. Test the actual boot ordering, not just boot followed immediately by tick.

4. **P2 — The second unclean exit drops the entry before raising its promised alarm.** `src/localVerify/LocalVerifyService.ts:718`. With `errorAutoRetries: 1`, the first unclean exit consumes the retry. On the second, restoration increments interruptions to two, then writes an error record and discards the entry at line 727. It never reaches `checkStarved()`, and the new interruption count is not retained in the queue. A probe restored that exact state and observed an empty queue, a `server-restarted` error record, and no starvation signal. **Smallest fix:** evaluate and emit the interruption alarm before the retry-budget drop, while retaining the existing bounded retry policy. Add a test spanning two unclean exits; the current test covers only the first.

5. **P2 — A new PR head inherits the previous head's “already alerted” flag.** `src/localVerify/LocalVerifyService.ts:1002`, interacting with the new per-head signal key in `src/localVerify/localVerifyWiring.ts:44`. The head-moved path preserves `starvedRaised` through `keptPlace`. Once head A has raised an alert, head B is created with `starvedRaised: true`; even two interruptions of B cannot raise its own attention item. This contradicts the new contract that a new head is a new episode. The latch transfer predates this patch, but must change for the new per-head alert contract to work. **Smallest fix:** reset `starvedRaised` when replacing a different head, preserving queue position and waiting time. Test that A and B can each emit once.

6. **P2 — The promised E2E restart lifecycle is absent.** `tests/e2e/local-verify-lifecycle.test.ts:107` and `tests/unit/lifeline/drift-restart-keeps-server.test.ts:48`. The added E2E test directly invokes the private `onStarved` seam with a fabricated interruption count, then boots an empty service. It never stops a run, restores it, or reaches the second-interruption decision. The lifeline wiring tests inspect source text; none drives drift through quiesce and then verifies successor adoption and continuing supervision of the same server. Consequently all added tests pass despite findings 1–4. **Smallest fix:** add the specified two-stop lifecycle through `buildLocalVerifyService`, with main observation before the first tick, and a behavioral lifeline handoff test asserting that the server/verify survives and the successor monitors it. Include the competing-restart and in-flight-health cases at unit tier.
