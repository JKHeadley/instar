## Durable Creation Contract

Add optional `creationContext` to the App `created` event:

```
{v:1,

 parentConversationKey?: canonicalConversationRef|null,
 parentBasis?: "explicit"|"source"|"project"}
```

Person sources contain no device identity. Work-board sources require their exact card id; session sources require their create request id. Optional source/project references are recorded context, never standalone authority. Durable parent identity is app:<uuid>, telegram:<positive-topic>, or the registry's stable Slack key slack:<team>:<channel>[:thread], not a mobile negative alias. Normalize bare App UUIDs. Persisted Work Board context is a PURE function of the immutable created-record bytes and origin: for any noncanonical Slack alias, every writer preserves the raw bounded source+origin but omits a durable parent identically. Do not resolve through a local registry while persisting that same-ID event. Legacy alias resolution occurs only in read projection/preview. Preserve original bounded source/project strings as provenance even when an older Slack locator cannot yet be resolved. Resolve mobile or legacy Slack locators only through existing read-only registry lookups plus recorded origin-machine scope; never mint or equate equal negative aliases on two machines. A legacy unqualified alias without a unique recorded-machine mapping is unresolved. Parent existence, access, tree precedence and cycle comparison all use the same resolved durable identity. Use current protocol/reference bounds, not truncation. Unknown enum/invalid references reject the new context; absent context remains valid legacy data. Source kind and producer ids are server assigned, not an arbitrary client claim. This metadata contains no conversation text or credentials.

Store the validated object in one nullable JSON column of the derived conversations index; add the column idempotently. The canonical JSONL remains the durable source. A missing column in an old index becomes null (legacy unknown), not fabricated provenance. Rebuild and replication preserve context. Context follows the deterministic earliest created-event tuple `(at,machineId,eventId)`; a legacy winning created event keeps context unknown. This does not change the existing conversation-owner winner or grant access. A mismatched/conflicting record is unavailable, never a placement claim.

The base digest contract is byte-exact: normalize eventKind from wire to logical kind=created; canonicalize the conversation key to app:<uuid>; hash UTF-8 bytes of the literal prefix `instar.app-created-base.v1\n` followed by JSON.stringify of `[canonicalConversationKey,eventId,"created",title,at,machineId,ownerPerson?[ownerPerson.machineId,ownerPerson.userId]:null]`. Use values from the validated normalized created event; absent ownerPerson becomes null. Exclude creationContext, ingestSeq and replication envelope fields. Do not mark a companion record committed before normal journal durability establishes it. The original canonical source/outbox may repair a missing companion, but never overwrite a conflicting signed record automatically.
