# Review of the Studio project purpose pilot

## Plain-language overview

The draft prepares a single Studio conversation to recover the owner's exact purpose as advisory context. The proposal uses an original verified Telegram message. Display requires separate direct permission for that exact disclosure. The draft has no production grant. The current operator-session flow remains responsible for confirmed purposes.

## Original versus reviewed design

The first design trusted a private local designation file. Review showed that agents and the service share a user account, so ownership and file mode cannot establish operator permission. The design now requires a reviewed release grant for one exact machine, project, destination, source reference, and wording digest. The production default has no grant. A retirement marker in persistent agent state also prevents a retired grant from becoming active after application rollback.

History is checked at startup, outside the recovery request deadline. Live recovery checks the current grant, verified owner, binding, confirmed-revision floor, retirement state, and exact staged packet. Codex also proves that the caller holds the current live session's token. Ordinary registry and diagnostic reads receive no quote.

## Targeted seventh pass closure

The cross-model reviewer closed the owner-account and Claude fallback findings. It found that the Codex fixture invoked the retirement callback before checking the current session token. That meant a wrong hook credential could trigger retirement and still produce ordinary context. The reviewer identified a gap in test evidence. No runtime disclosure was found.

The Chief of Staff authorized a fixture-only correction and accepted a focused retest, with no eighth review. The new negative control ran the generated hook with a signed token for the same name and topic from a different incarnation. At 10:36 p.m. Pacific it failed before the fix because the wrong token reached the retirement callback. After the fixture moved that callback behind the successful credential check, all four focused Codex lifecycle cases passed. The wrong-token run received ordinary context and could not trigger retirement. The correct-token run reached retirement, received ordinary context without the quote, and left the staged packet unchanged. The distinct Claude generated-hook test passed and also omitted the proposal while providing ordinary recovery.

## Fixed bounds and rollout

The pilot inherits the existing bounded Telegram lookup for its startup proof. A source that cannot be resolved leaves the proposal unavailable. The deployment preflight measures the exact approved source through the deployed adapter. The calling hook has a three-second request deadline. Each of the two parallel optional tmux reads has a 500 ms timeout, leaving the rest of the existing deadline for the server, packet checks and fallback. The designation is one small metadata object. The 2 KiB limit bounds synchronous reads while admitting the full object including ordinary formatting. Tests exercise a valid designation at the bound and an otherwise identical oversized file.

The approval scope is one Studio conversation. The development pilot and its rollback receipts must be verified before broader rollout is considered. The current draft makes no change to practice folding, in line with the existing pause instruction. Remaining fleet work stays with Jobs and Projects.

## Convergence verdict

Converged for the disabled draft after six review rounds and the one authorized targeted closure pass. The final external verdict was minor issues, limited to the Codex fixture proof documented above. The Chief of Staff accepted the passing red-to-green control as closure. Parent-principle fit passed. The advisory conformance output still notes the pilot's startup snapshot, inherited scan and short I/O limits, deployment to one machine, and separate fleet graduation. The draft stays inactive.
