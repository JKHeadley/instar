# Review round 4 (visual) — GPT-6 Astra (codex CLI), 2026-10-25

**Verdict: close.** The photographed design is now visually credible for MVP. The navy ground, faint grid, crab, tight Inter headings, teal navigation and restrained translucent cards clearly belong to the supplied instar.sh reference. Desktop has a convincing primary/secondary hierarchy; Settings has comfortable phone targets and a clean, visible Under the hood section. The reduced amber wash and corrected heading spacing make a substantial difference. Styling alone would no longer stop me calling this MVP. Two remaining uncertainty-presentation defects prevent an unqualified production-grade verdict.

I reviewed the four supplied screenshots, the four console source files, the plan and both reviewers' rounds 1–3. The phone Home capture includes an expanded promise; that extra height is purposeful disclosure. The fixed navigation appearing mid-capture is not a layout defect. Differences in live counts and machine health are not defects. The state examples below are isolated evaluations of the current view-model code, not claims that the pictured live data is wrong. No application code was changed or live-browser acceptance performed.

Ranked findings and smallest fixes:

1. **High — A partial queue loses its known urgency in the headline. MVP blocker.** In `home-model.js`, `buildNeeds()` returns `state: 'partial'` and `valueTone: 'attn'` when a peer fails, even when observed items need action. `headline()` counts only `state: 'attn'`; `console.js` also ignores `valueTone`. A direct probe with one URGENT item and one failed peer produced a “1 thing” card but **“Nothing urgent that I can see.”** This is the unresolved edge of round 3's hierarchy/honesty finding. **Smallest fix:** preserve the known action count independently of coverage in `buildNeeds()` and `headline()`, and use the same rule in `paintHeadline()`. In `paintCard()`, honor `valueTone` for the number while retaining the dashed partial treatment and peer explanation. Add a targeted `.card-value .n.attn` colour rule in `console.css`. The headline should say that one known thing needs the operator and qualify the incomplete coverage.

2. **High — Promises can still turn unverified coverage into “All quiet.” MVP blocker.** The pictured “partial view” label and dashed stale note are good. The branch producing them is incomplete: `buildPromised()` considers coverage sufficient as soon as any replica origin exists and none has a numerically old age. A replica with no `stalenessMs` produced `state: 'ok'`, no coverage label, and an **“All quiet.”** headline when the other cards were healthy. One fresh origin also does not establish that every expected machine is represented. **Smallest fix:** in `home-model.js`, treat absent/invalid replica ages as unknown and retain `coverage: 'partial view'` while completeness is unverified. Reuse the existing `.card-age` and `.card-note` markup for “Other-machine coverage unverified”; give replica rows “age unknown” when needed. This needs no new endpoint or visual component. It closes Astra round 2 #2 and round 3's still-open coverage finding.

3. **Medium — Machine freshness remains unnecessarily faint and crowded on phone. Non-blocking polish.** The first machine now correctly shows both load and age, but “struggling · 2.5/core · just now” becomes a dense, low-contrast tail. `.m-age` and `.m-load` still use `--text-faint`, unlike the corrected row metadata elsewhere. **Smallest fix:** in `console.css`, set `.machine .m-age, .machine .m-load` to `color: var(--text-muted)` and 13 px. At phone widths, put `.machine .m-age` on a second right-aligned line; remove its leading separator in the corresponding `paintCard()` markup. Keep the machine name and state on the first line. This completes the previous evidence-legibility fix without adding a column.

4. **Medium — Repainting preserves disclosure state but discards keyboard focus. Source finding; verify in acceptance.** `paintCard()` replaces the entire `.card-body` and `.card-foot` on each refresh and on “See all.” An open row stays open, but its focused button is removed. Keyboard users can lose their place immediately after expanding the list or during the 30-second refresh. **Smallest fix:** in `console.js`, give row controls stable keys and footer controls stable action identifiers; before replacing children, capture whether a control inside this card owns focus, then restore focus to its replacement with `preventScroll`. Do not move focus when it was elsewhere. Verify expansion and one timed refresh with the keyboard. This is a small completion of the existing interaction-preservation requirement.

5. **Low — Touch-target enlargement is only partly complete. Non-blocking polish.** Card links now have 44 px height, but “Open” still has only its narrow text width plus 4 px padding. The top Legacy chip is 40 px high. **Smallest fix:** in the phone rules in `console.css`, add `min-width: 44px; justify-content: center` to `.card-foot a, .card-foot .link-btn`, and make `.topbar .chip` 44 px high. The existing header and footer space can accommodate this without lengthening the page.

6. **Low — The safety meter still contradicts the revised warning colours. Non-blocking polish.** The “off that should be on” rows are now amber, but their meter segment remains red through `.meter .m-bad`; off-by-design remains striped like unknown coverage. That weakens the otherwise disciplined state vocabulary. **Smallest fix:** in `buildAllowed()` and the meter markup in `console.js`, give these segments explicit warning and intentional-off classes; in `console.css`, use amber for the former and solid subdued slate for the latter. Watching-only can use a lighter amber shade. Keep the existing counts and accessible meter label.

Earlier-round plan issues still open:

- **The incomplete-data contract is not fully implemented.** Findings 1–2 above are the release-relevant remainder. In addition, `buildAllowed()` validates only five summary fields while defaulting other fields used in its totals to zero, including `onStale`, `onBlind`, `offRuntimeDivergent`, `errored` and `missing`. A probe omitting those fields still produced a healthy “1 of 1 on.” Validate every required field used in the displayed total, or explicitly establish which omissions the source contract defines as zero. A failed guard read also still discards a successful mandate read; retain that known result beneath “Can't tell” for guards. These are the outstanding details of Astra round 1 #3, Argon round 2 #4 and Astra round 3's contract finding, despite the Review changes table marking the broader work accepted.
- **Phone/browser acceptance remains outstanding, as the plan acknowledges.** The lifecycle test exercises the server and view models, not DOM interactions. Record the existing 360/390 px acceptance checks: PIN with keyboard open, group links and Back, full row disclosure, “See all,” focus/open-state preservation across refresh, and partial/stale/failure appearance. The supplied captures support the aesthetic judgment; they do not establish those behaviors. No additional critique round is needed.

The earlier architecture and scope problems are closed in the revised plan: ordinary legacy links, separate PIN-gated actions, visible Under the hood links, uncapped inline lists, dark-only MVP, and inventory-gated legacy removal. The old query, timeout and activity-label drift has been reconciled. Query/hash preservation remains a gate for the later route switch, not a blocker to the console beside legacy. Fix the narrow honesty gaps and complete the already-planned phone acceptance; the remaining visual polish does not warrant holding MVP or reopening the design.
