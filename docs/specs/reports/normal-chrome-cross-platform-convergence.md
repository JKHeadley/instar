## ELI10 Overview

Some web jobs have to be done as a particular signed-in person: reading a usage page, changing a setting, finishing a sign-in. Account pages often treat an automated browser differently. Instar had two proven ways around that, built separately: Echo's on the Mac (small pieces of code run inside a normal Chrome window) and PP's on Windows (real mouse and keyboard input, the page read the way a screen reader reads it). Justin asked for them to become one method every Instar agent has.

This change makes one skill with one set of rules and a short section per operating system, ships PP's Windows driver exactly as reviewed and live-tested, and puts every Instar-side rule for Windows into the small wrapper agents call it through. The wrapper also solves a problem the live test found: on the operator's Windows machine, Instar runs inside WSL in a background Windows session that cannot see the desktop at all, so the wrapper hands the driver to the desktop session through Windows' own task scheduler.

The main trade-off: a browser a site cannot tell from a person's is powerful, and on Windows the input is genuinely a person's input. So the rules are explicit about what that may and may not be used for (the actions the operator asked for; never answering a human challenge; never faking presence), the wrapper enforces what it can (never the operator's own Chrome, never a flag smuggled in, never taking focus from someone using the machine unless the operator recorded that nobody is), and the two live tests bind "it works" to the exact bytes shipped.

## Original vs Converged

- **The Windows driver stays byte-identical to its tested bytes.** The first draft planned a header edit and an `F5` key in `native-drive.ps1`. Reviewers in every family said the shipped file must be the tested file. Now nothing in the driver changes; every Instar addition lives in the wrapper, which has its own live test, and reload uses the driver's existing `ctrl r`.
- **The wrapper became the enforcement layer, not a convenience.** Originally `ndrive.sh` only translated a WSL path. Review found the driver accepts any directory, any url and any executable, so the wrapper now refuses the operator's default Chrome profile folders, non-local or malformed paths, quote smuggling, flag-shaped urls, non-`chrome.exe` executables; scopes the binding file per agent; honors the "take focus anyway" override only against a recorded, dated operator declaration; runs `canfocus` before `invoke`; and logs every call and refusal content-free.
- **WSL is Windows for this skill, and session 0 is bridged.** The first draft said "Linux is not built", which would have told an agent in WSL on a Windows machine to give up. Now the skill names three cases (macOS; Windows natively or from WSL; Linux with no Windows underneath), and the Mama PC live test's discovery that the WSL shell has no desktop led to the interactive-desktop bridge.
- **Faking presence stays out; what real focus may do is decided.** PR 2283 said the operator brings the window forward. On Windows the driver can bring the bound window forward for real on an idle machine. The spec now says exactly when that is allowed (an operator-asked action, an idle machine) and what stays forbidden everywhere (synthetic presence signals, calling the endpoint behind a control, editing the DOM, answering a presented human challenge), and draws the passive-scoring vs active-challenge line the driver's own header did not.
- **Updating an agent's edited skill copy never clobbers it.** The first draft left edited copies untouched, which the constitution gate flagged as manual work. Now an untouched copy is replaced whole; an edited copy keeps every edit and gains the shared rules and the Windows section, with the full shipped text written beside it, and the new rules are stated to win over any older conflicting instruction.
- **The CLAUDE.md card is replaced only when it is exactly the shipped text.** Review found the first in-place replacement would have swallowed bold-led sections that follow the card and would have re-duplicated after a release revert. Now only an exact shipped v1 section is ever removed, wherever it sits, in CLAUDE.md and the shadows, CRLF-tolerant; an edited one is kept and the new card added beside it.
- **The Windows rules an agent had to remember became wrapper refusals.** Rounds 4 and 5 kept finding instructions the skill asked the agent to hold in mind: never a tokened URL on argv, confirm the page before every click, read before retrying after a timeout, outfiles on a local path, one driver at a time even after a kill. Each is now a deterministic refusal in `ndrive.sh` (`ERR secret-shaped-url`, `ND_EXPECT_HOST` → `ERR expected-host-mismatch`, the unknown-outcome latch, `ERR bad-outfile`, the orphan guard with its survivor record), each with its stated windows.
- **Verdicts are bound to bytes.** "VERDICT: PASS" alone proved nothing about the shipped files. Now the gate requires the reports' SHA-256 values to equal the shipped `native-drive.ps1` and `ndrive.sh`, enumerates every outcome (hash mismatch, non-canonical verdict, one run per distinct hash (plus one plan-defect re-run on the same hash) with only the final bytes deciding and a five-run cap, BLOCKED with a tracked re-test, no report in three hours), and a bridge timeout is reported as an unknown outcome rather than a clean failure.
