# Adversarial Review — Round 2 Resumed

Reviewer: independent inherited Codex agent. This is a source/spec review, not executed exploit evidence, implementation approval, or cross-family review. Read the resumed draft, its current conformance report, round-one adversarial/external findings and ledger, actual signature/reservation/send/storage code, and the sibling App exact-link client. No tests, external calls, source edits or messages were performed. Only this report was written.

## Findings

### A2-1 — DESIGN / High — Bind quote evidence to the replying base identity, not just the original and destination

**Concrete contract/source evidence:** The frozen v3 array in the draft Storage And Receipt V3 section signs canonical request hash, receivedAt, signing machine, destination and replyTo. It does not explicitly sign the replying eventId/messageId or require their reconstruction before accepting a witness. The new evidence wrapper targets a reply base by messageId and treats the complete witness as its attestation. Existing `src/core/AppRecordSignatures.ts:260-342` verifies device/body/receipt facts but does not verify a stored replying eventId/messageId against the signed request; its VerifiableRecord input does not carry those fields. Existing App send IDs are derived from deviceId and requestId in `src/server/mobileConversationRoutes.ts:965-968`; provider-backed stored sends use a different seed including payload hash in `src/server/mobilePairingRoutes.ts` near storeMessageId/storeEventId. Redacted bodies intentionally do not retain the request bytes from which requestId could otherwise be recovered.

**Attack:** Copy one complete legitimately quoted record and its unchanged origin/receipt/redaction into a different reply eventId/messageId in the same conversation, keeping its text, destination and replyTo unchanged. Its device signature and specified v3 payload still verify. A matching forged base plus deterministic quote-evidence witness is internally consistent under the draft's duplicate comparison, because both copied identities agree. The result can appear to be a separately authenticated quoted reply, outside the fixed reservation, or supply quote evidence to a same-text base that the signer did not attest. The deterministic evidence hash deduplicates an identical wrapper; it cannot detect this changed-base replay because the copied witness has a different hash. This is an attestation/identity gap, not a need to expand authority or rotate keys.

**Resolution:** Require quote verification to bind BOTH replying base eventId and messageId to the original admitted operation. Choose and freeze one complete approach before implementation: include those identities (or a canonical immutable-base digest covering them) in v3 signed bytes, or require authenticated deterministic reconstruction for every supported route and redacted representation. Do not rely on a local reservation existing on a replica. Match evidence to the exact reply event as well as its public messageId; a repeated public ID must not choose an evidence target. Preserve unquoted v1/v2 compatibility separately. Add same-destination changed-base replay tests for exact and redacted messages, evidence-before-base, both arrival orders and rebuild, with real ledger/key history. No claim is made that the present production verifier newly introduced the underlying unquoted weakness; the new quote-proof contract must not promote that weakness into valid quote evidence.

### A2-2 — DESIGN / High — A paraphrased authenticated stop must reach the existing classifier before quote-only refusal

**Concrete contract/source evidence:** The draft explicitly exempts only an *exact* authenticated emergency stop from source/signer admission. `src/server/mobileConversationRoutes.ts:990-1000` uses `isExactStopMessage()` as the fast path, while `:1142-1154` invokes `sentinel.decideInboundDisposition()` later, after normal preparation/persistence. Therefore a new quote-original or signer refusal inserted before that existing semantic classifier prevents it from seeing a non-exact stop. This independently supports the second conformance flag; it is not an assumption that every stop-like sentence is a stop.

**Attack:** An authenticated person uses Reply and writes “halt everything you are doing right now” while the selected original is no longer readable, its source is temporarily unmeasurable, or the quote signer is unavailable. The proposed new action returns 404/409/503 before the existing sentinel can recognize the emergency. An operation that the person ordered stopped can continue solely because their composer retained quote metadata. Requiring the person to repeat an exact token is an additional semantic blocker, not an enumerable quote-identity floor.

**Resolution:** Retain the exact fast path, but explicitly define how the EXISTING authorized stop/pause classifier receives authored text before quote-only blocking preflight. Reuse its current authority, trusted sender attribution, stop scope and one-operation idempotency; do not introduce a new keyword heuristic or treat caller-supplied reply metadata as a stop grant. When it confirms a stop, execute the existing stop path once without a quoted append or original disclosure. A classifier non-stop/unknown answer continues ordinary quote admission under existing failure policy. Test exact, paraphrased, negated/quoted stop text, and classifier failure with missing original/signer; do not blindly promote every phrase to stop. Audio-only semantic recognition remains limited by actual transcript availability and should not be fabricated.

### A2-3 — PRECISION / Medium — Distinguish quote revalidation reads from unchanged incremental event cursors

**Concrete contract/source evidence:** The current-reader section correctly requires clearing cached previews on focus/reopen and forbids displaying an old preview while revalidation is pending. Its instruction to refetch visible history pages “using existing cursors” can still be implemented incorrectly with the ordinary append-only events cursor. The prerequisite client in sibling `conversation-creation-context/dashboard/console/chats.js:2052` requests `/events?...cursor=...`, and its applyResult handles only returned events near `:2124-2127`. An original ACL change without a new reply event yields no replacement row for the cached reply. The sibling already has exact target reads and generation checks; this spec should reuse those rather than imply that an empty delta revalidates old content.

**Resolution:** State that successful empty incremental sync does NOT authorize a previously cached quote. Revalidation must obtain a current projection of each still-visible reply, through an actual history/point read with current reader checks, before restoring its preview/IDs. Existing history cursor use can position that read; it cannot substitute for rereading the reply. Keep the current clear-before-await rule, and test stale page plus empty delta plus revoked original, including foreground resume and failed/offline revalidation. This clarifies D12 rather than adding another polling service.

## Independent Contest Of Conformance Signals

1. **Multi-machine complete-proof custody:** The draft now deliberately retains complete evidence when it arrives and truthfully marks total old-codec loss as partial/unknown. That resolves the round-one unspecified-arrival-order problem in principle. The conformance flag correctly identifies a remaining transferable-proof substrate limitation, but does not by itself require a new all-member commitment protocol inside this bounded increment. Keep the separately tracked gap and partial compatibility visible; do not claim fleet-ready relation preservation or origin-offline recovery. My new A2-1 addresses a distinct exact-base attestation hole even when complete evidence survives.
2. **Exact-match stop:** Supported as A2-2, with the counter-boundary that the existing classifier decides semantic stop intent, not structural keyword expansion.
3. **No competing suite runs:** The unqualified phrase is too broad if read as a global exclusion rule. Treat as PRECISION / Low: name normal per-host/shared-resource admission and ownership; an independent idle host is not automatically forbidden. No additional test run was started by this review.
4. **Maturation dark window:** The report raises a genuine incompleteness in release evidence planning, but an arbitrary new soak duration or numeric quota would not fix it. Treat as PRECISION / Medium for this adversarial lens: name an existing owner/review trigger and concrete evidence required to decide each rung, including current-source/cached-revocation and provider/replay proof. Until then do not call the rung graduated. This is not a reason to claim current source approval.
5. **Weak parent fit:** Retained as an advisory. Exact identity and honest unavailable states directly serve the person selecting Reply; actual native placement/wording proof remains with the app owner. No surface approval is inferred from this server spec.

## Boundaries With No Additional Material Finding

- Closed caller selectors and server-derived physical namespaces reject fabricated author/quote/source-conversation input.
- Current actor, key ledger/person reassignment, source ACL and destination rechecks after media/routing awaits are explicitly required. Completed retries must retain those current checks; the testing section already names reassignment across a completed retry.
- Fixed reservation proofs and immutable replyMirror plus existing ambiguous-provider no-resend behavior address the earlier recovery wording; key rotation must verify fixed historical proof rather than mint a new admission.
- Evidence wrappers are non-recursive and grant no trust; evidence-before-base waits, conflicting *valid* evidence yields unavailable, and invalid/unknown evidence cannot supply a readable original. No separate evidence-cycle fix is needed beyond enforcing the declared closed witness kind.
- Typed App event identity and the merged sibling dependency prevent a shared public messageId from redirecting the original. Provider links remain a separately owned increment, so this draft no longer claims Instar governs provider membership at open time.
- Whole private proof stripping and unavailable output without source IDs/text/author/filename remain necessary, including the nested witness; an origin-verdict label alone is not authority.

## Verdict

Not yet a clean adversarial pass. Resolve A2-1 and A2-2 as design decisions; clarify A2-3. The prior findings and limitations remain preserved, and this report does not authorize implementation or release.
