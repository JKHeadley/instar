# codex-cli confirmation ok gpt-6-astra SERIOUS ISSUES
**Verdict: SERIOUS ISSUES**

Reviewed only the inlined spec and Round 9 summary; referenced implementation and architectural documents were not supplied.

- **DESIGN — “The PC checks the agent” / “Connection, liveness and revocation”: reconnect authorization is incomplete.** The spec requires the home machine to deliver the initial phone-signed grant after the handshake, and says owner-signed records expire after 10 minutes. It also promises unattended reconnection after weeks offline. It never distinguishes initial grant acceptance from subsequent authentication using durable authorization. A literal implementation would reject the expired grant on reconnect; repeatedly applying it would also conflict with later order numbers and modes. **Resolution:** specify that initial grant acceptance durably establishes the pairing. Subsequent connections authenticate pinned keys and use persisted authorization, without reapplying the grant. Define recovery behavior when that durable state is missing.

- **DESIGN — “Protecting the mode from the agent”: file validation occurs too late for network paths.** The specified sequence opens the requested path and then validates the resulting handle. The allowed scope is files “the person can reach”; UNC/network paths and non-file Windows namespaces are not excluded. Opening a caller-selected network path can initiate authentication before the post-open credential-location check. Thus Look only can cause credential-bearing network activity despite its restrictions. This is a design exposure, not an observed exploit. **Resolution:** define permitted path namespaces before opening anything. Default Look only to local regular files; reject network/device paths before opening, and retain handle-based checks afterward. If network shares are required, specify explicit permitted destinations and authentication behavior.

- **PRECISION — “Calls from other machines”: clock tolerance weakens the stated deduplication proof unless carefully scoped.** The spec rejects calls older than a newly created deduplication store but also allows five minutes of clock difference. It does not say whether that tolerance applies to the store-creation boundary. If it does, recently executed calls could be admitted again after store loss. **Resolution:** make the post-loss boundary strict, separate it from ordinary clock-skew handling, and test a replay immediately after store recreation.

The restricted extender identity and single-home architecture are clearly motivated. The remaining problems concern protocol lifecycle and filesystem semantics, rather than a need for more approval flows.
