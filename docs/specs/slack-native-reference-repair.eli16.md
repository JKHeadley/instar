# Slack references in agent replies

The Slack formatter treated every angle bracket as ordinary text. That made an agent's deliberate `@person`, channel reference, or Slack link appear as raw syntax, with no notification to the person. This repair recognizes only the specific native forms for one Slack user, one channel, and a safe web or email link when the agent explicitly adds `--native-reference TARGET` for each intended target to its bound relay command. Ordinary replies still escape them. It keeps Slack's broadcast forms, including `<!channel>`, `<!here>`, and `<!everyone>`, as literal text. Code examples are also kept literal. Links still need an allowed scheme, so a crafted unsafe URL does not become a clickable link.

The agent sees Slack history before replying. History used to label other speakers by their raw IDs, even when Slack could supply their names. The context builder now resolves each distinct speaker through the existing Slack user lookup and displays the person's name. It also encodes incoming message text before putting it in the agent's prompt. A copied incoming reference therefore remains data in an ordinary reply; the agent must explicitly list the intended Slack ID or URL on the relay command and write its native reference to notify someone. References to other targets stay literal, even when quoted in the same reply. The current sender's name, the thread destination, and delivery routing remain the same.

This is a reversible code change with no stored-data migration. The normal Slack formatter remains the rollback lever. A live post in Echo's isolated test Slack workspace demonstrated an active self mention, channel reference, and link while the broadcast tokens and a code example remained literal. The bot mentioned itself so no person was pinged by the test.
