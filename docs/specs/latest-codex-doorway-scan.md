# Packaged doorway scan migration

## Problem statement

The packaged launch default reads the reviewed Codex catalog. The installed recurring doorway scan and the read surfaces still assume a source checkout in places. An earlier migration draft would also enable an old disabled job when its schedule matched a shipped default. The old record cannot establish why it was disabled. This slice makes the scan runnable from installed releases while preserving operator choices and delivery continuity.

## Proposed design

### Installer and update

Use the existing built-in installer from both init and post-update. Seed a missing job with the daily 04:00 local default and keep it dark until authorized enablement. The cadence is a template default, so the existing job scheduling control can change it. Preserve each valid existing manifest's active schedule, enabled state and disable marker across update and repeat update. This includes a legacy disabled record without a marker, an enabled weekly record matching its old template, and a custom cadence. A malformed or unreadable record is a configuration issue. Keep it out of automatic enablement and surface the issue through the installer report so an operator can review it. A new default never overrides the existing kill switch or a recorded disable. The supported authenticated job control remains the way to enable an existing job.

### Package trust and live configuration

Resolve the wrapper, the prober and the reviewed catalog under the installed package root associated with the running server. The scheduler's existing script check establishes wrapper integrity. Extend release build integrity evidence to bind the prober and catalog, including any bundled local executable imports, to the existing signed Instar release lock. Only the fixture entry point may substitute a test verifier or run unsigned. An installed production run with absent signature evidence is unavailable. Validate stable package paths and bytes before execution. Use the verified bytes or a release path that the runtime cannot substitute after validation. Reject paths outside the package, unexpected symbolic links, missing assets and digest mismatches. The package test must show which bytes execute. A path string from the environment or current directory cannot establish executable authority. Keep the fixture prober override confined to the existing isolated canary entry point.

The scheduler owns the absolute state directory and the INSTAR_JOB_RUN_ID. Bind both and the verified asset paths after any generic environment overlay, and reject other attempts to supply them. Read the kill switch from that directory's authoritative config immediately before scheduled probes. A definite disabled value returns a disabled status and starts no subprocess. An unreadable or malformed config returns an explicit unavailable status and also starts no subprocess. The production scheduled argument accepts free probes only. This migration carries no recurring paid-probe authority under the existing doorway registry specification. The existing strict catalog freshness lint remains independent of scheduled reachability checks. Keep the legacy manual invocation's separate scope and consent rules. Use the existing bounded script runner and scrubbed result contract. Package integrity failures produce a failed job result rather than a fallback run against a project file.

### Observations and delivery

Write scheduled observations atomically to `<stateDir>/state/doorway-scan-scheduled.json`. Keep the existing manual file and its acknowledged delivery baseline separate. The scheduled projection records machine ID, start and completion time, and clamped doorway reachability. Bind success evidence to the scheduler run ID and the just-produced observation. Persist the attempt start in the scheduler run ledger before spawning the wrapper. A whole-run failure is job-scoped evidence. Persist each doorway start against that run ID before its probe. Doorways without a start record remain unattempted even if their run timed out. Preserve the prior observation timestamps for both interrupted and unattempted doors. Distinguish actual admitted attempts from disabled, busy, or backoff skips. A skip starts no attempt and cannot invalidate newer genuine observations. Record timeout, subprocess failure, and interrupted-start recovery there even when the observation file was never written. Store output by exact run ID. The previously committed observation stays accessible until a validated successor is committed by the scheduler ledger. An uncommitted row cannot overwrite the historical reading. Retain only the referenced committed and in-flight artifacts plus the existing bounded diagnostic history. Prune an artifact only after no ledger cursor refers to it. The reader reconciles the latest durable run with the separate last observation and marks an incomplete or newer failed attempt unknown for current reachability. Before recording a completed run, the scheduler independently reads and validates the durable row for that exact job run ID and machine. An old file, a process exit code or a scope log alone cannot prove freshness. Scheduled writes must use the scheduler's per-job execution custody or a single-writer fence when run admission can overlap. Manual and new scheduled observations may overlap without sharing writes. During transition the legacy scheduler and manual process still share one file. Require one common cross-process fence for both callers around legacy observation and baseline writes, acknowledgement and handoff. Disable admission of legacy entry points that bypass the fence before checking the last active writer. Keep that admission closed across snapshot, transfer and rollback. Reopen only the execution profile that owns the new generation. Refuse replacement when any older entry point cannot be revoked or a stale writer cannot be drained. A scheduled observation never advances the manual delivery baseline.

The package-backed reader and observation canary can ship independently. The installer keeps the existing execution profile for every previously enabled job until the development custodian signs off on equivalent package-backed delivery outside a source checkout. That approval is not inferred from release installation, a normal run, run-now, restart or rollback. The same profile gate applies to each entry point. Never ship a release that replaces an enabled non-source scan before the new packaged execution and notification path passes the legacy-enabled, no-checkout case. A replacement that sends scheduled notices must use its own machine-qualified delivery baseline, advance it only after a durable acknowledgment, and keep pending changes visible on retry. One writer owns the delivery generation. Persist a machine-qualified per-notice key and require recipient or delivery-store deduplication or an authoritative acceptance lookup by that key before a retry can duplicate delivery. Persist the acceptance receipt before moving the baseline. On a transport without keyed deduplication, an absent receipt does not authorize retry. Require proof that the prior send completed with definitive non-acceptance or that it was revoked before it could be accepted. An in-flight or unknown result remains pending. A transport with no durable identity remains on its legacy delivery profile. At cutover, the legacy writer must settle a shared-file notice whose ownership is ambiguous. Transfer a notice only when durable custody names a single old writer and the transfer atomically moves the pending cursor, notice keys and accepted receipts to the new writer. Under the same fence, initialize the new scheduled delivery baseline from the settled legacy acknowledgment and commit it with the new generation. Do this even when no notice is pending. The first new probe must compare against that baseline, so it cannot re-announce an unchanged finding or consume an intervening change. The resumed manual writer cannot adopt transferred keys. Reverse handoff must reconcile the current acknowledgment and pending notices into the legacy generation under the same fence. If that state cannot be represented or acknowledged safely by the older path, keep legacy admission closed and surface the unresolved rollback. A restart must resume the same owned generation. A quiet projection by itself is read evidence and does not fulfill the existing delivery contract. Preserve the original enabled path during migration until the replacement passes the delivery proof. New or previously disabled jobs remain dark absent the normal authorized enablement path.

Use one safe process-cached verified packaged catalog in the registry reader for the authenticated `GET /doorways` route and capability projection. The verified packaged catalog holds reviewed model IDs and remains the routing authority. Read the two observation stores separately. Accept a row only when its probe enum is explicitly recognized, its independently resolved machine identity matches this host, and its attempt and completion timestamps are plausible and finite. An actually attempted probe may legitimately report a malformed provider response. Missing or malformed stored rows, free-scope skips and failed collection are not valid reachability evidence. Persist the last actual observation and latest attempt as separate per-door records. Report both with source and timestamp, and expose the latest attempt outcome separately so timeout, subprocess failure, interruption, and missing evidence remain distinguishable. Preserve the earlier observation timestamp on failure and across restart. Accept a local wall-clock ordering only when the run starts no later than completion and completion is no later than server read time. A host clock discontinuity or equal timestamps with conflicting outcomes leave freshness unknown unless an independently ordered run identity resolves the tie. Distinguish disabled or never-observed from failed or stale status. A partial run cannot make carried-forward observations appear fresh. On a newer failed attempt the prior reading remains historical, with current reachability unknown, unless a newer valid probe supplies it. Reuse the existing bounded request and job timeouts. With a valid enabled cadence, mark an observation stale after the first scheduled occurrence following its completion plus the configured execution timeout. Derive that occurrence from the same cron expression and timezone as the scheduler, including custom schedules, and recompute it when cadence changes. Without an enabled cadence show the last observation as historical and scheduled freshness as unavailable. The manual delivery baseline is excluded from this read. Missing or malformed live evidence remains unknown with a provenance marker. If no verified packaged catalog exists, make the catalog unavailable explicitly. Do not silently substitute checkout data, synthesize model IDs or promote observations into routing decisions.

## Decision points touched

- Preserve pre-existing schedule and enable state — invariant; basis: irreversible-consequence; evidence: Enabling a job based on ambiguous legacy metadata can run work the operator stopped.
- Verify executable assets and config scope — invariant; basis: external-constraint; evidence: The built-in release trust root and the scheduler state directory are the authorities for the executable bytes and live kill switch.
- Accept and read observations — invariant; basis: enumerable-domain; evidence: Known catalog doorway IDs, bounded probe statuses, matching run identity and complete observations define the accepted read data.
- Advance the delivery baseline — invariant; basis: irreversible-consequence; evidence: A baseline advanced without an acknowledgement can consume the only record of an undelivered change.

## Multi-machine posture

Equivalent releases carry the same reviewed catalog. Every response identifies the machine that supplied the observation. The existing capability projection supplies machine-qualified reachability to peers. The local observation stores are recoverable caches, with distinct machine identities and no cross-machine write authority. Delivery identity stays machine-qualified through retry.
machine-local-justification: physical-credential-locality — a reachability observation describes the authenticated providers and CLI installation available to that machine.

## Frontloaded Decisions

1. Preserve any existing valid schedule and enable state. Missing job records get a dark default.
2. Verify shipped executable and catalog assets against the release trust root. Bind live settings and output to the scheduler's authoritative state directory.
3. Use a separate scheduled observation file and leave the manual delivery baseline writable only by the manual path.
4. Keep existing scheduled change alerts until equivalence evidence exists for a replacement. A scheduled success requires run-bound durable output.

## Verification

- Unit installation matrix covers missing, invalid, disabled with and without a marker, enabled at the old shipped cadence, custom cadence, repeat install and a recorded master opt-out in a missing-manifest scenario.
- Unit runner and scheduler tests check package root confinement, symlink and digest refusal, absent packaged asset, executable bytes, a fixture-only prober, and another project's working directory. Supply a different state directory with the kill switch off, on and unreadable. Assert child starts and observations, not just return strings.
- Unit state tests use controlled overlap. Seed a manual pending change that would produce a notice, run the scheduled probe during delivery, then verify manual state and its pending notice are unchanged. Confirm manual delivery advances only its baseline and failure retains it.
- Integration covers package-backed `GET /doorways` and capability projection in an agent directory with no checkout scripts. Verify newest verified observations, machine identity and absent and malformed data. Assert unsupported IDs cannot enter the catalog via observations.
- Lifecycle independently installs the tarball into a fresh or upgraded agent outside the source tree. Run a scheduled job through the production scheduler using a deterministic provider fixture, inspect the new run-bound observation, and verify no model session was created. Reopen the server and verify the same projection and disable state are read from disk. Exercise an enabled legacy manifest outside a checkout. At cutover, fail a legacy delivery, interrupt before and after receipt, restart, and verify exactly one writer retains custody while the manual baseline is unchanged. Cover newer skipped, wrong-machine, future, and partial-run rows against a valid earlier manual observation. Also cover a successful scheduled run followed by a timeout before the wrapper writes anything and restart with an empty manual store, a crash after a new run writes its file but before ledger commit, a timeout after one doorway starts and before the next, unchanged and changed first probes against the migrated acknowledgment, a stale-boundary virtual clock with changed cadence, a manual writer during transfer, a stale unfenced caller starting after the active-writer check, rollback to the older profile after an acknowledged and an unacknowledged packaged notice, and a crash after recipient acceptance but before the sender records the receipt, delayed acceptance after a receipt lookup, and conflicting equal-time outcomes in both file read orders.

## Maturation plan

- **test-agent-live:** Audit the actual packaged files and test in a throwaway agent with a deterministic provider fixture.
- **dev-agent-live:** The engine owner verifies the machine-qualified registry and scheduled run on an authorized development install, including the first failed-delivery retry across restart. The release verifier independently reviews package identity and written evidence before authorizing replacement of an enabled execution profile.
- **fleet:** Ship the installed reader and dark scheduled defaults through the normal release. Preserve intentional existing enables and disables during upgrade. The implementation registers the execution-profile ladder. The registered ladder reads machine-checkable evidence and surfaces qualifying or overdue evidence automatically to the existing weekly review. Two independent readings must agree the profile can advance. That review opens the reviewed promotion, and the release verifier records the outcome. Before authorized activation, a fresh install reports observations as not yet collected. The catalog lint tracks reviewed model age and does not measure reachability. The [standing doorway standard](../STANDARDS-REGISTRY.md#keep-the-doorwaymodel-map-current) explicitly specifies “A recurring, dark-by-default, cost-aware scan job” in the registry snapshot at revision `ddfbb8fd4ad2195064a9aa507d08c5a20e539749`, so graduation makes the supported job available for authorized activation and does not turn it on.
- **graduation criterion:** Independently verify package bytes, scheduled output that matches the run, no model turn, delivery retry parity, and preservation of prior settings.
- **dark-window:** A new or missing recurring job is dark. Existing enabled jobs retain their existing path pending replacement evidence.
