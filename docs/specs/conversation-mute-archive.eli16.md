# Quiet A Chat Or Put It Away Without Losing It

Muting a chat should stop its reply notifications for you. Archiving a chat should remove it from your usual list while leaving it in an Archived view where you can open or restore it. These are personal choices: they do not mute or hide a chat for someone else, delete its messages, or stop an agent session. New messages do not quietly undo your archive choice.

The server will remember mute and archive separately and share those choices between your agent's computers. The apps will receive those settings with each chat and can offer the right menu actions. A chat whose identity or current settings cannot be verified will say so instead of using another chat's choice. Your existing permission to read a conversation remains the boundary.

Notifications need particular care. Today a delayed push can become an anonymous summary, losing which chat produced it. New queued reply activity will retain its conversation identity so the server checks mute and current access immediately before sending, on both iPhone and Android. Account, approval and document notices stay separate, so muting a chat cannot silence a critical notice.

An older anonymous summary already saved before the update cannot be assigned to a chat honestly. It stays a generic summary rather than being deleted. If a saved summary exists, or another delivery computer cannot be inspected, the app tells you that an older summary may still arrive. It also distinguishes a choice saved locally from other computers still syncing, rather than promising that an offline older computer has already become quiet. Newly queued replies follow the new mute rule.

This work is authorized as the second parity server card. The app owner still implements and proves the actual menus, Archived view and notification behavior in a named native build. A server pull request or a passing API test alone does not mean the feature is live. Complete verification follows the shared queue, and the card remains open until the real mute, archive and restore journey is demonstrated.
