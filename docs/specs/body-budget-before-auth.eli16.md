# The server no longer reads big uploads from strangers (ELI16)

The agent's server is reachable from the internet through its tunnel address, so anyone who learns that address can send it requests. Before this change, the server read and decoded the whole body of every request, up to 12 megabytes (32 on one recovery route), before it checked whether the sender had any right to be there. A stranger could send many big requests at once and make the server spend memory and time decoding data it was about to refuse anyway. A broken body also made the server log a long error trace every time, as if it had crashed.

Now the server looks at the sender's credential first, which it can do without reading the body: the agent's key, a dashboard or memory session, or the id of a paired phone or machine. Those senders keep the full size limit. The few public addresses where other machines and agents talk to this one, and check their own signature inside, get 2 megabytes, far more than their messages need. Everyone else may send at most 64 kilobytes. A bigger declared upload is turned away before a single byte of it is read, and an upload with no declared size is cut off at the limit. A broken body now gets a short "invalid-json" answer and one log line instead of a crash-style error.
