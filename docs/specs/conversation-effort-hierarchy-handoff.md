## Outcome to ship

The owner opens Conversations in the dashboard or app and sees one plain headline and at most five named efforts/front doors. Only a decision, conflict, or relevant partial-data cue appears on a tile. `All` and search reach every worker transcript; `More`/`Updates` reveal summaries, provenance, and correction tools on demand. The owner can move with preview and undo and resolve a conflict. Telegram and Slack remain original conversation stores and deep-link destinations. Owner-scoped chat status is delivered only to a verified private or explicitly authorized audience; shared chats get a neutral app pointer. Routine worker updates change a digest without flooding parent chats.

**Visual integration:** Conversations must feel native to each host. Use the installed console's semantic tokens from `dashboard/console/console.css`: navy `--bg`, translucent slate `--surface`, `--text`/`--text-muted`, teal `--accent`, amber `--attn`, Inter typography, hairline cards, rail, dialogs, and visible focus states. Its light theme uses the same semantic tokens through `data-theme=light`. Use the mobile app's existing list, chat header, sheet, Back behavior, and light/dark theme components; verify those components against the actual app build before implementation rather than importing dashboard CSS into the app. The standalone sample demonstrates behavior and uses the installed console semantic colors in standalone fallbacks, but its CSS is not a new product design system. Compare rendered states with current app/dashboard screens before beta; reject a denser or visually separate screen.

## Authority boundaries

| Concern | Authority | Hierarchy behavior |
|---|---|---|
| Work status | InitiativeTracker / TaskFlow | Link an effort to a work record; do not rewrite status. |
| Conversation routing and identity | ConversationRegistry and platform adapters | Use typed Telegram `(chatId, topicId)`, Slack verified workspace plus `(channelId, threadTs?)`, or native app UUID. Never route by graph label or local alias. |
| Original history | Telegram observed capture, Slack/native app stores, source work record | Render the existing transcript and Instar-authorized source links. Telegram Bot API has no general history backfill; replicated observer-time segments preserve what Instar saw. Topic history is useful context with explicit coverage, not assumed platform-complete. |
| Placement and relation | New graph source event file | One primary parent in a mixed effort/conversation forest, typed cross-links, user corrections, and causal conflict state. |
| Personal view state | Principal-scoped preference authority | Collapsed branches, filters, and pins change only a person's view; they do not enter the shared graph event file or grant access. |
| Digest and decisions | Replicated, viewer-scoped derived cache and source-backed decision transitions | Build from visible source messages after privacy filtering; store coverage, citations, freshness, and verified-versus-reported status. Only source-backed open decisions get a committed Overview cue; an explicit observed owner question can show a distinct `Question` source cue while a sleeping peer blocks the transition. Never reuse global TopicMemory summary in a limited view. |

## Build order

1. **Dark storage/projection.** Add a versioned text-free event core, separate signed authorization receipt, and a final `commitCertificate` binding the membership epoch, all durable member receipts, and an independent `GraphCommitWitness` proof. Every member persists that certificate before success. Bind to `WriteAdmission`, signed lease history, and a signed installed-machine membership epoch. Fsync source and final certificate on **every installed machine** before reporting success; a sleeping member keeps the edit pending. Provision an independent witness before enabling corrections. An owner-authenticated recovery ceremony can decommission/replace a dead or stolen member using a surviving source/backup, fence its old epoch, and reconcile pending keys. Add journal/outbox repair, deterministic event-set reducer, source-level authorization, and a narrow signed dispatch/spawn `delegates-to` ingress. Put unlinked-effort title/outcome text in an erasable side store. Typed source/header erasure tombstones, per-item erasable keys, and source-to-derived dependencies cover captured segments, generated rollups, structured quotes, indexes, backups, and cache. A forget action is locally suppressed immediately but reports fleet-wide completion only after all installed members apply it or an authenticated membership transition removes a lost member.
2. **Dark read-only Conversations.** Add a hierarchy API that filters authorization before count, search, cursor, digest, and link generation. A cursor uses a short-lived authorized result snapshot, not the whole graph revision. Dashboard requires ordinary bearer **and** operator session proof; owner mobile uses signed device identity. The default Overview is one column, one headline, five tiles at most; a selected desktop item may use two panes. Phone detail hides list/search above the transcript and Back restores the originating screen/scroll. Keep flat routes intact; MSP keeps only authorized flat data. No decision cue yet.
3. **Manual corrections.** Add placement from All, relate, front-door choice, unlink, undo, conflict resolution, and personal Archive with the finite operation table in v3. Compare observed subject heads, not global revision; unrelated work does not conflict. A standby dashboard owner re-unlocks on the admitted machine. After witness-durable intake, a known sleeping member shows `Saved · Waiting for MacBook`, an owner read-your-writes overlay shared through the pending-list API, and witness-certified Cancel before commit; certified moves offer Undo. An ambiguous transport result uses status lookup and successor reconciliation, never a blind retry. Move of a certified front door remains refused until a replacement or clear is certified; the queued change alone is insufficient. Dismissal keeps a discoverable Pending entry; a real Cancel needs an all-member cancellation certificate and loses to an already committed move, which can then be undone. Probe the live inventory before making the tree owner-facing; if roots remain sparse, wait for D's suggestion review.
4. **Digests/decisions/suggestions/notices.** Refresh from source changes, dedupe primary-edge rollups, and replicate viewer-scoped digest versions. Persist typed source-backed decision transitions and offer Answer/Dismiss in the source sheet. Answer collects content/choice, previews audience, acquires one witness-wide claim for the exact occurrence and dispatches through a single durable `AnswerSendGateway` before sending, and hides the cue only after confirmed send plus witness-durable pending transition. A successor reconciles uncertain delivery from the gateway ledger and platform when possible; a missing message alone never proves not-sent, and only positive fenced no-dispatch proof permits another automatic attempt; an undeterminable send becomes `Answer needs review`. A delivered answer whose transition cannot certify becomes `Answer needs linking` with the sent ref; no automatic resend or silent reopening occurs. New agent asks emit typed requests automatically. Legacy high-confidence prose gets a non-notifying `Possible decision` cue by a deterministic rule; ambiguous prose is a candidate for review. Stable occurrence IDs separate multiple questions in one source; a time-bound pending source question can use one-voice notice and `Question` attention. Keep `evidenceCoverage` separate from screen-level `replicationState`. Use machine/store inventory and `catchUpReadProofs`; Telegram capture uses one fenced poller, durable source+independent witness before offset confirmation, and explicit outage/visibility gaps; recovery uses observed segments, while Slack may fetch history only when scopes, retention, pagination, and rate limits are verified. Keep worker claims separate from outcome-specific evidence; commit does not prove merge/deploy. Render offsets, name missing coverage, and keep generated rollups out of their own evidence. `All` provides optional suggestion review and per-item batch results. Five-tile overflow, unassigned decisions, and budget-exhausted notices remain discoverable. Pilot real topics before broad hiding or auto-placement.
5. **Audience-safe chat access.** The adapter binds the destination audience **before** any service read puts owner content in model context. A shared session gets only a neutral pointer capability; a private owner-bound session or structured renderer can read owner detail. Normal Telegram/Slack groups and unknown-audience topics receive only a neutral authenticated-app pointer; v1 rich chat reports use owner one-to-one DM or app. Corrections start as pending proposals and commit only from a same-owner, adapter-verified Telegram callback or Slack interaction bound to current subject heads; LLM text cannot confirm.

## Acceptance evidence required

- **Replay:** Different event arrival orders yield the same accepted event-set hash, heads, conflict state, and canonical tree. Include two incompatible owner heads, an agent event later than a user move, missing causal parent, duplicate ID with changed payload, forged owner label, mixed-authority and same-tier cycles, valid delayed old-epoch delivery, and a fenced new write. A local retained snapshot is labeled separately from the canonical revision.
- **Durability:** Restart after local fsync but before journal emission; an unwitnessed event stays pending. Acknowledged writes have a separate durable witness and **every installed machine's** durable receipt; permanently lose the writer and recover the highest acknowledged tail locally. A sleeping installed peer blocks success until it repairs or an owner-authenticated, fenced membership transition excludes it. The owner sees a pending overlay and Cancel/Undo at the correct stage. A standby device write forwards once or returns pending; a standby dashboard owner re-unlocks. Lease change mid-commit never yields false success.
- **Privacy:** Bearer-only dashboard access fails; expired operator proof fails. Every MSP grant combination receives only allowed transcript and flat inventory, never owner effort metadata or role-derived filters. Search and cursor are authorized before ranking/paging; unrelated graph edits do not restart a valid cursor. A shared Telegram/Slack session never receives an owner-only title/path/digest from the service at all; a canary prompt-injection test proves read-time denial. MSP and later history readers count in destination audience. An external Telegram delete is not falsely claimed as an immediate cache purge. Internal forget suppresses local serving immediately and erases side-store headers, all versions of typed captured sources, dependent rollups/quotes, backup keys, search, caches, and derived data during an offline-peer/crash/replay test without changing graph event hashes. Completion status waits for each installed member or a fenced decommission.
- **Product:** At 320 px, open a four-level worker, see the transcript immediately, return to the actual origin/search scroll, move with preview and visible Undo, and resolve conflict including Keep last agreed. The default screen has at most five tiles and one overflow attention row; seven urgent roots plus an unassigned decision remain reachable. A decision cue is separate from its tile and opens the exact authorized source. Optional suggestion review gives per-candidate accept/reject and batch results. A screen reader can perform the same actions. Dashboard and mobile visual comparisons confirm host typography, color, theme, navigation, spacing, sheet, and focus conventions across Overview, effort, transcript, and correction screens.
- **Attention and evidence:** Two owner devices racing to answer one occurrence, a writer paused immediately before gateway dispatch during failover, Cancel racing dispatch, and erasure during ambiguous/sent answer states all preserve one automatic dispatch attempt or expose owner-reviewed duplicate risk. A burst of 100 routine worker events updates digest state without 100 parent notices; a verified decision/result can produce at most one delivery operation within the budget, with ambiguous sends held rather than duplicated. Budget overflow remains in app. Two decisions of the same kind in one source have separate occurrence IDs; a cross-linked decision counts once and clears only after its own source-backed answer. Pending attention remains visible but notice-ineligible while a member sleeps. A worker claim of “done” with only a commit link stays unverified for merge/deployment. An old truncated history slice or a missing machine/store cannot support complete coverage; a surviving machine recovers the authorized observed range or names it missing. A verified merge may appear within a partial digest but cannot become effort-level done. Every timestamp retains its offset.

The design convergence verdict is recorded in the convergence report with this scoped exception; implementation remains open.
