# One approval to add a group of projects

The Chief of Staff keeps a list of the projects it watches. That list also decides where each project chat appears in the conversation tree. If a project is missing from the list, its chat can appear outside the project group, and the agent cannot give that work a proper shared status.

Today, adding one project through the dashboard asks for the owner's PIN. That works for one project, but it turns a single request to organize many project chats into many separate PIN entries. The new feature prepares one exact list and sends one approval to the owner. The message shows every project name, what the project is for, the Instar repository it uses, the way progress will be checked, and the owner's messages that asked for the organization. For this first batch, the ten conversations with live project sessions are included, whether the current conversation is in Telegram or in the app. The review details are private to the owner; they are never posted into shared project groups. If the list or its message cannot fit safely, the system refuses before sending anything. The old record for “Comment on documents from any computer” does not show a live session, so it is left out until that can be checked again.

Nothing changes when the agent prepares the approval. The projects are not added just because a message was sent. The owner gets a private message in each linked Telegram and Slack conversation. A private message in each linked Telegram and Slack conversation opens one review page. The page lists every proposed project and parent placement, shows the exact owner-request citations, and keeps approve and decline buttons next to the full list. There is no page-by-page review. Opening the page only shows the proposal; one separate tap approves the exact list. The first valid choice wins, and later choices do nothing. Declining records that choice and adds nothing. The owner must tap the button on that exact message. The button is tied to the exact list the owner saw. If a project becomes active or inactive, another project is already added, the owner's request changes, the message is stale, or the server cannot check the current records, the tap cannot add the batch. The owner can ask for a new review if the list needs updating.

If the connection fails while the approved set is being written, the same approval can finish only the projects from that list. The system checks which ones were actually saved and continues only the missing ones, with a limited retry schedule. If one project conflicts with a newer entry, it never overwrites it; it reports that entry as blocked while the other safe entries can finish. After repeated storage failures, it pauses and records an agent-owned diagnostic instead of asking the owner to tap again. It does not silently declare a partial result complete. A repeated tap cannot create duplicate projects. When the whole set has been checked and saved, the button is retired.

The feature keeps the existing one-project dashboard path. It also keeps the same basic rule: only an owner action can create a tracked project. The agent can prepare the information and ask clearly, but it cannot treat its own draft or its own claim as the owner's approval.

The pending ask and its Telegram and Slack message coordinates are replicated, so the owner does not have to approve again just because another machine takes over. If saving fails partway through, the system checks the same approval again after journal recovery or while a measured retry budget has room. If the budget runs out, it stops and records a repair task for the agent. After the journal recovers or the agent diagnoses the problem, it can resume the same approved list; the owner does not need to tap twice. The new receiver must read the exact current journal and authenticate the actual owner callback before it can proceed. The shared project records continue to use the existing replicated Chief of Staff journal.

This change is off by default until it passes its release checks. It adds one careful way to approve several project entries at once; it does not turn on new projects automatically.
