# The constitution check reads a spec whole, or says it did not check (ELI16)

Before anyone approves a new design for Instar, a built-in checker reads the design and compares it with Instar's rule book, a list of about a hundred standards. It flags any standard the design might break. Every design approval relies on that check.

On November 27 two problems with the checker came to light. First, it could only read the first 24,000 characters of a design. When a design was longer, it quietly cut off the rest and judged the part it saw as if it were the whole thing. A long meeting-transcript design kept getting flagged for problems that its later pages had already solved, because the checker never saw those pages. Second, when the checker failed to run at all, for example because the AI call behind it broke, it handed back an empty list of problems. An empty list looks exactly like "no problems found", and that is how a failed check got reported as a clean pass.

This change fixes both. A long design is no longer cut. The checker now sends the whole design every time. If the AI model can't take one that long, or the check runs out of time, the result says plainly that it wasn't checked. The author then shortens the design and checks the shorter version whole; checking it in separate pieces never counts as checking the design. Because the checker gives slightly different answers each time, the record now counts every run of the exact same text, on every one of the agent's machines, so nobody can show the approver only the cleanest one. A check that did not run now always says it did not run, with the reason, everywhere its result is used: in the response, in the record kept for approvals, in the command-line tool, and in the review process instructions. The approval reviewer now catches a message that claims a clean result from a check that never ran. Nothing here can stop work, because the checker still only advises. It just no longer pretends.
