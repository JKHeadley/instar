# Losing any machine never silences an agent

On 19 November the Mac Studio, the machine in charge for Echo and Luna, broke during a macOS upgrade. Echo had three other machines running, and none of them stepped in. Echo said nothing for over an hour, and then could not reply in the owner's main conversation for ten more hours. Luna was silent for eleven hours. This plan fixes the reasons that happened.

**First fix: no grabbing the lead at start-up.** After the rebuild the lead bounced between two machines about nineteen times overnight. A restarting machine read an old note saying it was in charge, couldn't reach the other machine yet, and grabbed the lead. Now a machine that starts up asks the others first. While the preferred machine answers at all, it waits. It only acts once the preferred machine has stayed silent for three checks over at least 45 seconds, so a real failure is still covered. This is built first, on its own. A temporary patch with the same logic runs on two machines today. An update wiped an earlier patch without warning, so the plan also says how a declared emergency patch either survives an update or makes the update stop and say so.

**The machine in charge keeps the lead when a spare restarts.** Luna lost her lead for 25 seconds every time her spare machine restarted. Now the machine in charge holds on. If the network splits and both machines think they are in charge, Telegram helps settle it, because it only lets one machine read messages at a time: the side without the higher-ranked machine steps back, and never for more than a few minutes.

**Muting a machine no longer means it can never step in.** Some machines were set not to read Telegram day to day, and the code quietly read that as "never take charge". Those become separate settings. An agent with several machines must keep at least two that are allowed and able to take charge. If it drops below that, the owner sees it on the Needs-you list in plain words, before anything breaks, with one tap to keep a machine out if they really want that.

**A machine only takes charge if it can really answer.** The laptop took charge but did not know who the owner was, so every conversation ran locked down and could not reply. Now a machine checks four things, all the time: it knows the owner, it knows the owner's private group, it is signed in to an account, and it has the conversation settings. Those records are copied, signed, to every machine. If no machine passes, the best one still takes charge and tells the owner why it can't reply, then hands over as soon as a better machine is ready.

**No more restarts when the lead moves.** Changing roles restarted the server, and the others only waited 48 seconds while a restart took four minutes, so every restart moved the lead again. Now the lead moves without a restart, the wait is set so a real failure is answered within five minutes, and the guard that stops repeated swapping is on.

**Any machine can carry a conversation's reply.** A conversation could only speak through the machine it ran on. If that machine was not in charge, or was dying, its replies sat in a queue. Now the machine in charge keeps any reply handed to it and sends it itself, even if the machine that wrote it dies, and an owner message waiting at Telegram is never marked received until a second machine has a copy.

**A rebuilt machine is recognised everywhere, and its old conversations move.** The rebuilt Studio got a new name, and two machines kept a list with the dead one on it, which split the agent without anyone noticing. Now the replacement, approved on the owner's phone, is passed to every machine, even through a machine in between. Machines compare lists, so a split shows up. Conversations that belonged to the dead machine move to a live one.

**The owner hears one plain message** when the lead moves, when it comes back, and when conversations cannot reply, and it says why. The routine ones arrive silently.

**A weekly drill proves it.** Once a week, at the quietest hour, a spare machine stops the one in charge for ten minutes. Within five minutes another machine must answer a test message with a tool. A conversation replying while the lead moves must still get through. The drill also restarts the spare machines to check the one in charge never goes quiet, and checks the lead comes back once with no bouncing. If nothing takes over, the drill ends early and everything comes back. One limit is stated: the drill cannot type as the owner, so it watches the owner's real messages after each failover to cover that part. A failed drill goes on the Needs-you list.
