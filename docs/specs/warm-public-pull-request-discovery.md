# Keep the Public Pull Request Inventory Warm

## Problem statement

A real GitHub scan found the existing permanent agent links pull request. The normal Work request gave up after five seconds during the first healthy scan. Subsequent requests used the completed inventory. The new lookup should be ready without asking the owner to repeat the question.

This increment applies **No Silent Degradation**, **Structure beats Willpower**, **No Unbounded Loops**, and **Signal vs. Authority** to the shared public pull request provider in the read-only work discovery design.

## Frontloaded Decisions

1. Start warming the existing shared provider from the ordinary eligible server lifecycle. The two HTTP routes and any existing advisory observer use the same process instance. Do not store another inventory or add a write path.
2. Retain the existing in-memory public snapshot and refresh it in the background before its retained window expires. Keep the existing two-minute threshold for the fresh label. Reuse one bounded flight, one timer and current shared rate-limit/backoff rules. The new warming cadence and longer cold path begin on one explicitly enrolled development home per shared GitHub credential. All other installations retain baseline on-demand behavior. Ordinary server startup and unrelated routes remain free to finish.
3. A first admitted request with no usable inventory joins the in-flight startup refresh. Let it wait up to the provider's existing bounded refresh window plus a small bounded response allowance. Match against locally verified public rows. A warm request reads the current snapshot promptly while a replacement is in flight.
4. Credential rotation, loss, shutdown and a failed authorization or public visibility check invalidate both scopes and disallow publishing from the old generation. Transport outages may return a still-valid earlier observation with the appropriate coverage. Coverage is evidence of a snapshot, time and scope, not a live visibility guarantee or an absence claim.
5. Network activity is fixed to the allowlisted public repository and bounded by the existing request, response, byte, history and page limits. Requests contain the fixed public repository, provider cursor and existing authentication. Requests carry no caller text, internal state or explicit cohort field. Candidate access and output recheck remain on the origin.

## Proposed design

On the server's successful startup path, check the explicit Work public-PR warmup enrollment, development status and at least one eligible lookup consumer, then call start once on the same injected provider used by Work and the legacy read. Only that same enrollment predicate admits startup and recurring activity. Route availability alone never admits autonomous warming. Hot-off cancels an enrolled flight regardless of which HTTP requests joined it, fences its publication, disarms the timer and stops new enrolled work. An attached request may report controlled unavailable. A later ordinary explicit request may start a baseline refresh after the cancelled flight settles. It never inherits authority from the old enrolled flight. Existing explicit reads outside the enrollment retain baseline behavior. Non-CLI server initialization and the CLI's optional provider injection must converge on one instance. Stop that instance on server shutdown, remove its timer, cancel supported network work and invalidate any completion that races shutdown. A stop before first start and repeated stop are harmless. Work has no timer of its own.

A complete scan in the live canary needed 27 page requests and 4.37 MB. Schedule each autonomous attempt eight minutes after the previous scan started, plus deterministic installation jitter in the range zero to 30 seconds. Respect a later upstream throttle or usage floor. Timer and demand share this schedule for complete retained snapshots. First-use and warm reads of complete retained data, including evidence older than two minutes, cannot trigger an early scan. A missing or incomplete requested scope can trigger repair after its normal retry cooldown, subject to the same rolling budget and floor. After a partial or failed autonomous attempt, the timer alone may initiate one early repair in that cycle after cooldown, even when no request has arrived. If that repair is also incomplete, return to the normal interval. Recompute throttle and credits before the repair and do not rearm after pause or stop. Reserve the existing 20-second absolute refresh allowance so a healthy replacement can complete before the oldest eligible observation reaches ten minutes. With no previous scan the explicitly enrolled process starts once after its listener opens. With one eligible process this corresponds to an extrapolated 216 page requests and about 35 MB at the eight-attempt rolling-hour ceiling, based on that single observed scan. Cap it at eight attempts and 300 page requests within a rolling hour per enrolled installation, including paginated cold request work and partial attempts. Persist only charged attempt/page reservations and upstream retry-not-before time in a small atomically written operational budget record under the same installed state home. Use the existing single-instance lock. The record contains no credential or inventory data and is shared by successive processes of the same installation. Reserve before work, including each page across both streams, and give budget reservations no authority over results. An exhausted allowance makes the provider wait and expose stale or unavailable coverage according to the age of existing evidence. The measured release artifact includes repeated four-scan observations, charged request/page counts, byte totals, GitHub throttle responses and effects on other GitHub consumers. Hold recurring activation beyond the one-process enrollment until shared credential admission and usage are verified for the next cohort. Retain an upstream throttle floor across local credential generations and enablement changes. Restore rolling usage before new enrolled activity and preserve the recorded throttle floor for all refresh entry points on this installation, including baseline explicit reads after hot-off and process restart. No request can begin an upstream page until that known floor expires. Explicit enrollment first atomically provisions the budget record, then durably records the exact enrolled home and machine in installation config, then sets the separate live enable flag under the exclusive installation procedure. The configured enrolled identity is independent of the budget file. A pause or restart retains it. Loss of the record must not make this home look never enrolled, including to the baseline route. Decommission may remove it only under the reviewed enrollment procedure when usage and upstream throttle windows are established to have passed. An enabled flag never bootstraps a missing record. A crash between provisioning, identity enrollment and enablement keeps warming off and preserves any already initialized record. It cannot create an additional allowance on restart. Missing, unreadable or inconsistent budget state on a previously enrolled installation prevents every upstream entry point, including while paused and across restart. Report unavailable until the authorized procedure recovers the prior budget or independently verifies it has expired. It cannot issue a fresh allowance. Credential changes cannot clear it. Honor rate limits found in failed or superseded flights and successful response headers that report zero remaining with a reset. For clock rollback or unknown expiry use the conservative remaining window. Never interpret lost local state as new upstream quota.

Coalesce startup, interval refresh and concurrent demand into one provider-owned flight. The provider has a 20-second absolute refresh envelope. Each page fetch and body read uses the earlier of that deadline and the lifecycle cancellation signal. A cold Work or Chief of Staff request joins the flight, with an inner lookup deadline of 21 seconds from route entry and an outer path-specific timeout floor of 22 seconds. The enrolled Work aggregate applies the longer PR deadline whenever no requested PR scope has usable retained evidence, including after restart, expiry, rotation or denial. Refresh eligibility is per scope and independent from response readiness. A known unavailable or incomplete sibling is retried once normal cooldown and the installation budget permit, even if another scope still makes an unscoped request ready. A scoped legacy read whose only scope is missing joins that attempt. A ready unscoped request returns known partial evidence promptly. Other providers keep their own shorter deadlines. A usable snapshot takes the warm path without waiting. The existing Work browser request has no shorter timer, shows pending during the cold read and disposes its wait on route exit. Verify the normal proxy and UI stay attached through this deadline. Request close only detaches that request. Startup, others' HTTP requests and periodic refresh do not depend on a browser's lifetime. Closing one cold caller cannot abort the shared scan or penalize another caller. A stopped lifecycle, credential rotation, observed denial or disabled cohort fences stale completions and leaves at most one active flight until its cancellation settles. A cold request arriving during generation turnover keeps its original 21-second deadline. If the replacement cannot finish within that same bound, return controlled unavailable and let the next eligible request join the current replacement. Do not serve prior-generation data or race overlapping scans to meet the deadline. Check current owner access, feature eligibility, applicable credential generation and response lifecycle after all awaited work on both routes. No new generic 408 is acceptable for a healthy provider scan.

Resolve both scopes before publishing. A known private, missing or unauthorized repository immediately clears current and retained observations, poisons pending publication and prevents a successful late sibling from republishing. A transient transport failure may preserve an earlier verified public observation with its original timestamp. The fresh label expires after two minutes, and retained data expires after ten minutes or sooner on denial or credential change. A pending scan alone cannot extend either validity. A warm response during the quiet period may show older observed evidence, explicitly labeled stale. It cannot support a fresh absence judgment. Report which scopes are present, stale, incomplete or unavailable. Existing legacy page-revision mismatch continues to require restarting the result page. Credentials are never stored in the inventory. Fixed upstream fetches reject redirects, omit private terms and never follow provider-supplied arbitrary locators.

## Multi-machine posture

This is a disposable per-process execution optimization over the same public source. Every eligible server can rebuild independently from the same fixed upstream. Only the initial explicitly selected installation starts autonomous warming; it does not coordinate rights or custody across machines. Existing Work routing stays responsible for owner admission. The agent adds no authoritative store, credential replication, or cross-machine dependency. Restart, machine handoff and simultaneous requests preserve the same retrieval contract.

## Decision points touched

- Public scope, credential generation and shutdown fencing — invariant, based on unauthorized disclosure consequences.
- Request, timer and provider budgets — invariant with measured initial limits. Evidence comes from a complete cold scan with one owner request and reuse under load.
- Retrieved candidate relevance — advisory. No result grants authorization, proves absence, or starts work.

## Maturation plan

Use a disposable AgentServer to prove startup before a request, a real private Work browser submit against a healthy eighteen-to-nineteen-second GitHub fixture, accessible pending state and exact known pull result, a fast warm repeat, and an unrelated route completing while the lookup waits. Join two cold requests, disconnect one, and confirm the other receives the result from the single flight. Cover owner or feature revocation on both routes before response, stop before listen completion, startup abort and retry, delayed cancellation during credential change with controlled unavailable and subsequent recovery, a joined ordinary caller in flight across hot-off, interrupted first enrollment and deleted quota state, including combination with a known throttle, pause, restart and an explicit read that must not touch upstream, late sibling after public-visibility denial, page revision change, throttle through rotation and timer disable, guard and quota recovery across rapid restart, one nominated home among two eligible homes, successful zero-remaining headers with a reset, hot-off plus restart during a persisted upstream Retry-After with no early network page, and sustained requests through a rolling hour with bounded attempts and no unexpected retention gap when upstream and budget permit. Verify coverage continuity at maximum jitter and a missing merged scope repairing while open remains usable, including a timer-only repair with no incoming requests. No timer rearm after stop.

On the explicitly enrolled development installation use the actual public provider and normal Work deadline with the original question. Require a first successful healthy request and repeated warm hits under the cohort's load. Confirm fresh and retained labels reflect actual age. Track startup, page count, byte consumption, time to first result and warm response latency across at least four scans. Record actual live first-request elapsed time separately from the synthetic near-deadline test. Record the reviewed wider rollout criteria separately. Report upstream failure without claiming availability.
