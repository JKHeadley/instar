# Why Mama PC's desktop needs a clearer status

Echo can reach the Instar agent on Mama PC, but that does not yet mean it can show or control the Windows screen. Instar runs inside WSL on that computer. A small companion program must start in the signed-in Windows session to capture the screen and receive mouse and keyboard actions. The current server turns desktop access off when that setup fails, which is the safe outcome, but it only says “off.” That leaves us guessing about the actual failure.

This patch makes the setup report which step failed. It records a short phase such as “checking the bridge address,” “building the companion,” or “starting its Windows task,” plus a fixed error code. Only Echo's authenticated maintenance endpoint can read that result. It never returns the Windows path, network address, installer output, screen, keys, or companion secret. A successful later start clears the failure. The normal user flow stays the same: open Echo's Desktop page, enter the existing PIN, choose a ready machine, and press Stop when done. A machine with a failed setup remains visible but cannot be opened.

Mini and M5 showed two separate issues at once: their screen helpers reported a locked console and missing macOS screen/input permissions. The picker will state both observations instead of hiding the permission problem behind the lock report. Their agents remain reachable. This wording does not unlock a Mac or grant macOS permission; it makes the next repair decision accurate. Live Windows screen, input, and Stop testing remains required before Mama PC is shown as ready.
