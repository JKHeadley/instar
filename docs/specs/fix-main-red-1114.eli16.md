# Main CI green again: what changed, in plain words

Every pull request on the instar repository has been held because two automatic checks on the main branch were failing. This change fixes both. Neither touches how instar behaves for anyone; one adds documentation and the other corrects a test.

**The documentation check.** A script counts how many of the server's web routes are described somewhere in the documentation site, and fails if fewer than 55 out of every 100 are. New routes had pushed it to 54. This change describes twenty-two routes that no page mentioned, each written from reading the code that handles it: the blocker ledger (where the agent records being stuck and walks each case through checks before it may call it a real wall), the self-unblock checklist runs, the requests an agent makes for the operator to grant someone a time-limited permission, the failure-learning reads, and the ledger of problems found while bringing up a new AI framework. They sit on a new reference page and in the full route list. Coverage is now about 57.

**The test.** One test checks that when Local Verify runs its own unit tests inside the test slot it already holds, those tests are not squeezed down to four workers. It proved this by watching more than four small probe tests run at once. But it never said how many workers to use, so the test runner picked its default, which is the number of processor cores minus one. On the Mac where the test was written that is fifteen, so it passed. On the GitHub machines, which have four cores, it is three, so it could never pass there. The code being checked was fine; the test was measuring the machine. Now the test asks for five workers, just as Local Verify always asks for a set number. If the squeeze were wrongly applied, the test would still see at most four and fail, so it still catches the bug it exists for.

**What to decide.** Nothing. It is safe to merge: documentation and a test only, no runtime code, fully undone by a revert.
