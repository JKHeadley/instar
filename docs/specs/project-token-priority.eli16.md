# Choose which projects matter most

The token pacing plan needs to know which projects matter most to you before it can suggest where scarce capacity should go. This change adds an explicit High, Normal or Low priority to each project tracked by the Chief of Staff. Projects you have not changed stay Normal. It is your preference, not a score an agent invents from how loudly a conversation was written.

The Work page shows the value and lets you choose a different one using its existing owner unlock. An agent's ordinary access cannot change your priority. The preference is saved in the existing replicated project records so your other computers see the same setting and a restart does not lose it. It is stored separately from the project's goal and done list, so changing priority cannot wipe your checks, undo a pause or pretend that work is complete.

This first slice records the missing input. It does not move running conversations, change models, spend tokens or turn off a job. The project's later assessment can read your priorities alongside measured headroom and reset times; any action still needs its existing authority. A high priority is never permission to override a pause or a manual model choice.

If this feature is reverted, projects continue under the old behavior and the additional preference records can be ignored. There is no credential change or session restart. The tests must demonstrate both who can set the preference and that two computers derive the same value from the same records, regardless of arrival order.
