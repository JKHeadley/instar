# Approval Requests That Reach You On This Machine

When an agent says it is waiting for your approval, there should be a real request you can act on. This repair checks that the request was saved and its card actually reached your configured chat, or is genuinely available on an accepted device. If the server cannot send it, the asking session gets a plain explanation instead of pretending that you have not answered. If delivery is uncertain, it says so; a lost network acknowledgement does not prove that nothing arrived.

Reading a GitHub pull request should not ask for permission to change something. We will recognize the exact observed fetch_pr read tool while preserving protection for creating, editing, merging, deleting, signing in and unknown tools. Approval messages will use the existing visible owner-decision channel. Routine automated reports will remain quiet.

The Chief of Staff narrowed this build to the local path after review found larger problems in recovery across machines. It does not fix forwarding, successor-machine recovery or shared acceptance recovery. Those findings remain recorded beside the existing trust-history startup issue. No machine gains permission to approve for you, and no uncertain request is automatically sent again.

The change still needs unit, real HTTP and lifecycle checks, normal commit hooks and full verification before it can merge. Controlled tests cannot prove a message reached your actual phone. We will not send you a real approval request as a hidden part of building or testing this repair. The status remains a proposed local repair until those checks are complete.
