# Keep Rollout Scans Off the Server Event Loop

## Problem Statement and Authority

The Studio agent server stopped answering health checks, restarted, then lost its lead during a slow boot. Post-mortem finding N79 records a boot missing renewal of its lease, the time-limited right for one server to act as leader, for 94.2 seconds against a 60-second lease lifetime (TTL). Timestamp and SafeGit audit records place canonical feature-rollout scanning (discovery of feature specifications and release state) across both boot stalls and the original health-check failure window. Attributing the observed lease gap to that scan is an inference from this overlap and the synchronous call path; the incident evidence does not measure its exact share of the delay. Reproduced before-and-after delays will be reported separately. server.ts invokes void reconcile(), but reconcile() executes synchronous discovery before its first await. In this code path, thousands of synchronous Git blob reads can block both health responses and renewal timers; that is a property of the code, not a measurement of their exact share of the incident delay. No original CPU profile exists, so other contributors remain unproven.

Chief message 70019126-16c4-4f41-b944-f740a64f0157 explicitly authorizes this bounded repair: “Ship the narrow async scanner fix first, using the existing SafeGitExecutor async spawn and readStream plus async file reads, and keep today's restart safety behavior unchanged.” The same instruction makes boot-demotion restart removal a separate service-fencing finding, after this fix lands. This is source authority for scope, not a claim that this draft is already approved. The idle Codex message-delivery baseline repair is separate.

Constitutional parents are Structure Over Willpower (actual asynchronous boundaries rather than a misleading void call), Liveness Before Load (health and authority timers remain available while observations load), Signal Versus Authority (scan observations cannot extend a lease or override fencing), and Never Silently Cut the Data a Decision Depends On (no partial successful inventory). The authorized repair preserves these standards through actual production wiring and responsiveness tests.

## Proposed Design

### Await asynchronous discovery in the existing process

Add asynchronous equivalents of local and canonical scanning in featureRolloutScan.ts. Reuse the same pure frontmatter, trace indexing semantics and artifact construction helpers, so synchronous isolated callers retain their API and result semantics. Local discovery uses fs.promises.readdir/readFile and awaits each file; it does not synchronously read an entire tree. Canonical discovery awaits SafeGitExecutor.spawn for the existing fetch and SafeGitExecutor.readStream for rev-parse, ls-tree and each show. Chief566c3db1 explicitly authorizes the scoped refspec +refs/heads/main:refs/remotes/<canonicalRemote>/main in the existing canonical fetch. The leading plus applies only to that remote-tracking mirror, so it follows a published canonical rewind and a custom fetch mapping cannot leave it stale. No --force flag, local branch, worktree or other destination may be changed. This replaces the former bare main ref argument, retains the same canonical source branch and standard remote-tracking destination, and does not force-update any local branch. The actual installed Git rejected the unprefixed explicit refspec on rewind with non-fast-forward, as captured by the allocated diagnostic. The inventory intentionally follows the currently published canonical main, including a rewind, matching the existing observation purpose; no new ancestry refusal is added. A rejected fetch takes the diagnosed complete asynchronous fallback. Add an actual rewind fixture to verify this policy rather than assuming a fetch rejection. After the successful canonical-main fetch, pin the currently recorded canonical-main revision with rev-parse --verify refs/remotes/<canonicalRemote>/main^{commit}, rather than process-global FETCH_HEAD. This targeted argument change is authorized within the scanner repair. Enumerate paths and read every blob using that immutable commit ID. A competing fetch from another remote cannot substitute its FETCH_HEAD. This promises a coherent currently recorded canonical-main snapshot at pin time, not necessarily the exact remote tip at the first fetch instant. If the remote-tracking ref is absent or unverifiable, diagnose failure and use only the complete local fallback; never use FETCH_HEAD as a substitute. Preserve other existing argument arrays apart from this explicitly authorized scoped refspec, canonical remote checks, source-tree allowances, environment scrubbing, audit funnel, fetch timeout and fallback semantics. Do not add raw child_process Git calls, change SafeGitExecutor's authority, or copy runtime credentials into another process.

Each Git invocation is one finite operation. Read operations retain the executor's existing 30-second deadline. Fetch retains the configured fetchTimeoutMs or its existing 30-second default. Its async wrapper enforces that existing deadline, since spawn currently does not apply opts.timeout itself. Fetch uses the executor's existing detached option on Unix so deadline/abort can kill only its owned process group; Windows uses the owned direct child, matching the existing platform capability without claiming independent descendant-tree guarantees. Read blob commands have no helper/pager arguments; close their unused stdin. An abort, deadline, spawn error, nonzero exit or output-buffer overflow rejects that command. Do not launch another Git command until the previous owned child closes. On Unix fetch timeout/abort uses SIGKILL on its owned process group, matching the existing readStream terminal kill policy, and observes child closure; a failed cleanup is surfaced and does not trigger a replacement. Do not add a retry controller or detached scanner process.

Collect command stdout/stderr up to the same 10 MiB-per-stream default used by the old execFileSync calls; exceeding it fails the command explicitly, rather than returning partial bytes. The value is inherited command-buffer compatibility, not a new permission floor or inventory truncation. No whole-inventory IPC or JSON roundtrip is introduced. Decode complete per-blob output only after a successful exit. Preserve UTF-8 across chunk boundaries by Buffer accumulation or a streaming decoder. The fetch diagnostic may omit raw stderr from user-facing messages; internal errors remain masked by existing server logging safeguards.

The existing canonical-to-local degraded fallback runs asynchronously too. Malformed trace content retains the existing skip semantics. In asynchronous canonical scanning, a blob read failure after ls-tree listed that path fails the entire canonical attempt, even if earlier blobs succeeded: absence or malformed content cannot be inferred from a transport/process error. Discard that partial array and use only a complete asynchronous local fallback inventory; if fallback cannot read its listed files, reject rather than return a partial inventory. The synchronous isolated API remains unchanged, so successful parity is required while this explicit failure distinction is tested separately. Whole discovery failures propagate or take the same asynchronous local fallback as before. Cancellation is terminal: it never starts a local fallback or silently converts cancellation into a successful empty scan. This distinction is tested separately from ordinary Git failure. No tracker observation is applied before discovery has completed successfully.

### Single-flight reconciliation and finite shutdown

ReconcilerDeps.listSpecArtifacts accepts an array or Promise of arrays, and receives an optional AbortSignal. Existing synchronous tests/callers remain valid. FeatureRolloutReconciler shares one whole reconcile operation across concurrent callers, including tracker application, rather than starting duplicate scans. Clear the flight only when that operation settles. No queued extra run or automatic retry is created.

A stop() method permanently refuses new reconciliation, aborts discovery, and awaits the existing operation. Before each new tracker operation, re-check the stopped state; an already awaited tracker operation may finish, but no subsequent tracker write starts. The stop promise settles only after that operation and owned Git cleanup have finished. It absorbs expected abort rejection as a normal shutdown outcome. Other scan failures are recorded through the same finite failure logger, and stop resolves after cleanup rather than throwing out of the server shutdown sequence. Both the initial and periodic void reconcile triggers attach rejection handlers. Dependency teardown continues exactly once after stop, including scan failure cases. Marking stopped and clearing the existing six-hour interval happen before tracker dependencies are torn down. Construct the reconciler where it is today, but defer both the initial reconcile call and interval creation until the existing SIGINT/SIGTERM handlers and restartWatcher shutdown listener are installed near the end of server startup. Before that point no scan child or scan timer exists, so a failed boot cannot orphan this scanner. At shutdown entry, clear the scan interval and mark reconciliation stopped without awaiting; then arm the existing hard shutdown deadline at its current location, and only then await stop before tracker dependencies close. stop awaits the existing flight with the above failure handling, so a hung operation remains subject to that deadline. Do not add another signal handler or shutdown runtime. Abrupt process death retains the existing supervisor child-cleanup responsibility; this build adds no detached long-lived scanner and does not claim to repair every hard-kill descendant issue.

Wire server.ts to scanSpecArtifactsWithCanonicalAsync. LeaseCoordinator remains the only lease authority. Its renewal timer remains outside the awaited scanner work on the server event loop. This repair adds no TTL grace, lease worker, signer, role-change policy, polling owner, or restart suppression. It does not prevent other unknown synchronous paths from blocking; those remain separate investigation.

### Responsiveness includes result application

Async filesystem/subprocess waits yield naturally. Discovery parses one blob at a time; it never receives a whole inventory IPC message. Reconciliation also yields to a real event-loop turn between artifacts, so Promise-only tracker updates cannot starve timers over a large inventory. Yielding does not change artifact ordering, success semantics, existing version-checked updates (OCC checks) or per-artifact error isolation. The tests must cover the complete discovery-to-application path, not merely a fake sleeping scanner.

## Tests Defined Before Implementation

Unit: async and synchronous local/canonical fixtures produce identical artifact values, including malformed/absent trace files and maturity contracts. A competing fetch from another remote forced between the canonical fetch and revision pin must not replace the canonical inventory; test two distinct commits and FETCH_HEAD movement explicitly. Also create a stale tracking ref at A with canonical main advanced to B and a custom remote fetch mapping; the successful production fetch must deliver B-only canonical artifacts to the tracker, and this success case may not pass by falling back. In a separate intentionally failed-fetch case, require distinct local-only artifacts from the complete diagnosed fallback. Never accept stale A as fresh evidence. Async Git wrapper covers nonzero exit, spawn refusal, split UTF-8, inherited buffer overflow, timeout, abort, an owned fetch helper that ignores SIGTERM, and no partial successful result. A canonical blob failure after earlier successful blobs must deliver only complete fallback inventory or zero tracker writes. Reconciler covers awaited discovery, rejection with zero tracker writes, concurrent calls sharing one run, release after error, stop during discovery and between awaited tracker writes, and refusal after stop. Shutdown on expected abort or ordinary scan failure must still close dependencies exactly once, after owned child cleanup. Test both cancellation and ordinary fallback failure.

HTTP integration: run a real minimal HTTP health server with the real async scanner/reconciler and a realistic large Git fixture. Drive repeated health requests from a separate process, recording scheduled send times even if the server loop stalls. Actual LeaseCoordinator renewal callbacks must advance while canonical blob reads and tracker updates remain in flight. Validate real awaited command use and active scan duration; a zero-duration stub or timer-only spy is insufficient. No production bot/server/lease files. Use isolated in-memory lease transport and temporary repo. Failed discovery must not mutate an existing tracker. Record health completions, successful confirmed renewals and ownership verdicts continuously, including the last confirmed renewal before discovery and first confirmed renewal after final artifact application. Use a monotonic clock and evaluate every confirmation interval intersecting the operation, including both bracketing intervals; comparing only scan-start and scan-end timestamps is insufficient. Assert maximum health-response latency and completion gaps remain within the isolated health deadline, confirmed-renewal gaps remain within the actual isolated lease TTL, and authority never lapses. The full scan fixture must span repeated real renewal opportunities. For application-specific starvation, use a large inventory with immediately resolving tracker operations and a pending real event-loop callback; assert that callback executes between the first and last tracker writes. A fast application phase is not required to last long enough for multiple renewals. Run the old synchronous path and the repaired path in isolated controlled processes against the same sufficiently large fixture; the control must reproduce a responsiveness gap rather than pass vacuously. Report the before-and-after gaps separately from the incident inference. No new production latency threshold is introduced.

Local fallback responsiveness is also mandatory: force canonical failure and repeat the complete external-process health and actual monotonic, bracketing lease-renewal harness through final tracker application. Use distinct local-only artifacts so this test cannot accidentally exercise the canonical path. The measured current source tree has 2,538 top-level specification Markdown files, totaling 29,793,727 bytes; the largest is durable-conversation-identity.md at 343,475 bytes. Generate representative isolated content including a file of that size; these measurements are fixture inputs, not new production limits. Apply the same gap, ownership and cleanup assertions.

Lifecycle: production-shaped construction and actual server wiring bind the async scanner and existing shutdown owner. Real temporary Git scan completes and leaves no owned live child. Abort a deliberately delayed owned Git operation, verify child exit and no subsequent command or fallback. Exercise actual real LeaseCoordinator renewal while a large scan runs, and verify health and renewal continuity through result parsing/application. Existing role-restart tests remain unchanged. A supported throwaway startup check without contacting a real owner proves the installed server starts and tears down safely. Complete normal verification must pass on the exact final revision before merge readiness. The verification coordinator, the Increasing Throughput session, must allocate targeted execution before a test starts.

## Side Effects and Rollback

The same Git fetch and file reads still occur at boot and on the six-hour cadence; they stop blocking the main thread. At most one Git command from this scanner runs at once, and one full reconciliation runs at once. No new cadence, permission, persistent controller, service, credential forwarding, or role policy is introduced. Shutdown stops observations before tracker dependencies close. Revert source through the normal pipeline to roll back; production restarts and lease recovery remain with their existing owner.
