# Every guard names the rule it enforces — ELI16

Instar keeps a list of its standards: the rules every part of the system has to follow. On 13 August 2026 Justin asked that references run both ways. The list names the code that enforces each rule, and the code names the rule it enforces. Then someone who opens a guard knows what it protects, and nobody deletes a guard without realising a rule depends on it.

A check already makes sure of this for the 70 files the standards list names. But the rule says *all* infrastructure, and many guards, gates and checks were never named in the list, so nothing asked them to name a rule. A dated promise in the list said that gap would be closed by 27 November. The date passed with the work undone, and since then every commit has been refused until someone either builds the check or moves the date.

This change builds it. The same check now also looks at every file whose name shows it is a guard, a gate, a sentinel, a watchdog or a similar deciding part (as a whole word, so "Delegated" or "navigate" do not count), plus every lint check and every hook. That is 286 more files. 21 of them already name a rule. The other 265 are written down as known gaps in a list that can only shrink, and its length is fixed in the check itself, so nobody can quietly add to it. A new guard that names no rule fails straight away, and a file on the list must come off it once it names its rule. Deleting the list does not switch the check off: a missing list counts as empty.

What it still does not do, stated plainly: it picks the files by their names, so a file that guards something but is not named like a guard is still outside it. And it checks that a file names *a* rule, not the *right* one. The standards list now says both, with a new dated promise for the first: either replace the name rule with the code's own record of what decides, or accept the name rule as the floor. Justin sets that date by approving this change.
