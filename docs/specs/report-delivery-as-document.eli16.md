# Reports go to a document, not a GitHub link (plain-English overview)

## What went wrong

Justin asked Echo for a research report. Echo wrote it as a file in the code repository and sent him a GitHub link. He wanted a native Instar document: something he opens in the Instar app, reads comfortably on his phone, and comments on line by line. Instar already has those documents. Echo just didn't use one.

## Why it happened

Every Echo session starts by reading a long instruction file. One part of it, a list of "when this happens, do that" rows, still said: when you produce research, publish it with Telegraph or the Private Viewer. The Private Viewer is the older way of making a private page, and on Echo it is now switched off in favour of documents: asking for a view is refused. So the one route the instructions named was closed. The note about documents existed, but only in a reference file the session does not load by default; the main file only had its title in an index. With no loaded instruction saying "a report is a document", the session reached for something familiar, a file in the repo, and an older note about making review files GitHub-friendly pushed the same way.

## What changes

- The two instruction rows now say: a report, plan or research write-up for a person becomes a document, and you send its link. They also say plainly that a file in a repo with a GitHub link is for code review, not for someone reading a report. The Private Viewer is only the fallback where documents are switched off.
- Agents that already exist get the corrected rows on their next update. The update only replaces the exact old wording; if an agent has rewritten that row itself, it is left alone.
- New agents' starting identity file says the same thing.
- The documents note itself now mentions the GitHub-link case.

## What does not change

Nothing new blocks or holds a message. A check that refused GitHub links would also refuse the many good ones, like a link to a pull request someone is asked to review, so the choice stays with the agent's judgment and this change fixes the instructions that judgment reads.

## What you need to decide

Nothing. This makes the instructions match a feature that is already approved and live.
