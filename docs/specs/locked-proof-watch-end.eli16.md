# A meaningful end-of-watch failure proof

Case 12.8 asks whether a failed relock at the end of the two-minute watch raises the matching security item within ten seconds, without restarting the server. Repeated manual unlocks can make the guard fail early. That is useful for a different case, but cannot establish this particular end-of-watch requirement.

The proof harness now waits for a locked, actively watched test-account session. It starts a separate recovery supervisor, records the exact guard and server identities, and waits for a durable ready acknowledgement before pausing them. Only then does it ask the person to unlock the test account once. It resumes the same guard after the watch ends, requires the native guard's actual failure timestamp, and resumes the same server so its normal sweep must report that exact duty. An early failure, a different guard or server, a late security item, or missing recovery evidence fails the proof.

The supervisor is independent of the driver. It has a fixed monotonic deadline and retains the original identities and login context in memory. If the driver dies or receipt storage becomes unreadable, it still attempts to resume those exact processes. Cleanup attempts a screen lock only when the original proof-account boot, login and console context is positively unchanged. It never sends fallback keyboard shortcuts. A different user or unreadable session produces visible failed recovery instead of locking someone else's session. Recovery cannot guarantee success after an operating-system failure, a killed supervisor, or loss of storage; missing confirmation always fails the proof.

This changes only a deliberately executed proof harness. It does not change the product's relock policy, helper signature, permissions, or TCC identity. Tests exercise detached recovery against inert sleeping workers, plus realistic runner timelines. No live Mac unlock, lock, process suspension, or human cue has been run during development. The human proof remains an explicitly scheduled operation; the implementation and its review are not a claim that the real-Mac acceptance case has passed.
