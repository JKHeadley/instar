# Confirm an engine change where you are already talking

When you ask Echo to move a project conversation to another engine, such as Codex, you should not have to open that project conversation just to repeat the request. Echo already has a route that can show an exact proposal in the conversation you are using. You reply "yes" there, and the server checks your identity and the destination again before applying the change. This repair lets that existing route include the engine as well as the model and effort settings.

There were two separate problems. The list of settings allowed across conversations excluded the engine in both the HTTP route and the final write surface. Also, proposals were sent as ordinary automated notices, so Quiet by Default could put a request for your answer into the quiet notification feed. The repair uses one shared list for the allowed settings and gives an armed proposal the existing owner-decision delivery category. That category is visible in the addressed conversation and retains its existing limit against flooding you. Ordinary automated reports stay quiet.

You still see the target conversation's name and the exact change before anything happens. The existing typed "yes" remains the confirmation; this repair adds no button. It does not bind you as the operator of another person's conversation, impersonate your message, or let an agent change an unbound conversation directly with its API credential. Another person's conversation and a team member's conversation remain refused, and the server checks those facts again when the confirmation arrives. Unknown destinations and the existing disabled switch also remain refusals. Escalation and message-signature settings still require confirmation in their own conversation.

The tests check the allowed path and the refusal paths, including a destination that becomes ineligible after the proposal. A real server and Telegram adapter check that the proposal reaches the addressed topic under Quiet by Default and that an ordinary report stays quiet. The lifecycle uses the same confirmation helper as production but does not pretend to exercise a real user's Telegram account. The draft must pass complete normal verification before it can merge. No live engine switch is part of building this repair.
