# Selected Local Conversation Import

## Problem statement

Copy explicitly selected Claude Code and Codex session files into private Instar history through native upload, preview and a fresh copy confirmation. Reuse the existing signed native transport, parser/snapshot foundations and private history store. Never open a client-supplied server path. A selected file is source material, not an instruction, connection, credential migration or job.

Apple owner echo-instar-apple-app-rebuild confirmed source d895ffb has signed ImportedData.post and fresh ZIP confirmation but no picker/host grant (handoffs6e7dc5e0 and7abe53d3,2026-11-22). Server owner143810 proposed path grants; round1 rejected their unproven locality and moved to native selected-byte upload. Native transport agreement remains explicit below. Existing ZIP route prefix is /mobile/imported-history.

## Intended outcome and governing constraints

The person chooses the private history to bring over and approves the exact preview; the agent performs acquisition, validation and copying. This serves The Person Decides; the Agent Does the Rest (master rule120), while exact authority and least revelation, recorded causes, bounded work, truthful completion, team privacy and single-provider operation remain governing constraints. Engineering resource defaults are owned implementation policies, not new constitutional limits or a request for operator approval. No amendment to the constitution or protected list is proposed.

## Team posture

All supporting modules are role-neutral and accept no owner identity from the manifest. The complete v1 native intake is an explicit owner-only exception: it handles that owner's personal provider account/local-session material and has no signed team grant to inspect another person's source files or disclose private imports. Current owner admission and historical per-record owner claims are separate requirements. Members and guests do not gain access through possession of an operation id, a paired signature alone or membership; denied reads must not reveal existence or counts. This intake introduces no sharing authority or share flag. Any separately supported sharing uses the owner's signed team record; a role label or unsigned body cannot widen it. A team of one uses the same path. Full HTTP/native proof includes member and guest negative neighbors before availability is claimed.

## Existing foundations and prerequisites

- Pending3388: mobileOwnerDeviceAdmission, privateImportedHistoryOwner, signed private search. These are not physical host attestation. Existing raw list/read is still broad; it must be tightened as part of this integration.
- Pending3387: ImportedHistoryStore.withWriter common cross-process writer, addConversation/flush, private directory checks and immutable-publication patterns. ArchiveStaging and AcquisitionArchives are NOT chunk stores or this operation’s cleanup owner.
- Local foundations: localSessionParsers, snapshotLocalSession and its current per-file byte ceiling; explicit non-user Codex sessions refuse. Existing parser returns representation and supports expectedRepresentation, but callers alone cannot preserve it across restart.
- Signed binary transport: DeviceRule.body='octet', req.rawBody signature verification, CHUNK_BYTES=1MiB from appMediaTypes. Reuse framing/authentication only, never media storage, member grants, events or replication.

## Proposed design

### Origin, identity and owner admission

A hostname/origin pin is NOT a physical-machine proof: the paired hostname may legitimately move to standby after a challenge. Retain no-redirect/no-cross-machine fallback, but protect every private body and private response with a target-authenticated application channel. A standby may receive opaque ciphertext, never private plaintext. Do not promise zero network traffic at a relay.

Use the registered target signing-key directory and authenticated P256/Ed25519/HKDF/AES-GCM pattern already used by DesktopSession.verifyTarget and DesktopAead. Reuse crypto primitives and trusted target-key resolution only, not Desktop/PIN/operator grants or media storage. New purpose/version domain separation is mandatory. New GET /mobile/imported-history/local/targets returns registered target ids/public signing keys/capabilities under current native-owner admission. /targets is DISCOVERY ONLY and cannot establish or replace trust, even over the paired hostname. The native client requires a Keychain-protected TrustedTargetPin whose machine id/signing key came from an independent bootstrap: (a) a verified local native creation/management receipt and its owned public identity file, or (b) explicit out-of-band verification on the actual target computer, such as scanning its trusted local management display. Source fact: MacCreateAgent.enroll obtains InstallLedger.appEnroll.agentDir from its local creation process, and LocalEnroll already reads files there; MachineIdentityManager's public identity path is .instar/machine/identity.json and signingPublicKey is base64SPKI. Add only public identity pin capture to that trusted local path, never read/copy private signing keys. A free-form folder or a body local=true is not a creation/management receipt. Existing remote hostname pairing or Desktop /targets JSON alone is NOT an independent machine-key anchor. Legacy targets lacking a real pin remain unavailable for private upload with a concrete Verify Computer action; never silently TOFU the network response. Apple owns this feature-scoped pin/bootstrap UI and cache, not a new operator/root-registry grant. Challenge-supplied keys cannot replace the pin. A changed enrolled key requires the existing trusted identity/re-enrollment path, never silently accepting a replacement with the same name.

Public POST /mobile/imported-history/local/challenge remains signed native-owner-only; public here means its body contains only non-private protocol metadata: selected machine id, fresh client P256 ephemeral public key and random client nonce/purpose. Server signs a versioned canonical target-key grant with the selected machine’s registered Ed25519 identity key, binding logical agent context, target machine, current boot, device id/key hash, client nonce/public key, server ephemeral public key, salt, channel id and expiry. Client verifies EVERY binding and signature against the previously selected registered key before any private manifest or file bytes. Wrong key/id/boot/domain refuses before upload. No signing/decryption private key is replicated to standby or passed to a child/model.

Derive direction-separated256bit AES-GCM keys with P256 ECDH and HKDF-SHA256 under instar-local-history-channel-v1, using the existing Desktop crypto/canonicalization pattern with explicit new-purpose context. Publish exact cross-language golden vectors. Use uint64 request sequences starting at1, distinct request/response IV domains, and AEAD associated data binding version/channel/target/boot/device/method/canonical path and request sequence. An octet record is8sequence bytes+ciphertext+16tag bytes. Existing CHUNK_BYTES bounds the ENTIRE wire record, so plaintextChunkBytes=CHUNK_BYTES-24; advertise that derived value and use it for offsets. Full normal device signature covers ciphertext rawBody; channel authentication never replaces current owner authorization. Buffer and authenticate the complete record/tag before exposing decrypted bytes to JSON/parser/storage.

All private manifests/chunks/apply/cancel bodies and private preview/status/library responses are sealed. Non-private target discovery/handshake may be ordinary signed JSON. Only opaque channel/sequence/operation routing ids may appear outside the seal. Private search words, refs, project/name selectors and paging state use sealed request bodies, not GET URLs or headers. Response AAD binds the exact authenticated request. Client serializes requests per channel. Server atomically checks authenticated EXACT-NEXT sequence, consumes it before dispatch, and rejects duplicate/out-of-order requests even if old ciphertext is freshly transport-signed; reuse DesktopAead.decryptInput progression semantics. Server emits at most one ciphertext response for a sequence; never encrypts different content under a reused key/IV. Any ambiguous network outcome discards the channel, authenticates the same target afresh, then queries operation/idempotency state before retrying a mutation. Business request ids and chunk offsets survive transport rekeying; they do not mint new authority. Do not silently reroute to another target or expose private replies in a relay’s plaintext.

Initial channel lifecycle policy is60seconds and one current channel per native device/target/boot; a new authenticated channel supersedes the old one for future calls, with already-in-flight responses safely drained before key disposal. This is conservative protocol-resource policy, not a human review deadline. Refreshing transport does not consume or extend operation authority. Channels are charged before creation, expire/dispose without request traffic, and hold keys in memory only. Their per-channel counters/keys never resume after process loss. Any reconnect/rekey verifies the selected registered target again. Changing machine identity/key invalidates old channels before decrypt/publication. Root/native operation grants remain independent and scoped to actual owner/device/key/target/boot.

All routes require a current signed non-browser native owner through mobileOwnerDeviceAdmission AND privateImportedHistoryOwner. Retain actual admitted deviceId,userId,role,keyHash provenance. Revalidate after async boundaries, during chunk handling, after parsing and inside writer admission. No bearer-only, browser, member, peer, shared-owner-conversation or ambiguous-distinct-owner fallback.

Server machine identity is injected from trusted bootstrap options.meshSelfId and/or coordinator.identity.machineId; if both exist they must agree. No 'local', project name or request body fallback. Missing identity makes capability unavailable, not a new identity created by a request. Boot epoch uses MobilePairingService.bootId.

The app keeps the frozen selection and chosen target on screen while the person reviews it. Issuing transport/nonce alone grants no file-copy authority.

### Native snapshot ownership

The Apple selection coordinator owns its local captures separately from server staging. Read only OS-selected/security-scoped files. Capture into a generated private0700/0600, backup-excluded app cache namespace; use authenticated streaming records with a fresh memory-only capture key, never a new persistent plaintext transcript copy or public media outbox. Use separated-purpose capture AEAD records with unique per-key file/record nonces and associated data binding capture id, file id, byte offset and an authenticated final-length/end record. Reject modified, reordered, duplicated, cross-file or truncated records before upload. Reuse the record discipline with a distinct native-capture purpose; a fresh key alone does not permit nonce reuse across blocks. Record bounded ids/timestamps/owned paths and device/account/selected-agent binding. Source names/provenance are not process arguments or logs. Hash the exact captured plaintext for the manifest; later original-file changes do not change the captured snapshot.

Before and during capture, the native coordinator enforces a device-local live free-space policy and shared outstanding-write reservations across its captures. Use the inherited disk floor max(2GiB,5percent of device capacity) as initial configurable policy, accounting for AEAD framing and metadata. Reserve each bounded block before write, recheck actual free space, and stop safely on capacity exhaustion without a silent partial selection or server upload. Previously allocated ciphertext is not double-counted as an unwritten commitment. Failed deletion remains charged. Test concurrent captures and low storage midway through a selected file; retain no plaintext, release only proven-disposed allocations and show an explicit capacity refusal. There is no arbitrary project-size ceiling on a device with sufficient capacity.

While the flow remains active, encrypted captures can support upload/retry or server-restart re-preview without another picker. Cancel, flow dismissal, terminal completion/refusal/expiry, or account/device change closes handles, drops/clears capture keys and deletes only owned captures. Apply the advertised operation lifetime with a24hour initial absolute maximum, not renewed by retries. While app runs, owned deadline disposal fires without another action. App termination loses memory-only keys; next launch removes proven-old owned encrypted runs before new capture. It cannot resume their plaintext; an interrupted server operation can still be checked through a fresh target channel. No key/bookmark is persisted merely to avoid a picker. Physical encrypted residue may await next launch/OS cleanup if the app is not running; do not claim immediate forensic deletion. Cancellation before any server contact is a required synthetic native test. Deletion failure stays charged and surfaced locally; do not forget an owned file because the flow object disappeared.

Successful pilot copies confer no authority to enable a user route or read real history.

Before EVERY normalized/temp output block write, reserve its additional disk cost. Before issuing each apply mutation permit, also reserve planned conversation/attachment append bytes, durable claim publication, manifest replacement and temporary-file growth.
