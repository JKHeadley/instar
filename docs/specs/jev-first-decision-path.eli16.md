# Jev-first decisions, in plain English

Instar asks larger AI models thousands of small questions each week. Those questions consume shared model capacity and often take seconds. Jev can answer many of them in a fraction of a second, and it reports how sure it is. The current system already uses Jev for a few new checks, but it has not moved much existing work away from larger models. This change gives existing checks one shared way to try Jev first.

A check still owns its decision. For example, the outgoing-message check decides whether a reply is safe to send. Jev only takes that decision when its answer is well outside a pretested uncertainty range and every rule the check needs was covered. If Jev is unsure, slow, unavailable, or returns an incomplete answer, the same larger model that handles the check today makes the decision. A small random sample of Jev's confident answers is checked by that larger model too, so we can see whether confidence keeps meaning accuracy. An agent with only one AI provider still gets the full feature.

Every decision gets a local record of the exact context the model saw, with secrets removed. The record also says what Jev answered, whether it handed off, which model finished the call, and what later evidence says about correctness. Raw conversation content stays on this machine and is not exposed through the dashboard or copied to peers. The dashboard and review job get aggregates: how many decisions Jev settled, how often the models disagreed, and how many larger-model tokens were actually avoided. We will not call an estimate a saving.

The shared path starts off for the fleet. Each check must pass a replay against real examples, including the kind of mistake that would let a safety violation through. Only then can it turn on for Echo, with a switch that restores the old path immediately. The first candidates come from the measured cost ranking. New candidates will be added as the regular review finds them. The remaining decision is which checks meet their own quality bars; those bars are written before the replay, and any miss keeps the check on its current model while we improve the question or context.
