# When a person calls out an agent failure

A serious failure should trigger more than an apology or a preference note. Instar already detects corrections. This change gives those detections a durable investigation process shared by agents, while leaving Echo's personal bug topics and intake queue alone.

A failure case keeps a small, secret-scrubbed record of the bad reply, the person's callout, the instructions and approvals behind it, the decisions made, and links to evidence. Facts that cannot be found stay marked missing. Ordinary preference corrections do not keep conversations. Failure capture works by default; people can turn it off. Automatic preference learning remains a separate opt-in.

The investigator asks whether the constitution lacks an adequate rule or an existing rule was not enforced. It can record that diagnosis before the repair is finished. It owns the work, links the normal product bug or action, and proposes any constitution amendment for the person's approval. It cannot grant itself authority to rewrite the constitution.

Cases remain open until evidence names an implemented repair and shows the original failure is prevented while legitimate behavior still works. The API requires both results, complete context and the current record version. The agent must actually perform the checks; typing a successful receipt cannot make an unrun test real. Repeated complaints reopen the case and retain the earlier closure evidence.

The investigator can see cases across the agent's machines. Scrubbed evidence and its full revision history are copied through the existing authenticated journal. Current reads and changes go to its original holder; if that holder is unavailable, complete copies remain readable with a clear stale label. Copies cannot authorize closure writes. If that machine is unavailable, the answer is unknown, never a claim that the agent has no cases. The process handles only a few cases per run and reserves its attempts before starting any model work. Three unsuccessful attempts pause that case until a new occurrence or substantive recorded evidence; restarting the server does not reset the budget. The unresolved case and its repair work remain visible.

The regression examples cover handing group setup to the person, assuming a locked screen prevents input, and saying an approved change awaits review without a link. Passing process tests does not declare those underlying incidents repaired. This change does not alter the constitution or the existing authority of outgoing-message checks.
