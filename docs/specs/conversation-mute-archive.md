# Personal Chat Mute And Reversible Archive

## Problem And Authorized Outcome

Today delayed reply pushes lose their conversation identity in a generic summary, and chat lists have no personal archive selection. Muting should keep a person quiet while archiving should put a chat away without deleting it or stopping its session. The native app owns menu presentation and release. Chief of Staff handoff5f955c7c-c366-44a1-a1aa-4aa925778a73 assigns this server work under the existing feature authorization; parent/source PR3655 is separately frozen during full verification. Each authenticated reader can silence conversation reply notifications and remove a chat from their ordinary list while retaining an explicit Archived view and unarchive action. No delete, message loss, history mutation, access grant or session stop is introduced. Closing a local window remains local.

## Constitutional Basis

Operator-Surface Quality governs the server-side control contract: mute/archive must be predictable personal actions, reversible archive must preserve the same chat, and confirmations must distinguish local save from unverified global delivery. These guarantees are structural API/state behavior rather than a claim that server code implements Apple layout. The app owner supplies native action placement and exact user-channel proof; the server exposes truthful readiness and reversible outcomes. Typed pending evidence supports Observation Needs Structure, while existing access boundaries remain unchanged.

## Rollout And Rollback

Existing users default to their readable missing preference state (false); no conversation is archived without a recorded action. Old clients ignore new fields and have no existing archive state. New clients handle unavailable/unsupported explicitly. Preserve old pending summaries with disclosure; retain the same push state-format compatibility expectations and actual prior-reader probe before changing writers. A rollback to older push code cannot drain the isolated new bound sidecar. It may create new anonymous legacy activity of its own, an explicit generic-summary downgrade that cannot enforce the new mute contract. The old-code count/urgency compatibility probe is not proof of recipient safety; the real old-drain isolation probe governs the supported rollback path. Mark delivery support unsupported/partial on native capability detection and preserve the older-summary caveat; do not call rollback notification-equivalent. A re-upgraded reader treats a missing typed marker, altered count or lost intended-reader binding as anonymous unknown state, never manufactures reply or document permission evidence. Every anonymous fold lacking independently durable intended-reader continuity is held by default, including unchanged-device and reassigned-device histories with identical final queue bytes. Current device id, current person binding or a guessed timestamp is never continuity proof. This increment adds no continuity-reconstruction subsystem and does not automatically deliver such unbound legacy folds; only already-held independently verified binding can permit the existing generic-summary behavior. On an entirely older fleet, unsupported is a client inference from missing capability/endpoint, not an extra wire enum value; the new server wire remains supported|partial|unknown. Where continuity cannot be established, hold that legacy contribution instead of delivering it to a reassigned person; preserve possible critical notices without marking them sent. Test isolated typed mixed reply/urgent-notice state plus newly created old-fold legacy state through downgrade/re-upgrade with unchanged and reassigned recipient histories ending in identical legacy bytes: without independent continuity both remain held, and no critical contribution is marked sent or deleted. Revert retains preference files/events harmlessly and returns old list behavior; it does not delete user data. Rolling back to code that cannot read typed queued state must preserve it without pretending it was sent; stage a compatible parser or safe recognizable extension before enabling the writer if the actual previous-reader probe would drop pending critical notices.
