# Find prior pull requests before answering or assigning work

On November 23, work on permanent `instar.sh` agent addresses was already in open PR #3342. Conversation history was partial across surfaces after a rebuild. Topic search and an 11-message database copy could recover part of it, while memory search returned no results. The Chief of Staff considered assigning a new design. The existing `dev:claim-check` searches PRs when given paths. At the point this question came in, the useful search input was a domain and the user's description.

## Behavior

Expose `GET /chief-of-staff/pr-search?q=instar.sh` to the local agent API bearer holder on a Chief of Staff-enabled development installation. Require the existing global agent bearer check and follow the transcript route’s explicit scoped-device exclusion. Deny even on an unconfigured installation with no master bearer. Reject other credentials before resolving GitHub credentials. The first approved repository is the public `JKHeadley/instar` development repository, selected by server code. The provider should be reusable for an operator-allowlisted repo as part of Spec A. User input cannot broaden credential scope. Callers cannot supply a repository or upstream URL. The GitHub server identity remains the one used by `resolveGitHubToken`. Use the existing direct GraphQL transport in `src/core/githubRuntime.ts`, so the calling session and the server can operate without the GitHub CLI. Respond with `Cache-Control: no-store`.

Add one Chief of Staff entry under `src/data/awareness`. The existing awareness registry inserts it into `generateClaudeMd` for new installs and migrates it for installed agents and Codex/Gemini copies. These are the two conversational entry points: when answering whether Instar work already exists, and before the Chief of Staff sends a new Instar design assignment or offers a new project binding. Send one literal per `q` parameter, 1–256 characters after trimming. A URL-encoded numeric literal such as `q=%233342` matches that exact number inside this inventory. For a known number outside the inventory, use the canonical URL `https://github.com/JKHeadley/instar/pull/3342` with that number. A text literal such as `instar.sh` matches it anywhere in a title, ref, or body. The route does not extract terms from prose. Try a distinctive phrase or alias separately. Read the bounded body excerpt and metadata as quoted evidence, and use the canonical public link to read the full record in a browser when more context is needed. Carry its URL into the answer or assignment where it is relevant. If results are empty, say what scope was searched. If the source is degraded, say what could not be verified. Existing owner-requested work continues through an outage with the uncertainty attached. Spec A owns any future enforcement at the binding, send or spawn boundary.

## Inventory and coverage

GitHub remains the authority. One server process maintains a read-through, in-memory inventory with independent open and merged snapshots. No files, backups, local routing tables, project fields or GitHub records are written. Initial cache policy is two minutes, twice the existing Chief of Staff GitHub evidence memoization interval. This covers adjacent answer and assignment turns sharing one scan. Concurrent requests share a refresh. Each completed state stream replaces its previous snapshot in one step. If the merged stream times out and the open stream completes, the result can still cite an open PR and marks merged coverage unavailable or stale. Upstream errors keep the last successful snapshot long enough for a useful degraded answer, up to ten minutes from the last success. This bounds how long an outage can leave an advisory answer relying on an earlier observation. Use a short retry cooldown to prevent a failed upstream fetch from multiplying with inbound queries. If neither requested state has usable coverage, return an explicit unavailable response. A changed or missing token invalidates both snapshots before a hit or publication. Each parallel refresh belongs to a credential generation. A denial in either stream immediately invalidates both cached scopes and their generation. Its sibling cannot publish, regardless of completion order. A later authorized refresh can populate both. An observed denial never serves stale or partial results. HTTP 401, 404, and 403 without a throttle signal deny access. HTTP 429 classifies as throttled. HTTP 403 requires affirmative throttle evidence, either zero remaining quota or a valid nonnegative Retry-After delay. A positive quota and routine reset timestamp do not mask an authorization denial. A GraphQL response carrying errors contributes no rows even if it also has data. Only a list containing exclusively recognized rate-limit error codes can preserve earlier data under the throttle path. An access or unclassified GraphQL error evicts both snapshots. A throttle honors the provider's documented retry or reset time, with a minimum short cooldown and a one-minute fallback when the provider supplies no timing. Other transient failures use a short cooldown and preserve still-eligible stale data. Responses and logs carry no upstream body or error text. The same token's upstream revocation is unobservable during the fresh cache window and is detected at the next refresh. Token values never enter browser responses, cache metadata or application logs.

Query the repository's PullRequest connection with separate open and merged state streams, each with cursor validation, a shared per-state time budget passed as the remaining timeout of every page, a page count bound and a retained-size limit. The shared transport limits each page to 4 MiB of decoded response bytes before JSON parsing, canceling the body stream on overflow. The separate 16 MiB limit constrains cumulative decoded row payload per scan. For open pull requests, follow cursors through the actual end of the connection across all authors and branches, ordered by creation time so ordinary updates do not reorder open traversal. For merged history, use updated-time descending and a initial 30-day window. This covers recent work missed after it moved from open to merged, while limiting the amount scanned for each cold start. Open work has no age cutoff. These three initial bounds are implementation choices and are returned as coverage metadata where relevant. Compare observed cold pagination cost and recall before widening or tuning them. Only include rows merged in that window. Stop at the end or once the updated-time stream crosses the window boundary, checking timestamps and ordering on the rows encountered. A scope may only be reported as complete when its end condition is reached. GitHub's mutable cursor traversal is a bounded observation, so state may change during or after a scan. Deduplicate by PR number. A normal open-to-merged transition observed across concurrent streams uses the merged row, including when the update times are equal. A merged pull request cannot reopen. Repeated nodes in the same state use the most recent row seen in that stream. Repeated or missing cursors, malformed or contradictory nodes, interrupted coverage and exhausted safety bounds end the affected stream. It may return fully validated earlier rows as positive evidence with `partial` coverage. Reconcile validated rows by pull request number before matching. Current observed rows replace prior rows even if an edit made the current body cease to match. Prior complete rows supplement only numbers the current observations did not see, until their disclosed retention expires. Validated merged evidence takes precedence over contradictory open evidence even at equal update times. This includes a prior complete merged observation that remains eligible during a partial refresh. Because a GitHub pull request cannot reopen after merge, a current open row cannot displace it. Each candidate carries the observation time and whether it came from the prior complete scan. Partial scans have unknown totals, including when no match was seen. Each response states the repository and each state’s freshness, observation interval, and merged cutoff if available. An unavailable state has no observation interval. When any requested state has incomplete coverage `matchCount` is null, and `knownMatchCount` counts matches already observed in the available results. Even a complete response covers only records visible to the server's GitHub identity and this query.

Search number, title, body and head/base refs case-insensitively. Titles rank first, with exact titles above substring matches, followed by refs and then bodies. Ties sort by latest update and then PR number. Return up to 20 rows per page with number, title, state, refs, timestamp and GitHub link. Return a body match excerpt no longer than 240 characters with a matching row and a flag showing whether the excerpt was cut. Verify the full record when omitted qualifiers could change the decision. The page size gives an agent a compact batch to read and has no effect on the total candidate set. Retrieve the rest with the same query and state plus the returned `nextOffset` and `revision`. A changed snapshot, scope or query or expiration of any contributing evidence invalidates the continuation with 409 and the caller starts again at the first page. If the scan is incomplete, a final page only ends the observed results. A complete-scope zero means no literal match for that query. The agent retries with aliases and synonyms and checks conversation evidence. Spec A covers semantic retrieval across sources.

GitHub output is untrusted quoted data. Nothing in a title, ref or excerpt has instruction authority. The route does not log search inputs or return full PR bodies, upstream errors, or authentication credentials.

A public-repo probe on November 23 read 222 open PRs in five 50-row pages, 0.69 MB, and about 2 seconds. It reached 1,100 merged rows across 22 pages before the update-time boundary, 3.68 MB, and about 10 seconds. The per-state deadline is 20 seconds. The 100-page and 16 MiB state limits bound a runaway scan and leave room for growth. Changing repositories requires a new review of the limits and current credentials. The merged window is a coverage decision for this immediate incident slice. An older known PR can still be read directly from its GitHub URL.

## Decision points touched

- Admission — invariant; basis: irreversible-consequence; evidence: The existing master bearer and principal boundary prevents team devices and scoped credentials from reading the development agent's GitHub view. The fixed repository allowlist prevents search input from expanding the server credential's scope.
- Source coverage and invalidation — invariant; basis: enumerable-domain; evidence: Each state stream reports fresh, stale, partial or unavailable using validated cursors, timestamps and bounded transfer. Contrast a completed empty response with a partial traversal that returned none. Observed denial evicts even a previously complete response.
- Relevance and next action — judgment-candidate. Floor: cite concrete links and state coverage limits before concluding broad absence. Default: surface and inspect plausible matches, then respond or assign through the existing owner workflow. Arbiter: the conversational agent in context. The same term may describe two different changes. Retrieval order, snippets, or a missing literal never decide that question.

## Multi-machine posture

Each eligible server has a disposable read-through cache, independently authenticated to GitHub. A machine that starts cold after a handoff queries GitHub directly. Live refresh or explicit unavailable are the same paths as initial startup. There is no replicated inventory or fallback to another machine’s credentials. Test the cold replacement machine independently.
