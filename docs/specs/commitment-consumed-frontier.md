# Commitment Detection Consumed Frontier

## Problem statement

Mixed Telegram and app message ids make the scalar lastProcessedId bookmark unsuitable for proving no new input. Existing jobs may exit successfully without proving which source rows were reviewed. Build a durable exact source/batch consumption receipt, then a separately dark skip gate. Do not change the existing schedule, model routing or live configuration. The historical 49.9M tokens/day is an earlier cache-inclusive measurement, not a current savings forecast.

## Proposed design

Internal scheduler service `CommitmentConsumedFrontier`, no new public API. Read flags live under `jobs.commitmentConsumedFrontier`: `enabled` and `skipEnabled`, both require literal true and default false. Missing/invalid config is off. Skip requires both flags. With enabled=false, no source/receipt IO, prompt change or new gate behavior. With enabled=true/skipEnabled=false, collect receipts and record only a shadow would-skip; still start the normal scheduled model run. No additional model calls or manual test sessions.

Source is exactly the existing local `.instar/telegram-messages.jsonl`, not upstream delivery. Stable async bounded snapshot: fixed file length, file identity (canonical-path hash/dev/ino/birthtime), size/mtime before and after, SHA256 of exact bytes; complete newline rows, valid JSON and required row fields. IDs are opaque strings. Keys bind source identity + physical byte start + raw-line SHA256, never numeric/timestamp ordering. Missing, unreadable, changing, oversized (>64MiB), malformed, incomplete-line or empty/no-history sources return uncertain and normal legacy review. Resource limits are structural input bounds, not semantic judgments.

A canonical receipt stores exact reviewed byte intervals, source identity, consumer body/protocol hash, machine and source-prefix digest. Never seed from the old bookmark. A scheduled normal run captures an immutable0600 batch JSON matching the same most recent100 complete physical lines that normal tail100 review sees, with a128KiB structural bound. KEEP THE ORIGINAL JOB BODY AND RECENT-INPUT FILTERING: append only a receipt protocol; do not replace semantic review, rewind to byte zero, advance the legacy bookmark on its behalf, or launch historical work. Rows not actually reviewed, including ambiguous legacy-bookmark cases, are marked uncertain. A missing receipt is no coverage, not permission to ignore history. Unknown/partial historical coverage always runs normal review. A separate explicit prepareRange helper may capture a caller-selected bounded historical range for an already-authorized review, but the scheduler never calls that helper or starts backfill. No gate can skip until verified ranges really cover every byte of the complete current source from zero. On the real36k-row source the cold-start history gap is expected; live savings are not promised before deliberate historical coverage is established. This is a complete safe dark capability, not an automatic history certification.

Batch bound to an unpredictable id and actual scheduler session name. The model retains its original tail100/scalar-bookmark source instructions and commitment/deadline/opt-out semantics; the immutable batch is additional evidence context only. Raw message text is untrusted data. Each exact batch row needs a typed disposition in a separate bounded acknowledgement file: reviewed-no-action, registered (nonempty action ids), or uncertain. Registered actions must really exist in EvolutionManager (active or retained archive). The receipt protocol uses reserved source.contentId `cf1:<stable canonical message sha256>:<ordinal>` and source.platform=commitment-detection. Stable message identity includes opaque message/topic ids, actual sender identifiers (Telegram/platform sender id, mobile person/device/event, or agent/session identity), transport/via/rowOrigin/provenance and sender-role distinctions, normalized timestamp and text, not byte offset or file identity, so exact mirrored copies do not create a different registration identity. Display names do not certify identity. Missing/invalid principal metadata makes messageKey=null and forbids keyed registration/certifying a registered outcome; it never fabricates a sender. An actually reviewed no-action outcome can still record its physical byte range. EvolutionManager enforces idempotence for this reserved namespace only when a live receipt-mode provider is true: reserved-mode registration refuses if the provider is false, missing or throws (it never falls through to legacy creation). With the provider true, the same key and canonical immutable action intent returns the existing active/archived action without saving; a different intent under the same key conflicts instead of creating another action. An unreadable archive is refusal, not empty. Crash after action creation before acknowledgement must reuse the action across restart, including after archival. This does not solve semantic ambiguity: an ambiguous older legacy action without this key remains uncertain and must not be blindly recreated. The acknowledgement must explicitly account for every exact batch row once, with no extra fields or keys. Missing/extra/duplicate decisions, invalid DTOs, changed batch content or mismatched identities reject the whole acknowledgement. An explicit uncertain row adds no coverage, but does not block recording independently reviewed later rows; partial coverage never skips. This records the normal model's review decision; it does not deterministically prove semantic recall or certify arbitrary model assertions.

Only scheduler completion with explicit session.status===completed, exact bound session id/name/run/batch and no declared failure or skip (not starting/running, skipped, failed, killed, unknown status, replay, or spawn error) may promote an acknowledgement. Success alone is insufficient. Revalidate exact source prefix and identity (appends after batch allowed, replacement/truncation/edits refused), consumer digest, actual immutable action-reference fingerprints and previous-receipt CAS. Retain ALL referenced registered actions for covered ranges and revalidate them against the real current active+archive view on every future skip assessment. A missing/reused/mismatched action after independent action-store restore makes the receipt uncertain; it must never auto-recreate an intentionally removed action. Mutable completion/cancellation status does not invalidate an existing registration record; immutable id/source/createdAt/intent mismatch does. Bound receipt metadata to1MiB,2048 merged ranges and10000 references; exceeding a bound returns review, never prunes proof into apparent completeness. Atomically write one canonical metadata-only receipt through the existing better-sqlite3 dependency, synchronous=FULL and an immediate transaction with previous-payload hash CAS and zero busy timeout. SQLite releases locks on process crash; do not introduce an immortal filesystem lock. No new dependency is added. JSON remains the canonical validated payload. Failure/lock contention/storage errors mean normal future review; never consume before success. The receipt service never writes the source or scalar bookmark; the unchanged normal model job retains its existing bookmark write and conditional-effect audit. In-memory active bindings prevent stale/replayed batch completion in the current process; durable previous-receipt CAS prevents concurrent/out-of-order progress. A crash leaves a review retry, not false consumption. Filesystem is trusted agent state, not a new security boundary against an actor already able to rewrite all server state; message payloads/acknowledgements are untrusted. Private batch artifacts contain only bounded source rows and are not exported in events or receipts. Clean up exact owned batch/ack artifacts after authoritative terminal completion through SafeFsExecutor; no directory-wide deletion. A lazy bounded recovery pass before capture reads at most128 owned batch files and one real session-state snapshot: proven terminal orphan bindings are cleaned, active/unknown bindings remain held and visible. Unknown orphan files do not count toward the current in-memory active-batch reservation cap, so they cannot permanently disable new capture. No age-only deletion or guessed lock reclamation; SQLite owns crash recovery. Storage exhaustion simply restores normal review.

Skip decision is exact: only an independently revalidated receipt whose merged reviewed intervals cover [0,current stable source length), with matching source identity, full digest, consumer digest, machine and ALL retained real action references can say no-new-input. Otherwise normal review. A new append after a check belongs to the next normal schedule, as it would after a normal reader's snapshot; the next check observes it. Shadow mode logs would-skip but does not skip. Active skip uses existing SkipLedger reason gate with explicit source-frontier detail; never count missing history as healthy. No effects or model launch on an actual no-new-input skip. Receipt capture and gate apply only to commitment-detection; script jobs and all other jobs unchanged.

## Wiring

Scheduler constructs the service (no IO in constructor). Capture only for enabled commitment-detection. Assess skip after ordinary writable/machine guards and before model capacity admission. Serialize receipt admission even if job.gate is absent. Assess/capture before the final synchronous claim+spawn section: reserve activeSessionSpawns before new awaits, then refresh/recheck job enablement/body, flags, role and session capacity after awaits; finally release reservations on every path. Take the claim only after those checks, so receipt preparation cannot strand a claim. Bind exact batch and returned session id/run when spawn resolves, and retain original conditionalEffects/bookmark behavior because normal body is unchanged. A valid acknowledgement is additional evidence, never a substitute for normal job success or its existing conditional-effect audit. Non-terminal notify callbacks never clean or promote a batch. A same-slug fence spans normal completion and receipt validation. Delayed terminal reconciliation runs at most once per trigger, after normal writable and role guards. Reserved receipt-session names make unbound or replayed callbacks inert before legacy slug-wide cleanup, including after reconstruction. An exact terminal run whose definition disappeared is unpromotable and cleans only its owned artifacts/maps and writable claim. Normal completion and claim release precede asynchronous receipt validation; demotion or optional telemetry failure cannot prevent that cleanup. Bind session before spawn; preserve the normal capacity, quota, ownership, actual framework/account and failure paths. Completion validates only successful bound batches. Server late-binds action lookup to real EvolutionManager.listCommitmentReceiptActions() (strict active plus retained archive indexed by actual action id/reserved key; conflicting immutable identities refuse, never use the lossy replication projection), and a receipt-mode provider for keyed registration, never a no-op; unavailable reader permits no registered disposition to certify. Receipt code owns its completion metadata and does not reopen parked audited-job-routing.

## Decision points touched

Existing normal model review remains the semantic authority. Exact byte-prefix equality is an enumerable no-new-input fact, not a regex commitment detector. Feature flags retain normal behavior by default. Every uncertainty proceeds to normal review. No new LLM authority, trust raise, user approval or outbound policy is introduced.

## Frontloaded decisions

- Default-off collection and separately default-off enforcement; no live activation or claimed token savings.
- Machine-local by design because source log and its inode are local. No copied/replicated receipt establishes a different machine's coverage; failover reviews normally until that machine has its own verified receipt.
- Model review remains semantic; receipt validates coverage and real referenced artifacts, not meaning or upstream delivery completeness.
- No initial cursor seeding, numeric-id comparison or timestamp skip. Cold start preserves the normal recent-message review and explicitly reports historical gaps; no automatic historical reprocessing. Optional historical capture never displaces recent work.
- Storage failure is review, not skip; no guessed lock reclamation. Rollback flags off restores legacy behavior immediately; code revert leaves inert metadata.

Integration: existing HTTP job-run path with real scheduler/frontier/action state, stand-in session manager only, proving enabled/dark/off and full coverage/no launch; no real model. E2E: production scheduler construction/start+server job route, success receipt survives service reconstruction, actual wired source/consumer verification, corrupted history forces normal review. New/existing agents: no default flag insertion; template/awareness reaches updates through normal registry/migration. Full test:all via throughput only.
