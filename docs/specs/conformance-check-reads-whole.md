# The constitution check reads a spec whole, or says it did not check

## Problem statement

`POST /spec/conformance-check` judges a spec against the constitution. Two checks downstream rely on it. **B25** is the outbound-message reviewer's rule that holds a request asking the operator to approve a spec or design unless the request carries this check's result. **R32** is the autonomous-run rule that lets a run's spec deliverable count as reviewed once this check has run on it. Two failures surfaced on 2026-11-27 while converging the meeting-transcript spec:

1. **Silent truncation.** `MAX_SPEC_CHARS` is 24,000. A longer spec was cut to its first 24,000 characters with `…[truncated]` and judged as if whole. The 67,000-character spec was flagged, run after run, for problems its unread later sections had already fixed, and the counts swung between runs. One run noticed ("the supplied draft ends mid-sentence"); the report did not.
2. **Degraded read as a pass.** A run whose model call failed returned `degraded: true, degradeReason: 'error'` with an empty findings list. The agent read that as "0 flags" and reported it to the Chief of Staff as a clean result. The fit judgment made it worse: when degraded it returned verdict `fit`.

Both are gates failing silently. Every spec approval rests on this check (B25 holds an approval ask that lacks its result), so a silent pass is the worst failure it can have.

## Proposed design

1. **Whole, always.** The 24,000-character cap and its truncation are removed. The prompt carries the whole spec, every time. There is no judging limit of our own: a spec the model, or its transport, cannot take fails the call, and the report says plainly that the spec was not checked. The real ceilings are the model's context and the 12 MB input ceiling below. Both model calls run on the locked-down reviewer path (`reviewerHardening`, with no tools offered): on Claude the prompt goes over standard input, never as a command-line argument, so the spec is not in the process list, cannot hit the operating system's argument limit (about 1 MB on macOS, 128 KB on Linux), and is not echoed into an error's command line. The pin is the concrete model the tier resolves to, so the judging model does not change. Codex already sends its prompt on standard input (its exec-json path; only its kill-switch path uses an argument). Gemini's shared adapter still passes the prompt as an argument. Gemini is installed and enabled for this agent on the Studio, but it is not on this check's route today (the check runs on Codex, which already uses standard input); if it ever were, an oversized prompt there fails loudly as not checked, never as a cut judgment. Moving that adapter is recorded, not made here. The label is `degradeReason: 'too-long'` when the provider's error says the prompt was too long (including `E2BIG`, the argument-limit error), and `'error'` otherwise. Because a provider's error can embed the whole command line, prompt included, and a spec may itself say "context window", the label is read from the error with the prompt text removed (stderr when the error carries it), so a timeout on such a spec is `error`, not `too-long`. Both labels mean not checked; the label only words the reason. There is no pre-call size check to tune or defend; the cap never was injection hardening, since the fence and the SECURITY framing do that whatever the size. On main, 393 of 1,862 specs were over 24,000 characters (24% of the last month's new ones). They were judged on part of their text, and are now judged whole. Host memory stays bounded by the input ceiling that already exists: an inline spec rides the server's general JSON parser (12 MB for an authenticated caller, `FULL_BODY_LIMIT_BYTES`), and a `specPath` file over that same ceiling is refused with 413 and `checked: false` before it is read, never read in part.
2. **Not checked is never zero.** Every degraded report carries a plain `notCheckedReason`, plus `charsTotal` and `charsJudged`. `charsJudged` counts the characters sent, whole, to a call that completed, so it is 0 for every degraded outcome. It records what was sent, not a claim about what a connection did with it. The plain reasons say only what is known: that no judgment completed and why, never how much the model read. `judgeFit` returns the new verdict `not-checked` (never `fit`) when degraded; it still never blocks.
2a. **The two calls share the route's time.** The review and the fit judgment run one after the other inside the route's 180-second request budget, whose clock starts when the route handler starts (after body parsing, so reading the file and loading the registry count; the middleware's own clock started slightly earlier, which the 10-second margin covers). The review keeps its 150-second timeout, capped by what is left of the budget when it starts; the fit call gets only what is left, less a 10-second reply margin, and is not started (not checked, "no time was left") when under 20 seconds remain. The fit call is made even after a too-long review: its prompt carries the spec with one standard, not all of them, so it can fit where the review did not. So a slow whole-spec review ends as a stated not-checked fit, never as a 408 that hides both results.
3. **Every caller says so.**
   - The route adds top-level `checked` (false when degraded) and `notChecked` (the reason).
   - The route records R32 ceremony evidence only for a run that checked the spec.
   - The ledger record keeps `degradeReason`, on local and peer records.
   - The B25 rendering shows a degraded record as `notChecked: true`, with its reason and `atRiskCount: "unknown"`. The B25 rule now also fires when a message reports a clean or numbered result from a record marked not checked, and still passes an honest "the check could not run, because …".
   - `instar spec conformance` prints "NOT CHECKED: <reason>" and exits 2. It waits 200 seconds (above the route's budget, where it used to give up at 60 and blame the server); a client timeout, a 408 or a 413 is also NOT CHECKED with exit 2. A fit judgment that did not run prints "NOT CHECKED (fit)" and exits 2: the route's `checked` is about the review only, and `fitChecked` reports the fit.
   - The route answers a `specPath` file over the input ceiling with 413, `checked: false` and a plain `notChecked`.
   - The awareness note agents read before an approval ask says a `checked: false` (or `fitChecked: false`) reply is not checked even with a 200 status, and asks for every run of the exact text to be reported, with a second run usually worth it, as the agent's judgment. Awareness entries are rebuilt on every update, so existing agents receive it with no migration.
   - The spec-converge skill gains one marked block, `INSTAR:CONFORMANCE_NOT_CHECKED`, which a `PostUpdateMigrator` step inserts into installed canonical, Claude and Codex copies (the same delivery rules as the experience-review lens: once, before the lessons-aware anchor, never over a customized, learned or linked copy). It says a degraded report is `unavailable: <notChecked>`, never `ran (0 flags)`; that a fit judgment with `fitChecked: false` counts the same; that a spec too long for the model is shortened and checked again whole, and that checks of separate parts never stand for the spec; that the request waits at least 200 seconds and a reply that times out, comes back empty or is not JSON counts as `unavailable`; and that a result handed to an approver reports every run of the exact text, one completed run being a sample, so a second is usually worth it (the agent's judgment). The bundled skill's example curl moves from `-m 90` to `-m 200`; installed copies keep their example (the migration inserts only the marked block), and the block's own "at least 200 seconds" governs.
   - The ledger tallies every run of the current text (`runsOfThisText`: total, not checked, how many runs found each count, and up to 24 distinct standards any run flagged, with `standardsOmitted` a lower bound on flags past the list, so an incomplete list is always said, never cut silently). The tally is shown whenever it says more than the record's own `atRisk` (more runs, more machines, more standards, or omitted ones). This is the approval summary B25 checks against: a histogram of counts plus the flagged standards. Which run flagged which standard is in each run's own response, which the agent reports; the ledger does not keep per-run lists.
     - Only tallies written by this whole-text reviewer count. A record from the old reviewer (no tally; it may have judged a cut spec) never seeds one.
     - A record with no tally is from the old reviewer, which cut long specs. It is rendered `legacy: true`, the merged view counts such runs in `legacyRuns` (and names a newer one in `newerLegacyRunAt`), and B25 holds a clean or numbered result that rests only on a legacy record. They are never evidence, and never fabricated into a tally.
     - The records section has a total budget of 24,000 characters per review (its worst case, about 6 Kchars a line, would otherwise be about 160 Kchars across 25 lines, on almost every outbound message); whole lines past it are counted in the existing "not shown" note, never cut mid-line. Typical lines are well under 1 Kchar, so the budget rarely binds.
     - A record keeps the tallies of its last three earlier texts (`earlierTexts`), so a revert to an earlier text resumes that text's tally, and a flip between versions stays visible as context. Runs of other texts are counted in `priorVersionRuns`. The rendering says once, in its header, that these are context and not evidence about the text asked about.
     - Across machines, the merged view shows the newest record's text and adds up every machine's whole-text tally of that text, whether it is that machine's current text or one it keeps in `earlierTexts`, and names the machines (`runsCombinedFrom`). A spread split across machines is one spread. A record without a tally (the old reviewer) is never turned into one.
     - Each rendered record carries `text`, the first 8 characters of the checked text's hash, so records of the same text are recognisable.
     - The rendering is never cut: every field is bounded where it is recorded (the arithmetic is beside the code, at most about 6 KB a line), so the old 2,600-character slice, which could cut the tally off, is removed. The tally comes before the standard names, and the tally's standards are left out when they equal `atRisk`.
     - A peer's degrade reason is a closed code; its prose is rebuilt locally, so no peer-written text reaches the reviewer's prompt.
     - The record keeps the fit judgment's outcome (`fitVerdict`, `not-checked` when it was asked for and did not run), and B25 also holds a request that says the design fits its parent principle while that record's fit was not checked. A peer's fit value is accepted only from the closed set.
     - B25 sees the tally, and holds a request that reports one run as the result while other runs of the same text, on any machine, differ, so a clean run cannot be picked from a spread. An honest "the check could not run" passes only if it also reports what completed runs of the same text flagged.
   - Two checks finishing together do not lose a run: the record step is synchronous (read, write, rename) inside the one server process that owns the ledger.
   - Known limit, stated: a new text starts a new tally, so an edit followed by one clean run shows a one-run tally. The earlier text's tally stays visible beside it. Binding approvals to the exact text is CMT-060.

The wording differs from the one first asked for ("too long to judge: N of M characters read"): the reason gives the spec's length but not N, because no judgment completed and the design makes no claim about how much a model read; N would always be 0.

Judging in overlapping parts was considered and not chosen: a part cannot see the section that resolves its concern. That is exactly how the 67,000-character spec drew findings its later text had already fixed. Refusal keeps one rule (a spec is judged whole) and pushes specs toward the size a reviewer can hold.

## Frontloaded Decisions

- Refusal rather than chunked judging, for the reason above.
- The 24,000 cap is removed with no replacement judging limit; the model's context decides. The only size bound is the existing 12 MB input ceiling, which protects host memory, and a file over it is refused whole, never cut.
- The 150-second review timeout is unchanged, and the fit call gets what is left of the route's 180-second budget (2a). A very large spec that runs past it now degrades loudly as `error`, where before it was judged on its first part. A size-aware timeout is a separate change, registered as tracked commitment CMT-061 (see Side effects).
- `charsJudged` and `charsTotal` are optional on the type, because existing callers construct reports; the reviewer always sets them.
- The CLI's exit code 2 is used for "not checked" (review or fit), distinct from a failed request, which exits 1.
- A fit judgment that did not run counts as not checked for the CLI and the skill; the route keeps `checked` about the review and reports `fitChecked` separately.
- How many runs: the agent's judgment, recorded as a decision row. The enforced part is structural: every run is recorded, and B25 holds a report that leaves out a recorded outcome of the same text.
- The conformance calls move to the hardened standard-input path in this change (the Chief of Staff's reviewer, 2026-11-27), with the pin set to the model the tier already resolved to. The "too long" label stays a reading of the provider's own refusal, not a measured size: there is no per-model context table to measure against, and both labels mean not checked. With the prompt on standard input the refusal no longer carries the spec. Gemini's adapter transport is a separate change (recorded in Side effects).

## Multi-machine posture

The new ledger state (`degradeReason`, `runsOfThisText`, `earlierTexts`, `priorVersionRuns`) is **proxied-on-read**: each machine records its own runs, and the existing peer read (`SpecCheckPeerCache`, `mergeSpecCheckRecords`) merges them, adding same-text tallies across machines. A peer that does not answer is left out, as the rendering already says ("the peers that answered"). Behaviour is identical on every machine.

If no not-checked record occurred in the window, the criterion is recorded as not exercised, not as met. Limit, stated: later runs update the ledger, so the read compares each ask with the B25 decision recorded when it was sent; where that record does not carry the evidence shown, the read says so rather than judging from the later ledger. ## Side effects and rollback

- Specs that used to be judged on their first 24,000 characters are now judged whole, about a quarter of new specs, so their findings may change. Larger prompts cost more: a 67,000-character spec is about 17,000 input tokens per call, about 34,000 per run (review and fit), about 100,000 for three runs, against a ceiling of about 12,000 per call before. On the command-line connections the whole spec is visible in the process list, as part of it was before; spec text is repository content.
- The B25 records grow by the tally and earlier texts on each outbound review; the shared note is said once in the header, and tallies are shown only when there is more than one run or more than one machine.
- The ledger still keeps its 500 most recent slugs (`MAX_RECORDS`), unchanged.
- Gemini's one-shot adapter (`buildGeminiOneShotArgv`) still passes the prompt as `-p <prompt>`. Gemini is installed and enabled on the Studio but is not on this check's route today; an oversized prompt there would fail loudly as not checked. Moving it to standard input changes the shared adapter every Gemini caller uses, so it is recorded for that adapter's owner rather than made in this fix.
- An autonomous run's spec deliverable now clears its ceremony arm only through a real check (R32) or a merged PR. A degraded run no longer counts.
- The route also reports `fitChecked`, because the fit judgment is a second model call that can fail on its own.
- Left out, and recorded: R32 and the B25 records identify a spec by slug, and a record keeps the checked text's hash (`contentSha`). Binding an approval ask to the exact text that was checked, so that an earlier check of draft A cannot stand for draft B, is a separate change to B25. It is registered as tracked commitment CMT-060 (on the M5 Pro), and the size-aware timeout as CMT-061, both targeted for 2026-12-05 and reported to the Chief of Staff.
- Rollback: revert the release. Installed skill copies keep the guidance block; that is harmless, because the block keys on `report.degraded`, which the older server also sends.

## Tests

- **Unit, reviewer:** a 200,000-character spec reaching the model whole, a provider too-long error reported as `too-long`, `E2BIG` as `too-long`, a timeout whose message embeds a spec that says "context window" reported as `error`, the prompt builders carrying the whole spec, a reason and 0 judged characters on every degraded review, `not-checked` fit verdicts, and the fit call not started when no time is left. These see the prompt at `evaluate`. **Unit, payload:** through the real Claude provider against a stand-in `claude` that records its arguments and standard input, a 200,000-character spec arrives whole on standard input, none of it in the arguments, with no tools offered and the pin equal to the tier's model, for both the review and the fit call.
- **Unit, migration:** the block inserted once into every installed copy before the anchor, idempotent, a copy with no anchor left alone and reported, and other skills untouched.
- **Unit, CLI:** NOT CHECKED with its reason, and exit 2 in both formatted and `--json` modes; NOT CHECKED (fit) with exit 2; a client timeout and a 408 as NOT CHECKED with exit 2, never "is the server running".
- **Unit, ledger:** notChecked rendering, the B25 rule text, the reason kept on local and peer records (a peer's prose replaced by the local text for its code), the per-text tally, a revert resuming its text's tally, a legacy record not seeding one (on record and in the merge, both orders), same-text runs on two machines combined including a machine's earlier text, the fit outcome recorded and shown, and a maximum-size record rendered whole as valid JSON with `standardsOmitted`.
- **Integration, route:** `checked`/`notChecked` when there is no provider, a too-long failure recorded but not counted as R32 evidence, a real check counted, the fit call given at most the time left (including time spent before the review) and still made after a too-long review, the route budget pinned equal to the middleware's, and a `specPath` file over 12 MB refused with 413 without a model call.
