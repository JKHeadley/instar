# A1 — Find existing work and give each record one authority

The November 23 Chief of Staff response to a permanent-address question treated the work as new. The approved design and implementation were already in PR #3342. The local history was incomplete after a rebuild, but conversation search could still find the relevant topic. Agents were directed to a memory index covering two files. A later installed-CLI replay produced “No claims found” on a keyword query without checking any pull requests. The public incident locator is PR #3342 and its linked versioned design. The owner-authorized replay fixture preserves the exact question and prior approval trail under their original audience.

Instar has a related problem with the records it uses to answer everyday questions. On the same installation, the Projects and Chief of Staff views returned 15 and 22 project rows, with four exact Telegram conversation-key matches. The legacy and scheduled job stores shared 16 slugs even though the scheduler emitted 84 unique effective jobs. Those counts warrant reconciliation. Independently, the old jobs PATCH writes the legacy file while the scheduler chooses an overlapping manifest as its effective definition. The two writers can disagree about enabled state for the same scoped slug.

## Constitutional fit

**Cross-Store Coherence Is an Invariant** governs declared agreement, repeated verification, and repair across stores. This design operationalizes that obligation for enrolled work records. **Structure beats Willpower** governs durable write seams and evidence-bearing work initiation. **Attributed Statements Trace to Their Source** governs provenance. **Signal vs. Authority** and **Judgment Within Floors** govern ranking, ambiguity, and departures from a suggested match. **Cross-Machine Coherence** governs visibility after recovery and handoff. **An Instar Agent Always Serves a Team** governs viewer, destination and record ownership scope.

A separate constitutional proposal can extend the parent article with two obligations. Every defined authoritative fact has one owner and an enforceable write contract within its scope. Durable work initiation consults existing evidence through a discoverable record. Adoption of new constitutional wording requires its own review and operator ratification. This spec applies the existing articles to Instar's first enrolled records. A1 defines record authority, read-only discovery, source linking, capture and recovery. A separate A2 design will review mandatory check-before-start receipts, work admission, and external dispatch fencing. A1 confers no authority to start work or retry external effects.

## Frontloaded decisions

1. Extend the existing state coherence registry with an authority contract. Keep each kind's adapter and underlying storage in its owning service. A work search index contains source references and derived searchable data. It cannot mutate a job, project, card, commitment, or PR.
2. Use native identities for each source and a stable work ID for relationships that span sources. One project may have multiple work items and conversations. A repository may contain branches with no known Instar work ID. Native ID and write ownership do not depend on the discovery index.
3. Use one read-only discovery query with source-specific coverage and current destination permission. Give users and agents evidence for what already exists and describe gaps.
4. Reuse platform-owned conversation history and the conversation effort graph. Add a provider contract for linked work, using the same access boundary. Provider presence and replay coverage are explicit. The index can be rebuilt with retained, authorized evidence.
5. Migrate jobs and projects using [Jobs, Projects, and Standing Responsibilities](jobs-projects-standing-responsibilities.md) through the authority contract in § Migration. Migrate each kind independently, with verified cutover and recovery. Other stores start as inventory entries and may enroll when their source owners can implement the same kind of enforcement.

## Authority contracts

The machine-readable state coherence registry describes persisted stores. The live tree has the implemented census at src/data/state-coherence-registry.json with scripts/lint-state-registry.js. A1 extends that existing seam and proves its normal CI wiring. Add a versioned authority declaration for each enrolled fact family. A declaration names the kind, scope and stable identity rules, owning service, accessible mutation entry points, physical store paths or replicas, version and conflict semantics, allowable read projections, retention and recovery source, and a reconciliation check. A family is a set of facts with the same owner and lifecycle. Different names, API routes or formats never establish separate ownership. Examples include a project's purpose and lifecycle, a Chief of Staff check occurrence, a job definition, and a machine's job attempt. Each example has an independent identity and a separate mutation contract.

At build time, registry validation requires one canonical contract per kind and scope, one canonical owner for each mutable field group, resolvable projection and migration edges, and explicit shared-file ownership. Extend the current persistence census to check enrolled writers against the protected owner modules and known storage adapters. Include tests that place a second project writer behind an alias, independently write a protected projection, or introduce an undeclared durable path. Static checking can recognize declared write seams and protected paths. Review and runtime audits cover semantic duplication the compiler cannot infer. Backward-compatible endpoints delegate mutations through the owning adapter. Replicas and restore journals replay the same versioned authority. They carry no independent write rights.

At runtime, the owner authenticates the caller, enforces scope and version, and returns the canonical ID and revision. Consumers write separate facts through their own contracts. A view declares source IDs, revisions, coverage and inclusion rules. For example, an oversight report can own its own cadence and assessment evidence while fetching current project state from the project owner. A cached projection rebuilds from its inputs and surfaces stale or missing coverage. A read failure never synthesizes an empty authoritative list.

## Capture and link work

Use the conversation effort graph's existing relationship and decision semantics. A work reference is a stable tagged union of existing EffortRef or verified native source-origin ID. An existing effort is reused. Tag generated summaries and discovery replies with source dependencies through the existing conversation provenance path. Those replies may be discoverable as replies but cannot independently prove a decision or other underlying fact. Verification resolves citations to authorized original evidence. A transient outage can leave a separately authorized reply available as a qualified lead. Revocation or erasure removes source-dependent fields from that reply's derived search record. If the dependency projection cannot isolate affected material, suppress the result and all derived fields and counts until it can. A historical transcript's own visibility alone cannot grant access to dependent evidence. Test a second lookup after the original approval is removed. A source adapter supplies the second form from its already accepted native record or verified source occurrence. It remains stable when the owner later links it to an EffortRef. Creating a card or document does not implicitly create an Effort. The graph owner authorizes manual effort creation and cross-links under its existing scope. An authenticated source adapter writes a versioned artifact-to-origin attestation through its own authorized journal contract. The attestation is an owning source record, with actor, scope, native revision and tombstone. It is not a new graph node or graph operation. The graph owner alone can authorize and revoke a typed versioned OriginEffortLink stored in its declared authority journal. It references an existing EffortRef and a verified source-origin reference. It is a new source-to-graph mapping record with revision, provenance and a tombstone, not an added hierarchy vertex or an existing conversation cross-link operation. It may attach an artifact that began without a conversation to a later EffortRef. One origin has one primary grouping link in its scope. An owner may relate it to other efforts without another result count. Reassignment CASes the current link revision and atomically supersedes it with the new one; a concurrent or stale command conflicts. Related efforts can remain references and do not duplicate the hit or count. Test competing assignments and reversed replay. Revoke and replay the two relations independently; the derived view serves their join only while both edges are authorized. Service dispatch may assert only the existing delegation relationship and only from verified dispatch evidence. Neither adapter may assert another service's decision, identity, or ownership. Attach source revision, occurrence, evidence origin, visibility and verification state to each typed reference. A work identity records its creation cause and accountable human principal or an explicit unresolved ownership state. A delegated agent handles the work inside that audience and authority. Sharing a card or project cannot widen access to the original discussion, an attached private decision, or a body excerpt across repositories. Before any private evidence can enter a model input or response, require both current source access and the adapter's destination-bound capability from the hierarchy privacy contract. An owner asking in a shared topic does not grant the topic access. Apply these checks to each field, match, link, excerpt and aggregate. If permission, erasure or custody generation cannot be established, omit that evidence with generic coverage. Permission never derives from the source text.

Source providers emit capture events from their owning write seams. A durable source transaction or atomic append records an outbox reference with the mutation. For a store that cannot yet emit atomically, first ship a replayable change feeder with explicit checkpoint and completeness evidence. Retry by scoped source ID, revision and event purpose. A failure can leave the source committed and discovery pending. The source remains authoritative and the service reports the backlog. Advance the contiguous completeness checkpoint only after durable application, a confirmed idempotent no-op, a verified immutable exclusion, or a verified tombstone. Re-evaluate a mutable exclusion after its policy epoch changes before claiming complete coverage. A temporary policy/read failure remains a retryable gap even if work at a higher position succeeds. Store the gap separately from the maximum observed offset and consult both before claiming completeness. Apply erasure before any replay can serve a result. The feeder reads beyond the last verified snapshot watermark and exposes the covered interval and unresolved gaps. If the source's retained lower bound advanced past the next consumer position, or a causal parent is missing, hold dependent attestations until a verified source snapshot covers that interval and supplies applicable tombstones. A current-state snapshot may restore current facts. The missing history remains partial unless its source evidence also survives. Test transfer across this boundary, including a deletion inside it. Render custody directly from the originating service. For conversations, relay the active source service's actual labels and proof level. In a deployment that implements the owned-custody redesign, local recording, off-device recoverability and shared commitment are separate claims. A single-member installation may establish shared commitment with no off-device copy. An independent copy alone does not certify shared acceptance where all-member proof is required. Other enrolled records respect their own verified durability policy. A stalled pending item follows its source's reconciliation and attention path. Enrollment never extends a Conversations-only Pending exception to job or project mutations. Capture binds each accepted event to its native source reference and WorkRef without changing when the source can accept new work. Ordinary captures and unresolved legacy imports may remain independently searchable; the owning service reconciles unresolved enrolled links using its existing bounded backlog and health cadence. Links are verified relationships; inferred matches and contradictory past assertions remain labeled candidates backed by source references. Conversation analysis attaches candidates to the message span and may propose aliases or work relationships. It may not convert an ambiguous conversation into an assignment, official decision, or new record of governed work.

Persist scoped work IDs and verified links under the graph owner's existing custody or its declared journal carrier, with scope, generation, tombstones and replay. Source records keep native IDs. Conversation text stays within the captured platform stores and their access policy. A derived index or cache may store text only under the source's visibility, retention and deletion conditions. Use existing first-party Git and PR pointers and read an optional machine-readable public PR block containing only separately authorized public associations. Producing a proposed block may assist the existing authorized PR workflow. A1 never publishes or edits remote metadata. Scope it to a fixed namespace and an allowlisted repository. Restoration accepts PR body claims as candidates until the owning relationship service attests them or verifiable public evidence independently corroborates them. Private conversation IDs, owner identity, summaries, customer data and access-bearing URLs stay out of exported metadata. Rebuild Git-linked relationships from GitHub after a loss, and recover other links and source records through their own approved custody and backup contracts. A PR body alone cannot restore a private approval.

## One discovery query

Expose POST /work/discover for an authorized read-only lookup. Before any provider invocation, authenticate the server-resolved principal and resolve the actual conversation destination or the existing owner-authenticated private Work view. A request-supplied destination cannot upgrade a shared audience. Reject missing, unsupported or mismatched principals/scopes through the existing auth middleware. Return Cache-Control no-store. Routine logs, traces and error diagnostics omit raw queries, evidence payloads, cursors and unauthorized metadata. Retained authorized user-facing history follows its source policy. The body carries the query and declared source scope so ordinary URL logs contain no raw search terms. The versioned v1 response has candidates, per-provider coverage, optional continuation and observation time. A full-source outage reports unavailable. A mixed result reports fresh, partial, stale and unsearched states by source. A revoked or changed continuation requests a generic restart without revealing prior results.

Compose source adapters for conversation and decision evidence, documents and specs, known Git refs and PRs, and canonical project, card and commitment references. Initial provider coverage includes retained authorized conversations, the existing public open and 30-day merged Instar PR lookup, known fetched Git refs and versioned specs, and canonical project/card IDs. A verified linked public PR preserves its canonical repo/number, observation provenance and work link under the existing retention and erasure policy. The graph/journal link carries identifiers and revisions. The PR provider rehydrates public title and description by verified repository/number independently of query and stores only the policy-attributed derived search projection. Authorized user-authored aliases stay in their native source. Recovery replays those sources or rehydrates known public pointers, before duplicating an old title in a new owner. No user-authored text becomes an immutable graph event. These pointers stay searchable when the PR ages out of the live provider's merged window, without asserting that old state is current. Graph or Git evidence can also lead to the source. Test the permanent-links question after the merged boundary with the local transcript and search index removed and rebuilt by query-independent hydration. A known unavailable historical pointer remains a qualified evidence gap when its owner cannot be rehydrated. Arbitrary old or unlinked PRs outside the current provider's inherited window are explicitly unsearched. Support selecting additional authorized historical windows when a provider later offers a bounded verified traversal; the initial window limits the observed corpus and cannot serve as an absence gate. A repository becomes eligible only when its owner allowlists it and its provider meets privacy and snapshot proof; public Instar is the first configured case rather than a universal hard-coded restriction. Include independent decision, document, commitment and job providers only after authorized enrollment. Missing sources are explicit. Initial PR coverage is the public Instar repository. Refresh the allowlisted corpus independently of any search text and match locally. The provider never forwards a raw or derived private query to GitHub. Apply the same egress constraint to other external providers. Cold-request tests capture outbound calls as well as diagnostics using a unique private marker. Private PRs remain unavailable until an enrolled adapter has allowlisted credentials and destination-aware authorization. Group by work ID only when the grouping link itself is authorized for the current destination, and return unlinked hits. The same two member-visible artifacts remain separate when an owner relates both to a private effort. Test that the owner sees the group, while the member sees the same rows, count and continuation before and after the private link. A result unit is one canonical work group or native artifact identity. Providers coalesce views only when an owning source attestation or canonical identity contract proves they represent the same artifact. One repository spec document exposed by two paths remains one hit. Two different documents and the PR containing their pointers are distinct evidence. Without verified equality keep both results and show their provenance. Favor exact IDs and refs, then combine lexical and semantic candidates. Each hit names what matched, its provenance, revision and supported state. Requested, approved, implemented, merged, released and deployed evidence stay distinct. Report expected and missing providers. No candidates establishes no general absence.

Apply one aggregate deadline beneath the caller's existing response budget. A bounded pool allocates per-provider budgets and tenant-fair capacity. Cancel in-flight search at the deadline where supported and ignore late returns for that response. Coalesce refreshes by provider and authorized credential scope. Each provider has its own in-flight and queue ceiling. Pass deadlines down to the actual I/O. An adapter whose work cannot honor a deadline runs in an isolated bounded lane, cannot occupy unrelated provider slots, and reports overload without admitting excess work. Bound aggregate result payload and use continuation for additional candidates. Record the distinct job classes for interactive, live capture and backfill. Replay capacity has its own concurrency, batch-byte and lease bounds. Prioritize live capture, release stopped leases and prevent a new owner from restarting a full replay when a verified checkpoint survives. Measure queue bytes, oldest lag, skips, timeout counts and latency before read-only provider graduation. Reuse the conversation search provider and the narrow Chief of Staff PR provider for those sources. Split slow reconciliation and embedding off the request path. Filter sources before ranking and hydrate only currently authorized evidence. When a provider cannot filter before its internal limit, the adapter scans forward until it fills the authorized page, the underlying source ends, or the declared budget ends. A budget stop reports truncated coverage. A page of private hits cannot silently hide a lower-scoring authorized match. Use stable ranking tiers followed by ordered canonical native IDs. The response freezes a bounded authorized result snapshot for combined ranking. Eligible snapshots have a bounded retention and per-tenant and process-wide byte/count admissions calibrated against measured provider output, consumer continuation capacity, and the existing caller transport budget. Expired, evicted or transferred snapshots return the same generic restart. Purge invalidated tenant data promptly on revocation or erasure. Reserve interactive capacity from replay/capture to protect against private backfill. Hidden-only row changes alone cannot alter an authorized page, exposed count or continuation when sources are healthy. General service overload is explicitly reported at the same generic scope, with no guarantee of identical wall-clock time. A continuation enumerates that observed snapshot and never mixes newly arriving candidates into it. When an independently sorted provider can produce stronger results later or cannot expose a safe ranking frontier, return its separately labeled provider pages instead of pretending the combined snapshot ranks the unseen corpus. Those pages enumerate provider-local native artifacts and explicitly local counts, not group totals. A later artifact can link to an already shown group without adding a second global group. The combined snapshot remains immutable. Test a second artifact from the same effort arriving only on provider continuation. Requesting fresh knowledge creates a new snapshot. Disclose meaningful search limits without revealing hidden row counts. Determine eligibility for each provider and audience at enrollment, before reading search terms or corpus rows. Sensitive providers must apply authorized filtering before limits or use a verified audience-specific projection. An unproven provider is generically unavailable for the entire affected audience; it does not become available or unavailable per query based on encountering hidden rows. Test an authorized match against enough hidden rows to exhaust an unfiltered budget and require the same result, coverage and continuation. Continuations bind the authenticated principal, tenant, query/scope, reply destination, audience/erasure generation, ranker version and relevant provider cursor/vector. Reauthorize before paging. Ordinary content edits and inserts leave the frozen snapshot and its ordering intact. A later explicit fresh query may see them. Reauthorize every page and restart on a snapshot generation change, explicit eviction, owner handoff, or a relevant access or erasure change. Never return a newly revoked hit from a snapshot. Hidden-only mutation does not change an audience-scoped logical revision, candidate count, continuation validity. An unauthorized change enters only an internal rebase while the authenticated scope stays otherwise usable. A provider that never replied contributes no candidate to that sequence. Source revisions preserve temporal lifecycle. A reverted merge, superseding approval or changed branch head is explicit evidence rather than an opaque confidence score. Evaluate each current state claim against the relevant owner and revision.

Separate evidence fields from control fields. Store provider output as untrusted structured artifacts with native IDs validated at the boundary. Models can suggest matches and wording. Current source or mutation authority validates every decision to publish, link or dispatch independently of model-supplied instructions, destinations or identifiers.

## Migration and reconciliation

First inventory installed rows and writers in read-only mode. Report each discrepancy by named authority, source version, stable identity, inclusion rule, and audience-safe diagnostics. Reconcile exact IDs or source-proven aliases automatically. Use current authorized revision history, source provenance and existing aliases to resolve verifiable cases first. The accountable human owner decides the remaining ambiguous matches or ownership. The enrolled store owner validates and records that decision. Install compatible readers and writers first. Enumerate startup jobs, installers, migration scripts, direct file writers and older live processes. Route compatible writes through one per-kind serialization point. When different owners currently share physical storage, separate their owned data or require one atomic writer for the entire physical file before cutover. A scheduler bookkeeping write racing a definition edit must preserve both authorized updates. Obtain proof that incompatible writers are quiesced or unable to write. Each kind's cutover plan names the transaction boundary and actual serializer covering source, target and pointer. A common atomic transaction can fence all three. For independent physical stores, hold admitted writers under a current durable epoch, drain previous in-flight writes and prove both verified heads cannot change through pointer publication, including at the actual storage replace boundary. A process that passed old admission must either finish into the final source sequence before drain or be rejected before changing bytes. Inject a pause before old storage replacement, publish the new pointer, then resume the writer and verify no unaccounted change. Under the durable owner epoch and fence, record the sequence of the final accepted source mutation, and apply every accepted mutation through that sequence, verify exact data and effect mapping, then publish only if the verified fence, source head and target head still equal the known confirmation. This single atomic compare-and-set prevents two processes from changing the owner at once. This transition is the sole authority pointer. Before publication a crash recovers the fence and resumes validation or aborts back to current legacy authority if safely reversible. After publication, clients and receipt mirrors follow the pointer idempotently. A stale binary cannot downgrade the published epoch. The canonical owner transaction verifies its current fence and epoch with the mutation. Consumers move their canonical reads to the verified new owner only after publishing that epoch. Failed or ambiguous fencing rejects new writes as retryable and retains last validated reads. A stale machine returning after cutover cannot accept updates until it acquires the current configuration and authority epoch.

Write resumable source-to-target receipts at every step. Preserve original records and source versions. Legacy endpoints route through the verified owner. Rollback before cutover restores read routing. After cutover, presentation rollback keeps every later canonical mutation and effect result. Only an independently reviewed migration through the same authority mechanism can reverse the canonical write owner. Approval is held by the accountable principal or existing protected change authority. Retired targets are never cleared as a rollback shortcut.
Reconciliation checks declared invariant, provider coverage, and migration residue on the existing health cadence. Repair from authoritative rows where identity and scope are verified and rebuild is safe. Use bounded retries, timed backoff and a circuit breaker from the owning service. Where correction needs judgment or data authority, retain evidence and surface a deduplicated existing health/attention item in the authorized audience after safe repair is exhausted. Key by owning kind, scope, invariant and repair epoch. Clear the active incident only when an authoritative recheck passes; a new epoch may alert on recurrence. Suspected or confirmed competing live writers fence new writes immediately and raise the existing critical alert if safe restoration cannot act first. Where the invariant itself is violated by two authorized writers, stop competing migration writes and keep the last validated view. Reconciliation never deletes or retitles legitimate independent records as a cleanup action.

## Multi-machine posture

Authority is scoped by record and owner, with the owner's approved lease/witness/journal semantics for cross-machine writes. The graph carrier owns EffortRefs and graph relationships under its existing owner epoch and approved custody contract. Do not extend witnessed Pending to a new cross-source link unless eligible under that contract. Default durable continuity links to owned-machine custody and expose the source owner's actual result until acknowledged under the enrolled proof. Each provider stores its source revision, event outbox/high-water in the corresponding canonical service's declared transaction or authorized journal carrier. Shared discovery checkpoints and derived rank data are replayable views of these inputs. Every provider enrollment selects its exact custody adapter and authority before a writer can graduate. A transfer record carries the new owner epoch, per-source verified upper and retained lower bounds, and canonical source custody state. Refuse stale owner writes and ignore old acknowledgments. A transferred topic can query covered evidence and replays recorded gaps before claiming full coverage. It can continue with properly labeled degraded results if a peer or provider is offline. A local search shard or cache is rebuildable and carries no independent authority. Restoration applies current authorization, tombstones and replica generation before serving. Erased or revoked aliases, embeddings, snippets and cached aggregates remain unavailable even if a backup still holds encrypted original bytes. Existing backup erasure policy controls physical history and key destruction. Preserve pending writes through the existing deliberate pending/offline contract, and report when independent durability has not been proven. Extend the current machine-loss recovery tests instead of creating a second backup framework.

## Decision points touched

- Protected writer and scoped identity admission — invariant; basis: irreversible-consequence; evidence: a competing accepted write can orphan revisions and make migration lose custom definitions. Match registered owner, caller, scope and source version before mutation.
- Verified references, primary grouping, read access and replay — invariant; basis: irreversible-consequence; evidence: a hidden relationship or erased artifact can leak content through a derived title or count. Require current destination and source access, valid IDs, link head and erasure generation before serving.
- Semantic retrieval and source relevance — judgment-candidate. The existing authorized ranking/agent path may rank or expand visible candidates, cite source evidence, or state uncertainty. Access checks, outcome provenance and search scope are deterministic. On ranker failure return authorized exact and lexical results with reduced coverage, or explicitly unavailable.
- Migration cutover, source freshness and permission — invariant; basis: irreversible-consequence; evidence: obsolete writers can create lost state and unauthorized projections can leak protected work. Require verified source and target heads, current scope and authority epoch before changing authority.
- Recoverable drift triage — judgment-candidate. Repair only from a verified authoritative record through the existing repair contract. The service arbiter may replay or rebuild, retain last validated data, or raise a deduplicated notice after bounded attempts. Default to retaining evidence when ownership is uncertain.
