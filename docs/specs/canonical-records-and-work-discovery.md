# Find existing work and give each record one authority

The November 23 Chief of Staff response to a permanent-address question treated the work as new. The approved design and implementation were already in PR #3342. The local history was incomplete after a rebuild, but conversation search could still find the relevant topic. Agents were directed to a memory index covering two files. A later installed-CLI replay produced “No claims found” on a keyword query without checking any pull requests. The public incident locator is PR #3342 and its linked versioned design. The owner-authorized replay fixture preserves the exact question and prior approval trail under their original audience.

Instar has a related problem with the records it uses to answer everyday questions. On the same installation, the Projects and Chief of Staff views returned 15 and 22 project rows, with four exact Telegram conversation-key matches. The legacy and scheduled job stores shared 16 slugs even though the scheduler emitted 84 unique effective jobs. Those counts warrant reconciliation. Independently, the old jobs PATCH writes the legacy file while the scheduler chooses an overlapping manifest as its effective definition. The two writers can disagree about enabled state for the same scoped slug.

## Constitutional fit

**Cross-Store Coherence Is an Invariant** governs declared agreement, repeated verification, and repair across stores. This design operationalizes that obligation for enrolled work records. **Structure beats Willpower** governs durable write seams and evidence-bearing work initiation. **Attributed Statements Trace to Their Source** governs provenance. **Signal vs. Authority** and **Judgment Within Floors** govern ranking, ambiguity, and departures from a suggested match. **Cross-Machine Coherence** governs visibility on a recovering or newly assigned machine.

A separate constitutional proposal can extend the parent article with two obligations. Every defined authoritative fact has one owner and an enforceable write contract within its scope. Durable work initiation consults existing evidence through a discoverable record. Adoption of new constitutional wording requires its own review and operator ratification. This spec leaves the registry article unchanged and applies the existing obligations to Instar's first enrolled records.

## Frontloaded decisions

1. Extend the existing state coherence registry with an authority contract. Keep each kind's adapter and underlying storage in its owning service. A work search index contains source references and derived searchable data. It cannot mutate a job, project, card, commitment, or PR.
2. Use native identities for each source and a stable work ID for relationships that span sources. One project may have multiple work items and conversations. A repository may contain branches with no known Instar work ID. Native ID and write ownership do not depend on the discovery index.
3. Require a recent, scope-bound discovery receipt before starting a new durable effort through enrolled entry points. A distinct purpose or legitimate continuation can proceed. Semantic similarity is a reason to inspect a match. Exact equality for the same scoped request is a concurrency invariant. Ordinary answers may state scoped uncertainty when sources are incomplete.
4. Reuse platform-owned conversation history and the conversation effort graph. Add a provider contract for linked work, using the same access boundary. Provider presence and replay coverage are explicit. The index can be rebuilt with retained, authorized evidence.
5. Migrate jobs and projects using [Jobs, Projects, and Standing Responsibilities](jobs-projects-standing-responsibilities.md) through the authority contract in § Migration. Migrate each kind independently, with verified cutover and recovery. Other stores start as inventory entries and may enroll when their source owners can implement the same kind of enforcement.

## Authority contracts

The machine-readable state coherence registry describes persisted stores and already has a durable-write path census. Add a versioned authority declaration for each enrolled fact family. A declaration names the kind, scope and stable identity rules, owning service, accessible mutation entry points, physical store paths or replicas, version and conflict semantics, allowable read projections, retention and recovery source, and a reconciliation check. A family is a set of facts with the same owner and lifecycle. Different names, API routes or formats never establish separate ownership. Examples include a project's purpose and lifecycle, a Chief of Staff check occurrence, a job definition, and a machine's job attempt. Each example has an independent identity and a separate mutation contract.

At build time, registry validation requires one canonical contract per kind and scope, one canonical owner for each mutable field group, resolvable projection and migration edges, and explicit shared-file ownership. Extend the current persistence census to check enrolled writers against the protected owner modules and known storage adapters. Include tests that place a second project writer behind an alias, independently write a protected projection, or introduce an undeclared durable path. Static checking can recognize declared write seams and protected paths. Review and runtime audits cover semantic duplication the compiler cannot infer. Backward-compatible endpoints delegate mutations through the owning adapter. Replicas and restore journals replay the same versioned authority. They carry no independent write rights.

At runtime, the owner authenticates the caller, enforces scope and version, and returns the canonical ID and revision. Consumers write separate facts through their own contracts. A view declares source IDs, revisions, coverage and inclusion rules. For example, an oversight report can own its own cadence and assessment evidence while fetching current project state from the project owner. A cached projection rebuilds from its inputs and surfaces stale or missing coverage. A read failure never synthesizes an empty authoritative list.

## Capture and link work

Use the conversation effort graph's existing relationship and decision semantics. A work reference is a stable tagged union of existing EffortRef or verified origin/effect ID. An existing effort is reused. The originating service mints the second form when a durable artifact starts work before a graph effort exists. It remains stable when the owner later links it to an EffortRef. Creating a card or document does not implicitly create an Effort. The graph owner authorizes manual effort creation and cross-links under its existing scope. An authenticated source adapter writes a versioned artifact-to-origin attestation through its own authorized journal contract. The attestation is an owning source record, with actor, scope, native revision and tombstone. It is not a new graph node or graph operation. The graph owner alone can authorize and revoke a typed versioned OriginEffortLink stored in its declared authority journal. It references an existing EffortRef and a verified origin/effect. It is a new source-to-graph mapping record with revision, provenance and a tombstone, not an added hierarchy vertex or an existing conversation cross-link operation. It may attach an artifact that began without a conversation to a later EffortRef. One origin/effect has at most one active grouping link in its scope. Reassignment CASes the current link revision and atomically supersedes it with the new one; a concurrent or stale command conflicts. Related efforts can remain references and do not duplicate the hit or count. Test competing assignments and reversed replay. Revoke and replay the two relations independently; the derived view serves their join only while both edges are authorized. Service dispatch may assert only the existing delegation relationship and only from verified dispatch evidence. Neither adapter may assert another service's decision, identity, or ownership. Attach source revision, occurrence, evidence origin, visibility and verification state to each typed reference. A work identity records its creation cause and accountable human principal or an explicit unresolved ownership state. A delegated agent handles the work inside that audience and authority. Sharing a card or project cannot widen access to the original discussion, an attached private decision, or a body excerpt across repositories. Before any private evidence can enter a model input or response, require both current source access and the adapter's destination-bound capability from the hierarchy privacy contract. An owner asking in a shared topic does not grant the topic access. Apply these checks to each field, match, link, excerpt, receipt view and aggregate. If permission, erasure or custody generation cannot be established, omit that evidence with generic coverage. Permission never derives from the source text.

Source providers emit capture events from their owning write seams. A durable source transaction or atomic append records an outbox reference with the mutation. For a store that cannot yet emit atomically, first ship a replayable change feeder with explicit checkpoint and completeness evidence. Retry by scoped source ID, revision and event purpose. A failure can leave the source committed and discovery pending. The source remains authoritative and the service reports the backlog. Advance the contiguous completeness checkpoint only after durable application, a confirmed idempotent no-op, a verified immutable exclusion, or a verified tombstone. Re-evaluate a mutable exclusion after its policy epoch changes before claiming complete coverage. A temporary policy/read failure remains a retryable gap even if work at a higher position succeeds. Store the gap separately from the maximum observed offset and consult both before claiming completeness. Apply erasure before any replay can serve a result. The feeder reads beyond the last verified snapshot watermark and exposes the covered interval and unresolved gaps. Render custody directly from the originating service. For conversations, relay the active source service's actual labels and proof level. In a deployment that implements the owned-custody redesign, local recording, off-device recoverability and shared commitment are separate claims. A single-member installation may establish shared commitment with no off-device copy. An independent copy alone does not certify shared acceptance where all-member proof is required. Other enrolled records respect their own verified durability policy. A stalled pending item follows its source's reconciliation and attention path. Enrollment never extends a Conversations-only Pending exception to job or project mutations. New enrolled work binds its origin and WorkRef in the authoritative commit or the provider's durable pending intent. Ordinary captures and unresolved legacy imports may remain independently searchable; the owning service reconciles unresolved enrolled links using its existing bounded backlog and health cadence. Links are verified relationships; inferred matches and contradictory past assertions remain labeled candidates backed by source references. Conversation analysis attaches candidates to the message span and may propose aliases or work relationships. It may not convert an ambiguous conversation into an assignment, official decision, or new record of governed work.

Persist scoped work IDs and verified links under the graph owner's existing custody or its declared journal carrier, with scope, generation, tombstones and replay. Source records keep native IDs. Conversation text stays within the captured platform stores and their access policy. A derived index or cache may store text only under the source's visibility, retention and deletion conditions. Use existing first-party Git and PR pointers and add an optional machine-readable public PR block containing only public artifact IDs and URLs when their association is separately authorized for public export. Scope it to a fixed namespace and an allowlisted repository. Restoration accepts PR body claims as candidates until the owning relationship service attests them or verifiable public evidence independently corroborates them. Private conversation IDs, owner identity, summaries, customer data and access-bearing URLs stay out of exported metadata. Rebuild Git-linked relationships from GitHub after a loss, and recover other links and source records through their own approved custody and backup contracts. A PR body alone cannot restore a private approval.

## One discovery query

Expose owner-scoped GET /work/discover for lookup and POST /work/discovery-receipts for authorized initiation evidence, using the same versioned v1 provider contract. A result has candidate and coverage sections, optional continuation, and the current observation time. A full-source outage reports unavailable, a mixed response reports partial, stale and unsearched per source, and a revoked or changed continuation reports a generic restart without revealing prior results. Both routes run through the existing common principal and destination authorization. Guidance, claim-check, and enrolled entry points call the same service. Compose sources over existing access controls for conversation history, verified decisions, docs, repository specs including known remote refs, branches, PRs, cards, commitments, projects and jobs. Prefer exact IDs, canonical references and literals. Then combine authorized lexical and semantic candidates with provenance and a relevant source excerpt. Expand through verified relationships, group by work ID when known, and return unlinked source hits alongside grouped results. Return the status of every requested provider with its covered scope, freshness bounds, failures, truncation and next page. A result includes why it matched and distinguishes requested, approved, implemented, merged, released and deployed evidence. State transitions belong to their source owner. A lead may indicate an existing design without establishing deployment.

For the first implementation, a registry of versioned intent profiles declares required provider roles. The source/target owner derives the profile from the verified operation and intended effect, irrespective of the presentation front door. A caller cannot substitute a weaker profile. Bind profile and version into the receipt; distinguish required-but-unavailable from omitted-by-caller. Repository status, design, spec, and software delegation cover authorized conversation and decision evidence, docs/specs, Git/PRs, and project/card ownership. General project and card creation cover conversation origin, relevant decisions, the canonical project/card roster and commitments. A job-owned finding covers the canonical job definition, current run/finding identity and assigned project's card set. A known exact target also requests its canonical owner. Minimum usable evidence for normal durable initiation is verified origin and current authorized owner/contended-start data. Repository design or delegation additionally needs an observed Git/PR or versioned spec provider result for the repository. A job-owned action additionally needs the authoritative finding/occurrence. Every profile defines this minimum independently of its desired broader provider set. Missing role coverage is explicit. Unenrolled workflows retain their usual direct routes. Branch coverage enumerates only known authorized refs, with observed revisions. The first PR provider covers the public Instar repository. Private PR coverage stays unavailable until a separately enrolled adapter establishes owner-allowlisted credentials, tenant revocation, and retrieval-destination checks. The discovery API names scope without revealing which private repositories or records exist to an unauthorized audience. When the current caller cannot access a source, report scoped coverage without revealing record existence, identifiers, counts or names from that source. Providers never bypass authorization to satisfy a lookup. Apply one aggregate deadline beneath the caller's existing response budget. A bounded pool allocates per-provider budgets and tenant-fair capacity. Cancel in-flight search at the deadline where supported and ignore late returns for that response. Coalesce refreshes by provider and authorized credential scope. Each provider has its own in-flight and queue ceiling. Pass deadlines down to the actual I/O. An adapter whose work cannot honor a deadline runs in an isolated bounded lane, cannot occupy unrelated provider slots, and reports overload without admitting excess work. Bound aggregate result payload and use continuation for additional candidates. Record the distinct job classes for interactive, live capture and backfill. Replay capacity has its own concurrency, batch-byte and lease bounds. Prioritize live capture, release stopped leases and prevent a new owner from restarting a full replay when a verified checkpoint survives. Measure queue bytes, oldest lag, silent skips, timeout counts and latency before enforcement. Reuse the conversation search provider and the narrow Chief of Staff PR provider for those sources. Split slow reconciliation and embedding off the request path. Filter sources before ranking and hydrate only currently authorized evidence. When a provider cannot filter before its internal limit, the adapter scans forward until it fills the authorized page, the underlying source ends, or the declared budget ends. A budget stop reports truncated coverage. A page of private hits cannot silently hide a lower-scoring authorized match. Use stable ranking tiers followed by ordered canonical native IDs. The response freezes a bounded authorized result snapshot for combined ranking. A continuation enumerates that observed snapshot and never mixes newly arriving candidates into it. When an independently sorted provider can produce stronger results later or cannot expose a safe ranking frontier, return its separately labeled provider pages instead of pretending the combined snapshot ranks the unseen corpus. Requesting fresh knowledge creates a new snapshot. Disclose meaningful search limits without revealing hidden row counts. Sensitive providers must filter before their limit or serve an audience-specific source with identical authorized coverage semantics; a generic unavailable state replaces a provider whose scan budget would allow hidden rows to affect the caller's visible result or delay class. Continuations bind the authenticated principal, tenant, query/scope, reply destination, audience/erasure generation, ranker version and relevant provider cursor/vector. Reauthorize before paging. A changed authorized generation or snapshot requests restart of the page sequence. Hidden-only mutation does not change an audience-scoped logical revision, candidate count, continuation validity, or exposed admission disposition. An unauthorized change enters only an internal rebase while the authenticated scope stays otherwise usable. A provider that never replied contributes no candidate to that sequence. Source revisions preserve temporal lifecycle. A reverted merge, superseding approval or changed branch head is explicit evidence rather than an opaque confidence score. Evaluate each current state claim against the relevant owner and revision.

Separate evidence fields from control fields. Store provider output as untrusted structured artifacts with native IDs validated at the boundary. Models can suggest matches and wording. Current source or mutation authority validates every decision to publish, link or dispatch independently of model-supplied instructions, destinations or identifiers.

## Check before creating or declaring absence

At common intake, derive a stable occurrence key from the verified native message, decision or request record. For multi-action messages, the intake service persists source-issued occurrence IDs before fan-out. Bind each occurrence to the native message revision and a verified source span or an owner-confirmed action entry. Normalize the set under the source owner and reconcile an edited message to explicit supersession mappings. Delivery order and the worker's ordering cannot assign new slots. An ambiguous extraction remains candid and requires origin verification through the current owner workflow before it creates a durable effect. The relevant owning service derives the canonical effect key from occurrence, mutation family, scope and destination where applicable. Preserve it across engine adapters, handoffs and compatibility endpoints. A generated intent label, rephrased title, or replay through a second surface cannot change the canonical operation. A new independent action requires its own authorized occurrence/effect. Verify a continuation against a currently authorized existing target. Emergency protective actions use their existing authority and a narrowly defined protective operation.

Issue an authenticated or opaque server-side receipt bound to the principal, tenant, canonical origin/effect, normalized intent/query digest, requested source set and relevant heads, destination and access/erasure epoch. Validate the selected disposition and evidence link in the authoritative service. Every intent profile declares a maximum receipt age derived from the enrolled entry point's measured context freshness and admission budget before enforcement. Use a shorter degraded availability lifetime, bounded by the provider's retry/cooldown or the ordinary profile limit, whichever ends first. Invalidate a degraded observation when required-provider recovery is seen. Check expiry and relevant heads in the mutation service. Age triggers scoped refresh or equivalent owner revalidation of still-authorized evidence. It cannot block continuing an already authorized existing effect. New durable work still requires a current owner-verified observation. A changed or expired receipt carries no creation right. The receipt grants no access or permission and cannot move to another action or destination. Before consequential creation, compare the observation to active starts and reservations in the owning contention domain, defined by tenant, mutation family and destination or repository scope. Track a monotonic start-journal revision for that domain. Bind the receipt to the discovery projection's highest contiguous applied start revision in that contention domain, never the greater current owner head. The owner transaction re-reads or checks that boundary under its serializer against the actual acceptance head for starts and reservations. Any unapplied delta makes the owner read accepted starts and in-flight reservations directly from the authoritative journal since the observed revision, including pending-outbox starts that discovery cannot find. If a receipt does not prove usable untruncated coverage for active work in that domain, the owner reads the full bounded active-start and reservation roster directly, including eligible items at or before the applied revision. The admission budget must either produce a usable current owner observation or take the common offline path. Compare the newly read authorized evidence with the proposed disposition and bind acceptance to that revised head. A hidden-only delta rebases internally and cannot visibly invalidate a receipt or change its disposition unless the same generic failure would affect the caller's authorized scope. Hidden rows are never returned, counted or described in unauthorized output. Apply across alternate front doors. Relevant source-head or audience changes invalidate affected evidence. Unrelated churn does not revoke an otherwise usable receipt. If a common query missed a concurrent start, refresh or record a decision about the newly visible candidate. Similarity alone never coalesces distinct originating actions.

Each enrolled owner journals the effect key and result in the same transaction as a local creation. For a remote dispatch the durable dispatch outbox records pending intent with that key, and receiving admission atomically claims the effect with the same key before executing. When execution crosses a subsystem, propagate the key and require idempotent downstream acceptance with result lookup. If the downstream cannot make acceptance idempotent, a crash with unknown outcome is recorded as unknown and reconciled through authoritative effect evidence. A timeout alone cannot trigger redelivery. A retry queries the same key and returns the committed result or pending state. Lease expiration releases work to another worker. A committed effect marker survives as long as the canonical originating action can be replayed. Each enrolled owner declares dedupe capacity and retention with its source-event contract. For monotonic native sequences compact a verified contiguous closed-origin watermark plus exception records. Preserve each unclosed or non-monotonic origin's compact terminal marker until its source is permanently closed to replay. A held, ambiguous or active effect cannot compact. Watermarks are scoped to source generation as well as native occurrence sequence. Redelivery below a verified closed watermark, or through an authoritative closed-origin tombstone, is rejected before any new side effect. Apply backpressure before admitting a new governed effect if doing so would require dropping the replay proof. If an enrolled seam cannot implement the same-owner transaction or the durable intent/receiver contract, keep it advisory. When recording a distinct purpose, optional relationship links remain independent of the primary disposition.

Before likely prior-work, status, availability or related-work recommendations on enrolled surfaces, the server delivery owner asks the existing bounded semantic routing/judgment path to classify the already authenticated turn. On Telegram Chief of Staff the seam is the adapter's verified-owner delivery before buildTelegramSessionText/sessionTextFor attaches prompt context, for any framework launched there. Apply the same bounded lookup to each enrolled Telegram live injection, durable queue drain and forwarded-to-owner path after reauthorizing the principal, destination and generation at execution. Perform the lookup before the delivery receipt so receipt-to-injection adjacency is preserved. Record degraded lookup internally. Mention the gap only when it materially limits the answer or proposed action, inside that normal response. Native app enrollment uses the authenticated conversation service's pre-input delivery seam. An unverified queue or forwarding path remains explicitly advisory. A Claude-only prompt recall hook may call the same service only when it receives a server-resolved principal and destination capability. A hook carrying just a session ID and text cannot hydrate private evidence. A Codex, Gemini, native or other path without this proof stays advisory. Off-topic factual turns retain ordinary delivery. An unavailable classifier omits additional context and records degraded classification, preserving delivery and scoped fallback. The outbound judgment path checks scoped assertions of novelty or absence and can send facts that were verified, a narrowed statement of searched scope, or uncertainty. A lookup result with no candidates never establishes a universal negative. The Chief of Staff and other enrolled agent surfaces use the same pre-answer evidence. At creation and dispatch, require a disposition: continue/link an authorized work item, explain the distinct purpose, or record incomplete coverage before proceeding within the existing authority. The existing duplicate-build guard, spec registration and instar-dev trace enforce this at durable spec entry. The project/card mutation services and dispatch owner enforce it at their own write seams.

Provider timeout can issue an explicitly degraded receipt when the minimum required evidence remains usable. If the central discovery service is unavailable or required provider coverage falls below the profile minimum, both cases enter the same offline path. The owner may record a signed unavailable observation bound to that action's canonical origin and effect. The observation describes the available evidence and cannot itself lower authorization or turn a provider's absence into clear coverage. An active non-enrolled or source-authorized continuation remains allowed, but new durable initiation waits in its own existing pending or retry state unless the owning service has a previously authorized urgent or offline operation policy. If no policy permits it, return a retryable failure before side effects. If semantic arbitration is unavailable, use the deterministic floors: replay an exact duplicate, allow ordinary scoped answer with uncertainty, and require the initiating agent or independently authorized principal to record a distinct-purpose or incomplete-coverage disposition. Direct API calls and remote dispatch follow the same floors. Test all supported framework adapters before each reaches enforcement.
## Migration and reconciliation

First inventory installed rows and writers in read-only mode. Report each discrepancy by named authority, source version, stable identity, inclusion rule, and audience-safe diagnostics. Reconcile exact IDs or source-proven aliases automatically. The accountable human owner decides ambiguous matches or ownership. The enrolled store owner validates and records that decision. Install compatible readers and writers first. Enumerate startup jobs, installers, migration scripts, direct file writers and older live processes. Route compatible writes through one per-kind serialization point and obtain proof that incompatible writers are quiesced or unable to write. Under the durable owner epoch and fence, record a final source high-water, drain through it, verify exact data and effect mapping, then compare-and-swap the authoritative per-kind state from fenced-and-drained to published using the verified receipt. This transition is the sole authority pointer. Before publication a crash recovers the fence and resumes validation or aborts back to current legacy authority if safely reversible. After publication, clients and receipt mirrors follow the pointer idempotently. A stale binary cannot downgrade the published epoch. The canonical owner transaction verifies its current fence and epoch with the mutation. Consumers move their canonical reads to the verified new owner only after publishing that epoch. Failed or ambiguous fencing rejects new writes as retryable and retains last validated reads. A stale machine returning after cutover cannot accept updates until it acquires the current configuration and authority epoch.

Write resumable source-to-target receipts at every step. Preserve original records and source versions. Legacy endpoints route through the verified owner. Rollback before cutover restores read routing. After cutover, presentation rollback keeps every later canonical mutation and effect result. Only an independently reviewed migration through the same authority mechanism can reverse the canonical write owner. Approval is held by the accountable principal or existing protected change authority. Retired targets are never cleared as a rollback shortcut.
Reconciliation checks declared invariant, provider coverage, and migration residue on the existing health cadence. Repair from authoritative rows where identity and scope are verified and rebuild is safe. Use bounded retries, timed backoff and a circuit breaker from the owning service. Where correction needs judgment or data authority, retain evidence and surface a deduplicated existing health/attention item in the authorized audience after safe repair is exhausted. Key by owning kind, scope, invariant and repair epoch. Clear the active incident only when an authoritative recheck passes; a new epoch may alert on recurrence. Suspected or confirmed competing live writers fence new writes immediately and raise the existing critical alert if safe restoration cannot act first. Where the invariant itself is violated by two authorized writers, stop competing migration writes and keep the last validated view. Reconciliation never deletes or retitles legitimate independent records as a cleanup action.

## Multi-machine posture

Authority is scoped by record and owner, with the owner's approved lease/witness/journal semantics for cross-machine writes. The graph carrier owns EffortRefs and graph relationships, including its existing owner epoch and all-member or witnessed Pending rules. Each provider stores its source revision, event outbox/high-water and effect markers in the corresponding canonical service's declared transaction or authorized journal carrier. Shared discovery checkpoints and derived rank data are replayable views of these inputs. Every provider enrollment selects its exact custody adapter and authority before a writer can graduate. A transfer record carries the new owner epoch, per-source verified upper and retained lower bounds, and any pending effect keys. Refuse stale owner writes and ignore old acknowledgments. A transferred topic can query covered evidence and replays recorded gaps before claiming full coverage. It can continue with properly labeled degraded results if a peer or provider is offline. A local search shard or cache is rebuildable and carries no independent authority. Restoration applies current authorization, tombstones and replica generation before serving. Erased or revoked aliases, embeddings, snippets, receipts and cached aggregates remain unavailable even if a backup still holds encrypted original bytes. Existing backup erasure policy controls physical history and key destruction. Preserve pending writes through the existing deliberate pending/offline contract, and report when independent durability has not been proven. Extend the current machine-loss recovery tests instead of creating a second backup framework.

## Decision points touched

- Protected writer and scoped identity admission — invariant; basis: irreversible-consequence; evidence: a competing accepted write can orphan revisions and make migration lose custom definitions. Match registered owner, caller, scope and source version before mutation.
- Exact request replay and alias proof — invariant; basis: enumerable-domain; evidence: matching verified source ID, operation and scope can be enumerated. Retry returns the prior result or the owning service's conflict.
- Semantic relevance, distinct-work disposition, and absence wording — judgment-candidate. The existing scoped initiating or outbound arbiter receives authorized results, coverage and alternatives. Allowed actions are link, continue, identify a distinct purpose, or avow uncertainty and proceed within established authority. Hard-deny inaccessible evidence or missing deterministic receipt on enrolled initiation. Default to a scoped answer or uncertain disposition when only incomplete evidence is available. The last fallback records coverage and permits only the previously authorized action under the owning service's policy.
- Migration cutover, source freshness and permission — invariant; basis: irreversible-consequence; evidence: obsolete writers can create lost state and unauthorized projections can leak the existence of protected work. Require receipt, current scope and validated head before changing authority.
- Recoverable drift triage — judgment-candidate. Repair only from a verified authoritative record through the existing repair contract. The service arbiter may replay or rebuild, keep the last validated data, or raise one notice after bounded attempts. Default to retaining the evidence and no destructive change when ownership is uncertain.
