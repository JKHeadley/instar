# Feedback worker test cache — plain-English overview

The feedback worker runs proposed fixes in a locked-down working copy. It can change source and test files there, but it cannot write into downloaded dependencies. That boundary protects the build tools the worker uses to check its own code. Some existing tests nevertheless wrote temporary output under `node_modules`, where those dependencies live. The worker's tests then failed before reaching the proposed fix. The SecretStore data-loss repair exposed this: three Telegram origin tests could not build their helper workers, and Vitest also tried to create its own cache in the same protected area.

This change puts generated Telegram origin test workers in the repository's ignored `.vitest` directory. That location is writable inside the locked-down copy and remains beneath the repository, so workers can still load native dependencies from the repository's `node_modules`. It also makes each main Vitest configuration honor the cache directory already supplied by the confined runner. Normal developer and CI runs keep their current cache defaults when that setting is absent.

The protection around downloaded dependencies stays in place. Tests still need to pass and the feedback executor still checks a failing regression test against the old code, its success against the proposed code, independent review, and an exact approved head before merge. The direct decision is whether to ship this test-only path correction so the worker can test its proposed repairs without asking for write access to protected dependencies.
