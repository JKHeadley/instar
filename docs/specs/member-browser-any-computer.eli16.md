# Documents from any computer, explained simply

**The problem.** Today a team member can comment on the agent's documents only through the Instar iPhone app, or from a computer they first linked with that app. Someone without the app can't comment at all. Documents stay switched off for everyone until that's fixed.

**The fix in one sentence.** The invite link you already send a new team member now also works on a computer. They open it, press "Use this computer instead", type the code you give them, and that browser can read and comment on their documents.

**How it goes for the member.** They open your invite link on their computer. Under the usual "scan this with your phone" code there's a new button: **Use this computer instead**. The page says "Ask Justin for your code. It's on his phone, in People, under your name." It also shows two groups of check letters, like `7F3A-91C0`. They type the code you give them and they're in, at the document they came for. The computer is set up for the machine it joined on. If a document link ever opens on another of your agent's machines, the page shows a button that takes them back to the right one. If that machine is rebuilt at the same address, the computer keeps working. If it's gone for good, they ask you for a new link. While the agent is answering from a different machine, Mara's comments are saved, and the "I left comments" message waits until her machine is answering again.

**How it goes for you.** You invite them the way you do now, or use the existing invite-another-device option for someone already on your team. Your phone gets a notification: "Mara is waiting for a code to use a computer". In People, the waiting computer shows its check letters, its browser, the address it asked from and the time, for example "Computer 7F3A-91C0, Chrome on macOS, from 203.0.113.4, asked at 13:04". You can ask Mara "do your check letters say 7F3A-91C0?", then read her the code by text, a call, or however you like. A week before a computer's 90 days are up you get a reminder, in case Mara needs a new link.

**Why it's safe.** It's the same safety step that protects every team member's phone. The code shows only on *your* phone, and nothing gets in without it. The code is also kept off the dashboard, which the agent itself can unlock. If a stranger grabbed the link, they'd get a waiting computer with no code. Mara's own try would then say "this link was already used", and you'd see check letters that don't match hers. Guessing the code is blocked after a few tries. One trick stays possible, as it does for phones today: someone who intercepts the link could show Mara a fake copy of the page. That's why the button names your agent's real address, and why you only give the code if Mara's page is on that address.

**What the computer can do.** Only documents: read the ones Mara can see, comment, and send "I left comments" into that document's conversation. It can't read her chats, see anything she can't, or reach anything of yours. A guest's computer can only read. If you lower someone to guest, their computer keeps reading but stops commenting.

**How long it lasts.** As long as Mara keeps using it: roughly three to four weeks from the last use (the page always shows the exact date), and at most 90 days in all. After that she asks you for a new link. It ends sooner if she taps "Forget this computer", if you remove her from the team, or if you tell the agent "remove Mara's Windows computer". Each person can use up to 3 computers at a time. You can change these numbers by asking the agent, for everyone or just for one person.

**What it doesn't do, and why.** It doesn't use passkeys (a fingerprint or security key on every comment). A passkey can't show the person what they're actually signing, so it wouldn't stop a misbehaving agent much, and it would mean a fingerprint prompt for every comment. Computers also can't add *other* computers on their own. Each one comes from your invite. That's where the earlier design kept getting stuck. One limit is honest and unchanged: the page is served by the agent itself, so the protection is only as strong as the agent's own machine. One practical note: Safari may clear a site's storage if it isn't used for about a week, so Mara may need a new link more often in Safari than in Chrome or Firefox. If that happens, Mara asks you for a new link.

**While your machines update.** A new computer can't join while one of your machines still runs an older version of the agent. The page says which machine, and if it lasts more than a day you get a note naming it. A machine that's just asleep doesn't block anything.

**The iPhone app.** No app update is needed. The app already shows waiting devices with their codes, and the notification uses the app's existing alerts. A clearer "Invite to use a computer" button can come later as a nice-to-have.

**Rollout.** Off for everyone except development agents, like documents. Once this ships, the first of the two things holding documents back from everyone is done. The documents plan said that would be "the passkeys project". This is that project, done without passkeys. There's one honest trade-off: a passkey would have needed a person's touch for every signature, and a browser key doesn't. So before documents go out to everyone, you'll get one Approve/Decline asking whether you accept that. Nothing goes to everyone without it.
