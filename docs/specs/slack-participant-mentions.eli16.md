# Slack mentions tag people who are in the conversation

When an agent writes a Slack mention such as `<@U0C62ABNDK8>` in a reply, the person should be tagged. Since the November 4 repair, the Slack formatter turned every such mention into plain text unless the agent added a special `--native-reference` flag to its reply command. Almost no agent knew about that flag: it was described only in a comment inside the reply script and in one line of a Slack session's start-up text. So the operator kept seeing messages like "<@U0C62ABNDK8> Justin passed on your note" printed as raw characters, with nobody tagged.

What changes: before a Slack message is sent, the adapter looks at the person IDs written in it. For each one it checks two things with Slack: is this person in the conversation (a member of the channel or direct message, or someone who already posted in the thread), and is this a real, active person rather than a bot. If both are true, the mention is sent as a real tag. Everything else stays plain text exactly as before: IDs of people who are not in the conversation, bots, the agent itself, deactivated accounts, the broadcast forms `@channel`, `@here` and `@everyone`, and anything inside code. The explicit `--native-reference` flag still works for the rare deliberate case outside these rules, such as tagging someone who is not in the channel or linking a channel.

Safety: the November 4 change existed so that text copied from somewhere else could not ping arbitrary people or the whole workspace. That protection stays. Broadcasts can never be activated this way, and a person who is not already in the conversation is never tagged without the explicit flag. Someone who is in the conversation already sees the message, so tagging them adds a notification but does not reveal anything to a new person. If Slack cannot answer the membership question (a missing permission, an error, or more than 2.5 seconds), the mention goes out as plain text and the message is still sent. The member list is remembered for five minutes per conversation so ordinary replies do not cost an extra Slack call each time.

Agents learn about this from a short new section in their CLAUDE.md (added for new agents and, through the update path, for existing ones) and from the one line in every Slack session's start-up text, which now says to write `<@USERID>` and that people in the conversation get tagged automatically.

Writing `@Name` as plain words is not converted into a tag. Doing that safely would need a name directory for every member and a rule for two people with the same name, which is not cheap or unambiguous, so the guidance tells agents to write the ID form instead.

What to decide: nothing beyond the PR review. This is a small, reversible change; reverting it restores the November 4 behavior.
