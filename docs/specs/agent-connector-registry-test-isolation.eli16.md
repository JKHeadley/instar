# Give Agent-Connection Tests Their Own Registry

The agent-connection tests check that registering an agent creates a real JSON registry entry, updating the same path keeps one entry, different paths remain separate, and heartbeat timestamps are valid. Those checks previously used the running computer’s actual registry. Before each test they backed up that file, removed it, and later restored it. A successful test could therefore temporarily erase live entries or overwrite a legitimate concurrent update during restoration. Restoring a shared file afterward does not make the test private.

This change gives each registry test its own temporary home and registry. The production registration function chooses its registry path when its module loads. The test therefore evaluates a fresh copy of that real module while its environment points at the temporary home. It immediately restores both environment values, including their original absence, even if importing fails. It also clears the module cache afterward so later ordinary imports cannot reuse the temporary environment. Only the returned registration function retains its private module state.

The tests still use the real registration code and real files. The original entry, update, separation and heartbeat assertions remain. An additional regression creates two independently loaded private writers, calls them after the ordinary environment has returned, and checks that each registry contains only its own entry. Cleanup removes only the test’s temporary directory. The tests never back up, remove, read for comparison, or restore the operator’s real registry.

This changes test ownership only. Production paths, registration rules and the normal test-runner admission remain unchanged. The whole original unit file is verified under the ordinary runner environment after independent review and coordinated allocation. There is no historical unsafe baseline invocation. Complete verification remains a separate coordinator-owned gate after publication. Reverting the test change needs no migration, live registry repair or restart.
