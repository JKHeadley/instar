# Add a new agent from a phone you already use: the plain version

**What happened.** Justin paired his iPhone with a brand-new agent that Echo had set up for a test. The phone said "Tap Approve on Pairtest's dashboard". That dashboard wanted a PIN Justin never had, because Echo made the agent, not him. So Echo asked him in chat to send it a key, and Echo approved the phone by hand. Justin said it was confusing: the phone told him to tap something, and the agent told him to say yes. He wants this to be one obvious step that nobody can get wrong.

**What exists today.** A phone that is already paired with an agent as its owner's phone can approve a *second* phone for that *same* agent with Face ID. But a brand-new agent has never met your phone. The app makes a separate key for every agent, so to the new agent your phone is a stranger. The only ways in are a code sent by Telegram or shown on the dashboard behind a PIN.

**What is new.**

1. **Your existing agent vouches for you.** When one of your agents (say Echo) creates a new agent for you, it runs one command that writes a line into the new agent's settings (and the line is copied to any later machine of that agent when it joins): "phones vouched for by Echo belong to my owner". It writes Echo's public "vouching" key, a key Echo uses for nothing else and only Echo can sign with. When your phone opens the new agent's pairing link, it sees the new agent trusts Echo, and it knows it already has Echo as your phone. So the screen shows one button: **"Approve with Face ID"**, under "Use Echo, which is already on this phone, to approve Pairtest." You tap it and look at your phone. The phone asks Echo to sign a short note: "this phone, with this key, waiting on this agent, is my owner's". Echo signs only after Face ID on a phone that is already Echo's owner phone. The phone hands the note to the new agent, which checks Echo's signature and finishes the pairing. No PIN, no chat, no codes, no keys to compare.
2. **The waiting screen only shows ways that actually work.** It no longer says "tap Approve on the dashboard" unless someone has that dashboard open and unlocked right now. It shows one main instruction, the easiest that works, and keeps the rest under "Other ways". Typing a code is always the last fallback.
3. **A fix for agents with no Telegram.** Such an agent used to hand out a pairing link that could never finish, because it thought it would send the code by Telegram. Now it either uses a path that works or refuses to make the link, with a plain reason.

**Safeguards, in plain terms.** The note names one exact phone, one exact key and one exact agent, and lasts two minutes. It can be used once, and only by the phone it names. So someone who steals your pairing link still can't use your Face ID approval for their own phone. Nobody can add "trust Echo" to an agent through its web interface: it is only written into the agent's settings file by whoever creates the agent, and that person already controls it fully. An agent can't sign such a note for itself through its own interface, because the request must come from your phone with Face ID. One honest limit: a program running on Echo's own machine could in principle use Echo's key directly. That is the same kind of limit as today, where such a program can already read the dashboard PIN.

**What the reader needs to decide.** Nothing new is asked of Justin. This does nothing until an agent's creator writes the trust line, and the existing off switch for phone approvals turns all of it off. Phones paired this way stay paired if it is ever rolled back.
