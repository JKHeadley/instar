# Blocker hand-off across machines and surfaces — ELI16

When I truly need your help with a task, I should ask for the smallest thing that solves the problem. If a one-time code or password is enough, I should give you a secure way to provide just that. Before asking, I have to check what I can do myself and prove why your help is needed. The existing blocker system needs one real request recorded before it can formally classify the blocker; this design sends that minimal request first, then verifies the classification before it spreads the request. Remote desktop is also a direct tool you can open whenever you choose; it does not require a blocker.

The request will have one underlying record, even if you see it in Telegram, Slack, dashboard chat, or the dashboard's attention list. Each place will show the same machine, task, and current status. If you solve it in one place, I'll verify that the original problem is actually fixed, then mark the other places complete. If a device is offline, its old message may take a moment to update; the dashboard will show when it last synced. A reply saying “done” will prompt verification, not erase an unresolved problem.

You can open a short remote-control session for any installed machine whose desktop adapter is ready, whether or not I am blocked on a task. Enter your dashboard PIN to open that machine’s logged-in desktop. You can click and type in its open apps, including changing files and settings. You do not have to open another bot chat, copy a command, or compare a fingerprint. The first Mac adapter requires its macOS desktop session to be unlocked; the dashboard PIN does not unlock the operating system. The session expires after ten minutes, ends sooner if idle or disconnected, and can be stopped immediately. The PIN proves you have the dashboard credential; it does not separately verify your Telegram identity. I won't see the live screen through this session, and the system won't save video or keystrokes. If the session was opened to solve a blocker, closing it doesn't claim the task succeeded; I'll check the actual result afterward. The goal is to make this work on every machine where an agent is installed, including Macs, Windows PCs, Linux desktops, and Windows hosts running an agent inside WSL. That requires a working display and input adapter on each kind of machine. A headless machine or a host missing permissions will say clearly that remote control is unavailable and offer another way to solve the blocker. If the machine holding the original blocker evidence is offline, another machine can show the last known request but cannot safely grant control or declare it solved until the evidence is reachable again. We will only advertise a platform once a real end-to-end test proves it works.

Justin's first phone test showed that the Mac viewer closed quickly, occupied only part of the screen, and made pointer movement hard. The first quality repair makes the viewer fill the phone, keeps phone scrolling from fighting remote gestures, adds a trackpad mode, and tolerates a skipped screen image or brief capture failure. An eight-minute active public-browser test now stays connected and stops cleanly. It displayed about 2.4 images per second in a ten-second sample. The second quality pass keeps one Mac screen-capture process running during the grant, takes only the newest image, and avoids resending an unchanged screen. If network limits drop a changed image, it offers that image again. Real video-rate measurement and physical phone checks remain the acceptance tests before claiming AnyDesk-like smoothness; hardware video encoding is the next design stage. The two-minute no-input limit remains for this first pass; simply watching the screen does not reset it.

After a manual fix, I may point out an existing auto-login or repair option that would prevent the same interruption next time. I will ask once for that kind of task, remember a refusal, and respect a firm “don't ask again.” If you later express frustration about repeatedly doing that same work, I may offer the specific option once more. Saying yes starts the normal approval setup; it does not silently give me new access.

This is a security-sensitive addition. The Mac Studio test is enabled after its local display, input, PIN session and revoke checks passed. The fleet stays dark while Windows, Linux, WSL and the remaining rollout checks are built and tested. Each machine needs a working adapter and its own permission checks before its desktop appears as ready.
