# Compare the Two Project Lists

## Problem statement

The general Projects list and the Chief of Staff project list can describe overlapping work, but each has its own records and inclusion rules. A similar title does not show that two entries are the same project. Give the owner a read-only way to compare the general Projects list, which can include finished projects, with the Chief of Staff list, which shows confirmed projects that are still open. The lists have different inclusion rules. This comparison is a preliminary inventory before any decision about moving project ownership.

## Frontloaded Decisions

1. Add one on-demand, development-gated comparison in the existing owner's private Work Projects view. Reuse the scoped private Work session boundary. Keep ordinary Projects reads and writer authority as they are.
2. Read each owning source independently. Prove the current audience, applicable source revision and coverage before treating a source as complete. A source without that proof contributes only eligible observations and an explicit limit, or generic unchecked coverage when the shortfall cannot be disclosed.
3. Link only using a current source-attested Chief of Staff binding's exact initiative ID and a uniquely matching, currently authorized Projects row. Display multiple claimed matches as conflicts only when the relation and participating rows can all be disclosed. Titles, textual similarity, URL strings and stale mirrors supply no key.
4. Keep job state, accepted project state, delivery, replica recovery and authority changes out of scope. The comparison has no repair, write, confirm or merge action.
