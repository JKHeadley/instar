# One provider is enough, and don't wait for the next meeting

This adds two lines to Instar's rulebook.

The first says an agent with only one AI provider must still do everything. A second provider can make a feature better, faster or cheaper, but can never be what makes it work. Nothing checks this yet, and the rule says so, with a date (2026-12-21) by which the check must exist.

The second names a habit to watch for: tying ready, cheap work to the next scheduled review when it could start today. The tell is a due date that equals the next regular slot, with nothing actually being waited on.

No code changes. Agents behave the same until the check is built.
