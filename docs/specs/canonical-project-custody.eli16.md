# Give every project one trustworthy record

The Projects screen and the Chief of Staff can disagree today. Both can hold useful history, including a project you approved as finished. We want them to read the same project record while keeping the Chief of Staff's notes and check-ins.

We will first show what matches and what needs a decision. If a Chief of Staff conversation is only being watched, it can stay that way. If two records disagree about a project's goal, checklist, or completion, you can see the authorized evidence before a decision changes the record. An old approval stays in history when the checklist it approved has changed. When you have authorized the Chief of Staff to close a project automatically, it rechecks that the evidence is current and only reports completion after the shared record accepts it. If you still need to make a decision, the project remains open.

On a shared setup, Instar will only acknowledge a project change after every enrolled computer that is allowed to hold that project has the full saved change and proof that it was accepted. If a required computer is unavailable, you can still see the last verified project state, with any gap labeled. A retry returns the same result once the required computers have saved the change and its proof. Until then, the change stays pending and the project screens show the last verified shared revision you still have permission to see. The first migration covers projects whose authorized computers are the same. Setups with different groups of computers keep their current writers while we show the differences.

Before switching project writers, we will stop one of two test computers immediately after it acknowledges a change. The other must show the exact saved revision from its own records, without an extra copy from the stopped computer. We will also test old clients and interrupted migration. If the required evidence is missing, the current writers remain in place. These changes do not alter jobs or start additional project work.
