# Keep Real Search Tests Independent Of A Fresh Install

The verification run creates a clean dependency install for each candidate. The real semantic-search tests previously used a model cache inside that dependency folder, so each clean install could start downloading the same roughly 90 MB embedding model again. That download ran inside a test setup hook intended to initialize the feature. The saved failed verifier contained unfinished model downloads; the same unchanged tests passed with a completed cache. Because the verifier deleted its detailed reports, this evidence supports a cold-download explanation without proving the precise cause of every earlier failure.

This change prepares the exact real model before test workers start. Its four assets have committed checksums. A completed, verified installed cache can seed a machine-local cache that survives disposable worktrees. Otherwise a separate bounded preparation downloads and verifies the assets. Concurrent preparation uses the existing locking library, including heartbeat and stale-lock recovery. The preparation has a finite budget inside its parent process timeout. Acquisition errors fail setup visibly. The search tests load local files only, keep the same real model, floating-point format, thread settings, semantic expectations and SQLite extension, and release their model and server resources. They do not substitute a pretend embedding or skip coverage when preparation fails.

Two other tests assumed that a short sleep meant an asynchronous operation had completed. The Grok version-policy tests now observe the actual subprocess callback while preserving the real command and its result. The session test waits until its actual terminal pane shows the expected prompt. Deliberately delayed fixtures reproduced both old failures and remain in the corrected tests. These changes affect test fixtures and test configuration only. They do not change session admission, account selection, command safety or production search behavior.

The candidate preserves both repairs already combined in its parent commit. Focused checks and independent review establish the scope of this repair; the complete verification run is still owned by the coordinator after the Chief of Staff publishes the successor. The missing raw-report retention is tracked separately as ACT-517.
