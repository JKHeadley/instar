# Approvals reach your Instar app

When your agent asks to do something that needs your approval, the request should reach the Instar app you paired. Today a configured Telegram bot takes precedence even if you have never opened its private chat. The agent then says the request could not be delivered. The request can remain stuck while you see nothing asking for your decision.

This change makes a device that you have set up to approve the first destination. The app shows the exact change and asks for the existing Face ID or Touch ID confirmation. Pairing alone does not grant approval power, and the agent cannot approve the change for you. Telegram is still available for people who use chat, but it does not stand between a working approving device and your decision.

Requests that could not reach chat also appear in Needs-you. If the agent asks again after your device is ready, it moves the same request into the app without extending its lifetime or changing what it asks. Nothing happens until you approve that exact request. If delivery or reading fails, the interface says so instead of silently showing an empty list.

The first live check will resend the Work Board policy request to your app. You will decide there whether to start those waiting cards. The change does not start them on its own.

The app must also show the whole request before it can approve. The current phone app limits the number and length of the paragraphs it reads. The server now formats long requests into pieces that fit those limits, keeping emoji and combining characters together. It does not change the proposed action or its signed identity. If an older request is too large to show completely, it stays waiting with an explanation and the server refuses approval. A shortened preview can never stand in for the complete change.
