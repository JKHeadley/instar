# Browse App Chat Attachments

An owner using the signed App chat browser can browse photos, videos, voice recordings or files in the current chat, including attachments without a caption. The first release works on the history available on the connected computer. It uses the existing file playback presentation and adds an exact, owner-authorized open action for the selected attachment. The broader media discovery draft remains under review for sender filters, text search, previews and other platforms.

## Route and authorization

Add a signed-device GET at `/mobile/chat/app/:key/attachments`. Use the App UUID path pattern, active-device gate, conversation read permission, and the live owner check used by current mobile owner actions. Register the exact UUID path in both the dashboard-browser allowlist and active device route map in `mobilePairingRoutes.ts`. Mark it as a conversation read, require owner admission at the handler, and share the existing App history read rate limits. Accept one required `kind` from `MEDIA_KINDS` and one optional opaque `cursor`. Reject duplicates, unexpected keys, arrays and out-of-contract values before querying. Do not accept a search string, requested computer, scope or cross-chat reference. Read records asynchronously. Reserve one browse slot per device and four per server, with a two-second handler deadline. A late record read retains its slot through descriptor cleanup. Evaluate current signed admission, current conversation availability and per-message read entitlements on every page. Immediately before publishing the assembled page, recheck live device and conversation admission and verify the authorization and exact attachment references for every collected match against current state. Use a publication check with no asynchronous gap before sending. If the server cannot prove a collected match is still authorized and current, return HTTP 503 with attachment-page-changed, without metadata or a continuation cursor. Clear the displayed page and offer explicit Retry from the incoming cursor. HTTP 403 owner-device-required or HTTP 404 unknown-conversation cancels the walk, clears all rows and releases playback. For an exact Open, HTTP 404 attachment-unavailable disables only that attachment, leaving the other results visible. Test an overlapping purge during Older and the same purge discovered during Open. A missing or tombstoned conversation has the same response as inaccessible conversation history. No bearer, team or unauthenticated access. When native App media is disabled, both new routes return the existing media-off response. A browser with pre-existing attachment tiles still uses its ordinary history behavior.

Use private no-store responses. The browser calls only this route. A 404 or exact legacy `403 device-not-allowed` from an older server, or a response lacking the exact version and shape, becomes unavailable. A browse-page 401, 403, 404, 410 or media-off result clears the current rows and releases playback before stating that attachments are unavailable. Existing 401 and revocation handling also follows the established signed-client path. For content requests, lost admission, an unknown conversation or media-off clears the sheet. An exact attachment-unavailable response within a currently authorized live chat marks only that result unavailable and leaves the other rows usable. It never retries through search or pool history. The browse route never calls peers, engine or file fetchers. Opening an attachment uses the separate exact local-content route described below. The browser never substitutes the hash-only media path.

## Bounded continuation

Traverse the existing App history order `(at DESC, eventId DESC)` and one-row look-ahead. Share the same indexed browse window and event reader. Decode the timestamp and event-ID tuple from the authenticated cursor and bind each as a separate parameter in the store query. Do not encode or decode a comma-delimited boundary because the existing data validator does not prohibit commas in these fields. Budget at most 50 index rows, 1 MiB of indexed event bytes, 15 returned message rows, and the existing 10 attachments per event. Inspect `byteLength` before reading an event. The stored index excludes the newline in both append and catch-up. Use a bounded positional read for exactly the indexed payload length plus its trailing LF and, except at offset zero, the preceding framing LF. Charge framing bytes to the same work budget. Reject short reads, missing boundary LF, interior LF and out-of-file positions before parsing, with no variable-length fallback. Consume impossible zero, negative, noninteger or indexed lengths with payload plus LF over 256 KiB as incomplete without opening the record. A parsed row must agree with the consumed index row’s timestamp, event ID and canonical chat, and have a valid message kind. A single valid event fits the budget because the existing maximum is 256 KiB. Validate every consumed ordering key against the cursor representation before consuming it. An unrepresentable index key makes the page unavailable without advancing. When any budget stops the walk, seal the oldest actually consumed index row. An index look-ahead alone does not consume it. For 51 index rows with a match only at row 51, the first request returns no matches and keeps Older. The next request returns the match exactly once. Consume hidden messages, nonmatching kinds and structurally unreadable rows, using the same forward progress on a sparse page. Erroneous indexed rows never supply matching evidence. A read that fails across the store returns unavailable without advancing. A response containing a structurally unreadable authorized range uses `coverage: "incomplete"` without naming rows. Structural uncertainty that prevents applying authorization is reported only as a generic incomplete local range. Each page reports `coverage: "local"` when no unreadable records were observed in that page. A browser keeps an incomplete notice through the current walk once seen.

Apply per-message authorization before checking attachments. Use the canonical server attachment kind, with exact agreement among recorded attachment ID, chat, message, index, content hash and size. A known purged exact reference is definitively excluded. If the matching attachment has no index reference, or its reference is inconsistent, omit it and mark the page incomplete. A correctly indexed unpurged attachment with unavailable bytes may still appear. Test the distinction between confirmed purge and missing evidence as well as how both affect exhausted empty-list copy.

Seal the normal browse boundary in an authenticated and encrypted cursor with an explicit version, current owner-admission device ID, device key hash and person ID, canonical chat, and selected kind. Store a fixed-width keyed scope digest of that identity tuple in the token, not separate unbounded identity fields. Use a per-server-start random key and authenticated encryption with a unique nonce. Bind the route name in associated data and bound the encoded token before decrypting. Keep no server-side paging session. A bad or wrong-scope cursor returns one generic invalid-cursor response. Reauthorize even when the token is valid. A server restart invalidates tokens and the browser offers to restart from the newest page. The cursor hides the underlying row identifiers and timestamp. It grants no right to read future pages.

Pagination is an evolving local view. A page includes rows exclusively older than its incoming boundary. A newly replicated row can arrive on either side of that boundary. Continue the current walk on the older side. Refresh restarts from the newest page and picks up updates to previously scanned ranges. A response with a continuation means there are older rows to check, even when no matching row was returned. A null continuation means the end of the current stored view, with no claim about missing replicas. Return no scan counts, permission-denial reasons, peer identifiers, unread markers or pins. Cursor presence conveys that the local browse range may continue, with the same owner-only scope as ordinary owner history pagination.

## Response and browser

Return `{v:1, kind, scope:"local", coverage, rows, nextCursor}`. Each row names the current chat's authorized event and message, timestamp and matching attachment descriptors. Each row has exactly `{eventId: string, messageId: string, at: string, attachments: Attachment[]}`, with at least one attachment. Each attachment has exactly `{attachmentId: string, index: number, kind: MediaKind, filename: string, size: number, mediaType: string}`. Use the existing event IDs and timestamp format, nonnegative integer attachment indexes, validated media size and type, and the original validated filename, rendered as text using wrap and a full-name accessible label. Exclude content hashes, transcripts, declared metadata, bytes and paths. The row excludes body and author identity. Measure the actual serialized response candidate including envelope and its prospective opaque next cursor. Stop before consuming a row that would exceed 128 KiB. A near-ceiling match withheld because the envelope and cursor push it over must lead the next page. The maximum encoded single row fits even at six escaped bytes per stored UTF-16 code unit: ten descriptors each with a 255-unit filename and 128-unit media type, plus fixed identifiers, integers and syntax, and a 128-unit event ID, 128-unit message ID and 64-unit timestamp fit within 32 KiB. Test this ceiling using adversarial escaping and valid worst-case fields. No capped page may skip a match. Return one row per message, already newest first. Use the existing messages index as the sole event selector. Its messageId primary key admits one canonical index entry, and the index joins one exact event by canonical chat and event ID. Iterate this index before applying the match budget. Test duplicate source events for one message across pages and verify only the indexed event can appear. Attachment order follows index. The response carries no raw continuation boundary. Reject the entire response if its envelope or any row is malformed, including a response with both valid and invalid rows. Never show valid-looking rows from a rejected response.

Add a browse action in the open App chat. Choose one kind at a time and show the results in a separate in-chat sheet, with date and attachment name. Render passive filename, kind and date. Load bytes only on a deliberate Open through the exact signed content route, never through an auto-fetching tile, generic hash cache or peer. Reuse existing safe playback presentation for fetched bytes. Keep at most the current page in the DOM. Do not promise deep message navigation in this slice. Keep the composer, selected files, current position and loaded chat history intact when browsing. Give each sheet instance and selected kind a local generation and abort controller. If the prior request still holds the browse slot, HTTP 429 with attachment-browse-busy is retryable. Offer an explicit Retry that preserves the newly selected kind and the incoming cursor of that page. A late response for an older kind cannot change Retry or its cursor. Bind the sheet generation to the current signed session and connected replica. An observed session invalidation, sign-out, owner-read denial or replica change clears rows, aborts requests and revokes playback immediately, including while the sheet is idle. Use the existing signed-chat refresh to observe server-side revocation while the sheet is open. If that refresh cannot establish current access, clear the sheet until a fresh authorized read succeeds. Exercise a populated idle sheet and active playback on both invalidation and replica change. Closing, reselecting or changing chat invalidates results, suppresses delayed downloads and paint, aborts outstanding requests, and revokes sheet-owned object URLs. Allow one active open per sheet. Coalesce repeat clicks on the same attachment. A different selection aborts the first read and increments an open-specific generation. A late completion from the superseded read must discard its bytes and cannot open playback or save. Revoke the previous playback object URL when it is replaced. Do not retry opens automatically or reuse the ordinary chat media cache. An accepted Older action aborts any pending open, increments the open generation and releases the previous playback. A kind choice or accepted Older action may advance through empty pages until it finds a match, reaches the end or consumes three sequential page requests through the existing browser read budget. Treat three as an adjustable UX default. Cancel the walk on sheet close, kind change, conversation change or when the sheet is no longer foreground. Once the action budget ends, leave Older visible when a continuation exists. Never silently advance past a populated page. Use “No matching attachments on this page” for a zero-match page with continuation. Use “End of the history available on this computer” with a null cursor. An exhausted walk with no matches may say “No matching attachments found during this browse” only if no page reported incomplete coverage. Otherwise say “Reached the end of history on this computer. Some records could not be checked.” Offer Refresh at exhaustion to start a new walk from the newest page, so a newly replicated match can appear above the old cursor. Use existing focus, Escape and keyboard interaction for the sheet.

## Exact content open

Add `GET /mobile/chat/app/:key/attachments/:attachmentId/content` to the signed owner route and browser allowlists, with the 64-lowercase-hex attachment ID format. Use the existing independent media-read limiter. Apply the normal media per-file byte ceiling and bound concurrent browse opens to one per device and four per server. If an active slot is occupied, return a retryable busy response before opening any file. Validate unsupported Range syntax before reserving a slot or hashing. A new selection may briefly see busy while its abandoned request releases the old slot. Show an explicit Retry and leave the latest selection visible. Resolve the selected reference by exact attachment ID and verify its live chat and message authorization and its authoritative event tuple before locating local bytes. Reuse the safe file open, streaming headers and content disposition of existing App media delivery. Require a regular descriptor in the verified private media store with the exact indexed byte length. Read and hash the same opened descriptor asynchronously before serving any byte. Compare SHA-256 and pre/post descriptor identity, length and change timestamps. The verified store publishes immutable blobs atomically. Do not re-open a path, trust a stale check record or call mutating quarantine from this read. Recheck current device, live chat and exact authorized tuple after all awaited opens and verification, immediately before headers. Deny a lost grant, rekey, deleted message, purged ref, mismatched tuple, unavailable or quarantined blob without leaking any other reference. Handler authorization distinguishes only the caller’s current signed admission, whether the chat is available to that caller under ordinary history rules, and an attachment unavailable within that authorized live chat. Never say whether a denied or nonexistent chat actually exists, and never indicate why one exact attachment failed. The final check before headers is the publication boundary. A change after data was already sent cannot retract those bytes. Use the existing scoped media response timeout classification for the exact content route. The handler applies a 120-second measured default across admission, hashing and streaming, with a wider outer media middleware deadline. If an outer timeout, error or client close already settled the response, suppress late publication and run the same cleanup. Test timeout before headers and during streaming through production middleware. This default bounds the response window and limits the amount of outstanding work. A filesystem open can remain pending beyond the window and prevent further exact opens. Propagate one abort signal through hash and send streams. On deadline after publication destroy the stalled response. Before publication return unavailable where the client can still receive it. Guarantee one descriptor close and one slot release on normal finish, timeout, disconnect, invalid range, open or hash error and stream error. A filesystem open that has not settled still occupies both the device and server slot after timeout. Mark the client outcome settled, stop new work, and close any late descriptor before releasing that slot. Once hashing or streaming has started, finish cancellation and descriptor teardown before releasing admission. If all four filesystem opens remain unresolved, exact opens stay busy until the operations settle or the operator restarts the serving process after checking storage health. The feature does not initiate a restart. Report stalled slots through existing aggregate evidence without identifiers. Verify that four unresolved opens never admit a fifth and that a controlled restart on a healthy disposable store restores admission. Record deadline use and validate it against the existing local media file ceiling and the no-progress case. A user who opens one occurrence is never redirected to another occurrence of the same hash.

The browser uses only this route for an explicit open from the sheet. No browser or server fallback to hash-only reads, and no remote fetch or enqueue on missing local bytes. Ordinary history downloads remain on their existing route. Exact streaming has the existing content safety headers and local safe playback behavior. Reuse the existing supported single-range response behavior after the same authorization and descriptor verification. The existing browser player still performs a deliberate whole-file open. A requested range does not change the access check. Autoplay, automatic save, previews and new background caching have no role here.

## Frontloaded decisions

Use the existing App chat and its history order, one kind per request, signed owner devices only and the local replicated view. Team readers retain ordinary history and file access. Expanding this new route to them requires a live post-await recheck that binds the admitted team grant as well as the device and selected message. Existing live owner admission supplies the equivalent check for this first release. Adopt a distinct route so legacy software cannot forward a media query it does not understand. Attachment discovery requires an exact authorized reference. A user may explicitly open the selected attachment through the exact local route. No additional permission prompt, data index, remote query, preview process or browser disk cache is required.

## Standards trace and multi-machine posture

The existing replicated App event and attachment-reference stores remain authoritative. Each server projects what its replica currently has and declares that scope. Another computer may have later events, and the client restarts pagination after changing computers. No new authoritative machine-local state is introduced. The ephemeral cursor binds a particular browse and does not make conversation data machine-local. *Verify the State, Not Its Symbol* requires exact reference corroboration before returning a match. *A Safeguard Must Leave a Benefit* preserves a one-step kind choice and continuation through sparse history while withholding unverified metadata.

The 50-index-row budget uses the dashboard's existing history page size. The 1 MiB bound fits at least three maximum-sized events with framing. A fourth may exceed the budget by its framing bytes and then starts the next page, the 15-row render window keeps the sheet manageable, and the existing ten-attachment limit provides the per-event reference bound. The 128 KiB response bound derives from the bounded projection and caps transferred work. These stop one request with continuation and impose no terminal traversal cap. Use the per-start key lifetime rather than a wall-clock expiry. It lets an authorized person continue after a reading pause. Derive the exact wire-size bound from a fixed envelope, 32-byte scope digest, nonce and authentication tag, and the existing 128-unit event-ID and 64-unit timestamp bounds with worst-case UTF-8 and JSON escaping. Validate the encoded input against that bound before decoding. Treat row, byte and render budgets as measured release defaults, adjustable inside the same continuation and authorization contract.

## Rollback

Removing the browser action and route requires no data migration. Existing history, search and media routes retain their current behavior. Existing attachment controls remain available in chat history.
