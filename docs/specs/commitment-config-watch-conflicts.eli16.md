# Stop per-topic promises from fighting over one shared setting

When someone asks the agent to change a setting, a promise tracker writes down what was asked and keeps checking that the setting still has the requested value. If the value drifts, it puts it back and tells the user "it looks like that setting reverted". If that keeps happening, it sends a one-time "this keeps reverting, it looks like a bug" warning.

On 2026-10-28 Justin saw the Attention topic fill with the same two alerts roughly every fifteen minutes overnight. The cause: two requests about two different topics ("swap this topic to Opus 5.5" in one, "swap this topic to gpt-6-sol" in another) were both written down as checks on one made-up shared setting called `topic.model`. One setting can hold one value, so on every check the tracker put one value back and thereby broke the other. Each promise reached about a thousand alerts. The bug-like warning did fire, but it did not stop the repeats.

This change fixes three things inside the tracker itself, so it holds no matter who records the promise. First, a request whose setting name points at a topic or session is no longer treated as a shared setting. It is still recorded as a promise, but as a plain follow-up with no automatic check and no automatic writes; the real per-topic model choice lives in the topic profile, which this tracker never touched. Second, if a new request expects a different value for a setting that another open promise already watches, the older promise is retired and marked as replaced by the newer one, because the newest request is the user's current word. Third, once the "keeps reverting" warning has been sent, later reverts are still corrected quietly, but they no longer post an alert each time. The prompt that spots promises in conversation also now says per-topic requests are not setting changes.

The decision is whether this narrow fix is ready to ship. A revert restores the old behaviour, and no stored data needs repair; the two live promises were already withdrawn by hand.
