# Safer account work, and updates while npm is unavailable

Echo should offer to do account setup when it can safely do it. Asking Justin to perform the whole task by hand wastes his time. But doing the task must not mean taking dangerous shortcuts: a backup login code can have consequences beyond signing in. In this incident, npm warned that using the recovery code would suspend publishing for three days. The agent read just the beginning of the page and missed that warning.

This change adds protection at the normal Chrome browser tool used in that incident. Before running arbitrary browser JavaScript it checks whether the page is a recovery step or carries an account lockout warning. On those pages, the tool returns an advisory before running the requested script. It gives the agent a complete-read path and requires an explicit review decision tied to the current page before continuing. The agent must use the whole page and conversation to decide; a bare flag is not user approval to spend a recovery code. A local approval note cannot establish that permission. Ordinary password and OAuth sign-ins remain automated. Agents also receive the instruction to read every part of an account page before acting and to offer safe help before asking the user to do a task manually. Browser restrictions must not be worked around by spending recovery codes.

The second part supplies a temporary publishing route through GitHub. A developer can build an exact main revision and put a development package on a GitHub prerelease without touching the npm publishing account. Each package comes with its source revision and a checksum. An explicit install command takes that package through the same staging, native dependency checks and safe replacement procedure used for ordinary updates. If validation fails, the currently installed agent stays in place. Restart still uses the normal process that protects active conversations.

Development packages are for chosen development and test agents. They do not move ordinary users onto an experimental channel. They keep the stable patch number, so the next normal npm patch automatically replaces them after publishing resumes. Each machine needs its own explicit install, because native dependencies belong to that machine. GitHub and public dependency downloads still need to work. This does not promise that every possible browser tool can prevent every provider lockout; it protects the supported path and makes the account workflow safer without disabling ordinary automation.
