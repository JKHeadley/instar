# Keep Registry Tests From Changing Each Other’s Inputs

One test checks that the standards auditor notices when an authored document changes without rebuilding the packaged copy. Previously, that test edited the actual checkout’s document for a moment and restored it afterward. Other test workers can read that file during the edit. A separate count check can therefore see one additional article even though the file has returned to its original bytes by the time someone investigates. Restoring a shared file afterward does not protect concurrent readers.

This change gives the mismatch test a private temporary authored document. It copies the source inputs that the real auditor scans and the file references needed to establish that those inputs belong to the same build. The real packed resolver continues to read its normal artifact. Before the edit, the auditor must select the private fixture and report a verified baseline. After the private document gains one article, the same auditor must report the specific authored-document mismatch. The test checks that the real checkout document stayed unchanged during the private edit and that the packed article count did not change.

No production behavior, account settings, host limits, standards counts, approval records, or release floors change. The fixture uses portable file copies and the normal guarded cleanup path. Independent review covers the fixture design, and focused verification must exercise the complete registry asset and live count test files under ordinary admission. Complete verification remains the coordinator’s responsibility. A revert removes the fixture change without any migration or live repair.
