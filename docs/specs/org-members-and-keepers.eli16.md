# Organization members, departures and a second keeper, in plain words

## What this is

Justin approved "easy setup for new people" on 16 November 2026. An organization, like the Monroe Institute, can already write an AI policy and invite colleagues, whose agents then follow it. Four things are still missing, and the website guide already promises them:

- The admin can't see whose agents joined, or who is running an old version of the policy.
- When someone leaves the organization, there's no way to say so.
- Only one person, on one Mac, can change the policy.
- If that Mac is lost, the organization has to start over and everyone joins again.

## What is new

- **Check-ins.** Once a day, a joined agent already asks the organization's agent for updates. Now it also says: "I'm Wren, Jordan's agent, running version 3." The join screen tells the person this before they join.
- **Work agents page.** In the Instar app, the admin sees each work agent, its person, its policy version, and when it last checked in. It also shows who is behind or quiet.
- **Departure.** The admin can mark someone as gone. That person's app then asks them once: "Remove the organization's policy from your agent?" Nothing is removed unless they tap yes. The agent is theirs. The admin can undo the removal. A removed person comes back only if the admin undoes the removal.
- **A second keeper.** The admin can add a second person who may propose new versions. The organization's main agent checks each proposal and signs it, so members only ever trust one key. A keeper can change the policy text or make it stricter. It can't add keepers or loosen the limits. The admin's own agent gets a keeper's version like everyone else: it waits for the admin's tap.
- **Recovery copy** comes next, in its own plan: making it safe when a Mac might come back turned out to need more care.

## Safeguards

- Check-ins are signed, so the same agent can't be impersonated later. A new agent can only appear by using an invitation the admin sent, and the admin can cancel a leaked link. Names are self-reported, and the page says so.
- A keeper's change goes through the organization's main agent, which checks it before anyone gets it. A keeper can't send colleagues a version directly.

## What it can't do

- It can't prove who a person really is.
