# A Safe Record of Which Messages Were Reviewed

The commitment detector looks through recent conversation messages for promises that should become tracked actions. Its old bookmark is useful for the existing review, but it cannot prove that every message was examined: some message identifiers come from different systems, and a successful job can still leave gaps. Skipping the next review based on that bookmark could miss a promise.

This change adds a separate receipt that records the exact source rows a successful review actually handled. Each row must have an explicit result: reviewed with no action, linked to real registered actions, or uncertain. Uncertain rows stay uncovered. The server checks the source file, the actual completed session, the job instructions and any registered actions before accepting the receipt. If a linked action disappears after a restore, the next run reviews normally. Registrations with the same reserved message identity and the same action intent reuse the retained action, including after a restart or archival; conflicting intent is refused.

There are two switches, both off by default. The first collects receipts while continuing normal reviews. The second permits a skipped run only when verified receipts cover the entire unchanged local source. Missing history, malformed evidence, changed messages, storage problems and ownership uncertainty all preserve normal review. The existing recent-message instructions and bookmark remain in place.

This does not automatically reread old history or establish that a model understood every promise. A large existing source will have historical gaps, so immediate savings are not promised. The change introduces no extra model calls, changes no live schedule and enables neither switch. Turning both switches off, or reverting the code, restores the existing behavior; local receipt files then remain inert. The next decision is whether to publish this tested dark capability, with full verification handled by the shared test service. Live collection, historical coverage and any eventual skip rollout remain separate work.
