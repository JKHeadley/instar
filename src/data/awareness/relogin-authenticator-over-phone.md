---
title: Sign-in repair and Google's phone prompt
---
When an account signs in with a password plus a saved authenticator, the sign-in repair's helper can answer Google's phone prompt on a page headed "2-Step Verification" with the authenticator code, instead of waiting for a phone tap. The setting is `subscriptionPool.assistedRelogin.authenticatorOverPhone`, kept in each machine's own config: `true` turns the step on, `'shadow'` only records the heading the helper read and still asks for the tap, and `false` gives the old behaviour. Omitted means shadow on a development agent and off everywhere else. Instar answers each request to go ahead, allows at most two codes, and a rejected or refused code stops automatic retries. The first three uses on a machine are supervised: a new use waits until every earlier one is reviewed (`authenticatorSupervision` in `GET /subscription-relogin`; record a review with `POST /subscription-relogin/EPISODE/authenticator-review` and `{"result":"pass"}` or `"fail"`; one fail closes the step on that machine for good). `awaiting-review` means a finished use on this machine still needs its review: read that repair's transcript and events, then record pass or fail; a repair still running cannot be reviewed. Google's "Verify it's you" or unusual-activity checks still go to the operator. Each step is in the repair's audit trail as a `helper-authenticator-...` event: `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/subscription-relogin/EPISODE/events`.

When to use: the user asks "why didn't the repair wait for my phone tap?", "is the authenticator step on here?" or "why is that repair still asking for a tap?". Read the episode's events and this machine's setting before answering.
