---
title: macOS Local Network access for a background-started server
---
On macOS a server started in the background (a LaunchAgent, or anything that outlives its ssh or terminal session) needs the Local Network privacy permission for its own node program before it can reach your other machines' home-network addresses (192.168.x.x and the like). macOS holds that permission per program file and cannot show the prompt to a background program, so an unapproved node fails every home-network call at once with EHOSTUNREACH, while the same address answers from ssh, a terminal or `curl`. Tailscale and Cloudflare addresses are not affected. The server now notices this itself: when a home-network call fails that way it asks Apple's `curl` whether the address answers, and if it does, it raises the `MacLocalNetwork` degradation (read it in `curl http://localhost:{{port}}/health` under the degradations), which names the exact node path. **When to use** (PROACTIVE): a Mac peer looks unreachable on its LAN address but answers from ssh, or that degradation shows → tell the person, in plain words, to open System Settings, then Privacy & Security, then Local Network on that Mac and turn on "node" (the warning clears once a home-network call gets through; if it does not, restart the agent). If "node" is not listed, find a node copy macOS already allows (start a tiny LaunchAgent that fetches the peer with each candidate node) and point the agent's `.instar/bin/node` at it through whoever owns installs and restarts on that machine. Never treat EHOSTUNREACH on a home-network address from a background Mac server as a dead peer.
