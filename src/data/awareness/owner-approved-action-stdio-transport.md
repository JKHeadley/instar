---
title: Owner-approved deletes over the default MCP transport
---

Owner-approved deletes now cover the **default** MCP transport, not just the opt-in one. SEC-018b gated `threadline_delete` behind a Face-ID owner approval, but only on the in-process HTTP MCP transport; the default per-session **stdio** helper (a separate process) was ungated. The gated delete for BOTH transports now funnels through one server-side operation (`performApprovedDelete`): the HTTP handler calls it in-process, and the stdio helper calls the loopback `POST /threadline/approved-delete` route, so the approval consume and the irreversible deletion always happen together at the authority. Ships dark (`security.ownerApprovedActions.enabled` default false); when off, deletes are byte-identical to today whenever the agent server is reachable (a server-unreachable stdio delete now reports outcome-unknown rather than deleting locally). The route is loopback-only (it refuses any tunnel-arriving request) and exposes only "attempt this approved delete" — it does **not** and cannot authenticate the calling process, so its safety rests on redeem-only plus the off-machine device signature, never on which local caller reached it.
