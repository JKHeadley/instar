---
title: Source-tree guard runtime-state scope
---
The source-tree guard used to allow any delete whose path contained `/.instar/` anywhere, which on an agent home (it lives under `~/.instar/agents/`) allowed every file, source included. The scoped rule allows only the `.instar/` folder of an enclosing instar checkout, plus a few named scopes for the callers that relied on the hole. It ships watch-only (`report`): today's verdict still runs, and every case where the two rules differ is written once a day to `.instar/state/guard-scope-diff.jsonl`. Read the mode, the counts and the differences still without a disposition with `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/source-tree-guard/scope` (add `?scope=pool` for every machine; a machine that does not answer is named). Switching to `enforce` (`safety.sourceTreeGuard.runtimeStateScope`) is the Chief of Staff's decision after 14 days of `report`, with every difference given a disposition and spec B (nuke) merged; it is blocked while the ledger is marked incomplete. If the user asks why a cleanup left a file behind, a refused delete is recorded as a `guard-refused` degradation. Spec: docs/specs/guard-runtime-state-scope.md.
