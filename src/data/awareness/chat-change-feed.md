---
title: Smaller Telegram And Slack Chat Updates
---
Telegram and Slack history reads can omit exact rows a client already holds. Send `knownRows=` on `GET /telegram/topics/<id>/messages` or `GET /mobile/chat/slack/<id>/messages` to get a baseline and `changeFeed.rowHashes`. Keep the actual rows and their ordered SHA-256 hashes together. On the next read, send the hashes comma-separated as `knownRows`; the answer contains changed rows plus the full current page hash list. Reconstruct the complete page before sharing it with another tab. Missing or inconsistent baselines require an empty `knownRows` request. Hashes cover the final privacy-shaped rows, so delivery and origin changes resend the row and old timestamps never hide arrivals. This diffs the existing bounded newest page; it is not an unlimited catch-up cursor. Plain and scroll-back reads omit `knownRows`. The web chat uses this automatically, with its full 30-second read retained. Native apps may adopt it; older agents ignore the query and return a full page.
