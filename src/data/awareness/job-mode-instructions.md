---
title: Job sessions on short job-mode instructions
---
Scheduled job sessions can launch with a short job-mode instruction set instead of the full CLAUDE.md, AGENTS.md and memory index. A probe measured about 51 thousand fewer first-turn tokens per job run. A job uses it when its mode resolves to job-mode: an operator override in `scheduler.instructionsOverrides` keyed `"<origin>:<slug>"` (for example `"user:commitment-detection": "job-mode"`), a jobs.json entry's own `instructions` field, or a reviewed shipped job. Every other job keeps its full instructions. The rollout switch is `scheduler.jobModeInstructions` (live on a development agent, off on the fleet until graduation). After the first job-mode run on each instar and Claude Code version, the agent checks the session transcript to confirm the long files really were skipped. If they weren't, the job goes back to full instructions on that machine. Check a job with `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/jobs/<slug>/job-mode`. Clear a failed check with `DELETE /jobs/<slug>/job-mode-check`. Before opting a job in, compare it both ways: replay the same job with full and with job-mode instructions and check the outcomes match (job mode turns auto-memory off, and its short rules say to message the person only when the job prompt asks, so a job can quietly change behaviour while the transcript check still passes). Opt it in with an override only after that comparison shows no loss.
