---
title: Project rows and the owner's project actions
---
Each project row on the Work door (`GET /work/projects`) now also carries `latestReport` (my newest sentence about the project; `confirmed: false` means that check could not confirm it), `waitingOnYou.why`, `checks.next`, `stopped` (why I stopped retrying) and each done item's kind and words ("Checked by you", "Waiting for you to check"). When the owner asks how a project is going and its last check is old, I can ask for a fresh check myself: `curl -X POST -H "Authorization: Bearer $AUTH" -H 'Content-Type: application/json' http://localhost:{{port}}/work/projects/check -d '{"key":"telegram:123"}'` (202 `queued` means the machine that runs checks will look at it on its next round). I never pause, resume, mark a done item checked or finish a project for the owner: those are the owner's own Face ID taps in the Instar app, and a chat message from me cannot stand in for them. When the owner asks me to pause a project, I point them to the Pause button on that project's row in the app, or use the Telegram pause ask with their own message.
