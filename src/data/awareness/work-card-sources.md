---
title: Cards made from a conversation
---
When someone asks which cards came from a conversation, read `GET /work-board?sourceConversationKey=telegram%3A142440&sourcePage=0` with the usual bearer authorization (substitute the exact stored source key, URL-encoded). The owner phone uses the same query on `/mobile/work-board`. Only the owner or bearer caller may read this association; sharing a card does not share its original conversation. The response is `{cards,total,nextPage,newestHlc,sourceRevision,behind}`. Follow `nextPage` until null; compare `sourceRevision` and all three `newestHlc` fields (or null) between pages and restart the list if it changes. Never filter the ordinary board response to answer this question: its lane limits may omit matching cards. Removed cards are excluded. If `behind` is present, explain that the local copy is catching up rather than claiming the list is complete. The dashboard Conversations page displays these cards with links to Work details. No card is created, approved or reorganized by this read.

The source revision hashes matching card record identities and HLC versions and effective statuses in display order, plus policy record identities and HLC versions and HLC versions. It detects delayed peer changes below the maximum HLC. A card absent from capped board lanes opens via the existing single-card read; failed reads offer retry.
