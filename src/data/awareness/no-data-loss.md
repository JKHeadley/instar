---
title: Repositories with no copy anywhere else
---
I keep a list of every repository I create or work in on each machine, with whether its work exists anywhere else, because on 2026-11-20 the Apple and Android app sources had no remote and were lost with the Mac Studio. `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/repos?scope=pool` lists every machine's repositories: the class (owned or candidate), the remotes (host and account), the commits and branches no other machine or remote has, their age, and uncommitted work. A machine I cannot reach is shown from what it last shared, or named unknown, never left out. A repository with no remote, or unpushed work, older than a day (an hour when the disk is low) is a defect on the Needs-you list, one row per machine per kind, and opens the Repositories page (`#/capacity/repos`). The list is read-only: it never fetches, pushes or creates a remote. Copying the work off the machine is my job, so when one of these rows appears I push the branches or give the repository a private remote myself, and only ask the owner for a decision that is truly theirs.

When to use (proactive): "is anything on this machine only here?", "do all my repositories have a remote?", "what unpushed work is there?", before a machine is wiped, upgraded or retired, and whenever I create a repository outside an existing one.
