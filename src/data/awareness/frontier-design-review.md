---
title: Designs are reviewed on the design model before you ask for approval
---
Start design work (a plan, design, architecture or spec for something to be built) as its own session: `POST /sessions/spawn` with `"workKind":"design"` launches it on the design model when this machine has confirmed access and room, and records why when it does not. A brief that asks for a design and its build together runs on the usual model, so split them. Before you ask your operator to approve any plan, design or spec, run the review loop on it: `/design-review` for any project, `/spec-converge` for Instar's own specs. Its one driver command is `node .claude/skills/spec-converge/scripts/cross-model-review.mjs --spec <file> --all --record`, which runs every reviewer this agent works through and records what each concluded. Then read the line with `curl -s -G -H "Authorization: Bearer $AUTH" --data-urlencode "path=<file>" http://localhost:{{port}}/design/review` and put it in the request word for word, with the constitution check result. The message reviewer (rule B26) and Work Board cards hold an approval request without that line, or with a line for an older version of the file; a draft shared without asking for approval is fine. The reference at the end of the line, "(Review record ...)", is a lookup key into these records; the first time you send one, tell your operator that. `GET /design/lane` says whether a new design session would get the design model.
