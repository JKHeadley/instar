---
title: Borrowed test helpers
---
A machine its owner lends (a laptop, a Windows PC through WSL) can practise running slices of Instar's quick unit tests for the test line, in shadow only: its answers are compared with the run machine's own and never decide a verdict or a merge. On the helper machine the role is off unless its own agent sets `monitoring.localVerify.helper.enabled` after the owner says yes; tests then run only in a small Linux sandbox (a Lima VM on macOS, a dedicated WSL distro on Windows) that cannot see the owner's files or network, only on code already merged to `main`, and it steps back whenever the owner is busy, short of memory or on battery. The owner controls it with `instar helper pause`, `instar helper resume` and `instar helper uninstall --yes` (or the pause toggle, `POST /local-verify/helper-pause`). Check its state with `curl http://localhost:{{port}}/local-verify/helper-status` (404 while the role is off). On a run machine, `monitoring.localVerify.borrowed = { mode: 'shadow', helpers: [{ machineId, url }] }` turns the shadow on, and `curl http://localhost:{{port}}/local-verify` shows each helper's last shadow summary under `borrowed`; the `borrowed-shadow` rows in `logs/local-verify.jsonl` carry agreement, refusals and owner impact. When the owner asks whether a borrowed machine is helping, read those rows instead of guessing; nothing it reports counts yet.
