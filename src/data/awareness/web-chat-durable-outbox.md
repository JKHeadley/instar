---
title: Pending web chat sends survive closing the tab
---
The dashboard can save a browser-local encrypted copy of a message and its selected files before clearing its composer. With an approved browser and supported server, opening the dashboard resumes the same pending operation when connected; the original conversation need not be open. Automatic recovery requires browser Web Locks. Otherwise the pending copy stays available for explicit original-request recovery. It does not send while the browser is closed, and it does not cache received conversation history.

Queued means saved locally, not delivered. An uncertain send keeps its original request identifier and content for review; do not tell the person to create another copy automatically. The pending-sends view explains what is waiting or held for the current browser identity. Its Save file copies action recovers retained local file bytes without sending another message. It never silently re-signs an older identity's pending operation. Exact emergency stops held offline or after uncertainty require a new current explicit Send. Signing out or definitively removing this browser invalidates its pending copies before erasing them; cleanup failures are shown explicitly. Read `GET /mobile/browser-devices/status` for this server's versioned outbox support; that answer does not prove browser storage or message acceptance. Restoring after a full historical downgrade requires the documented flag-off and recovery-generation review procedure before automatic recovery is enabled again.
