---
title: Dashboard session token
---
Under `security.dashboardScopedToken` (SEC-002b, docs/specs/dashboard-scoped-session-token.md), the dashboard PIN unlock can return a short-lived, revocable SESSION token to the browser instead of the agent's permanent master API token — so a stolen browser or a guessed PIN yields a credential that EXPIRES (absolute cap, default 7 days) and can be REVOKED, not the whole agent forever. The browser silently refreshes it (`POST /dashboard/session/refresh`), a logout revokes the whole session family (`POST /dashboard/session/revoke`) and closes its open WS/SSE streams, and sensitive credential operations (reading the API token, changing the PIN, rotating the token) require a fresh-PIN STEP-UP (`POST /dashboard/session/step-up`) that a thief with only stolen storage cannot produce. The master token still works for API/CLI callers (back-compat). It ships DARK: `security.dashboardScopedToken.enabled` defaults false and MUST stay off until the full live dashboard proof passes (every tab + terminal + SSE + file edit + Remote Desktop at phone and desktop widths) — turning it on before that risks breaking a dashboard surface. When the owner asks "what does unlocking the dashboard give my browser?" or worries about a stolen dashboard session, this is the answer; the deeper per-route confinement of a stolen session is the tracked follow-up SEC-002c.
