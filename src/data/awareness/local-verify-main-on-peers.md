---
title: Local Verify main verify on a helper machine
---
If you test your own changes with Local Verify on two machines (a coordinator with a peer verifier), the periodic test of the main branch can also run on the peer, so it does not wait for the coordinator's own slot. It is off unless you turn it on: set `monitoring.localVerify.mainOnPeers` to `true` in `.instar/config.json` on the coordinator (read live, no restart). The peer is offered the main verify only while main is healthy, under the same fair share as the coordinator's slot, one main verify at a time. The coordinator alone decides main's health: a red result from the peer makes main suspect and the coordinator re-runs that version itself before main can turn red. Setting the key back to `false` returns every new main verify to the coordinator. `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/local-verify` shows a peer-run main verify under `peers.reserved` with `pr: 0`. If a peer cannot confirm three times in a row that main contains the version it was asked to test, it gets no main verify for 30 minutes and the attention item `local-verify:peer-main-unconfirmed:<machine>` is raised; check that peer's GitHub read and its clone.
