---
title: Local Verify main verify on a helper machine
---
If you test your own changes with Local Verify on two machines (a coordinator with a peer verifier), the periodic test of the main branch can also run on the peer, so it does not wait for the coordinator's own slot. It is off unless you turn it on: set `monitoring.localVerify.mainOnPeers` to `true` in `.instar/config.json` on the coordinator (read live, no restart). The peer is offered the main verify only while main is healthy, under the same fair share as the coordinator's slot, one main verify at a time. The coordinator alone decides main's health: a red result from the peer makes main suspect and the coordinator re-runs that version itself before main can turn red. Setting the key back to `false` returns every new main verify to the coordinator. `curl -H "Authorization: Bearer $AUTH" http://localhost:{{port}}/local-verify` shows a peer-run main verify under `peers.reserved` with `pr: 0`. If a peer cannot confirm three times in a row that main contains the version it was asked to test, it gets no main verify for 30 minutes and the attention item `local-verify:peer-main-unconfirmed:<machine>` is raised; check that peer's GitHub read and its clone. Peer results are signed: the peer signs each answer with its machine key over the request it ran, and the coordinator checks it against the key it has pinned for that peer; an answer that fails the check is thrown away, that verify runs on the coordinator, and `local-verify:peer-result-unverified:<machine>` is raised. A peer whose key is not pinned on the coordinator is never sent work. A peer's pass on main only goes so far: it never turns on isolation re-runs or writes flaky history, and once the main commits only peers have checked reach the refresh age (at most two and a half hours, sooner when this machine's own main runs are slow), the coordinator checks main itself; main turns suspect at most three hours after the first merge the coordinator has not verified. A coordinator that has not yet run main itself keeps main local until it has. If the coordinator's own run fails on a commit a peer called green and no third machine settles it, that peer stops testing main and `local-verify:peer-main-disagreement:<machine>` is raised; the owner clears it on the console under Work, then Development (the card "A helper machine no longer tests main", button "Let it test main again", PIN unlock). `GET /local-verify` shows all of this under `peers.trust`.
