## ELI16

Justin set a rule: any feature that spends AI tokens must be fully auditable — how many tokens, by which feature, on which model — before the cartographer's paid background sweep is ever switched on. Most of the metering plumbing already existed (every internal AI call flows through one funnel into a per-feature ledger at `/metrics/features`); this PR closes the four holes in it. (1) Codex-routed calls used to record ZERO tokens — exactly the route the sweep uses. They now run `codex exec --json` through a streaming parser: token counts come from the event stream, while the actual answer comes only from a separate file codex writes, so weird model output can never corrupt the result. A kill-switch (`intelligence.codexExecJson:false` or `INSTAR_CODEX_EXEC_JSON=0`) restores the old behavior instantly per machine. (2) Failed calls used to lose their cost — a timed-out call that already burned tokens recorded null. Error rows now carry the real numbers, including the final count flushed after a kill signal. (3) There was no per-model split — the ledger now breaks every feature's tokens down per model and framework, including cached-vs-fresh input. (4) Tagging was optional — all 8 untagged callsites are tagged in this PR (zero grandfathered), and a new lint in the CI chain fails any future untagged LLM call, with an empty-baseline ratchet test pinning the allowlist, the funnel exemption list, AND the wiring exclusions so there's no dodge channel. Tripwires make backsliding loud: a per-framework usage-coverage number, a once-per-process drift alarm, and a live canary that runs one REAL codex call and fails if counting broke (it skips politely on environmental trouble, so it never cries wolf). The audit log that the new per-call temp-file cleanup feeds also gains 16 MB rotation with a marker entry, so a shrunken log is explainably rotated rather than mysteriously truncated. The rule itself is now a constitution standard ("An Unmetered LLM Call Is an Unaccountable One"), ratified by the operator directive. The sweep stays OFF — this PR is its enablement precondition, not its enabler.
