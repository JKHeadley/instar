## What Changed

Discovery marker tests load the real marker functions under private temporary homes. They preserve the original missing, corrupt, CRUD and persistence checks, and a new two-home regression verifies independent marker files and deletion. Production discovery and normal runner admission are unchanged.

Promoting the feedback consumer now approves one exact, server-proposed batch instead of any hash-shaped string. The new `GET /feedback-factory/consumer/promotion/proposal` returns the queued work items the consumer would claim next, in claim order. The batch is capped at the per-run claim cap and at most 50 items. Each item shows its id, title, priority and report count, and the response carries a `proposalSetHash` (sha256 over a domain line, a marker of the previous promotion record, and the sorted work ids).

Responses always say whether Promote can be offered on this machine (`localAction`) and summarize any existing promotion record. When nothing can be promoted, the response names the state: `configured-simulation`, `already-live`, `no-work`, `non-owner`, `restore` or `unavailable`. A non-owner reads the owner's proposal and marks it `servedBy` the owner. A configured dry run wins over an existing record.

`POST /feedback-factory/consumer/promote` still needs the operator PIN. It now also re-derives the batch immediately before writing and refuses a stale or invented hash with a named 409. The hash also binds the previous promotion record, so an approval cannot be replayed after a revoke.

The record stores the approved work ids. The live consumer claims only those items until each has been tried under this approval (judged by attempt count, so machine clock differences don't matter; a held approved item pauses other claims until revoked and re-approved), and a revoke mid-run stops further claims; then the promotion continues at the approved per-run bound. A record written before this change (not bound to an approved set) no longer turns the consumer live and is reported as needing re-approval.

## What to Tell Your User

Running discovery tests no longer touches the computer’s in-progress setup marker. No user action is needed.

When you turn on automatic work creation from feedback, you now see the exact items it will start with and approve that list with your PIN. If the list changes before you confirm, you'll be asked to look again, so you never approve something you didn't see.

## Summary of New Capabilities

No new product capability or setting. This repairs ownership of test state.

- `GET /feedback-factory/consumer/promotion/proposal`: the exact batch a consumer promotion would approve, its hash, and why promotion is or isn't available here.

## Evidence

The production module captures its marker path before the original tests substitute a temporary home. No unsafe historical baseline was executed. The sole authorized sequence passed 53 unit tests and 30 integration tests, with zero failures, skips or recorded unhandled errors and zero exits. Raw results and independent review are preserved with the candidate. Complete verification remains coordinator-owned.

Before this change, a promote call with `evidenceHash: "a"×64` and no queued work returned 200 and recorded a live promotion. The drain lifecycle e2e did exactly that. Now the same call returns 409 `promotion-not-pending:no-work`.

The new integration suite covers:
- the capped claim-order batch;
- an invented hash refused with `promotion-proposal-changed`, and a wrong bound refused;
- a hash going stale when a new item is queued before confirm;
- promotion succeeding with the fresh hash, then refusing a replay as `already-live`, and refusing the pre-revoke approval after a revoke;
- the live drain run claiming only approved items until each is attempted, with no fallback;
- a legacy syntax-only record not going live and being reported for re-approval;
- dry run winning over a valid record;
- a revoked record proposing again;
- a non-owner read proxied with `servedBy` and `localAction: false`, including with the owner unreachable.

Related unit files (feedback, capability index, routes, awareness) pass 2,770 tests; all feedback integration files pass 95 and all feedback e2e files pass 55. All 55 lint steps pass. A cross-model second-pass review ran eight rounds; every correctness finding was fixed, and the remaining items are documented safe-direction trade-offs.
