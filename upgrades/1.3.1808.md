## What Changed

Members can link their own computer for Instar Documents, still switched off for the fleet (`documents.enabled`, development agents only). A computer that isn't linked shows a QR code on the document page; the member scans it with the Instar app (People → Link a computer), checks the code matches, and confirms. Before confirming, the app shows which kind of computer asked and how long ago (`POST /mobile/browsers/link/lookup`), with a reminder to only scan a code on a computer in front of you. The computer can then read and comment on the documents that member can already see, and send the "I left N comments" message for them, for up to 30 days. A guest's computer can read only. Each person may link three computers. Forgetting one on the phone, removing the person, revoking the phone that linked it, or the 30 days passing all end the link on every machine (`POST /mobile/browsers/link`, `GET /mobile/browsers`, `POST /mobile/browsers/:id/forget`).

Adds the core library for Instar Documents (spec `docs/specs/instar-document-viewer.md`): the signed, replicated row format, per-machine chains, the deterministic fold with per-reader visibility, the access rule, the on-disk store (ingest, pending re-check, purge, prune, export and merge-restore), and the text algorithms (projection, anchoring, word diff, content-defined chunking). Nothing imports it yet: no route, config, hook or migration changes, so agents behave exactly as before.

Instar Documents gets its page and its people-facing writes, still switched off for the fleet (`documents.enabled`, live only on development agents). A document opens at `/docs/<id>` as its own page with a strict content policy; the app gets a one-minute single-use code (`POST /mobile/docs/:id/open`) and a computer browser signs its own open. People comment, reply, resolve and send comments from the page, and every write is signed by their own phone or computer (`instar-docpage-v1`); every machine re-checks that signature before showing the row. The owner moves a document to another conversation from the phone with Face ID (`POST /mobile/docs/:id/primary`), and a shared document never moves back to private. When the agent answers a comment, the commenter's phone gets "New answers to your comments" (push kind `document`). The agent can walk related documents and conversations with `GET /docs/graph`, and every session starts knowing its conversation's documents.

Fixes for Instar Documents found by driving the real document page as a user on two machines (still switched off for the fleet; development agents only). A member's linked computer can now press Send. Comments show where they came from ("from Mia's computer"). When a document's conversation is deleted, Send is turned off and says why. Comments a computer wrote before it was forgotten, or before its person was removed, now stay on every machine instead of disappearing from some. A test-only switch (`documents.loopbackOrigin`) lets a development agent with no tunnel hand out links the iOS simulator can open.

Instar Documents gets its server side, switched off for the fleet (`documents.enabled`, live only on development agents): the agent API (`POST /docs`, `GET /docs?conversation=`, `GET /docs/:id/data`, versions, compare, comments, replies, links, `GET /docs/session-context`, `GET /docs/health`), the phone reads (`GET /mobile/docs`, `GET /mobile/docs/:id/summary`), and replication between machines by version-vector pull (`POST /api/documents/rows`, `/api/documents/push`). A document is visible to exactly its conversation's audience; the agent can't share, move or speak as a person. Documents are kept out of ordinary snapshots. `mayUseConversation` refuses `doc:` refs.
