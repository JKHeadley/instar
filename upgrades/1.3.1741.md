## What Changed

- **"Did my held reply arrive?" now gives the sending machine's own answer, from any machine.** On an agent with more than one machine, the held-reply outcome check used to answer only from the asking machine's own records. When another machine had done the send and ended the reply, this machine said "unknown, not safe to resend" while the sending machine knew the answer (F2 in `docs/specs/native-conversation-base.md`). The check now asks the machine that sends to Telegram (the execution owner) over the existing signed machine link, using the `receipt` verb with a new `reader: true` flag, and asks the machine that wrote the reply whether it still holds it. It then applies one fixed table: a delivery anywhere is delivered; a duplicate ending is delivered; a newer copy is followed to its own answer; the owner's failure with the writer no longer holding it is not-delivered (with the cause); anything missing is `unknown` with the missing fact named in `why`. It never says "safe to resend" on missing evidence.
- **The answer says who gave it.** New fields: `answeredBy`, `asOf`, `ownerAnswered`, `why` (`owner-unresolved`, `owner-no-record`, `author-unanswered`, `timeout`, `refused`, `old-version`, `owner-read-off`), `reason`, `failure` (`refused`, `never-left`, `deadline`), `supersededBy`, `duplicateOfMessageId`. Existing fields are unchanged.
- **Suppression reasons are read, not guessed.** A suppressed reply with no stated reason (every one written before this release) is now `unknown`; before, it read "not delivered, safe to resend", which invited a duplicate when the reply had been ended as a duplicate. Quiet notices and retired historical notices read "not delivered, ended on purpose" with `safeToResend: false`.
- **Bounded.** The route answers within 4 s (the reply script waits 5 s). Each ask gets at most 2 s, owner and writer are asked in parallel, concurrent asks for one reply share one call, a machine that just timed out is answered at once for 2 s, and a final owner verdict is cached (1024 entries). A held reply that was never handed to another machine makes no network call.
- **Switch.** `messageOrigin.ownerRead.enabled` (default on, read live, never written) stops this machine asking; its answers then fall to the cautious row (`unknown`, `why: owner-read-off`). `messageOrigin.forwardToHolder.enabled: false` has the same effect. Tuning: `ownerRead.budgetMs`, `ownerRead.cacheEntries`.
- **The reply script follows `safeToResend`.** A `not-delivered` answer with `safeToResend: false` now prints "ended on purpose ... Do NOT resend it" instead of "safe to send it again". The previous script version's hash is registered so installed copies are replaced on update.
- **Status.** `GET /telegram/origins/status` gains `ownerRead`: ask, timeout, refusal, old-version and cache counts, ask and route p95 latency, and `routeOverBudget`. A machine without the reader shows `state: unknown`.

## What to Tell Your User

When one of my replies was held up and I check whether it reached you, any of my machines now gets the answer from the machine that actually sent it, instead of saying "I can't tell". I still never send something twice when the answer is unclear.

## Summary of New Capabilities

- The held-reply outcome route asks the execution owner and the writing machine, and answers with `answeredBy`, `why` and the delivery cause.
- `receipt` mesh verb: optional `reader: true` for any same-agent machine (state, reason and message ids only, never message text).
- `messageOrigin.ownerRead.enabled` switch; `ownerRead` counters on the origin status.

## Evidence

- `tests/unit/telegram-origin/held-reply-outcome.test.ts`: one case per table row 1 to 11, the reason-aware classifier (null reason is `unknown`; duplicate is delivered; failure causes), row 9 each way.
- `tests/unit/telegram-origin/origin-owner-read.test.ts`: an older holder's raw `suppressed` with no outcome is `old-version` and nothing is safe to resend; closed-set checks; coalescing, cache, timeout memo, per-ask budget; superseded chains and loops; the route deadline.
- `tests/unit/telegram-origin/origin-delivery-resolution.test.ts`: the `reader` branch answers by role, refuses a revoked or foreign-agent key, and the ladder's raw `state` is unchanged.
- `tests/integration/telegram-origin-outcome-owner.test.ts`: three runtimes on the signed mesh; owner failure plus a holding author reads `pending` on a machine with no row, then `not-delivered` once the author ends its row; owner stopped with 20 ids all answer inside 4 s with `why`; a not-yet-forwarded reply makes no mesh call.
- `tests/e2e/telegram-origin-owner-read-alive.test.ts`: the route on the production boot path returns 200 with `source: 'execution-owner'`.
