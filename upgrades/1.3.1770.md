## What Changed

- **Conversations suggests efforts.** The Conversations Overview has a new "Review suggestions" page. The agent proposes groups of the owner's unassigned conversations (one model call per build, `ConversationGraphSuggestions`, reflector tier), each with a one-line reason and Accept/Reject. Plain code validates every group before it is shown: only conversations it was offered, 2 to 12 per group, none in two groups, no group mixing two bound projects, nothing already rejected. Accept runs the ordinary owner changes from the dashboard (create effort, name it, preview and move each conversation), waiting for each to commit and resuming from opaque progress if a machine is slow. A rejection is remembered. Routes: `GET /conversation-graph/suggestions`, `POST …/refresh`, `POST …/:id/reject`, `POST …/:id/accepted` (owner operator session; mounted with owner corrections). Spec: docs/specs/conversation-graph-suggestions.md.
- **The Chief of Staff conversation is the root of the Overview.** `GET /conversation-graph/roots?view=overview` returns it as `root`, and the dashboard draws it as the top row with every effort under it. It cannot be placed under anything: node reads report `moveEligible:false` (`chief-of-staff-is-root`), it has no move destinations, preview says not eligible, and the write ingress refuses the placement with 409 `chief-of-staff-is-root`.

A feedback executor session that cannot reproduce a report because an earlier commit already fixed it can now name that commit in its result file (`fixedByCommit`). Trusted code checks that the commit exists in the source checkout, is contained in the attempt's base, and was committed after the item's first report. When it is, the item is held `already-fixed` after that one attempt instead of being given a second session. When the check fails, the attempt counts as plain `not-reproducible`, as before. New reports still bring a held item back.

Same-machine agent trust (`threadline.localRouteTrust`, still dry-run) now keeps evidence the maturation ladder can judge it by (CMT-1141).

- Every decision row in the evidence log names its sender in a top-level `subject` (the fingerprint, else the cleaned claimed name). Each would-refuse row also keeps the sender and the reason (`refuseReason`, for example `untrusted-may-not-message`), at most one row per sender and operation per minute, each saying how many it stood for.
- The ladder bar for the next rung (dev-agent-live, which turns refusals on) adds: at least 3 distinct senders, at least 1 would-refuse decision, and no would-refuse graded wrong (graded with `POST /maturation/evidence`, `kind: outcome`, `reason: would-refuse`, `gradesEventId`).
- Evidence rows gain an optional `subject` field any feature can use to count distinct things on its bar.
- A drill, `scripts/drills/local-route-trust-drill.mjs`, runs two throwaway agents (no channels, no relay network) and proves an unprofiled same-machine sender with its relay off gets a would-refuse row while its message is still delivered.

- **A Telegram photo or file is readable on the machine that runs the session.** On an agent with more than one machine, a photo stayed on the machine that polls Telegram, and a session on another machine was told to read a path that existed only there (F3 in `docs/specs/native-conversation-base.md`). A file now travels by attachment id in a structured `media` field (Telegram adapter, lifeline, app files sent into a topic, the mesh `deliverMessage`, the durable inbound queue, spawn and respawn bootstraps), and the machine serving the session builds the file line itself: a private copy when the file is here, `[file still copying: <name>]` and later one `[file now available: <path>]` line when it arrives, and after 5 minutes one line saying it has not arrived yet (the wait continues). Where native media is off, the session is told the file is stored on another machine.
- **Text a person types is never read as a file.** Every path tag form (`[image:`, `[document:`, `[video:`, `[voice:`, `[file:`) in person-supplied text becomes `[typed image:` and so on, on Telegram, the lifeline, Slack and iMessage, before it is forwarded, queued or logged. Before, anyone who could post in a conversation could make the session read any readable file on the machine.
- **Older machines stay truthful.** The text always carries one path-free sentence per file ("[The user sent a photo (attachment `<id>`, `<name>`). It is stored on another machine and cannot be opened here.]"), so a machine still on the previous release tells its session a photo was sent and which one. A message from an older poller is resolved by its own message id and its path is discarded.
- **Lifeline-forwarded files are now captured** into the media store like polled ones, so they can follow the session to another machine.
- **Topic history never holds a path**: a file shows as `[photo]`, `[file: <name>]`, `[video]` or `[voice note]` with the caption.
- **New routes.** `GET /conversation-media/path?conversationKey=telegram:<topicId>&platformMessageId=<id>` (or `&attachmentId=`), Bearer plus the session bind token, returns a readable local path or `not-on-this-machine` with the reason. `GET /conversation-media/status` shows waiting files, the observed event lag and outcome counts.
- **Storage.** The inbound queue gains a nullable `media` column and the media index gains a `pending_media_events` table, both created on open. A durable sweep (at start and every 30 seconds) reconciles waiting files, and retries a "now available" line that found no running session.

## What to Tell Your User

Your Conversations page can now organize itself. Open "Review suggestions" and I'll show you groups of your conversations that look like one piece of work, each with a short reason. Tap Accept and I'll make the effort and move those conversations in, or Reject and that suggestion won't come back. Nothing moves until you accept. Your Chief of Staff conversation now always sits at the top, with every effort under it.

Automated fixing wasted effort on reports that had already been fixed: each one was tried twice. Now, when a worker shows which earlier change fixed it and that change is really there, the report is set aside after one try.

Nothing changes for you. Messages between agents on the same computer are delivered exactly as before. Behind the scenes, the safety check that may later refuse untrusted senders now has to show it has seen several senders and made correct refusal calls before it is allowed to start refusing.

When you send me a photo or a file in Telegram, I can now open it even when the conversation is running on a different one of my machines; if it is still on its way I say so and pick it up when it lands. And if someone types something that looks like a file reference, I treat it as their words, not as a file to open.

## Summary of New Capabilities

- Owner-reviewed effort suggestions for existing conversations, with one-tap Accept or Reject.
- The Chief of Staff conversation is always the top of the Conversations Overview and cannot be moved under anything.

| Capability | How to Use |
|-----------|-----------|
| Already-fixed reports set aside after one attempt | Automatic |

- Would-refuse evidence rows naming the sender and the reason, for same-machine agent trust.
- A stricter, evidence-based bar before same-machine agent trust can enforce.
- An optional `subject` field on maturation evidence rows for distinct-count bars.

- Telegram files by attachment id through every carrier, resolved on the serving machine.
- Typed path tags are inert on Telegram, Slack and iMessage.
- `GET /conversation-media/path` and `GET /conversation-media/status`.
