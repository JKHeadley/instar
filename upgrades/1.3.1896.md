## What Changed

Third batch of the bounded-input derivation review (10 more baseline entries). The session watchdog's "is this command stuck?" check used to show the model only the first 200 characters of a running command. A line like `cd <long folder> && npm test` could be judged from the `cd` alone and interrupted with Ctrl+C. The model now sees commands up to 2,000 characters whole. A longer command is not judged. It is checked again on every poll and interrupted only after the hard time limit (default 30 minutes). Before, any command the check could not decide on was skipped for good, so that time limit never actually applied. Disputing a commitment with a reason over 400 characters now gets a clear error asking for a shorter one, instead of the reason being silently cut to 200 before it went into every session's shared context. Accepted reasons are now stored whole. Follow-up nudges to other agents now say when a quoted request was shortened. Eight other sites were reviewed and kept, each with its reason written beside it.

## What to Tell Your User

Nothing to do. Long-running commands with long folder paths, such as test runs inside a project folder, are less likely to be stopped by mistake.

## Summary of New Capabilities

- The stuck-command check sees the whole command, or waits for the hard time limit, which now actually applies.
- Commitment dispute reasons are stored whole, or refused if too long.

## Evidence

New unit cases fail on the old code: a 200+ character `cd … && npm test` now reaches the check whole and is judged legitimate; a command over the bound never reaches the check, is not interrupted before the hard limit, and is interrupted after it; a 600-character dispute reason is refused, and a 300-character one is stored whole. All SessionWatchdog suites pass. Per-site readings: docs/audits/bounded-input-review/batch-3.md.
