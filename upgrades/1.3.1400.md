## What Changed

- **A route to another machine that stops working now demotes itself.** The previous change (shipped in the same release) made your agent pick the best *allowed* way to reach another of your machines. Allowed is not the same as alive. Pool reads now report each attempt's outcome into the same route-health record the rest of the mesh already keeps, so a route that is genuinely usable and then dies stops being chosen — and gets its place back when it starts answering again.
- **Who this actually matters for:** two machines on the same local network, where a local address is a real candidate. Where your machines are on different networks, a peer's local address was already being skipped, so the first change was enough on its own.
- **It judges the route, not the answer.** A reply that comes back — even an error reply — proves the route carried traffic, so only a genuine connection failure or timeout counts against it. Otherwise every machine answering "that feature is switched off" would have looked like a broken network.
- **One place does the dialling now.** Every cross-machine read goes through a single function, and a test fails the build if a future one is written the old way — so this cannot quietly stop working as new reads are added.

- **On Linux, restarting the agent's service no longer kills every session.** The service file had no setting for what to stop on a restart, so systemd stopped everything the service had started, including tmux, which holds every conversation and autonomous run. One `systemctl --user restart` wiped them all out (seen on a Windows/WSL machine on 2026-10-22, where a live autonomous run had to be revived by hand). The service file now says `KillMode=process`: only the agent's main program is stopped, and tmux and its sessions keep running. This matches how macOS already behaves.
- **Existing Linux installs are fixed on update.** The updater adds the line to the agent's service file (keeping a dated backup), leaves any setting the operator chose alone, and reloads systemd so the very next restart is already safe. It restarts nothing.
- **`instar server restart` still restarts the server.** Because the service restart now leaves the server running, that command stops the server's own tmux session as part of the restart (Linux and macOS), so new server code loads. Agent sessions are not touched.

- **Issue topics can live in their own Telegram group.** A new optional setting, `issuesChatId` in the Telegram messaging config, names a second forum group (for example "Echo Bugs"). `POST /telegram/topics` with `"kind":"issue"` creates the topic there and answers `"group":"issues"`; without the setting it uses the main group as before. Inside Instar these topics have ids of 10,000,000,000 plus Telegram's thread number, translated only where Instar talks to Telegram, so sessions, the reply script and reminders work unchanged. Sends, the lifeline's notices, cross-machine forwarded replies and prompt-gate edits all reach the right group.

## What to Tell Your User

Nothing you need to do. If one of your machines sometimes seemed unreachable for the "all my machines" views even though it was running, this is the second half of that fix: your agent now remembers which routes failed instead of trying the same dead one every time.

If your agent runs on Linux, restarting its background service no longer ends the conversations and long jobs it is in the middle of. Nothing for you to do.

Bug and problem topics I open while working can now go into their own Telegram group, so they stop crowding your main topic list. I set the group up myself from your signed-in Telegram; you don't need to do anything.

## Summary of New Capabilities

- No new capability. The feedback half of the cross-machine read fix: a dead-but-allowed route now demotes itself instead of being chosen forever.

- No new capability. Agent sessions on Linux now survive a restart of the agent's service.

- Optional "<agent> Bugs" Telegram group for issue topics (`issuesChatId`, `POST /telegram/topics` with `"kind":"issue"`).
