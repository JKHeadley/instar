## What Changed

- **Health check can run as its free script on development agents.** On a development agent whose settings no longer list `health-check` among the jobs kept on the old way, the health check now runs its plain script instead of starting a Haiku session every 5 minutes. Before, a lock built into the code held it back whatever the settings said. In script mode the health check makes no AI call: it only reads the agent's health page and disk space, and sending unusual results to Jev stays off in code. Every other agent is unchanged.
- **Schedule changes to built-in jobs survive updates.** Each install records the schedule it shipped as `shippedSchedule` in `.instar/jobs/schedule/<slug>.json`. On the next update, a `schedule` that differs from it is kept as the operator's choice. One that still matches follows a new shipped default. An invalid saved schedule is reset to the shipped one and reported.

## What to Tell Your User

If you've asked me to run one of my built-in checks less often, that change now survives Instar updates. I may need to make it once more after this update, because older updates could undo it. On development agents the health check can also run as a free plain script, with no AI session every few minutes.

## Summary of New Capabilities

- Built-in job schedule edits persist across updates (`shippedSchedule` tracking in the per-job schedule file).
- `health-check` may run as its script on development agents (code-owned no-model allowlist).

- `tests/unit/job-cost-runner/JobScheduler-script-runner.test.ts`, `tests/integration/health-check-script-runner-route.test.ts`, `tests/e2e/job-cost-lifecycle.test.ts`: health-check is `script` on a development agent once config omits it, runs with zero sessions and zero tokens, rolls back when listed again, and stays on its session on the fleet.
- `tests/unit/scheduler/InstallBuiltinJobs.test.ts`, `tests/unit/PostUpdateMigrator-builtinScheduleEdit.test.ts`: a schedule edit survives the real update path, unedited schedules follow new defaults, and the CLAUDE.md note is added once.
