## What Changed

A done item that names several "PR owner/repo#N merged" phrases now passes only when every named PR merged into the default branch. Before, the first one decided. Any unmerged PR fails the item; an unreadable one (or one in an unlinked repo) makes it unknown.

## What to Tell Your User

When a project's finish line lists several pieces of code, I now count it done only when all of them are merged, not just the first.

## Summary of New Capabilities

- Chief of Staff done items can require several merged PRs in one line.

## Evidence

- tests/unit/ChiefOfStaffDoneItemEvaluator.test.ts: 5 new cases (all merged, one unmerged, one unreadable, fail outranks unknown, unlinked repo).
