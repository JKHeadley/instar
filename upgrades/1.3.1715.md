## What Changed

The live Slack path ignored a refused conversation start, so the message was dropped and the person heard nothing (fb-73ad5b9e-f14). Both spawn checks now run the existing safe relay rewrite first, and a refusal worth retrying goes to the new `SlackRefusedHold`: kept on disk, retried through pool routing on a fixed schedule of about two hours, person told at once, operator told after three failed tries, person asked to resend after the last. An emergency stop empties it. The readiness check now runs before a conversation's resume entry is used, so a refusal no longer costs it. The operator-notice routes moved to a shared function, used by this and the sign-in key monitor.

## What to Tell Your User

If I can't start up to answer you on Slack, I now tell you straight away, keep your message and keep trying for about two hours. If it still fails I'll ask you to send it again. Before this, a message could go unanswered with no word from me.
