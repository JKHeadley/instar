## What Changed

- A config-change promise whose key names a topic or session (for example `topic.model`) is recorded as a plain follow-up promise with no config check and no automatic config writes.
- When a new config-change promise expects a different value for a key that an open promise already watches, the older promise is withdrawn and marked as superseded by the newer one.
- After a promise has escalated as "keeps reverting", later reverts are still corrected but no longer post an alert each time.
- The promise-detection prompt now says per-topic requests are not config changes.

## What to Tell Your User

If you ask me to switch the model for one topic, I will no longer report that it "reverted" every few minutes because another topic uses a different model. And if a setting really does keep reverting, you get one warning, not an endless stream.

## Summary of New Capabilities

Promise tracking no longer turns a per-topic request into a watch on a shared config setting, retires an older setting watch when a newer request expects a different value, and stops repeat "that setting reverted" alerts once the "keeps reverting" warning has been sent.

## Evidence

Live on 2026-10-28: two promises for different topics (Opus 5.5 and gpt-6-sol) were both recorded on `topic.model` and posted about 1000 alerts each to the Attention topic. New unit tests reproduce that case and the two other gaps; four of them fail on the old code and pass with this change.
