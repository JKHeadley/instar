## What Changed

SEC-129. `GET /recommended-services/:id/confirm` is reachable before any sign-in. For a service that copies the agent's secrets (Bitwarden), it used to list the name of every stored secret. It now returns only `copiesCount`. The names come from `POST /recommended-services/:id/confirm` with `answer: 'names'`, which needs the page's live token and the PIN (the same `checkConfirmPin` as a yes or no, with its guessing limits), never spends the token, and changes nothing. The confirm page (`dashboard-pair/service-yes.js`) shows the count and a "Show their names" button that uses the PIN typed above.

SEC-131. The stop-gate router blocks a stop once when the session has a green pull request, and remembers that with a marker file. The marker used to be written in the shared temp folder with a plain write, which follows symlinks. It now lives in `.instar/state/stop-gate-markers/` (folder mode 0700) and is created exclusively with mode 0600: an existing file or link counts as already fired and is never written through. If the marker cannot be created, the reminder is skipped instead of repeating. The hook is rewritten on every update, so existing agents get this automatically.

The lifeline's server supervisor gives a respawned server a startup allowance (`startupGraceMs`, 10 minutes) with an absolute ceiling of 3 × that allowance per unhealthy episode, measured from `firstSpawnedAt`. A healthy tick cleared `firstSpawnedAt`, but the next tick re-anchored it to the running server's long-past `spawnedAt`, so a server healthy for more than 30 minutes met its first outage with the ceiling already exceeded. Because a respawn resets `spawnedAt` but not `firstSpawnedAt`, every respawn in that outage got only the ~60 s alive-but-unresponsive allowance, and boots slower than that were killed repeatedly. The anchor is now set only while the current spawn has not yet answered healthy (`lastHealthy < spawnedAt`). A server healthy for any length of time gets the full allowance on its next respawn; within one unhealthy episode the anchor stays at the first respawn, so the ceiling still ends a hopeless stretch. Missing-session immediate respawn, the circuit breaker, restart backoff, sleep/wake and CPU-starvation handling are unchanged.

Telegram topic names now reach every machine of the agent (spec `docs/specs/topic-name-replication.md`, closes CMT-2095, Studio outage ledger N40).

- Only the lead machine polls Telegram, so only it learned topic names and renames; when it died, standbys showed "Name not available". Names now ride a new replicated kind `telegram-topic-name-record` (store `telegramTopicNames`) on the existing WS2 record path. Each machine applies the winning name to its topic registry and keeps a copy in its own journal, so a rebuilt machine learns every name from any survivor.
- Ordering: a rename beats a name held from before the update, which beats a creation name; then Telegram's own time and message order. A late rename notice or a message quoting the topic's original name never undoes a newer rename. A name held from before only fills a blank on another machine; the lead's ones rank above the standbys'.
- Session binds keep the replicated name; the session label follows a rename on standbys too.
- Unsent names are retried while the server runs (paced batches under the journal's rate cap), not only at restart.
- On wherever the coherence journal runs. Off switch: `multiMachine.stateSync.telegramTopicNames.enabled: false` (read at boot). A machine on an older build ignores these records.

SEC-132. The six calls `BusinessApiBackend` makes to Meta's Graph API (the token check in `connect()`, text, template and interactive sends, read receipts and reactions) had no timeout, so a stalled connection could leave a send hanging forever and back up replies behind it. Each call now passes `signal: AbortSignal.timeout(15000)`. A call that times out rejects like a network error, so the existing failure and retry handling applies.

## What to Tell Your User

- **Secret names stay private**: "My Bitwarden yes-or-no page now says how many secrets it would copy. To see their names first, type your PIN and tap Show their names."

- **Safer reminder notes**: "A small note my stop check leaves for itself now stays in my own folder instead of the shared temporary folder."

- **Slow restarts are no longer cut short**: "When my server had been running fine for a while and then needed a restart, I was only giving the restarted copy about a minute to start up, so a slow start got killed and retried over and over. It now gets its normal ten minutes, and I still give up on a copy that never starts."

If your agent runs on more than one computer: conversation names and renames now show correctly on every computer, and they are no longer lost when the main computer goes down. Nothing to do.

- **Steadier WhatsApp**: "If WhatsApp's servers stop answering, I now give up after 15 seconds instead of getting stuck: a message goes back in my queue to send again, and a read tick or reaction is just skipped."
