## What Changed

- Alerts now name the conversation and the machine they are about, instead of their internal numbers. "Topic 28730's pin has waited…" becomes 'Topic "Release notes"'s pin has waited…', and "Machine m_cc2e… is flapping" becomes "Mac Mini is flapping". This is applied where every alert is created, so all alerts get it. An open alert whose wording only changes this way is not sent again.

- On a phone, the session message box now stays just above the dashboard's bottom bar, including inside the Instar iPhone app, whose own tab bar used to push the box underneath. A sideways-scroll rule had also stopped the box from staying pinned; that is fixed.
- The dashboard menus no longer show tiles that only say where their content moved ("Now inside Plans" and similar). Old links to those pages still open the page they moved into. The Send content tile is gone; attach files from the session's own message box.

- A voice note sent from the Instar iPhone app into a native app conversation without a phone-made transcript is now transcribed on the server, with the same code and provider Telegram voice messages use (`GROQ_API_KEY`, else `OPENAI_API_KEY`, or the Telegram config's `voiceProvider`). The session receives `[voice:<path>] <transcript>`, the same form as before, now with a real transcript (docs/specs/mobile-native-chat-media.md §4.5.1, increment 2).
- With no provider configured, when the provider fails, or when it takes longer than 60 seconds, the message still arrives with the file path and an honest note: `[voice:<path>] (transcription unavailable: <reason>; the audio file is at that path)`. It used to say only `(no transcript)`.
- The Telegram transcriber moved into a shared module, `src/core/VoiceTranscription.ts`. Telegram voice messages behave exactly as before.
- A phone transcript, when present, is still used as is; the server does not transcribe that note again.
- CLAUDE.md (new and existing agents): the App conversation media section says voice notes are transcribed here and what the unavailable note means. Existing agents get the one sentence refreshed in place.

- A message the agent sends while its server is restarting is now delivered after the restart. The restart placeholder answers "still starting up" and never sends anything, but the recovery check treated that answer as "may already be delivered", so those messages were never sent.

- When the dashboard reads lists from your other machines, a broken Cloudflare route no longer counts as working, and a read moves on to that machine's next route (for example Tailscale) instead of giving up. Only routes the existing safety check already allows are used, and requests that change something are never retried.

## What to Tell Your User

Alerts now say which conversation or machine they mean by name, not by number or code.

On your phone, the box for typing to a session is visible again at the bottom of the screen, including in the Instar app. The Work, Capacity and Settings menus are shorter: tiles that only pointed to another page are gone, and their old links still work.

Voice notes you send me from the Instar app now reach me as text even when your phone could not transcribe them, as long as a transcription key is set up (the same one Telegram voice messages use). If there is no key, or the transcription fails, I still get the recording and can tell you that I could not read it.

Messages I send you while I'm restarting (for example during an update) now arrive once I'm back, instead of quietly going missing.

The dashboard should say "part of the list could not be checked" much less often: when one way of reaching a machine is down, it now tries the other ways.

## Evidence

- A live agent had open alerts titled "Topic 28730's pin has waited 2892h unfulfilled", "Machine m_cc2ec651… is flapping" and "Conversation telegram:61449 keeps re-duplicating". Unit tests cover naming each shape, leaving unknown ids alone, and an existing alert being renamed without a second post.

- Reproduced on the live dashboard at 390×844 and 390×640 with a simulated 68px app tab bar: the bottom bar covered the message box at every scroll position.
- After the fix, on the preview: the box sits directly above the bottom bar in all 12 checked cases (two heights, with and without the tab bar, scrolled top/middle/bottom), and the page still does not scroll sideways.

- Unit tests: provider choice (explicit, Groq before OpenAI, a missing explicit key never swapped for another vendor), the request shape (file media type, model), and each dispatch outcome on real stored blobs: transcribed, phone transcript kept with no server call, no provider, provider failure, past the deadline, nothing wired.
- Integration test through the HTTP pipeline: an AgentServer with a provider key and no Telegram; a voice note sent from a paired phone without a transcript reaches the session as `[voice:<path>] bring the blue folder` (the provider got the M4A as `audio/mp4`); a failing provider still delivers the path with the unavailable note.
- E2E (feature is alive, no provider): a voice note without a phone transcript arrives with the unavailable note and a readable file.
- Migration test: the CLAUDE.md voice sentence is refreshed once in an installed section.

- Reproduced on a live agent: three messages sent during a server restart were stored with the placeholder's exact answer and were then marked "may already be delivered" and never sent.
- Unit tests cover the placeholder answer (replayed), a different 503 answer, a lookalike body with an extra field, and the placeholder body with a different status code (all three kept uncertain).

- On a live agent, one machine's Cloudflare route answered "could not reach" (HTTP 530) on every read while its private Tailscale route worked, and the broken route kept being chosen. Unit tests cover the fallthrough, the credential guard on fallback routes, no retry for non-read requests or timeouts, and unchanged behaviour when no other route is known.
