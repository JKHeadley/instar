## What Changed

`scripts/doorway-scan.mjs` now runs a real scan. Its `main()` used to print a
"ships DARK" note and exit 0, so the job and its canaries reported success while
no scan-state file existed and `GET /doorways` said `never-run`. It now probes
each door, writes `.instar/state/doorway-scan.json`, and delivers a change only
through a confirmed attention item. The job script reports `ok` only when that
file exists and this run stamped it. A new `scan-state-missing` canary proves
that check can fail. A fatal prober error now exits 1 instead of 0, and a
stored `reachable: null` stays unknown instead of turning into `false`.

## What to Tell Your User

The weekly doorway check now really runs. Before, it reported success without
checking anything. If a way of reaching a model stops working, you hear about it
once, in plain words. It costs nothing to run, and it stays off unless switched
on.

## Summary of New Capabilities

- The doorway-scan job writes real scan-state, so `GET /doorways` can report `scanned`.
- A doorway-scan run with no fresh state file counts as failed, and a daily canary proves it.

## Evidence

`tests/unit/doorway-scan-run.test.ts` runs the real script against a real PATH
and reads the result through the `GET /doorways` reader. Before the change the
script wrote no file; after it the reader reports `scanned` with one door
answering and one not installed. The live run on Echo is recorded in the PR.
