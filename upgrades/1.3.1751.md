## What Changed

- **The sign-in repair result shows one line per machine.** After "Turn on automatic sign-in repair" (or "Switch back to asking first"), the result sheet showed every machine's answer run together in one paragraph: each answer was an inline `.row-sub` span, which is only a block inside `.row`. It now shows a one-line summary ("Done.", "Done on some machines." or "Not done.") and a list with one line per machine: a ✓ or ✗, the machine's name, and what happened.
- **The Pair page lists phones and browsers in separate sections.** `/dashboard/pair` and the legacy Phones tab now show "Paired phones" and, below it, "Paired browsers", instead of listing browsers under "Paired phones". Each row is the device's name plus one short detail line ("Paired since Sep 30, 2026", "Last used on this machine Nov 11, 2026, 2:00 AM", "Not used yet", "Waiting to confirm"). The repeated "Paired · Browser ·" text is gone. The remove control is a short "Remove" button that stays on one line, with an accessible label naming the device. The legacy tile reads "Paired devices", because it counts both kinds.
- **A short dashboard UI quality standard** (`docs/specs/dashboard-ui-quality-standard.md`): one item per line, group by kind and say the kind once, a name plus one short detail per row, buttons never wrap, no sideways scroll at 390px, and checking at 390px and 1280px before shipping.

## What to Tell Your User

The dashboard screens you flagged are cleaned up. The automatic sign-in repair result now shows one line per machine. The Pair page has separate sections for phones and browsers, each row is just the name and one short detail, and the Remove button stays on one line on a phone.

## Summary of New Capabilities

- None. This is a layout fix to two existing screens, plus a written UI standard for dashboard screens.

## Evidence

- `tests/unit/dashboard-phones-browser.test.ts`: `pairedGroups` (both copies) splits phones from browsers with one detail line each and no repeated kind tag. The legacy panel renders "Paired phones", then the phone row, then "Paired browsers", then the browser row, and its `Remove` button (aria-label names the device) revokes the right device.
- `tests/unit/dashboard-pair-page.test.ts`: the Pair page row has a name "Old phone", the detail "Paired", and a `Remove` button labelled "Remove Old phone".
- `tests/unit/console-auto-repair-model.test.ts`: `resultLines` gives one line per machine in server order, with its name (or "A machine") and outcome.
- Loaded in Chromium with realistic data at 390px and 1280px wide, light and dark: the Pair page, the legacy Phones tab, and the result sheet built with the same code as `autoRepairTap`. No horizontal scroll (`scrollWidth === innerWidth`), and every Remove button is 44px tall (one line).
