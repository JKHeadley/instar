## What Changed

New App conversations record whether a person, a session or a Work Board card created them, together with an optional parent. Owner conversation lists expose verified hierarchy while keeping unresolved generated chats available. Existing explicit placement choices take priority, and unreadable parents are not disclosed.

The owner-only `GET /mobile/conversations/parent-preview` provides a read-only proposal for existing chats. It does not move, rename or delete them. Older machines can omit creation metadata; this is reported as unknown or unplaced, with no promise of recovery while the creator is offline.

## What to Tell Your User

- New agent-created chats can be grouped with their verified parent. Existing chats can be previewed before any placement change. The native app release and its verified behavior are reported separately from this server update.

## Summary of New Capabilities

| Capability | How To Use |
|-----------|-----------|
| Recorded App chat origin | Creation paths record the source automatically; session creation accepts optional `parentConversationKey` |
| Safe hierarchy metadata | Owner list rows expose `creationSource` and `hierarchyState` without changing access |
| Existing-chat placement preview | Read `/mobile/conversations/parent-preview`; `dryRun:true` and `canApply:false` prohibit applying it |
