## What Changed

The feedback executor's rework path now passes the previous independent-review findings to the next attempt even when an attempt in between stopped before publishing. `writePreviousReview` used to read only the immediately previous attempt, so a rework that stopped on reroute capacity, a lost lease or a restart made the following attempt start without the findings. It now reads the latest earlier attempt that published a PR; the rest of the rule (that attempt must be closed as `review-failed-closed` with stored findings) is unchanged.

Besides testing each change, the coordinator machine tests the main branch itself. That main test waits in the same line as the changes and, while main is healthy, lets changes go first for up to 90 minutes. Until now it then ran on the version of main it had been queued for, which by that time main had usually left. A pass on an out-of-date version does not cover the newer merges, so a second main test was due at once (2026-11-16: twice in one day, about 80 minutes of back-to-back main tests each time while eight changes waited).

- When a queued main test starts and main is healthy, it now runs on main's version as observed at that moment (through the release-commit alias, so a release commit of an already covered version starts nothing new). The log records `main-replaced` with `why: stale-at-start`.
- Unchanged: while main is suspect or red, the queued version (the re-run of a failed version) runs as queued. If main's version cannot be read, the queued version runs.
- The newer version's own delayed enqueue is marked handled, so it is not queued a second time.

Conversations → Review suggestions no longer reloads itself every 30 seconds. The console's periodic page refresh re-ran the Conversations page, which cancelled an Accept or "Accept all projects" mid-way and redrew the same list, so a tap looked like it did nothing. The suggestions view now refreshes only on its own Refresh button, and a running Accept holds any page refresh until it finishes. When an Accept stops (the PIN unlock lapsed, or another machine has not confirmed a step yet), the card says why and offers Continue.

## What to Tell Your User

When an automatic fix is turned down by its safety review, the next try now always starts from the reviewers' notes, even if a try in between never got going.

Nothing changes for people who run one machine without the test line. If your agent tests its own changes, the periodic test of the main branch now always covers the newest version in one run, instead of testing an old version and then starting over, so changes waiting to be tested get the machine back sooner.

- "The suggested-projects page stays put now: it won't reload under you, and Accept all runs through. If it has to pause, it tells you why and you can tap Continue."

## Summary of New Capabilities

None. This is a fix to the existing feedback executor.

- No new routes or settings. One scheduling decision corrected.

- Review suggestions stays still while you work on it, and Accept / Accept all are no longer cancelled by the page refresh.
