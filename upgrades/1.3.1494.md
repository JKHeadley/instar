## What Changed

The scheduled decision-grading script can now receive a narrow independent
outcome grade. The server checks the quality ledger before and after the grade
pass in one SQLite writer transaction. It grants an idle proof only when all
six grading points have zero decision rows, the cursor boundaries stay unchanged, and
the pass reports no grades. The proof is stored separately from the ordinary
receipt that Jev sees. After a routine verdict, the worker links that proof
to the model call as a correct outcome. Every other case remains unknown.
The Jev rollout gates remain off.

The decision-quality read view now includes a separate, read-only section for
scheduled script-result supervision. It reads direct Jev and outage-replacement
call records from the durable job-supervision journal and checks their coverage
against independent job-run history. The section shows provider/model, prompt
hash, verdict, cost, and later independent grade for each call, with missing
records and unknown grades visible. Pool reads strip peer data to a small
allowlist. These direct calls are not counted as IntelligenceRouter decisions.
Jev result decisions remain off.

The next release starts at 1.3.1494 because npm accepted 1.3.1493 as a
staged publish but did not make it available for installation. Later publish
runs received a 409 conflict when they tried to reuse 1.3.1493. This version
bump lets the already merged job-supervision audit and grading changes ship.

- An agent-local exclusive lock spans directory counting and Git worktree creation. A crash-left lock fails closed for inspection.
- A symlinked `.worktrees` folder is refused before chmod or lock acquisition.
- The reaper checks ignored files and exempts no untracked or ignored path. Its existing repository selection and enable/dry-run settings are unchanged.

## What to Tell Your User

We can now verify one simple result independently: the grading job had nothing
to grade and ran without changing its cursor. This will help measure Jev when
the guarded trial starts. Results with any grading history still need stronger
outcome checks, so Jev is not live yet.

The audit view can now show each Jev check of a scheduled script result, its
cost, and whether later evidence showed it was right. Missing records are
visible instead of making the accuracy number look better. This prepares the
quality review; it does not switch on Jev decisions yet.

The release pipeline got stuck on an unavailable npm version. The next
published release skips that number and includes the merged changes.

New CLI worktrees stop at a bounded physical count. Existing work and unique ignored files are preserved for review or verified archival cleanup.

## Summary of New Capabilities

- Scheduled grading passes with a truly empty quality ledger can record a
  separate idle effect proof.
- The job-supervision worker links that proof to a later routine verdict as
  one independently graded model outcome.

- Read `directJobSupervision` from `/decision-quality` for a local call audit.
- Use `?scope=pool` to see which machines supplied that audit and which did not.

- Release publication can proceed past the unavailable 1.3.1493 version.

`instar worktree create` stops at 500 child directories per agent and serializes concurrent creation calls. The reaper now keeps checkouts containing ignored files, including cache folders that may contain unique work.
