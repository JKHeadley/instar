## What Changed

The dangerous-command guard matched only exact phrases, so a destructive git command with a flag in the middle, or with `git -C <path>`, got past it. It now also catches those forms for the hard reset, clean and force-push checks. A push with `--force-with-lease` to your own branch is still allowed.

Registered Google sign-in browser profiles now refuse Playwright activation, debugging-protocol launches and unsafe browser MCP configuration. Native Claude and Codex tool hooks also refuse ordinary automated access to these profiles. Normal Chrome sign-in repair remains available; tests should use disposable profiles.

Every console line that marks something as a warning now declares how the person acts on it, and `tests/unit/console-warning-paths.test.ts` fails a new warning that doesn't. Warning page headlines get "Ask the agent about this". `GET /mobile/health-issues` no longer uses a reporter's raw text as a title, and iMessage follows its present state instead of the 30-minute event window, with Remote Desktop as its action.

## What to Tell Your User

Nothing changes for you. A safety check now catches more spellings of the same dangerous git commands.

Testing tools are now kept away from the saved Google browser logins used for subscription repair. A failed repair is checked before asking you to act.

Every warning on the dashboard now has somewhere to go, at least a way to ask me about it. If iMessage is down it stays listed until it's fixed, and the screen says what fixes it. If you don't use iMessage, ask me and I'll turn it off.

## Summary of New Capabilities

No new capability. The guard covers flags and global options placed between `git`, the verb and the destructive flag, on new and existing agents.

Code enforcement for saved sign-in profile safety, including existing-agent hook updates and browser startup checks.

`askLink` and `pageHead`'s built-in ask link in the console, and a checked floor for new warnings. New action screen `desktop` on the health answer.

## Evidence

Unit boundary tests, HTTP activation integration test, and migration-to-hook execution lifecycle tests. Incident review confirmed an unsafe Playwright launch; it did not establish historical sign-out causation or a completed repair.
