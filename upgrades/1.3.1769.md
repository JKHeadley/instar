## What Changed

- **The Chief of Staff note is readable.** Projects that look finished are grouped under one headline with the count ("4 projects look finished and need your OK"). Each gets a short block: a short name (the initiative title or conversation name, else the goal's lead, never cut mid-word), how many automatic checks passed, the judgment item(s) it waits on quoted from its done list, and a link to that project. The repeated "every automatic check passes. Confirm it's done?" line is gone.
- **Buttons name their project.** Blocks are numbered and each button reads "Done: <n> · <project>" (and "Unpark: <project>") instead of four identical "Confirm done" buttons. The button ids are unchanged. In the owner's private chat, three or more buttons now get one row each; a two-button pair (Approve / Decline) keeps its single row.
- **Links open on a phone.** The note links to the console's Chief of Staff page through the public tunnel (`/dashboard/console/#/work/chats`, and `?c=<conversation>` per project). With no public link, the note carries no link instead of a localhost one.
- **Footers name the machine.** A machine with no pool nickname now shows its own name (from pairing or its identity) in message footers instead of "Machine m_xxxxxx"; the raw id appears only when the machine has no name at all.

- **The dashboard card matches.** The Chief of Staff rows on the dashboard use the same short project names (no more 80-character mid-word cuts), and each opens that project's conversation. `GET /chief-of-staff` gains a `title` per project.

When the agent refuses a file because files in app conversations are turned off, the refusal now carries an action: `{kind: "team-switch-on", setting: "files", label: "Turn on files", method: "POST", path: "/mobile/team/switches/turn-on", configPath: "mobilePairing.native.media.enabled"}`. The owner-only, Face ID-proven switch that turns team settings on for the whole agent accepts a third setting, `files`. It sets `mobilePairing.native.media.enabled` (with pairing and native conversations) on every machine and restarts each machine that changed. Telegram and Slack sends with files now say "Files are turned off on this agent." when that is the reason, instead of "not available yet", and carry the same action. The `/app/session-reply` files refusal also tells the agent how to turn files on. (fb-9b920619-b1a)

A reply forwarded from another machine and delivered by the lease holder is now recorded in the holder's own topic history (`OriginMesh` submit → `runtime.options.onForwardedDelivered` → `TelegramAdapter.recordRecoveredOutbound`). Before, only the sending machine recorded it, and only when the forward answered cleanly. When the sender got "acceptance unknown", no machine recorded the reply at all.

That gap caused a real stall in topic 141868 on 2026-11-11. A progress note ("round 6 running, report to follow") was held on the M5 at 19:35 UTC while the Studio was unreachable. At 19:41:37 the session's next message, a decision question, was delivered (Telegram 141952), but the M5 got "acceptance unknown" back, so neither machine wrote it to history. The held note's overtaken check (`reviewQueuedReplyHistory`) reads local and pooled history only. It found nothing newer and released the stale note six seconds later (141953), right below the question. The operator waited for the promised report while the session waited for his answer, for 2 h 43 min.

With the holder's row in place, the pooled read the overtaken check already does finds the newer question and retires the stale note. The Studio's own topic history also stops missing replies sent from peer machines, so overseers and anything else reading one machine's history no longer see a silent topic. The pooled history read already dedupes by direction + Telegram message id, so a reply recorded on both machines shows once.

The "Scheduled job ... is not running" warning no longer fires for jobs whose start check simply answers "nothing to do" (polling jobs with an empty inbox). A real warning now says why in plain words and links to the job's page in the dashboard (runs, skips, Run now), and waits for the public link rather than send without one. Sending from the Instar app into a Telegram topic now uses the agent's one verified operator when no owner is configured, instead of refusing with "This agent has no Telegram owner to speak as."

- **Pairing invites say who may approve.** When an agent cannot approve a forwarded pairing invite, it now says it can't tell who is allowed to approve new connections for it (or that only that person can), instead of talking about an "owner" that could be confused with the other agent's claimed owner. It never names anyone.
- **No "✓ Delivered" after a turned-away invite.** If a forwarded invite is refused, unusable, or pairing by invite is off, the server now tells the Telegram listener it was refused, so the misleading "✓ Delivered" tick no longer follows. A valid invite waiting for Approve or Decline is still acknowledged; nothing is paired until Approve is tapped.
- The missing tick needs your agent's Telegram listener to be on a current version; if it was already running an older one, it keeps the old tick until its next normal restart. If an invite was accepted but its Approve prompt could not be sent, no tick is shown either; that is not a decline. The accepted invite may remain pending until it expires; it must not be resent automatically.
- Who may approve, and how pairing works, is unchanged. Setting up an approver and resuming a waiting invite are still separate, tracked work and are not part of this update.

Pairing messages that send the owner to the dashboard now carry a direct link (Echo Bugs topic 10000002573; Instar feedback fb-300d9f7d-6d3, fb-9566b1d3-f4d).

- **The refusal for a pasted invite** (for example, an agent with no owner set) links straight to the console's Other agents page with "Connect another agent" open and the paste box focused: `…/dashboard/console/#/people/agents?connect=paste`. The invite itself is never put in the link.
- **The link uses the agent's real address** through the shared operator-link resolver: the tunnel when up; the local address only with no tunnel, said plainly ("opens only on the computer it runs on"); and, while a tunnel is still starting, no link with a plain reason.
- **Refused or expired button taps:** a toast cannot hold a link, so the link is posted once per invite (every 10 minutes at most) in the invite's topic, and the toast points at it.
- **The Finish prompt with Telegram approval off, the "finishing by myself" notice, and the Telegram adapter's fallback reply** use the same linked sentence. The shared core notice text takes an optional host line and is unchanged without it.
- **Someone known not to be the approver** (another member of a group chat) gets no dashboard address: the reply says the person who approves new connections can do it on the dashboard. The adapter's no-handler tap toast names the Other agents page instead of the old Threadline tab.
- **Agent instructions:** the "Connect with another agent" section of CLAUDE.md gains one line: every dashboard pointer in pairing is a direct link (`GET /tunnel` + `/dashboard/console/#/people/agents`, `?connect=paste` for pasting), never the invite in a link. `PostUpdateMigrator` adds the line to existing agents that already have the section (content-sniffed, idempotent).
- Builds on PR #3087 (refused-invite receipts and approver wording), which is unchanged.

A Slack mention an agent writes as `<@USERID>` is now sent as a real tag when that person is in the conversation: a member of the channel or direct message, or someone who posted in the thread, and an active person rather than a bot. No flag is needed. Mentions of anyone else, bots, `@channel`/`@here`/`@everyone`, and anything inside code still go out as plain text, as before. The `--native-reference ID` flag still activates a deliberate mention outside these rules. If Slack cannot confirm membership (missing permission, error, or more than 2.5 seconds), the mention stays plain text and the message still sends. Agents get a short CLAUDE.md section about this, added on update for existing agents, and the Slack session start-up line now describes the default.

## What to Tell Your User

My daily Chief of Staff note is now much easier to read: each finished-looking project gets its own short block saying what passed and what I need you to judge, with a link you can open on your phone, and each button says which project it confirms.

If the app says files are turned off, there is now a "Turn on files" button right under the refused message. One Face ID tap turns files on for the whole agent, and the app sends the files again once the agent is back.

When a conversation is served from one of your other machines, its replies now show up in the main machine's message history too. This also stops an old "I'll report soon" note from popping up under a newer question after a brief network hiccup.

You'll stop getting "this job isn't running" warnings for jobs that are fine and just had nothing to do. When one of those warnings is real, it now says what's wrong and has a link straight to the job. And if messages from the app to a Telegram conversation used to fail with "no Telegram owner", they go through now.

If I can't accept a pairing invite you forward, I'll now say plainly that it's about who may approve connections for me, and you won't see a "Delivered" tick that makes it look like it went through. You can still approve it from the Threadline tab on the dashboard with your PIN.

When I can't take a pairing invite from Telegram, I now give you a link that opens the right dashboard page with the paste box ready. If I have no address your phone can open, I tell you that plainly.

When I mention someone who is in our Slack conversation, Slack now tags them properly instead of showing a raw code. I still cannot ping the whole channel, and I will not tag people who are not part of the conversation unless I mean to.

## Summary of New Capabilities

- Grouped "looks finished" blocks in the Chief of Staff note, with per-project buttons and phone links.
- Machine names instead of raw machine ids in message footers.

| Capability | How to Use |
|-----------|-----------|
| Turn on files from the app | Tap "Turn on files" under a refused file (owner phone, Face ID); `POST /mobile/team/switches/turn-on {setting: "files"}` |

- The lease holder records every peer reply it delivers in its own topic history (history only, never a send).

- Job warnings carry a direct link to the job's dashboard page.
- App-to-Telegram messages work on agents set up without an owner setting, as long as one operator is verified.

- None new. Clearer refusal wording and an accurate delivery tick for forwarded pairing invites.

- Direct dashboard links in every pairing "use the dashboard" message.
- `#/people/agents?connect=paste` opens the console's invite paste box.

| Capability | How to Use |
|---|---|
| Slack person mentions | Write `<@USERID>` in a Slack reply. People in the conversation are tagged automatically; others stay plain text. |
