## What Changed

- **A restart no longer locks a scheduled script onto its session fallback.** When the server stopped while a script job was running, that run stayed "running" in the records forever, and the next start's record check held the job permanently, so it went back to starting an AI session every time. Now, at the next start, such a run is recorded as failed with the reason `interrupted: the server stopped before this script finished`, both record books agree, and the job keeps its script. Real disagreements between the run history and the supervision record still hold the job.
- **Holds can be lifted, and every lift is recorded.** A hold written by the restart check is lifted by that same check once it finds nothing wrong for the job. Any hold can be released with `POST /jobs/SLUG/supervision-hold/release` and a written reason; it is refused while a run still disagrees. `GET /jobs/SLUG/supervision-hold` shows the hold and its release history. Releases are kept in a new `held_slug_releases` table in the supervision ledger; nothing is deleted silently.

## What to Tell Your User

If one of my scheduled checks got stuck running the expensive way after a restart, it goes back to its cheap version on its own after this update. A restart in the middle of a check now just counts as one failed run.

## Summary of New Capabilities

- Interrupted script runs are settled as failed at the next start instead of holding the job.
- `GET /jobs/:slug/supervision-hold` and `POST /jobs/:slug/supervision-hold/release` (reason required, audited, refused while the cause persists).

## Evidence

- `tests/unit/job-cost-runner/JobScheduler-interrupted-script-run.test.ts`: an interrupted run (registered or not) is settled and the next fire runs as a script with no session; a pre-fix census hold is released with an audit row; a real result disagreement keeps its hold and refuses release; another machine's pending run is left alone; a non-census hold is never auto-released.
- `tests/unit/job-supervision-store-interrupted-and-release.test.ts`: store settle/insert/no-touch rules, audited release, the release table added to an existing ledger.
- `tests/integration/job-supervision-hold-routes.test.ts` and `tests/e2e/job-supervision-interrupted-run-lifecycle.test.ts`: the real server answers auth, validation, 404, 409 and 200; after a restart the shipped health-check job reports runner `script` in `GET /jobs`.
