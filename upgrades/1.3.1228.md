## What Changed

Window 32's run-liveness gate now recognizes the normal production Telegram
topology where a separate lifeline owns polling and the main server adapter is
intentionally send-only. The gate consumes the existing fresh, token-matched
poll-owner lease; missing, stale, future-dated, corrupt, or mismatched leases remain non-green.

## What to Tell Your User

Autonomous liveness checks no longer mistake the healthy Telegram lifeline for
an outage just because the main server is running in send-only mode.

## Summary of New Capabilities

- W32 can verify Telegram reachability through either the server poller or the
  established lifeline-owned poller.
- Lifeline reachability requires a token-matched lease whose age is inside the
  closed 0–90-second interval, rather than a configuration label or process file.

## Evidence

The booted AgentServer lifecycle test now uses the production shape: an
unstarted send-only adapter plus a fresh lifeline poll lease. Before the fix,
the first active projection stayed non-green and the test failed; after the
fix, all five predicates pass. A second production-path assertion rejects a
future-dated lease, while unit coverage also pins stale, invalid-time, missing,
corrupt, and wrong-token evidence.
