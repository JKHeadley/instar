## What Changed

- **Reading another machine's session no longer needs a shared API token.** Machines of one agent that were joined with different tokens could not read each other's session transcripts or pool history ("token refused"), and the credential URL guard refused others ("peer URL refused"), F4 in `docs/specs/native-conversation-any-machine-access.md`. A new signed mesh verb, `session-transcript-pull`, serves one page of a session's record (or the machine's own session list), and `topic-history-pull` gains a `shape: 'pool'` with whole rows, `before` / `beforeMessageId`, up to 100 rows and a 512 KiB cap. `GET /sessions/NAME/transcript?machineId=`, `GET /sessions?scope=pool` and `GET /telegram/topics/N/messages?scope=pool` ask over the signed verb first and say how each machine was read (`via`).
- **The bearer hop is a narrow fallback.** It is used only when a machine says definitely that it cannot serve that kind of read: `no-handler`, `claim-unauthorized` from a machine whose version advert is absent or older than this release, or a history answer without the `shape: 'pool'` echo. A timeout never falls back to sending the token; the machine is listed in `asleepOrUnreachable` with its name and last-seen time. What each machine has answered in signed form is remembered per machine, per kind of read and per version: `GET /pool/signed-reads` (`signedCapable`, `bearerFallbackNeededBy`, counts).
- **Nothing is cut silently.** Each transcript entry carries `index` (its place within its record) and `clipped: true` when the 4,000-character cut applied; `full=1` returns it whole. A page that stops inside one record continues with `nextBeforeIndex`. A row larger than the cap comes cut on a character boundary with `rowTruncated: { row, totalBytes, from, to }`, read on with `rowOffset` / `rowIndex` / `byteFrom` (history: `row` + `byteFrom`). The machine's own API token and dashboard PIN are removed before any clip or cut.
- **Who may read a transcript.** The owner only, and only where the owner may see every conversation the session served, resolved at read time from this machine's team record. While the team log has a gap or the team puller is refusing, the read is refused ("This machine cannot confirm who may see this session right now."). A session of someone else's private conversation is refused ("This session serves a conversation that is private to someone else."). Phones, members and guests never read a transcript; no device route is added. On an agent with a team, an older machine's answer (no conversation list) is refused.
- **CLAUDE.md** gains "Reading another machine's sessions (signed pool reads)" for new and existing agents.

- **Session transcripts can be copied to every machine (switched off for now).** Slice 3f of `docs/specs/native-conversation-any-machine-access.md`, built so a machine that is asleep no longer takes the session behind a conversation away. With `multiMachine.stateSync.sessionTranscripts.enabled` on, the machine that ran a session copies new transcript rows as they are written (on the token-ledger poller's 60-second cadence, and at session end) as **checkpoints of whole redacted rows**, carried by the replicated journal under a new kind, `session-transcript-checkpoint`, and landed on every other machine in a copy store of its own (`.instar/state/transcript-checkpoints/`, git-ignored, outside backups).
- **Whole rows, redacted on the source.** The source removes its own API token and dashboard PIN from each row before a checkpoint leaves it; a row with a secret is redacted inside its parsed JSON, so a short numeric PIN inside another number cannot break the row. Only a trailing row that is not complete yet is held back between reads. Offsets, byte counts and `sha256` describe the redacted rows a replica holds and verifies; `sourceThroughOffset` is the source file offset of the end of the last whole row emitted, written in the same atomic write as its checkpoint (an outbox), so a crash at any point resumes with no gap and no repeat.
- **A manifest that states its coverage.** Each machine derives, per session, how far its copy reaches (`throughAt`, `complete`); a gap in the checkpoint sequence stops coverage at the gap and a checkpoint that does not verify is not assembled. A read never presents a partial copy as the whole transcript.
- **Reads.** `GET /sessions/NAME/transcript` answers from this machine's copy when the machine that ran the session does not answer (or is not recorded here): `via: "copy"` with `copy: { throughAt, complete, sourceAwake, sentence }`, for example "Copied through 14:02; the machine that ran it is asleep; later rows are not here yet." `GET /transcript-copies` lists what each copy reaches, with no transcript text.
- **Audience.** Owner and agent only, resolved at read time on the reading machine from its own signed team record over the union of the conversations every held checkpoint names (most restrictive wins), with the same refusals as the live read, the currency refusal included. No device or team route reads the store.
- **Bounds.** A row larger than 3 MB is copied as a marker naming its size (`withheldRows`); at most 256 MB of source rows per machine per day (`bytesPerDay`); the journal keeps two 32 MB archives of the kind (each machine has already landed what it pulled). The applier accepts a checkpoint only from the machine that ran the session.
- **Maturation.** Dark on every agent (a `DARK_GATE_EXCLUSIONS` entry) with a sensitive ladder entry, `multiMachine.stateSync.sessionTranscripts`, until its live date (CMT-047, 2026-12-02). Turning it on also needs the coherence journal's replication on.
- **CLAUDE.md** gains "Transcript copies on every machine" for new and existing agents.

## What to Tell Your User

I can now read any of my sessions and conversation history on any of my machines, even when those machines were set up with different keys. If a machine is asleep, I say which one and when it was last seen instead of saying there is no history. A session's working record is shown only to you, and never for a conversation that is private to someone else.

Nothing changes yet: this is switched off. When it is turned on, I will be able to read the full working record of a session even while the machine that ran it is asleep, and I will always say how far my copy reaches. Only you can see a session's record, and never for a conversation that is private to someone else.

## Summary of New Capabilities

- `session-transcript-pull` mesh verb (transcript and list modes); `topic-history-pull` `shape: 'pool'`.
- Signed-first pool reads on the transcript, session-list and topic-history routes, with `via` and `asleepOrUnreachable`.
- `GET /pool/signed-reads`: per-machine, per-kind signed capability and the bearer fallback still needed.
- Transcript paging by offset plus entry index, `clipped` marks, `full`, and the oversized-row continuation.

- Transcript checkpoint replication (dark): `multiMachine.stateSync.sessionTranscripts`.
- `GET /sessions/NAME/transcript` answers from a copy with stated coverage (`via: "copy"`).
- `GET /transcript-copies`: what each copy reaches, per session.
