## What Changed

New dev-gated server service (`docs/specs/ecosystem-idea-pipeline.md`). Each week it reviews a
watchlist of similar projects: trusted code fetches and reads, and AI services return closed-schema
judgments. Each idea is checked against our source and specs by two blind reads, reviewed against the
Instar 2.0 purpose, classed by what it would change, and ranked into bands. The default outcome is no
change. A framework reads outside text only after two must-fail file-read probes through the same call
path real reviews use; to pass them, `IntelligenceOptions.noLocalTools` and
`reviewerHardening.noTools` ask Codex and Claude for calls with no local tools. The default path of every
other caller is unchanged. `scripts/lint-ecosystem-adoption.mjs` joins the lint chain: it fails a default
change for a tagged spec unless `docs/proofs/<idea>.json` passes, and no spec is tagged yet.

⚗️ Experimental, development agents only: copying runs wherever native app conversations are on (`mobilePairing.native.enabled`, dark on the fleet), even with `mobilePairing.native.media.enabled` off, so switching media off never strands a copy (as the spec requires); the media flag gates only the phone's media routes. Files sent in app conversations now reach every one of the agent's machines. Each machine copies every file that a message it holds refers to, over the existing signed machine-to-machine channel (a new `app-media-pull` verb), at most 1 MiB at a time, and keeps a copy only when its length and SHA-256 match the message. Copying runs in the background at a bounded pace (at most 8 slices every 5 seconds), pauses below the free-disk floor and, for at most an hour at a time, while the machine reports itself overloaded. A partial copy comes from one machine only (so a damaged copy is blamed on the machine that sent it), and a machine re-checks a file whose size or time changed before serving it, setting a damaged one aside. Brakes: a file no machine can provide is retried with a growing wait (30 seconds up to an hour) and given up after 7 days with one notice; a machine whose copies keep failing verification is skipped for 15 minutes, and for the rest of the day after the third time, with one notice. Each machine lists the files it holds every hour; `singleCopyBlobs` counts files only this machine holds, and a file left on one machine raises one notice after the other machines were asked to copy it and still have not. A download of a file still copying answers `202 fetching` when a copy can actually start, and otherwise `404` with the reason (no connection to the other machines, the disk floor, no reachable machine holding it, or given up); a message whose file has not reached the delivering machine within 60 seconds is delivered with `[file still copying: <name>]`, followed by one `[file now available: <path>]` line when it lands. `GET /health?scope=pool` shows every machine's `appMedia`.

- `GET /mobile/conversations` pages app conversations and Telegram topics on one cursor, so no conversation is cut from the list and left unreachable when there are many Telegram topics.
- `GET /mobile/conversations` and `GET /mobile/chat/app/:key/messages` accept `?scope=pool`: every machine's rows merged, a machine that did not answer listed in `pool.failed`, and a row only another machine holds marked "couldn't check here".
- With native app conversations on, a message sent from the app into a Telegram topic is no longer refused for a pairing invite, a desktop code or password-like text: the invite or code is removed and the rest delivered, password-like text is delivered with a `credentialShaped` signal, and the 📱 copy posted in the topic hides it.
- App history rows say how the signing phone was approved (`originApprovedVia`: `telegram-dm` or `dashboard-pin`), so the app can show "approved on dashboard".

- A later loss of an autonomous run's liveness check now gets its own 15-minute at-risk window after an earlier recovery returned the run to active. The old recovery attempt remains spent; it never refreshes the executor twice.
- A run that never recovers from the first loss still fails on the original deadline.

## What to Tell Your User

If you develop your own project, I can check similar projects each week and show you ranked ideas, each
checked against your code. It only gives advice: it changes nothing and contacts nobody. It is off unless
you ask for it.

Nothing yet: this ships dark and needs the next iPhone app build. On a development agent with more than one machine, a file you send in the app is copied to my other machines, so any of them can open it.

If you use the Instar iPhone app with native conversations turned on: your conversation list now always shows every conversation, however many Telegram topics you have, and the app can show conversations from all your machines. A message you send from the app into a Telegram topic is no longer turned away because it contains an invite or something that looks like a password; the invite is removed, and the password-like text is sent as you wrote it (the app asks you first) but hidden in the copy posted to the Telegram topic.

A brief interruption after a previous recovered interruption will no longer stop an otherwise healthy autonomous run immediately. The run still pauses active work while any liveness check is red and fails if that interruption persists for 15 minutes.

## Summary of New Capabilities

- `GET /ecosystem-ideas`, `GET /ecosystem-ideas/:id/evidence`, and PIN-gated decisions through `POST /ecosystem-ideas/plan` and `/commit`.
- The console's Work group gains an Ideas page.

- Mesh verb `app-media-pull` (slice, inventory, nudge), registered-peer read class.
- `GET /mobile/media/:sha256?ref=` answers `202 {state: "fetching", retryAfterMs}` while a file is copied here.
- `GET /app/media-path/:attachmentId` pulls a missing file for up to 30 seconds and says plainly why when it cannot.
- Authenticated `/health` → `appMedia.singleCopyBlobs` and `unrecoverableBlobs` are measured (null when they cannot be); `?scope=pool` adds `appMediaPool`.

- `?scope=pool` on `GET /mobile/conversations` and `GET /mobile/chat/app/:key/messages`.
- `originApprovedVia` on app history, sync and the device's Telegram history read.

- Autonomous run liveness tracks each later interruption's observation deadline correctly while keeping one recovery actuation per run.
