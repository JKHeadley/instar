# W32 lifeline delivery reachability — plain-English overview

Echo receives Telegram messages through two cooperating processes. The lifeline process owns Telegram's one allowed long-poll connection, while the main server keeps a send-only Telegram adapter for replies and other server work. That is the normal production topology. Window 32's new run-liveness gate originally looked only at the main adapter's `started` flag. Because a send-only adapter is intentionally not started as a poller, the gate called Telegram unreachable even while the lifeline was actively receiving this conversation and the server was successfully replying.

The gate now accepts either of two concrete delivery signals: a healthy in-server poller, as before, or the existing fresh Telegram poll-owner lease written by the lifeline. A reachability-specific reader requires the lease to match the configured bot token by hash and have an age between zero and 90 seconds. Missing, malformed, stale, future-dated, or token-mismatched leases do not make the predicate green. This intentionally differs from the unchanged startup collision guard, whose original one-sided age check accepts matching future timestamps. The liveness authority still combines the reachability signal with the other four required facts—bound executor, fresh heartbeat, advancing durable work, and admitted/unexpired lifecycle—and remains the only component allowed to label the run active.

No new poller, message, timer, configuration key, or persistent schema is introduced. The same lease that structurally prevents two Telegram pollers from competing now also tells W32 that the deliberately split production topology is reachable, through stricter positive-evidence semantics. Unit tests cover fresh, stale, future, invalid-time, missing, corrupt, and mismatched cases; a wiring test pins the consumer; integration tests retain the five-predicate transition contract; and the booted AgentServer lifecycle test now runs with a send-only adapter plus a fresh lifeline lease and explicitly rejects future-dated evidence.
