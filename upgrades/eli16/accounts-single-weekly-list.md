# Accounts In One Reset-Ordered List

The Accounts page currently separates services into groups and puts heavier usage first. A pending wider-page change can also lay accounts out as several cards across the window. Justin asked for a calmer presentation: one list, with the account whose weekly allowance resets soonest at the top. That makes the order easier to follow and helps identify the weekly allowance that will renew next.

The repair makes one continuous column across all services. Each row says which service it belongs to, so a Claude or Codex account remains easy to identify without separate groups. The weekly reset controls the order. A five-hour limit remains visible with its own usage bar and reset time, but it does not move the account around. Accounts with an unknown or expired weekly reset come after accounts with a known future weekly reset. Equal times use the account name; a stable identifier resolves otherwise identical names without being shown as a label.

The page still uses its freshest account reading from the machines that answered. Machine chips, usage warnings, sign-in actions, partial-data explanations and the account detail sheet stay available. The list uses the available width, including when the wider dashboard change is installed, and stays in one column on a phone, laptop or wide window. Other dashboard pages keep their existing layout.

This changes presentation only. It does not choose which account a session runs on, alter quota measurements, sign into accounts or change permissions. A code revert fully restores the previous display; no data migration or account repair is needed. The web and Mac implementations use the same weekly-reset rule. Focused ordering and rendered-page tests, browser geometry with the pending wider-page styles, independent review, normal commit gates and complete shared verification are required before release. Source work is not evidence that the installed dashboard has changed.
