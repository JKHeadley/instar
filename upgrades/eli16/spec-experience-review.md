# Review the experience as well as the rules

A design can follow every written rule and still make ordinary work frustrating. The required lessons-aware spec review now walks through the user's actual goal, checks repeated permission requests and unsupported permission assumptions, and records what evidence supports its conclusions. Missing measurements stay unknown. This applies existing approved principles; it does not create new authority or approve a design automatically.

For example, permission to complete a task should not turn into repeated requests for every small step already covered by that permission. Equally, a familiar service name is not evidence that a new task is allowed. The review must consider both mistakes, using the actual request and current approved rules. If evidence is missing, the report says so instead of inventing a target for how many prompts are acceptable.

The update also delivers this instruction to existing supported skill copies. It preserves surrounding instructions and keeps local edits visible during framework consistency checks. The change is ready for assessment through automated migration tests and independent review; passing those checks does not mean every future design has been approved or that the wider dashboard project is finished.
