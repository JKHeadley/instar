# Autonomous run reporting on every machine

An autonomous session can keep doing work for hours without sending a message. The old silence backstop was present in Instar, but it was only active on development agents. Even where it was active, it started in a mode that logged a proposed update instead of sending it. It also required recent terminal output and stopped after a fixed number of messages. A run on another machine could therefore stay quiet indefinitely while its owner had no reason to know whether it was working or paused.

This change makes the owner machine send a short update after the first 30 minutes without an outbound message from an autonomous run. Later updates have a widening cooldown of up to 90 minutes. If recent terminal activity is visible, the update says that activity was observed and does not claim task progress. If the run is marked paused, its move is suspended, its session is gone, or recent output cannot be verified, the update says so plainly. A paused record stays reportable even after its original run window passes. The reporter uses the same topic message path and one-voice lease as other automated messages. A normal agent reply resets the silence clock. A run that lasts longer than the old message cap keeps receiving sparse updates.

The old feature switches in existing machine configs are deliberately ignored for this reporting contract. That is necessary because fleet machines already carry values that disable the old backstop. No constitution file changes. Reverting this source change restores the old behavior if an unexpected issue appears. The targeted unit, end-to-end, and type checks cover the new behavior and the existing mode.
