# The last stretch of the feedback pipeline: letting a reviewed fix actually merge

Every automated feedback fix must pass a review by two AI models, Codex and Claude, and then pass the merge checks. None has ever got through. This change removes six separate obstacles and leaves the review in place.

**The Claude login.** On a machine like the Mac Studio, every Claude login lives in the account pool and the default login is signed out. Sessions start under a pool account, but the Claude reviewer started on the default login and got "Not logged in". The review needs Claude's pass, so it could never pass. The reviewer now gets the account a new session would get. That choice exists when Telegram or Slack is connected, with pinning on or at least two usable accounts; otherwise it stays on the default login, as sessions do. A configured sign-in key, or a login the process already names, still wins. With no account free, the call fails and the review stays refused. Other internal calls do not change. The audit log also dropped why a reviewer failed, which hid this. It now records the reason.

**Two review rules.** Rule 3 refused all file deletion, and reviewers applied that to tests removing their own temporary folders, which most tests here do. Rule 5 refused all text addressed to agents, including sample prompts that tests feed to code. A fix following our standards could be refused for doing so. Rule 3 still refuses a credential in any file and new reach in shipped code. Tests are now judged on a shorter list: network, home or credential paths, dynamic code, shelling out to anything but git or node on their own temporary folder, or writing or deleting outside it. That is narrower than the old rule, which covered tests in full. Rule 5 still refuses steering of the review and any guidance telling an agent to run a command, contact a host, handle a secret, bypass a check, suppress a report or trust a source, whatever the bug report says. Test input, plain documentation and review records are excused when they address nobody.

**The merge script.** The executor ran the merge script in the agent's source checkout. On this machine that is an old copy from August, so merged improvements never reached it. It now runs the script from the installed package.

**A Vercel status.** Vercel marks every fork pull request as failed until someone authorizes a preview. Nothing was built, but the merge script refused any red check, and all executor PRs come from a fork. It now ignores exactly that refusal on a verified fork. A real Vercel failure or a GitHub Actions job named Vercel still refuses. If the status can't be read, the merge stops.

**A documentation check.** The docs coverage check on main was just below its floor and would have refused every merge. One more command is documented.

**The secret check.** Before a fix is published, the executor looks for anything shaped like a credential and holds the fix for approval if it finds one. It scanned whole files, and 440 files here already match, often test data or a pattern used to detect secrets. So a fix to `src/commands/server.ts` was held however clean it was: five finished fixes sit on hold this way. It now scans the file before and after the fix, and holds it when any credential-shaped value is new. New files, binaries and any file whose original can't be read still hold on any match. A review also found that a long key block sitting across the scan's internal window boundary could be missed, so those windows now overlap enough to see it whole. Fixes already on hold stay on hold, because releasing those is an approval.

**What this gives up.** A reviewer now judges whether test input or a record really addresses nobody, where before it refused them all, and a crafted fixture could try to exploit that. The prompt still treats the whole diff as data and both models must pass. Claude's review can also pick an account that has just run out, because readings can lag. That review then fails, and the 429 can briefly trip the Claude limit breaker for other calls. A secret-shaped value copied from elsewhere in the same file no longer holds the fix, since it is already in the repository.

**Your decision.** Nothing is needed. Reverting this change restores the earlier behaviour. Between an update landing and the restart, an old server runs the new merge script; a mismatch refuses the merge rather than letting it through. Agent guidance with commands stays refused, so those fixes need the repository owner's approval.
