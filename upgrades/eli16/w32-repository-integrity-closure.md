# W32 repository-integrity closure — plain-English overview

Window 32 adds two closely related pieces of infrastructure: a truthful preparation carrier that keeps setup work moving without falsely calling a run active, and a liveness authority that calls the run active only while its executor and evidence are genuinely alive. The implementation and its direct lifecycle tests were green, but the repository-wide quality gate found four integration obligations that the focused feature tests did not cover.

This small closure change makes those obligations explicit. Existing-agent awareness migration now recognizes all three W32 documentation sections and bounds nested-bullet extraction at their real line prefixes and neighboring sections, so Codex/Gemini shadows receive complete W32 guidance without malformed bullets or unrelated content. The write-domain registry now classifies every W32 liveness, cadence, work-receipt, recovery, and preparation route as machine-local, because those records describe the executor on one specific machine and must never be merged with another machine's state; that classification also feeds the existing write-admission observability log while leaving the outcome unchanged. Synthetic migration fixtures now say exactly what they model: an anchor-compatible layout that retains later preparation behavior while exercising the older state-parse migration. Finally, W32's intentional fail-closed return paths are documented for the silent-fallback audit: a missing preparation record returns a visible refusal to its caller, and a failed executor rebind is persisted before the authority terminates loudly.

No new endpoint, timer, message, or autonomous action is introduced. This change closes repository-level discoverability, migration, ownership, and audit gaps around behavior already implemented in the approved W32 work. Rollback is a normal code revert; it writes no new persistent schema and does not alter existing W32 ledgers.
