# Claude transcript resolution honors the session's live config home — plain-English overview

Every Claude Code session writes a transcript file that Instar reads for two things: a heartbeat ("is this session still doing something?") and, for Window 32, one of the five facts that must all be true before an autonomous run is allowed to call itself active. Instar looked for that file in one fixed place: the default Claude home folder under the user's home directory.

That location is wrong for a whole class of sessions. When Instar spreads work across several Claude subscriptions, it launches a session with its own Claude configuration folder (the `CLAUDE_CONFIG_DIR` environment variable), and Claude Code writes the transcript inside that folder instead. Echo's Window 32 observer is exactly such a session. The result was a live, actively working session whose heartbeat read as missing, so the run-liveness authority correctly refused to call it alive, and the older age-based liveness protection quietly did nothing for these sessions because it never found a transcript either.

The fix is small and structural. The transcript path resolver now accepts the session's live configuration folder and, for Claude Code only, looks under that folder's `projects` directory. Every place that holds a real session and probes its transcript — the Window 32 liveness sampler, the session manager's freshness and drain probes, the session-recovery growth check, the stale-session backstop, and the session reaper's idle proof — reads the session's actual configuration folder from its tmux environment and passes it in. For pooled sessions this also means three protections that were silently inert now work as they do for every other session: a genuinely idle duplicate can be drained and closed, a genuinely idle session can be reaped under the usual pressure rules, and a session stuck at the context wall can be compacted or respawned. In each case only the transcript becomes visible; the pane, process, and attempt-count checks that already governed those decisions are unchanged. A test-only root override still takes priority, a blank value falls back to the default home, and Codex or Gemini sessions never consult this variable.

Nothing here decides anything on its own. It only changes where an existing fact is read from. If the environment cannot be read, the probe falls back to the old path and stays honest about a missing transcript rather than guessing. Unit tests cover the precedence rules and framework isolation, a real session-manager test drives the tmux environment read on both sides of the boundary, and the production-path lifecycle test now boots the server with no transcript shortcut: it fails without the change and passes with it.
