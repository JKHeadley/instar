# Changed HTTP routes must prove they are alive

The Testing Integrity standard says important features need tests at three levels, but until now no repository check could stop a route change that carried no live-path test. The old route-pairing hook only looked for route-shaped text in an E2E file and could be bypassed; it did not execute the test or observe the server response.

This change establishes a deliberately narrow, mechanical first enforcement slice. The repository derives every direct Express HTTP route from production TypeScript. When a route declaration is added or its handler expression materially changes, the normal lint pipeline requires route-specific E2E evidence. It finds the canonical evidence call, runs the owning E2E test, sends a real Supertest request through a real `AgentServer`, verifies that the concrete request matches the declared route, and accepts proof only after the exact expected 2xx response arrives. `ALL` routes name the concrete request method used. A missing test, a skipped or failing test, a 404, a 503, malformed proof, missing tools, unreadable source, or an unresolved fleet base all stop the check as failed or not-proven.

The denominator is derived from code, recurses through `src`, has no exception list, and must be non-empty. Existing historical routes are not retroactively certified; the check is a change ratchet against protected fleet `main`. The caller cannot supply a base through an argument, environment variable, configured URL, or mutable tracking ref: the guard queries the hard-coded canonical fleet URL for the server-advertised `main` SHA, computes the merge base internally, and fails closed if that identity or object is unavailable. Non-literal route expressions are counted, but a changed one is rejected as not-proven because an exact evidence identity cannot be derived safely.

This does not claim to solve the judgment word “significant,” certify Tier 1 and Tier 2 coverage, or cover features without HTTP routes. It enforces the route/Tier-3 kernel that can be enumerated without author declarations. Rollback is a normal code revert: the check writes no runtime or user state.
