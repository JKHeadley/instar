## What Changed

The approval gate recognizes when the GitHub connector is opening, editing, or merging a pull request. It identifies the target repository and uses the matching permission. Setting an initial standing permission requires the owner's approval even when its displayed level already matches the default.

## What to Tell Your User

You can approve a standing permission for your agents to open pull requests through the GitHub connector. When the gate holds an action, the message directs you to Changes to approve in the paired app or to your private approval chat, depending on how approvals are set up.

## Summary of New Capabilities

GitHub pull request creation uses the write permission. Editing uses the modify permission, and merging requires approval for the exact action.

## Evidence

The tests cover the connector names, invalid repository inputs, owner proof on the initial setting, prior restrictions, and approval through both the app and private chat.

Standing GitHub pull request permission is limited to the JKHeadley/instar repository. Other repositories still require approval for each pull request action.
