## What Changed

Three fixes rooted in `docs/specs/feedback-factory-operating-drain.md` (lines 121 and 270), after the live 2026-10-14 incident on the Mac Studio in which eight HTTP 429s on the approved model's lane (drain_audit rows 2042, 2045–2051) demoted the readiness authority for four days:

- **`src/feedback-factory/drain/FeedbackDrainService.ts`** — the three-strike demotion (`readiness-authority-repeated-invocation-failure`) is gone. A tick with no usable answer (timeout, provider error, rate limit, rejected answer) is counted (`recordAuthorityTransientFailure`) and exposed; only the spec's closed list demotes (`ReadinessContractViolation` at once, the spend brake). After `READINESS_STALL_NOTICE_TICKS` (6) failed ticks in a row the service raises ONE attention item per stall episode (`feedback-drain:readiness-stalled:<authority>:<generation>:<since>`, "Feedback sorting is not making progress"), naming the last failure and saying nothing is paused. No retry out of cadence is added (line 270).
- **`src/feedback-factory/drain/FeedbackDrainStore.ts`** — the counter now opens a stall episode (`authority_readiness_stall_since`) on its first strike and stamps `authority_readiness_last_success_at` on clear; `readinessProgress(authorityId, generation)` returns `{ consecutiveFailedTicks, stalledSince, lastSuccessAt }`.
- **`src/server/routes.ts`** — `GET /feedback-factory/drain/status` carries `readinessProgress` beside `lastReadinessFailure`.
- **`src/core/CodexCliIntelligenceProvider.ts`** — in exec --json mode the thrown Error for a non-zero exit now carries the LAST `error` / `turn.failed` message from the stdout event stream (bounded to 240 chars, secret-scrubbed) after the stderr tail. The parser's pre-filter admits those two event types; `agent_message` / `turn.completed` handling is unchanged.
- **`src/scaffold/templates.ts` / `src/core/PostUpdateMigrator.ts`** — the readiness brake wording is narrowed (no more "three runs in a row"), the status sentence names `readinessProgress`, and a new stall-notice bullet sits right after the pause-alarm bullet; all three migrate idempotently to existing agents.

The feedback drain's readiness authority demotes itself to `proposal-only` on three brakes (`readiness-spend-brake`, `readiness-schema-provenance-or-routing-failure`, `readiness-authority-repeated-invocation-failure`), and only the operator's dashboard PIN restores it. That boundary is deliberate and unchanged. The demotion was silent: on the Mac Studio it fired at 2026-10-14T16:30:21Z after three consecutive `Codex CLI error (exec --json, exit 1)` runs, and the drain produced no work items for four days with no notice to anyone. While paused, every drain tick is refused at the gateway (403 `current registered readiness agent required`), so nothing inside a tick ever ran to notice.

- **`FeedbackDrainService`** gains an optional `raiseAttention` dependency and a private `alarmIfPaused(authority)`: when the authority's posture is `proposal-only` it raises ONE attention item, id `feedback-drain:readiness-paused:<authorityId>:<generation>`, title "Feedback sorting is paused", the existing `brakePlainWords(reason)` text, and the restore path (approve the sorting model again on the dashboard Feedback Drain tab; nothing restores it automatically). Priority HIGH for the wrong-model/prompt brake, NORMAL otherwise. Called right after each of the three `demoteAuthority` calls, and from the tick's authority-unavailable branch.
- **`FeedbackDrainService.notifyIfReadinessPaused()`** (new, fire-and-forget) is called by `FeedbackDrainTickProxy.acceptOwned` on its 403 refusal, on the canonical owner only, so a pause that predates the process or whose first notice failed is told by the next refused tick.
- Dedup: an in-process set plus the durable attention store's own id idempotency (`TelegramAdapter.createAttentionItem` returns the existing item for a known id). Enqueue errors are swallowed (`@silent-fallback-ok`) and retried by the next refusal.
- `AgentServer` wires `raiseAttention` to `telegramAdapter.createAttentionItem`, the same funnel triage uses.
- CLAUDE.md template and `migrateClaudeMd` gain the "A paused sorter is announced once" bullet under the Feedback Readiness Authority section.

No change to the brakes, the PIN restore path, or any authority state.

`threadline-mcp` 0.4.4 called `require('http')` inside an ES module (in `isListenerAvailable` and `sendViaListener`), so every relay connection threw `ReferenceError: require is not defined` before it started. Nothing using 0.4.4 could connect. This imports `node:http` instead. No other change.

## What to Tell Your User

If the model that sorts feedback reports is rate-limited or times out for a while, sorting no longer switches itself off. Each failed attempt is retried at the next scheduled run, and if that goes on for about three hours you get one notice saying sorting is not making progress and naming the error. Nothing needs your approval for that; it clears on its own when the model answers again. The brakes that do need your dashboard approval are unchanged: the spend cap, a different model answering, or an answer that breaks the rules. If the sorter is currently paused by the old rule, approve it once on the dashboard; that rule cannot trip again.

If my feedback sorting ever pauses itself (it does that on purpose when its spending cap is hit, when a different model answers, or after three runs in a row without a usable answer), you'll now get one notice in your Attention topic saying why and that approving it again on the dashboard is what restarts it. Before, it paused silently, which is how it sat stopped for four days in October without anyone knowing.

If your agent uses Threadline through threadline-mcp, the last version couldn't connect to the relay at all. This one does.

## Summary of New Capabilities

- Readiness progress age on the drain status route: failed runs in a row, since when, last success.
- One deduped "not making progress" attention item per stall episode.
- Codex exec --json failures carry their real cause (for example a 429) in the error text.

- One plain-English attention notice when the feedback sorter pauses itself, naming the reason and the restore step.

- None. A fix only.
