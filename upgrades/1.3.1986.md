## What Changed

SEC-173, a file editor fence gap. The dashboard file editor (`POST /api/files/save`) keeps a never-editable list of paths whose contents decide what the agent runs. The list now also covers the repository's own `.git/` folder (including a worktree's `.git` pointer file and nested copies) and `.gitmodules`. Separately, the editor now refuses to save any file that has an execute bit, wherever it sits, and the reader shows such files as not editable. Viewing every one of these files is unchanged. On Windows, which has no execute bit, only the list applies.

## What to Tell Your User

- **Editor fence**: "The file editor on your dashboard can still open everything it could before, but it no longer saves changes to the agent's git folder or to script files."

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| The editor refuses git internals and script files | Automatic |

## Evidence

- `tests/unit/sec173-file-editor-git-fence.test.ts`: through the real save route and a real repository, a save into the git folder is refused and the file is unchanged; case variants, a worktree pointer file, nested copies and `.gitmodules` are covered while `.github/`, `.gitignore` and `.gitattributes` stay editable; a script and a symlink to a script are refused and the reader marks them not editable; an ordinary file still saves.
