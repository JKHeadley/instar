## What Changed

- **Dated promises now have something running their reminder check.** The check for promises whose date has arrived (`commitments.checkInReminder`) existed, but its only driver was a scheduled job that stayed off because each run would have started a full session. The server now runs that check itself every 5 minutes, with no session and no model call.
- **It stays in dry-run.** Nothing is sent by default. `logs/check-in-reminder-tick.jsonl` records which promises would be reminded, ids only, so the trial has real evidence. `GET /commitments/check-in-reminder` gains a `tick` block.
- **One pass at a time.** The timer and the manual pass route share one running pass. A pass stuck for 10 minutes is reported instead of overlapped.
- **Each machine reminds its own promises.** A row owned by another machine is never reminded here (`other-machine`).
- **Off switch.** `commitments.checkInReminder.tickEnabled: false`, read at every tick. `tickIntervalMs` sets the cadence and applies at server start.

The opt-in replacement benchmark now rejects malformed model replies as failed audited calls. It records model identity and usage reported before failure, and attaches usage reported after a timeout to that failed call while its store remains open. Haiku calls request schema-constrained JSON and require the CLI's served-model report. Codex calls can pin one model without an automatic model-retirement retry. Named corpus cases can be selected while retaining the daily token cap.

## What to Tell Your User

Nothing changes for you yet. Your agent now keeps track of which dated promises are due, but it still sends no reminders. That stays off until a trial is reviewed.

The optional backup-model test now checks the exact response format and keeps the model and token usage reported for a failed or timed-out call. The change improves the audit trail; it does not turn on live backup decisions. Haiku and Luna still need more evidence before either can be used as a live backup.

## Summary of New Capabilities

- Dated check-in reminders are checked automatically by the server, without starting a session, in dry-run.

The bounded benchmark can select named synthetic cases and record whether each model reply had the required format. Audited Claude calls can require schema-constrained JSON and a served-model report. Audited Codex calls can hold one model pin without an automatic retirement retry. Failed calls retain available model and usage observations without allowing a late answer to settle a job result.

## Evidence

`tests/e2e/check-in-reminder-tick-exactly-once.test.ts` boots the real server, timer, commitment store and Telegram adapter over a stubbed Telegram endpoint: one due reminder is sent exactly once across several ticks and a restart, no session is spawned, and the default config sends nothing.

The October 30 Luna trial produced 17 expected parsed labels from 17 distinct synthetic cases; four “cannot tell” cases need a strict-format rerun. The earlier Haiku trial is unqualified. The production rollout gates remain closed. See `docs/specs/job-result-supervision-v2-benchmark-evidence.md`.
