## What Changed

The package completeness test now uses npm's error log level so its existing retry classifier can see `ENOENT` details. It permits a bounded 16 retries after the initial `npm pack` attempt only for temporary `instar-desktop-capture-test-*` helpers created by a parallel macOS test. Other packaging failures still fail on the first attempt.

Pipe session cleanup now stamps each new tmux session with a random session-local proof. It recognizes an owned, retained dead pane when tmux 3.7c clears its PID and removes that exact session without signalling any process. Live panes still require the recorded PID and the proof.

## What to Tell Your User

A parallel test timing race no longer turns a healthy macOS full suite red while checking the package.

The M5 can also clean up its own retained dead tmux sessions safely, avoiding another unrelated merge-check failure.

## Summary of New Capabilities

Dead tmux panes with a cleared PID are now cleaned up by their recorded tmux session ID without a process signal. Published package contents are unchanged.

## Evidence

Two M5 full-suite runs of the same commit each had 54,070 unit tests pass and only the package completeness test fail. The package test passed alone. A focused concurrent run with the macOS helper test reproduced npm `ENOENT` for a temporary helper. A further run with the larger retry bound still failed because `npm pack --silent` returned an empty stderr on failure; `--loglevel=error` returned the exact error text. The corrected full-suite result is required before merge.

The M5's PR #2521 Local Verify run passed all unit tests but failed the existing process-ownership integration test. Repeating that test with an isolated `TMUX_TMPDIR` reproduced its dead-pane cleanup assertion consistently. The same test passed without the isolated tmux directory, exposing the environment-specific path. With the nonce fix, the isolated M5 test passed all eight cases, including a mismatched proof that left the dead pane alone and zero process signals. Full exact-head verification remains required before merge.
