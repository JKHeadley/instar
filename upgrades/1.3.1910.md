## What Changed

Codex work now runs on the GPT-6.2 models released 2026-11-17: the `balanced` tier uses `gpt-6.2-sol` and the `capable` tier uses `gpt-6.2-astra`. The `fast` tier stays on `gpt-6-luna`, since there is no GPT-6.2 small model. Both new ids are recognized for topic pins, the dashboard model picker and the configured Codex default. Echo Bugs topics now default to `gpt-6.2-sol`. A machine whose Codex CLI is older than 0.166.0 uses `gpt-6-sol` or `gpt-6-astra` instead of starting a session that fails. Session launches also use the older model when the CLI version cannot be read. A fallback is recorded on the session and in the audit log, not posted in the chat (this also retires the older gpt-6.1 chat note). Feedback readiness and triage approval proposals name a model the local Codex can run. List prices for both new ids are recorded so spend is reported from the first call. The feedback reviewer and feedback triage checks accept the GPT-6.2 model of the same size. A model you chose yourself in settings or on a topic is left as it is.

After a restart, the shared conversation history re-reads every saved record once to confirm it is intact. On a large history this took minutes, and it ran inside the one-at-a-time step that every save also goes through, so saves waited behind it until the Conversations page gave up ("your agent is not answering right now"). The check now runs on its own in the background, one at a time, and saves no longer wait for it. A check that takes more than 2 seconds is named in the log with its duration.

On an agent running on more than one machine, every save to the shared conversation history went through the same one-at-a-time step as the background check of the other machines. When a machine was slow, that check took up to a minute and saves waited behind it until the Conversations page gave up ("your agent is not answering right now"). A save now waits at most 3 seconds for that step and then goes through on the history that is already open, as reads already did. Separately, the background history check (one to two minutes of reading on a large history) starts at most once every 5 minutes instead of after every save.

When an agent changes how much it trusts another agent through `threadline_trust`, the record now says `agent-proposal` instead of `user-granted`, because the tool is only ever called by an agent session. MoltBridge profile approvals made with the agent's own key now record `approvedBy: 'agent-proposal'` instead of `'human'`. Behaviour is unchanged: the agent can still do both at the Basic security level, and every reader that accepted the old label accepts the new one. No code may treat `user-granted` as proof that a person approved something; a test fixes the files that mention it.

Your agent can answer contacts through the Messages app on your Mac. A real iMessage is tied to the sender's Apple account. An ordinary text message (SMS) is not: anyone can send a text that shows one of your contacts' numbers. Until now the agent treated such a text as that contact.

Now only real iMessages count. A text message (SMS, RCS or similar) that claims to be from a contact is left alone:
- no session starts;
- nothing is answered;
- its words and pictures never reach the agent's conversations.

You still have it in your Messages app. Once a day the agent tells you how many it set aside, and which numbers they claimed.

Internal groundwork for the identity and security plan. This adds the code that reads a signed owner record, a list of signed entries saying which keys speak for the owner, and works out the same answer on every machine. Nothing uses it yet, so nothing changes for you.

Imported Claude and ChatGPT messages longer than the secret scrub's proven bound (1,000,000 characters) were scrubbed in pieces cut at whitespace. Secret shapes that include whitespace, or a long run with no whitespace near the cut, could be split so that neither piece matched. Long messages are now scanned in overlapping windows with every match kept in whole-text coordinates, and a match that reaches a window's edge is removed through to the next whitespace. Messages up to 1,000,000 characters are scrubbed exactly as before.

Local Verify re-runs a failed test file once, alone, when a lane's only problem is one to three failed files, and clears the file if it passes. On a pull request it refuses that re-run for any file that imports a file the pull request changed. A pull request that edits widely imported code therefore got no re-runs at all, so one flaky test anywhere failed the whole verify (a security fix failed three verifies in a row this way on 2026-11-18).

A new switch, `monitoring.localVerify.importRelatedRerun`, off by default, allows one narrow exception. With it on, such a file is re-run alone three times and cleared only if all three pass, and only when every test that failed in it has already failed and then passed alone, by the same full name, on a green main verify this machine ran itself in the last 7 days. A test that is not on that list, a file the pull request edited, a file-level error, a failed name that occurs twice in the file, or a file whose sequence of test names differs from the one main saw: no second try, as before.

Whatever the switch says, Local Verify now records which named tests failed and passed alone, so the evidence exists when the switch is turned on. Run logs are kept 30 days and then removed; until now they were never removed.

## What to Tell Your User

Codex now uses the new GPT-6.2 Sol and Astra models for everyday and heavy work. If a machine still has an older Codex version, it keeps using the previous models until Codex is updated.

- **Accept all right after a restart**: "Accepting suggested projects no longer stalls for minutes after your agent restarts; the history check that caused it now runs in the background."

- **Accept all on a busy machine**: "Accepting suggested projects keeps going when your machines are busy; saves no longer wait behind the agent's background checks."

- **Honest records**: "When I change how much I trust another agent, or approve a MoltBridge profile, my records now say it was my proposal rather than claiming you approved it."

- **Text messages**: "I only act on real iMessages now, because an ordinary text can show anyone's number. If you text me while iMessage isn't working, I'll let you know and you can resend it as an iMessage or reach me another way."

- **Owner record groundwork**: "Nothing changes for you yet; this is the foundation for a signed record of who owns your agent, shared by all your machines."

- **Safer import of very long chats**: "When I bring in your old chats, passwords and keys are removed before anything is saved. That now also works when one sits right where a very long message is split for checking."

Nothing changes until this is turned on. If your changes are tested with Local Verify and a pull request that touches widely used code keeps failing on tests it did not break, ask me to turn on the second try for import-related tests. I will then let such a test file run alone three more times, but only when the same test has recently failed and passed by itself on the main branch, which shows the test is unreliable without your change. On the first day it helps little, because that record starts empty; expect the full effect after about a week. Every time it clears a file I record which test, when main showed it unreliable, and both failure lines, and after a week I can run a review that compares how often each cleared test failed on main before and after. You can turn it off again at any time, with no restart.
