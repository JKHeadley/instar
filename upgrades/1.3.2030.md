## What Changed

The command safety hook recognizes literal search arguments and simple source-file output as data before applying its existing SQL rule. Executable or uncertain contexts keep the original SQL matching. Active expansions, rg execution flags, mixed commands and unsupported programs are not blanket exemptions. Shared init/update logic and a byte-identical standalone template keep installation paths aligned.

## What to Tell Your User

Read-only searches and ordinary source-file edits no longer get mistaken for database changes just because their text resembles SQL. Existing command protections remain in place.

## Summary of New Capabilities

No new setting or authority. This repairs how the existing safety hook interprets command data.
