## What Changed

- The built-in `hook-event-reporter.js` (PostToolUse, every tool call) exits on the server's reply instead of always waiting a fixed 50 ms after sending; the 50 ms timer remains the upper bound. Both the `init` copy and the update copy (`PostUpdateMigrator`) change, so existing agents receive it on update.

- Seventeen shipped job templates (health-check, the feedback-factory jobs, llm-decision-grading, correction-class-review-backstop, feedback-factory-action-list and the ten that ship disabled) now carry a `runner: script` form: each run is a small Node script that prints one `JOB_RESULT ok|skipped|failed` line instead of starting a Claude session. Script runners ride the development-agent gate (`jobs.scriptRunners.enabled` omitted): the first development-agent wave runs only deterministic llm-decision-grading as a script. Correction-class-review-backstop remains a session because its backfill endpoint can call an LLM with pending benchmark coverage. The other conversions keep their existing session path even with a saved opt-in until the new model-call audit is certified. On the fleet every converted job still runs its body as a session exactly as before. Rollback is live: `jobs.scriptRunners.enabled: false`, or a slug in `jobs.scriptRunners.disabledSlugs`.
- health-check works out a reason set on every run. Critical reasons (`disk-critical`, and `undelivered-reminders` from commitment-checkin-reminder) push on the same run; recoverable ones are a calm attention item that sends one message only after 6 hours or on recurrence.
- Supervision is layered (`docs/LLM-SUPERVISED-EXECUTION.md` gains a "Script job (layered Tier 1)" row). Jev triage, its outage replacement, model-written anomaly narration and the daily model review are built but code-gated inactive until benchmark and decision-quality audit coverage is complete; config cannot bypass the gate. Daily must-fail canaries still exercise the two active scripts against a loopback stub and must see them fail (one HIGH attention item per machine, `script-canary:<machineId>`, when any canary fails). Anomaly notices use deterministic text while the narrator is inactive.
- Measurement: job sessions are attributed per slug in the token ledger, `GET /jobs/cost` reports per-job tokens against a frozen 7-day baseline, `GET /jobs/triage` lists recent triage decisions, and a one-time rollout report goes to the Updates topic 7 days after a slug flips on a machine.
- The dashboard Jobs tab shows each job's runner, last result, 7-day tokens against the baseline and the last day's triage decisions. CLAUDE.md gains a "Scheduled jobs run as scripts" section for new and existing agents.

- New `docs/research/RUST-TRIAL-2026-10.md`: measured answer to "where would Rust speed up Instar", with the Rust probe and benchmark harnesses embedded. Documentation only.

## What to Tell Your User

Nothing to do. Each tool call finishes a few hundredths of a second sooner because a background script no longer waits longer than it needs to.

Most of my scheduled background checks start a full AI session even when there is nothing to do. Development agents now begin a staged move to small scripts: the deterministic grading job goes first. The correction-class backfill, model-backed supervisor and busier checks stay on their current paths until every new Jev and LLM call can be benchmarked and reviewed for accuracy in bulk. A daily self-test checks that each active script can still report a real problem. Regular agents keep their current job execution until a later release.

## Summary of New Capabilities

- None; efficiency fix.

- Script runners for converted job templates, with a live rollback switch.
- Daily must-fail canaries for active scripts. Jev triage, its outage-only replacement and the daily cross-job review are installed but inactive pending audit certification.
- `GET /jobs/cost`, `GET /jobs/triage` and `POST /jobs/script-supervision/pass`.
- A one-time 7-day rollout report per job and machine.

## Evidence

Server reply time for `/hooks/events`: ~7 ms median locally; the old script waited 50 ms after sending by construction. `tests/unit/hook-installation.test.ts` runs the installed reporter against a real local server (event delivered with the expected path and payload, exit 0) and asserts the early exit; `tests/unit/hook-event-reporter-early-exit.test.ts` asserts the migrator copy. Related suites pass: 5 files, 50 tests.

TypeScript build and lint passed locally. Focused unit tests passed for anomaly delivery, triage, outage backup, routes, config defaults, cost reporting, script trust and the five busiest scripts. Full suite, the 48-hour development-agent observation and the seven-day cost comparison remain rollout gates; they are not claimed as complete here.

Measurements in the report: Rust MCP probe 3 ms / 0.2 MB private vs Node Threadline helper 155 ms / 44.6 MB private (median of 7); hook start-up 20–70 ms CPU each vs 10 ms for bare `node`.
