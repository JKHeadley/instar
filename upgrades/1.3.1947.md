## What Changed

Three tests that failed full verify runs on a loaded machine, and passed alone, no longer depend on how busy the machine is. Test files only; no runtime code changed.

- `tests/integration/cartographer-eventloop-worker.test.ts`: the two event-loop cases measure the CPU time the test's own thread used between two turns of the loop. They no longer measure how late a timer fired, which also counted time the processor spent on other programs. A new case checks the measuring probe itself.
- `tests/e2e/session-management-e2e.test.ts`: the build-context respawn case and the slow-start case wait for the session manager to report the message injected. The build-context case also waits until the pane directory is recorded and checks the recorded value.
- `tests/unit/job-portable-bundle.test.ts`: the real python file helper is still used, with its 1.8 to 3 second limit lifted to 60 seconds inside this test file.

The helper's time limit in product code is unchanged and remains reported as fb-fe25893b-2ad.

A fourth test, `tests/integration/graph-witness-chunks.test.ts`, failed about one run in 64 for a different reason: it damaged a piece of data by overwriting its first character with `A`, which changed nothing when that character already was `A`. The damage now always changes the data.

`instar nuke --here` now keeps CLAUDE.md, AGENTS.md, GEMINI.md, .gitignore, .claude, .codex, .mcp.json and instar.config.json exactly as they are and removes only the `.instar` folder. It no longer restores those files from Git, which could overwrite edits. It lists what it kept, before confirming and at the end. `instar nuke <name>` no longer commits everything before its backup push: it pushes only existing commits, warns first that uncommitted changes are not in the backup, and reports whether the push worked.

`GET /work/projects` (and `/mobile/work/projects`) no longer shows "Not known yet" for a project whose checks run fine but whose judge could not reach a verdict. Those rows are settled from what the checks read: `state: "quiet"` with `stateWords: "Quiet since <time|yesterday|Mon D>"`, or `state: "stalled"` with `"Stalled since …"` once nothing has happened for max(48 h, 2 × the project's check cadence) while a done item is still open. `state: "unknown"` remains only when the checks could not read the project, and its words say why ("Not checked yet: …", "Couldn't check: no check has run since …", "Couldn't check: the last check could not read the project's evidence"). Each row gains `stateSince` (ISO; the last time anything was seen happening, set for quiet and stalled). A judge-given "stalled" now also reads "Stalled since …". `ChiefOfStaffLoop.projectsOverview()` adds `lastProgressAt`, `lastEvidenceChangeAt`, `lastCheckUnreadable` and `cadenceHours` per row. Day words use the agent's `timezone` setting. Display only: no Chief of Staff verdict, check, restart or message changes.

## What to Tell Your User

Nothing to tell. This is an internal repair to automated tests; nothing an agent or its user sees has changed.

- **Removing Instar from a project**: "If you remove me from a project folder, I now leave your files like CLAUDE.md and .claude exactly as they are and only remove my own .instar folder. I'll show you which files I kept, and I can look through them with you if you want to clean out Instar notes."
- **Deleting an agent**: "Before deleting an agent, I now back up only what's already committed and tell you plainly that anything uncommitted won't be in the backup, so nothing private gets uploaded by surprise."

- **Every project has a clear status**: "Projects I track no longer say 'Not known yet' just because I could not tick off their done list. They now say 'Quiet since …' or 'Stalled since …', and I only say I couldn't check when I really couldn't, with the reason."
