## What Changed

The Gemini pay-per-use lane's working parts are in place. It stays off until the operator approves it once with their PIN, and nothing in this release does that.
- **One door to Google's Gemini API, inside the server.** It counts the request's tokens first, reserves the most the call could cost, makes one call (never retried), and books the real cost from Google's own counts. If it can't tell whether Google charged, it counts the call as spent. The key is read by one piece of code and travels only in a request header.
- **Two uses.**
  - A second opinion any session can ask for (Hydrogen by default, Neon on request).
  - Gemini Neon as an independent reviewer in spec reviews. Where the lane is set up, it replaces the Gemini CLI there, with no CLI fallback.
- **One machine spends.** Every other machine forwards its requests to the designated machine and waits for the answer, and a request is never paid for twice. Stop actions reach the spending machine. If it can't be reached, the stop is kept and retried until it is confirmed, and the agent never says "stopped" before then. The spending machine checks every 10 seconds that another machine can still see it, and stops spending within about a minute if it is cut off.
- **A safety fix in the money layer.** The spending check identified machines by a setting most agents never set, so on an agent with several machines every machine would have looked like the single allowed spender. It now uses each machine's real identity.

The last piece of the Gemini pay-per-use lane is in: the one approval that turns it on, and the check that has to pass before it spends. It stays off on every agent until its operator approves it.
- **One approval, one PIN.** The agent prepares a plan on the machine that will spend. The plan lists every limit in plain words: Justin's $50 a month, plus the agent's proposed $10 a day, $2.50 per call and a $10 limit on uncertain charges, each marked as changeable. Approving it with the PIN turns the spending controls on and restarts the agent server by itself, with the same safety checks as the existing restart button. If the spending controls were already on, nothing restarts.
- **Checks before the plan is even shown.** The plan appears only when the new key is shown to be on the spending machine alone, no other machine holds it, no other machine claims the lane, and the key never appeared in the account lane's transcripts. Anything missing is named.
- **A proof call before real use.** After approval the door waits. One tiny call on the cheapest model must succeed, Google's prices must be confirmed, and one reading of Google's bill must be on record, before reviews and second opinions can use it.
- **Stopping is instant from any machine.** The agent can lower a limit, turn off a caller or freeze the key without asking, and it reaches the spending machine. Raising anything still needs the PIN.
- **Seeing it.** The Spend tab and the phone show this month's Gemini spend against its limit, and asking "how much have we spent on Gemini?" gets the real figure.

Pay-per-use provider keys (the Gemini pay-per-use key and any vault name starting with `metered_`) are now confined, ahead of the Gemini pay-per-use lane:
- **Sessions cannot read them.** The vault reader script refuses these names before it looks anywhere, in every mode, with "refused: metered key — readable only by its door".
- **They no longer copy to other machines.** Vault sync now filters per machine: a metered key goes only to the one machine designated to spend it, and with no designation (today) it goes nowhere. A machine that receives one from an older peer drops it.
- **They never enter a child program's environment.** A Google API-key credential is now refused instead of being passed to a child as an environment variable, and a new check proves the key's value never reaches any of the five frameworks' child environments.
- **One reader, enforced at build time.** A new lint refuses any code that reads one of these keys by name outside the door that will own it.

This also stops a paid path that was spending outside Instar's money limits: the standing security-review job ran the Gemini CLI with the bench key on its command line. Its Gemini voice now reports as unreachable until the metered lane is live.

The Gemini pay-per-use lane was driven end to end the way the operator will use it, on throwaway test agents talking to a fake Google, before anyone is asked to approve it. Four things were wrong and are fixed here:

- **The setup plan had no screen.** The approval card points at the Spend tab, but the Spend tab never showed the Gemini setup plan or took the PIN for it. It now does, at the top of the tab: the plan's first line ("Gemini joins as a reviewer and a second opinion. Choosing it as a conversation's engine is not in this version.") leads, every committed field follows in the server's own words, and one PIN approves it. The approval restarts the server by itself, so the page never asks for a second PIN.
- **The spending controls failed their start-up check after every restart on a multi-machine agent.** The start-up self-test of the spending controls was held to the same "is the spender still confirmed by the other machines?" check as real spending, and that confirmation does not exist yet at boot. The money layer therefore came up "probe failed" after every restart and nothing could spend until someone re-checked it by hand. The self-test is exempt now; real spending still needs the confirmation.
- **Long Gemini calls were cut off after 30 seconds.** A second opinion, a review or the one release proof could take longer than the server's 30-second default, especially from a machine that forwards to the spender, and the caller got a timeout while the call kept going. Those routes now wait as long as the call itself can take. With the spender down, a forwarding machine now answers "the machine that spends cannot be reached" instead of a timeout.
- **The documented way to store the key had a missing piece.** The key is meant to travel from the Secret Drop straight into the vault without ever being shown (`… --run -- secret-set.mjs gemini_api_key_payg`), but `secret-set.mjs` did not exist. It does now: it reads the value from stdin only, refuses a terminal and refuses a value on the command line, and prints nothing but the key name and length. New agents get it at setup; existing agents get it on update.

Also new, read-only: the release view on the spending machine says whether its "still the spender" confirmation is current (`lease` in `GET /routing-spend/gemini-payg/release`).

The live test itself ships as a script (`scripts/gemini-payg-live-test.mjs`): two real servers paired as one agent's two machines, a fleet-default agent and a single machine, a fake Google, headless Chromium on the real dashboard, and a signed scenario record for the setup flow and for the spender-down drill.

This release builds the rules Instar will use to spend on Gemini by the token. Nothing can spend yet: the paid Gemini door is still off and has no checked price, so no paid call is possible.

- **Monthly limits.** A pay-per-use key can now have a monthly limit as well as a daily one, counted in a chosen time zone. The Gemini key's default is $50 a month and $10 a day, on Pacific time. Each charge stays in the day and month it was made in, even if the zone later changes.
- **Per-door rules.** The paid door now has its own rule record:
  - the most one call may cost ($2.50);
  - a ceiling on uncertain charges;
  - a share of the month for second opinions (40%, $4 a day);
  - one paid pass per review round;
  - which kinds of callers may use the door.
  Adding a caller or raising a share needs the owner's PIN. Lowering a limit or removing a caller is instant.
- **Honest charges when a call goes wrong.** For the Gemini door, a call that fails after it was sent, or never reports back, counts at its full reserved cost, because Google may have billed it. If the real bill later arrives lower, the limit does not give the money back. If it arrives higher, only the difference is added.
- **Clear reasons when a call is refused.** There are 13 new reasons, such as "this caller is not allowed", "the proof check has not passed yet", "too big for the checked price" and "other calls are still finishing, try again in a moment". Each has its own status code and plain message, and keeps them when passed between machines.
- **Repeated requests are safe.** Resending a call with the same id returns the original call instead of paying again, even after a restart.
- **Prices must be checked.** A price not yet checked on Google's page counts as out of date, and the Gemini door refuses a request larger than the checked price covers.
- **No paid models in the default routing.** Background routing now uses only subscription models by default. A paid model is used only where it is explicitly allowed.

## What to Tell Your User

- **Gemini is wired in, still off**: "The pieces for the Gemini pay-per-use lane are in: second opinions from Gemini Hydrogen or Neon, and Neon as a reviewer of design documents. Nothing can spend yet. It switches on only after you approve it with your PIN, and I'll send you a card for that when it's ready."

- **Gemini can now be switched on**: "The Gemini pay-per-use lane is complete. When the new key is ready I'll send you one card with every limit spelled out; one PIN approves it, and I handle the restart. After a small test call it's live for reviews and second opinions."

- **Paid keys are locked down**: "Keys that bill by usage are now locked inside the one piece of Instar allowed to use them. My sessions can't print them, and they don't get copied between machines. A security-review job that had been spending on one of them outside my limits is stopped."

- **Nothing changes yet**: "Before I ask you to approve Gemini I ran the whole setup on test copies of me with a fake Google, and fixed four things that would have bitten — including a Spend-tab screen for the approval that was missing. Nothing is switched on, and no money moved."

- **Spending limits ready for Gemini**: "I've built the spending limits for the pay-per-use Gemini lane: $50 a month and $10 a day on Pacific time, with a cap on how much any one call can cost. Nothing is spending yet. The lane stays off until you approve it and its price is checked."

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| Gemini second opinion (after go-live) | Ask me for Gemini's view on something |
| Gemini Neon as a spec reviewer (after go-live) | Automatic in spec reviews once the lane is on |

| Capability | How to Use |
|-----------|-----------|
| Switch the Gemini lane on | Approve the card I send, with your PIN |
| See Gemini spend | Ask me, or look at the Spend tab |
| Stop or reduce Gemini spending | Ask me ("stop Gemini for now") |

| Capability | How to Use |
|-----------|-----------|
| Metered keys confined to their door | Automatic |

| Capability | How to Use |
|-----------|-----------|
| Gemini setup plan on the Spend tab | Opens automatically on the Spend tab when a setup is proposed; approve with your PIN |
| Store a key without showing it | `secret-drop-retrieve.mjs <token> <field> --run -- node .instar/scripts/secret-set.mjs <name>` (agent-side) |

| Capability | How to Use |
|-----------|-----------|
| Monthly caps with a period time zone | The caps view on the Spend tab shows the monthly cap, the zone and this month's spend |
| Per-door paid-call policy | Set through the owner's PIN plan; lowering is instant |
