## What Changed

- The base check reports an empty test selection as `test-not-found-at-base`.
- The head check requires at least one passed test before it can publish a fix PR.
- The confined build prompt asks the session to run the exact reported test name and verify a nonempty result.

The journal job-claim cutover now has a code-owned readiness floor. It stays on
the existing bus claim path, even if its feature flag is enabled, until peer
claim receive and pool-wide acquisition are implemented and tested together.
The machine heartbeat no longer advertises journal-claim support prematurely.
Claim completion and script attempt IDs follow the mechanism acquired for the
fire, so an old local lease cannot affect a bus-run result.

The first converted grading job now gets an independently recorded server
receipt for each scheduled run. The scheduler checks that the script's reported
counts match the server's counts before treating that result as supported by
independent evidence. The counts are also available as structured fields to
the later Jev check. A missing or mismatched receipt leaves the result open.
The Jev result-decision gate remains off pending outcome grading and rollout
evidence.

## What to Tell Your User

Automatic feedback fixes must now show that their named regression test actually ran. Empty test selections are stopped with a clear reason.

Scheduled jobs continue using their current claim path. This closes a possible
double-run risk in a multi-machine pool while the new claim authority is still
being built. Jev result decisions remain off.

The grading job now has a stronger check on its own "OK" result. The server
confirms that the requested work completed and that the reported counts match.
Jev is still off until the broader result-supervision proof is complete.

## Summary of New Capabilities

The feedback executor now rejects a fix when its named regression test selects no tests, even if Vitest exits successfully.

- No new user action. The cutover now reports support only when its full
  cross-machine safety path is ready.

- The first converted script can provide independent evidence for a result;
  other scripts still need their own verified evidence before routine closure.

## Evidence

Live attempts on 2026-10-28 exposed a 33-skipped, zero-executed Vitest run. Focused tests cover both base and head empty selections, normal passes, and the prompt. Full-suite and CI evidence will be attached to the PR before merge.

The production claim store has no peer receive caller or pool-wide atomic
acquisition. The lifecycle test checks that a coherent two-machine flag cannot
select a local-only journal claim; the unit wiring test checks both the claim
gate and heartbeat advert use the readiness floor.
Integration tests cover stale local claims on both completion paths.

Unit tests cover token mismatch, count mismatch, restart persistence, schema
migration, and a late receipt. The authenticated route test covers forged and
valid receipts.
The full installed-script lifecycle test checks a real run obtains sufficient
evidence from the server-owned receipt while its supervision status remains
unchecked with the model gate dark.
