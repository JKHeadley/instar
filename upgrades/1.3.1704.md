## What Changed

Two changes. A finished fix waiting to be re-checked could be thrown away if the lease number changed before its turn, because the code looked for the fix in a folder it had already moved. It now finds it there. Also, a fix attempt's setup and final checks run inside the server process, so a restart loses them. The executor now registers a restart hold during those stages; each hold ends after two hours at most, and the updater's existing deferral limit applies per version. The executor also stops starting new attempts while an update restart is waiting, so holds don't chain.

Update restarts now wait for a test a helper machine has accepted, normally for up to 21 minutes, so that work is not thrown away. Local Verify also records when it skips a helper machine because that machine runs different test logic, and when the two match again. The skip rule itself is unchanged.

App and Slack conversations can switch engine and model, as Telegram topics could. The dashboard and the iPhone app offer the switch on any session that has a conversation. The phone's door route takes a conversation reference (`telegram:N`, `app:<key>`, `slack:<team>:<channel>[:<thread>]`), and `GET /sessions` rows carry `conversationRef`. App and Slack sessions now start on their conversation's engine and model. A switch restarts the session with the conversation kept, and says so in the conversation. Slack resume records store the engine they were made under, so a switch never resumes the old engine's transcript. Moving between machines is still Telegram-only (next part).

Spec reviewers now inventory and independently contest every fixed limit on agent behavior. An invariant classification must declare a concrete basis and evidence; the convergence writer refuses missing declarations, and reviewers reject circular explanations such as “deterministic counts.” The conformance prompt asks the same question. Existing stock skills receive the update through the migration path.

## What to Tell Your User

Finished feedback fixes are no longer thrown away while waiting for a re-check, and updates wait a limited time while a fix is in its final checks.

Nothing for most agents. On machines that share testing with helpers, an update may apply a few minutes later so a running test can finish. If a helper stops taking test work because it is on older code, that now shows up in the logs instead of going unnoticed.

You can now change the engine or model of an app or Slack conversation from the app or the dashboard, the same way as a Telegram one. The conversation carries on, on the new engine. Moving those conversations to another machine comes next.

Spec reviews now challenge arbitrary limits on agent growth and behavior. Real safety and protocol constraints still require evidence explaining the particular boundary.

## Summary of New Capabilities

- Update restarts wait for a feedback fix attempt in setup or verification, up to a limit.

No new user action. Two new log events, `peer-skipped-skew` and `peer-skew-cleared`, appear in the Local Verify audit log, and `restart-held-for-peer` now also covers update restarts.

- Engine and model switching for app and Slack conversations (dashboard and phone)
- `conversationRef` on `GET /sessions` rows
- `POST /mobile/sessions/door/<reference>` for any conversation
- `/topic-profile/app:<key>`

No new user action. Reviewers distinguish genuine floors from arbitrary caps and require an intelligent assessment path when appropriate.
