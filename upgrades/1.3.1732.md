## What Changed

This slice adds the per-prompt delta hook, running in shadow (context-budget-layered-summaries §7.7, §9.5; Phase 1 S15). The UserPromptSubmit hook injects a Telegram topic's briefing and recent messages. It now makes one request, `GET /topic/:id/prompt-context`, instead of two. While in shadow, the session receives exactly what the two older calls produced.

- **Measurement.** On an agent with `contextBudget.enabled`, the route also computes the delta. The delta is what is new since the last prompt for this topic and session, or since the post-compaction seed. Both sizes go to a local log under the layer store, with ids and hashes only and never text. The log is bounded at 2 MB with one rotated segment. Codex sessions and sessions never seeded measure the delta as the full output, which is today's behaviour.
- **The comparison surface.** `GET /context-budget/delta-shadow` shows how many prompts were measured, the median and p95 sizes of full and delta output, the items the delta would leave out, and the candidate re-fetches. Whenever anything was left out, the re-fetch count reads `unknown` with its reason, never zero.
- **Reduction stays off.** Returning the delta needs `contextBudget.deltaHook.enabled` on that machine (default off). Even with it on, it is refused unless that machine's compaction canary reads `healthy`. Each refusal is logged with its reason.
- **Suppression.** While a fold is open for the topic, or the session holds a fold marker, the hook prints nothing.
- **The 10,000-character limit.** On Claude Code, the hook's whole output now stays under 9,000 characters. Claude Code passes hook output to the model whole only below 10,000. The oldest history lines go first, then the end of the briefing. Codex output is unchanged.
- **Older servers.** An older server answers 404, 503 or something unreadable. It still gets the two older calls.

## What to Tell Your User

Nothing changes for you. On development agents I now measure how much repeated conversation context each message carries. That tells us whether sending only what is new would be safe before anything is changed.

## Summary of New Capabilities

- `GET /topic/:id/prompt-context`: the per-prompt hook's single request, full output while in shadow.
- `GET /context-budget/delta-shadow`: the shadow comparison's aggregates.
- `contextBudget.deltaHook.enabled`: a per-machine switch, off by default and refused unless the canary reads healthy.
