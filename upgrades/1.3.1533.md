## What Changed

The feedback executor now holds any confined worker change to the repository's `.instar` tree before publication. The final change-set gate checks added, edited, and deleted paths, including case aliases and literal backslash filenames. Both supported worker sandboxes also deny writes to that tree. This fixes the observed path omission that let worker-supplied decision and trace records appear in an executor pull request.

## What to Tell Your User

- **Safer feedback changes:** “Feedback workers can no longer provide their own audit records. If a report needs to change agent state, I will hold it for the trusted development path.”

## Summary of New Capabilities

No new user action is needed. The existing feedback publication gate now protects agent state and audit files alongside the other protected tooling paths.

## Evidence

Before this change, the executor's path predicate classified `.instar/instar-dev-decisions/new.json` as publishable; the published feedback PR #2442 includes worker-supplied decision and trace files. The regression builds a real change set with added, edited, deleted, and literal-backslash filenames beneath `.instar` and confirms every entry is held. At the committed branch head, focused unit tests passed 143/143, full unit tests passed 53,568 with zero failures, and the production lifecycle E2E passed 2/2. The separate HTTP integration and aggregate suite results are recorded in the PR review packet when complete.
