## What Changed

- A voice note sent from the Instar iPhone app without a phone transcript is still transcribed on the server with the same provider Telegram voice notes use (`GROQ_API_KEY` or `OPENAI_API_KEY`). The transcript is now saved with the conversation as its own replicated `transcript` event, instead of living only in the line the session received.
- Before the transcript is saved or delivered it gets the same treatment as a phone transcript: the pairing service's inbound scan runs over it (a dictated pending pairing code declines that pairing), and pairing invites and desktop-code lines are removed.
- The transcript is unsigned and kept outside the signed message, so it never changes `originVerified`. History and sync show it on the file as `serverTranscript` (`text`, `provider`, `at`, `machineId`, `signed: false`, `late` when it was late). The phone's own `transcript` field is unchanged.
- The session still waits at most 60 seconds. If the transcript is not ready by then, the line reads `(transcript not ready after 60 s; …)`. When it finishes, it is saved marked `late`, and an app conversation's live session gets one `[voice transcript ready: <path>] <text>` line (or `[voice transcript unavailable: <path>] (…reason…)` if it failed). With no live session, that line waits for the next delivery's context.
- A voice note that reached this machine only after the message was delivered (the `[file now available: <path>]` line) is transcribed when it lands, and the transcript rides on that line.
- At most 3 provider calls run at once per process. A note still waiting for a slot when its 10-minute ceiling passes ends as "transcription unavailable: timed out waiting".
- Invite and desktop-code removal also runs when a stored transcript is read (session lines, the next delivery's context, history, sync), so a transcript a peer stored without scrubbing cannot carry one.
- A transcript reaches the session once: a "now available" line kept for later and a late transcript line never both carry it.
- Each voice note is transcribed at most once per machine. A failure is recorded with its reason and never retried; a transcription interrupted by a restart reads "the server restarted before the transcript finished". A transcript another machine already made is reused.
- The provider call itself may now run up to 10 minutes (it was cut at 60 seconds, which made a late transcript impossible).
- Older peers do not know the `transcript` event kind: they refuse it and count it, exactly as they refuse `media-message`.

## What to Tell Your User

Voice notes you send from the app without a phone transcript now keep their transcript: it is saved with the message and shows in the app, marked as made by the agent rather than signed by your phone. If transcribing takes longer than a minute, I get your voice note right away and the words follow a moment later. If transcription fails or no transcription service is set up, I tell you why, and I can still listen to the file.

## Summary of New Capabilities

- The `transcript` app-conversation event kind (replicated with `appConversations`).
- `serverTranscript` on voice attachments in app history and sync.
- Late transcript follow-up lines in app conversations.

## Evidence

- Unit (`tests/unit/app-voice-transcript-event.test.ts`, 41 tests, including the second-pass findings: the 3-call limit under a burst of 8, queued-past-ceiling, peer transcripts scrubbed on read, and no duplicate delivery in either direction): the event validator on both sides of every field rule; the replicated envelope round trip with nothing dropped; an older peer's validator refusing and counting the record while the current one accepts it; one winning transcript per attachment in either arrival order; scrub and scan order; cut-with-note past the store limit; one transcription per attachment, failures never retried, a restart-interrupted run read as a failure; late transcripts stored `late` with exactly one follow-up line, or a note for the next delivery; a Telegram conversation stored with no follow-up promised; notes that land later transcribed and carried on the "now available" line; the signed record byte-for-byte unchanged.
- Integration (`tests/integration/mobile-native-media.test.ts`, 5 new tests, one with a peer-authored transcript carrying an invite): through the production device authenticator, a voice note without a phone transcript is stored as a scrubbed, scanned transcript event, shown as `serverTranscript` in history and sync, with `originVerified: "verified"`; a phone transcript is never replaced; a late transcript arrives as one follow-up line and history shows `late: true`; a failing provider gives an honest line and stores nothing.
- E2E (`tests/e2e/mobile-native-media-alive.test.ts`, 1 new test): an AgentServer booted on a development agent with `GROQ_API_KEY` set calls the real provider path once, delivers the scrubbed transcript, and the paired phone's history shows the unsigned `serverTranscript` beside a verified signature.
