## What Changed

CI-only. `.github/scripts/setup-ci-tmux.sh` now runs its two apt commands with `Acquire::Retries=0` and 15-second `Acquire::http::Timeout` and `Acquire::https::Timeout` (was `Retries=2`, `http::Timeout=20`, no https timeout). On PR 3078 (GitHub run 43055208211, attempts 1 and 2) all eight unit shards, integration and E2E failed in "Ensure tmux" before any test ran: `apt-get update` hit the 180-second bound (exit 124) while retrying the same stalled Azure Ubuntu mirror. The runner's own apt setup says retries are spent on one URI before apt tries the next mirror in its configured mirror list, so our higher retry count used up the whole bound on one bad mirror. Sources, signing keys, signature checks, the pinned tmux 3.6a, its checksum, curl's `--retry 3` download, the 180-second bound and every workflow test command are unchanged. No installed-agent behavior changes.

This restores the exact script hunk of commit 210e8af53d (first proposed in PR 3080). PR 3080 was closed automatically, unmerged, when its stacked base branch was deleted after its documentation parent (PR 3081) merged; it was not rejected, and its script change never reached main.
