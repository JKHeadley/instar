## What Changed

- New setting `hooks.nativeEventReporter.enabled` (default **off**). When on, and this machine's Claude Code is 2.1.310 or newer and the server listens on loopback, the event reporter on 7 events (`PostToolUse`, `SubagentStart`, `SubagentStop`, `Stop`, `TaskCompleted`, `SessionEnd`, `PreCompact`) becomes a Claude Code native HTTP hook that posts to the new loopback-only route `POST /hooks/native-events`, instead of starting `hook-event-reporter.js` once per event. The settings are reconciled at server start, before each Claude Code session launch, and on update, in both directions: turning the setting off restores today's command entries exactly. A setting that is on but cannot take effect reports a `NativeHookEvents.notInEffect` degradation.
- The native route checks the caller (loopback, no forwarding headers, token, 4 MB cap) before reading the body, then keeps only a fixed set of fields: no command text, no tool output, and message tails are redacted before the last 200 characters are kept. It answers at once and stores through a bounded queue. Counters are on the authenticated `/health` under `hookEvents`.
- Events now carry their real names and the fields their readers use, so readers that never received data were reviewed first: the compaction check on `PreCompact` now looks only at the compacting session (it would have checked every conversation), the subagent "still running" signal stops counting a subagent after 60 minutes without a stop and is cleared by its own session's end, and the subagent stall warnings are logged but not typed into the session unless `monitoring.helperWatchdog.injectAlerts` is on (default off).
- The dashboard's per-session telemetry is looked up for the session's current run, so it is no longer always empty. Hook telemetry folders are git-ignored and never served by the file viewer.

## What to Tell Your User

Nothing changes unless this is switched on. When it is, I report what happens in my sessions straight to my own server instead of starting a small helper program after every tool I use, which saves a little processor time and memory on every step.

## Summary of New Capabilities

- `hooks.nativeEventReporter.enabled` in `.instar/config.json` (off by default; new sessions only).
- `monitoring.helperWatchdog.injectAlerts` (off by default).
- `hookEvents` counters on the authenticated `/health`.

## Evidence

Measured on the Mac Studio, Node 24.14.1, Claude Code 2.1.310, against a real server built from this branch. Per event, the command reporter costs one process, 88.7 ms wall (p95 95.1 ms), 30 ms CPU and 55.7 MB peak memory (60 runs under `/usr/bin/time -l`); the native path costs no process, a 1.0 ms round trip (p95 4.5 ms) and at most 1.6 ms server CPU. A real `claude -p` session (10 Bash, 1 Read, 1 Edit, 1 subagent, 1 blocked Telegram curl) started 17 reporter processes (530 ms CPU) with the setting off and 0 with it on; with it on all 17 events were stored with their real names (13 PostToolUse, SubagentStart, SubagentStop, Stop, SessionEnd), versus 4 stored as "Unknown" with it off. The telegram-origin guard blocked the Telegram call in both runs. With the server stalled 3 s, each native hook waited 1.0 s and gave up.
