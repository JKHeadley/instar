## What Changed

- **safe-merge reads `main`'s branch protection the way a non-admin can.** It used to call `GET /branches/<b>/protection`, which answers 404 for a non-admin login, and treated that as "no protection", so it never saw the 12 GitHub Actions checks classic protection requires. It now reads `GET /branches/<b>` (`protection.required_status_checks`). Those 12 contexts are pinned with their producer in `ACTIONS_FLOOR_CONTEXTS` (`REQUIRED_CONTEXTS_FLOOR` plus the classic list, excluding `instar/local-verify`), which the synchronous path, `--admin` included, now enforces. A required `instar/local-verify` is read from the combined-status API.
- **A `local` merge floor for safe-merge and the green-PR watcher** (spec `docs/specs/local-verify-merge-authority.md` §3, piece 3 of 4). Off unless `monitoring.greenPrAutoMerge.floor` is `local` and the server reports the floor as effective, which requires GitHub's own settings to require `instar/local-verify` and no classic checks. Under it, safe-merge skips the Actions waits and admits a PR only on the server's local-verify record for that exact head and base (plus the merge-time body checks, operator approval of the exact head for harness-changing or protected PRs, and the main-health repair rule); anything unreadable refuses, and it never falls back to Actions. The watcher's candidate filter becomes record-gated and local merges run through a new `sync` MergeRunner strategy (no `--auto`, no `--admin`). New shared module `scripts/local-verify-floor.mjs`.

- **local-verify: the server can run the full test suite on a pull request's merge with `main` and keep the result** (spec `docs/specs/local-verify-merge-authority.md` §2, piece 2 of 4). New `src/localVerify/` (inventory and lanes, report evaluation, a parser-based skip/removal ratchet, the harness-changing classifier, the run orchestrator and its child entry, `LocalVerifyService`) and routes `POST /local-verify` (`{"pr":N}` only), `GET /local-verify`, `GET /local-verify/record`. Each run uses a private bare clone under `<agentHome>/.worktrees/.verify/`, `merge-tree` + `commit-tree` of base and head, `npm ci`, the build, the `npm run lint` list and the three test lanes with `--allowOnly=false`, under per-step deadlines. Results go to a durable journal that survives restarts. Only PRs from the agent's or the operator's GitHub login, from this repository, are verified. `SafeGitExecutor` (`localVerifyCloneOk`) and `SafeFsExecutor` (`localVerifyScopeOk`) gain carve-outs scoped to `.worktrees/.verify/`. Off by default (`monitoring.localVerify.enabled`); 503 with no instar source checkout; 409 on a standby. Nothing reads a record yet: posting the pass/fail mark and the merge-tool changes are the next pieces.

- **local-verify posts (or, by default, logs) the `instar/local-verify` commit status** (spec `docs/specs/local-verify-merge-authority.md` §3, piece 3a). A 60-second loop on the lease holder projects each open PR's status from its local-verify record (or mirrors the Actions checks for PRs that stay on the Actions floor), posts only on a change, through one serialized writer per head, and withdraws `success` when a condition stops holding. A post-merge `main` verify (debounced, capped) with `main-suspect`/`main-red` states stops merges except a repair while `main` is red. The local floor takes effect only when GitHub's own settings require the check and classic protection requires nothing. New `GET /local-verify/status`. Posting is off unless `monitoring.localVerify.postStatuses` is true.

- **The green-PR watcher can now recognise its own leftover merge process on macOS.** After a crash or restart, the watcher looks for a `safe-merge` process left over from the interrupted attempt and kills its process group only once it has proven the process is its own (a per-attempt token). That proof read `/proc/<pid>/environ`, which macOS does not have, so on a Mac a leftover was never confirmed and never killed. The token now also rides the command line (`--attempt-token <hex>`, a new identity-only safe-merge flag, advertised as the `attempt-token` capability and passed only when the probed script advertises it), and the watcher reads it with `ps -o args=`; `/proc` environ stays as a Linux fallback.
- **An unconfirmed live leftover is kept, not forgotten.** Before, the watcher deleted its in-flight record even when the recorded process was still alive and unconfirmed, losing its only handle on it and letting a new merge attempt start beside the old one. Now that record is kept (marked `reapIncompleteAt`, audited `orphan-reap-incomplete`), and every new attempt is refused with `skipped:orphan-unresolved` while the recorded pid is alive. Once the pid is gone, the PR's state is re-checked and the record cleared, and merging resumes on its own. The refusal does not count against the PR's retry ladder or the breaker, and raises one attention line (posted once; removed, with the aggregate re-posted, when attempts resume or a warm-up reap succeeds). A reused pid does not block forever: the record stores the attempt's deadline, and once the attempt's deadline + kill grace + 5 minutes have passed, the record is cleared without a kill (audited `orphan-presumed-foreign`) when the process's command line reads successfully and shows no safe-merge. If it cannot be read, or it is a safe-merge we cannot prove is ours (a hung one can outlive its deadline), the record is kept. Identity also requires the pinned safe-merge path on the command line. Any surviving record is now resolved at the start of every attempt, so a confirmed live leftover is killed there too, not only at warm-up.

- **The unit tests run in parallel, and the full suite runs each file once.** `vitest.config.ts` (what `npm test` runs) is now the unit lane alone: `tests/unit/**` and `tests/real-world-state/**`, files in parallel with `maxWorkers` from `tests/setup/lane-workers.ts` (`INSTAR_TEST_WORKERS`, else 8 on a 12+ core host, else half the cores). It used to also include `tests/integration/**` and `tests/e2e/**`, so `npm run test:all` ran every integration and e2e file twice. Integration and e2e keep their own configs and stay one file at a time until their isolation follow-ups (port-reuse race, per-run tmux socket) land. `vitest.e2e.config.ts` now runs `build-dist.globalSetup` (a no-op when dist is current), because the dist-gated e2e files used to rely on the unit config having built dist. First piece of `docs/specs/local-verify-merge-authority.md` (§1).

## What to Tell Your User

Nothing changes yet for you. The merge tool now correctly sees which GitHub checks your main branch requires; it used to miss them. The part that lets merges trust my own local test run instead of waiting on GitHub stays off until you approve the switch.

Nothing changes for you yet. This is the part of the "stop waiting on GitHub" work that lets me run the whole test suite myself on exactly the code a change would merge. It's switched off until the rest is built and you approve the switch.

Nothing changes for you yet. This is the part that will post a pass/fail mark on each pull request from my own test runs; for now it only notes what it would post, and stays that way until you approve the switch.

Nothing to do. On a Mac, if a merge attempt was interrupted by a restart, I can now tell whether the leftover process is mine and clean it up. If I can't tell, I leave it alone and pause auto-merging until it exits, rather than starting a second merge next to it; you'd see one "auto-merge is paused" note in that case.

Nothing changes for you. My full test run is faster now: the unit tests run eight at a time, and nothing runs twice.

## Summary of New Capabilities

- safe-merge `--capabilities` reports `floorModes`.
- `monitoring.greenPrAutoMerge.floor` (`actions` default, `local`).

- `POST /local-verify`, `GET /local-verify`, `GET /local-verify/record` (instar source checkouts only, off by default).

- `GET /local-verify/status` (floor in force, main health, last pass; instar source checkouts only).
- `monitoring.localVerify.postStatuses` (default false).

- safe-merge accepts `--attempt-token <hex>` (identity only) and advertises `attempt-token` in `--capabilities`.
- New MergeRunner outcome `skipped:orphan-unresolved`; `reapOrphan()` can return `{ reaped: false, outcome: 'orphan-reap-incomplete' }`.

- `INSTAR_TEST_WORKERS` sets how many unit test files run at once (default 8 on a 12+ core machine).
