## What Changed

When Cloudflare rate-limits a quick tunnel, the `cloudflared` wrapper can emit the
API base it was talking to — `https://api.trycloudflare.com` — on its `url` event
instead of an assigned tunnel hostname. `CloudflareQuickProvider` accepted it, so
`TunnelManager` reported `running: true` / `state: "active"` while holding an
address that answers HTTP 405 to every request.

The provider now validates that an emitted URL is an *assigned* quick-tunnel
hostname (https, exactly one label under `.trycloudflare.com`, and not `api`)
before accepting it. A non-conforming URL is rejected through the existing
`classifyError` path, so a refused tunnel is classified, backed off, and able to
fall back — instead of latching a false healthy state.

The check validates **shape, not reachability**, and claims nothing more.

Also adds `grok.com` and `x.ai` to the convergence-check well-known domain
allowlist, which already carried `openai.com`, `anthropic.com`, `claude.ai` and
`x.com`.

## What to Tell Your User

If your agent's tunnel gets rate-limited by Cloudflare, it now tells you the
tunnel failed instead of reporting it as active. Previously it could believe it
had a working public address when it did not — and any link it built for you
(a private view, a secure form for a credential) pointed at a dead address with
nothing anywhere indicating why.

Nothing changes when tunnels are working normally.

## Summary of New Capabilities

None — this is a correctness fix to existing tunnel behaviour. The visible
difference is that `GET /tunnel` now reports an honest failure state where it
previously reported a false active one.

## Evidence

- Found live 2026-10-21: `GET /tunnel` returned
  `{"url":"https://api.trycloudflare.com","lifecycle":{"state":"active","lastFailureReason":"rate-limited"}}`,
  and `curl` against that host returned HTTP 405 (Cloudflare error 10005).
- Two operator links in a row were built on that dead host — a private view and a
  Secret Drop form requesting a payment card.
- `tests/unit/cloudflare-quick-url-validation.test.ts` — 9 passing cases covering
  the real hostname, the observed `api.trycloudflare.com` regression, the apex,
  multi-label hosts, two suffix look-alikes (`evil-trycloudflare.com`,
  `trycloudflare.com.attacker.test`), plaintext http, non-URL junk, and case.
