## What Changed

Quiet by Default no longer holds back buttons only the owner can answer. `TelegramAdapter.sendOfferList` (the Chief of Staff note with Unpark / Confirm-done, the Chief of Staff pause ask, the machine-enrolment offer) was sent with no category, so the gate recorded it in the quiet feed and the send returned nothing. These sends now carry a new protected category, `owner-decision`. It is stamped only in-process, never by a request, and only when the caller set no category of its own. The gate delivers it, up to 10 per topic per 10 minutes, and it cannot be configured or redirected. The owner-pause source floor also now refuses a marker whose date is not the cited message's date (`date-mismatch`).

A fix for a problem reported through Instar's feedback channel, written by the feedback executor and merged only after it passed the independent review at its exact head. Feedback item: feedback-1ddb71cc-9930-4e8e-b165-6df63f57e4da. It changes 1 shipped file(s) and 2 test file(s); the pull request lists them.

Each machine now keeps its owner's choices for its weekly clean restart. "Skip once" means no restart for the next 72 hours. "Change window" sets which hours of the night the restart may use (at least 2 hours). Every agent on the machine follows the same choice. A restart already announced keeps its time. These controls can only make a restart later or move it; they never start one. The status shows the skip and the window in use.

The admin of an organization now sees a Work agents list in the Instar app. It shows each joined agent, its person, the policy version it runs, and when it last checked in. Joined agents check in once a day with their daily update check, signed with their own key. A new agent can appear only by using an invitation link the admin made, and links can be cancelled. The admin can mark someone as gone. That person's app then asks them once whether to remove the organization's policy; nothing is removed without their tap. The admin can add up to three policy keepers. A keeper proposes new versions, and the organization's agent checks each one and signs it with the organization key, so members still trust only one key. A keeper can tighten the policy but never loosen the limits. Members who joined before this version check in only after allowing it once in the app.

The admin of an organization can now save a recovery copy: a file encrypted with six words that the app shows once. If the Mac that publishes the policy is lost for good, another agent can take over the same organization from it, and colleagues' agents keep their policy without joining again. Recovery is refused while the old address still serves the policy, and the person must confirm the old Mac is retired. Keepers and invitation links come back switched off, and work agents come back unconfirmed, until the admin confirms each one. The first version published after a recovery jumps by 1000, so colleagues never refuse it as old.

A project in Work can now have apps: pages one tap from its row and from a strip at the top of its conversation, with a pinned link in its Telegram topic. The first app is the Feature maturation board. The agent can suggest an app once per project; only the owner's tap attaches, declines or removes it, and a "no" is remembered on every machine. The row shows the app's headline with the time its numbers were read, and says plainly when the numbers could not be read. New routes: `POST /work/projects/:key/app-offers`, `POST /work/projects/:key/apps/:appRef/answer`, `.../pin-retry`, `.../opened`, `GET /work/projects/apps/stats`. A new replicated record kind, `project-app-record`, carries offers, answers and pin steps; older machines skip it. Switch: `projectApps.enabled` (on for development agents, off elsewhere; needs the Chief of Staff).

## What to Tell Your User

Questions I send you with a button, like "Unpark this project?" or "Pause this project?", now reach you instead of sitting in the quiet notifications list. Routine reports stay quiet as before.

A problem another Instar agent reported has been fixed. Nothing changes in how you use me; tell me if you still see it.

- **Machine care controls**: "You can skip a machine's next restart, or move its restart to different night hours. The Machine care page that shows these controls comes next."

- **Work agents**: "If you publish your organization's policy, the Organization tab now lists each colleague's agent, which version it runs and when it last checked in."
- **Second keeper**: "You can add a second person who can update the policy. Ask them for their keeper code, and read the key code back to them before adding it."

- **Recovery copy**: "Save a recovery copy of your organization from the Organization tab: a file plus six words to keep apart. If this Mac is ever lost, another agent can take over without colleagues joining again."

When one of your projects would be easier to follow as a page than as long status messages, I may suggest one, once. You'll see the suggestion on the project's row in Work with Attach and No thanks. Once attached, the page is one tap from the row and from the top of the project's conversation, with a pinned link in Telegram, and my updates there get shorter: what changed, plus the link.
