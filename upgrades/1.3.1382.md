## What Changed

- **The release-note check now blocks a merge instead of only reporting.** `.github/workflows/release-fragment-gate.yml` no longer sets `WARN_ONLY: '1'`, so a release-relevant PR with no `upgrades/next/*.md` fragment fails the check rather than passing with a `verdict=FAIL warn-only=1` notice. CI-only: no runtime code, no config default, and no agent-installed file changes.
- **The flip is recorded against its own criterion in the spec.** `docs/specs/RELEASE-FRAGMENT-GATE-SPEC.md` gains a "Flip record" section stating that the D3 criterion was NOT met: D3 reads `logs/release-fragment-gate-rollout.jsonl`, and nothing has ever written that file, so the soak was unmeasurable by construction. The operator flipped it on observed evidence instead — five merged fixes reached users unannounced on 2026-10-21 because the warn-only verdict blocked nothing.
- **Rollback lever kept and named.** `scripts/check-release-fragment.mjs` is unchanged — its warn-only branch stays exactly as shipped, so re-adding `WARN_ONLY: '1'` to the workflow env restores the soak posture in one line. The lever is named in the workflow header and in the spec's flip record.

## Evidence

Reproduced against the deployed checker, on the same file list, before and after the change:

- **Before** (`WARN_ONLY: '1'` set, as the workflow shipped it) — a release-relevant PR with no fragment: `::notice::release-fragment-gate verdict=FAIL warn-only=1 (not blocking during soak)`, **exit 0**. The verdict was correct and the merge proceeded.
- **After** (env removed) — same file list: `::notice::release-fragment-gate verdict=FAIL blocking=1`, **exit 1**.
- **After, with a fragment present** (this PR's own file list): `release-fragment-gate: OK — a release-note fragment is present.` / `verdict=PASS exempt=none`, **exit 0** — so the flip does not fail a compliant PR.
- `tests/unit/check-release-fragment.test.ts`: 9/9 pass.
- Production occurrence this replaces: on 2026-10-21, PRs #2250/#2251/#2252/#2254 merged and shipped in 1.3.1374/1.3.1375 with no release note of their own. Confirmed by reading the published package contents, not by version numbers. The gate had already judged them release-relevant; warn-only meant the judgement did nothing.
