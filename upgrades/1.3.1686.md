## What Changed

Anything an agent credits to a person, in its notes, rules or messages, can now be traced to the logged message it came from, or says plainly that it has no source. A note can no longer harden unnoticed from "Justin corrected me" into "his standing rule". A history keeps every wording of a claim, on every channel with a log, across an agent's machines. A check runs when a note is written and after a message is sent, and a daily report lists what cannot be supported. The report never edits a note. It uses the agent's own subscription within fixed daily limits and needs no purchased service. Live on development agents, where it only records. Off on every other agent; an update adds no restriction to any existing agent.

The web console has a phone mode for the Instar iPhone app. Opening `/dashboard/console/?phone=1#/<page>` (or `#/<page>?phone=1`) shows only that page: no top bar, no section nav, no Legacy chip or link. Short page names such as `#/accounts`, `#/files` and `#/pace` work in phone mode, and Pace has a page of its own there. The mode lasts for the page load and respects the phone's safe areas. Without `phone=1` the console is unchanged.

Coverage enumerates validated local model definitions through their canonical producer, without reading advisory placement/availability classifications. Foreign, unreadable and truncated inputs stay unknown or incomplete; observed-empty is distinct. The unavailable-coverage warning offers its own action without pointing elsewhere.

The remote desktop page's locked-Mac password box (`#lockedPassword`) and its reason line (`#lockedPasswordReason`) now start below the top bar (`.desktop-bar`) instead of over it. Before, the box sat at z-index 8 from `top: .5rem` and nearly full width, above the bar's Stop button (z-index 5, `top: 0`), so a click on Stop landed on the box while it showed and a person could only end the session by closing the tab. `dashboard/desktop.css` only.

Existing maturation contracts can name intended outcomes, owners, evaluation methods/versions, quality safeguards and exact recorded baselines. Reads compare those baselines with fresh compatible latest observations and disclose missing, ambiguous, stale or incompatible proof. The existing summary exposes scoped declaration counts and one-feature detail, including peer reads. Malformed metadata remains invalid through reconciliation rather than disappearing as missing.

The Linux systemd unit now sets `Environment=INSTAR_SUPERVISED=1`, the same as the macOS launch file, and an update migration adds it to existing units, with a backup beside them. The unit starts the bash boot wrapper, so before this the lifeline never saw systemd as its parent, and every self-restart was skipped: watchdog, planned upgrade and version skew. The setting takes effect at the service's next start.

Watchdog self-restarts are also bounded on every platform:
- at most 6 per rolling 24h;
- the restart-storm alarm now counts the restart being decided, so it can fire;
- a malformed entry in the restart history reads as a corrupt file;
- two new degradations report when self-restart gives up (`TelegramLifeline.selfRestartExhausted`) or the history file is corrupt (`TelegramLifeline.restartStateCorrupt`).

Eighteen more faults in the locked-screen proof driver, and one gap in its evidence (`scripts/locked-proof/`), found in the live runs on the Mac Mini on 2026-11-05 after the first six fixes shipped in v1.3.1684. Proof tooling only; no runtime code changes.

1. The `typing` trigger meant "the input helper is running". That helper runs for the whole grant, so case 12.2e ("Node killed mid-typing") killed the server before any password was sent and judged a run in which nothing was typed. `typing` now means a duty exists in state owed, Enter is not yet pending, and the helper is running. Cases 12.9 and 15.9 use the same trigger.
2. Case 12.5a ("Guard killed in owed") killed the guard and then waited for a relock without ever ending the session. While a grant is live and its server alive, an owed duty stays owed and the Mac stays open for the person using it; the server's job is to replace the guard. The case now stops the viewer once the replacement guard has taken over, so it can show the Mac ending locked.
3. The `revoke` step used an operator session the driver had made for itself. The server only lets the session that opened a request end it, so the revoke was refused with 403 and the case went on to judge a grant that was still open. The step now uses the viewer page's own session, read from the page's unlock answer, and throws when a revoke is refused.
4. The "guard or typist still running after the duty closed" rule also fired when no duty had ever existed, because the input helper of a live grant counts as a typist. Case 12.17 types one letter, opens no duty and expects the grant to stay alive, so it could not pass. The rule is now judged only once a duty exists and has closed.
5. Case 12.9 waits for a duty's 10-minute deadline but had no timeout of its own, so the driver stopped watching after 270 seconds and the case could never reach its second step. It now watches for 840 seconds.
6. "Deadline immediately before Enter" (15.3) aimed Enter a fixed 1.5 seconds after the grant's ceiling. Typing the whole password takes 0.73 seconds on the Mini, so typing was due to start after the ceiling, when the page has closed the password box. Enter now trails the ceiling by half the typing time taken from calibration, so the ceiling falls while the password is being typed.
7. The check for the owner's security item looked once, straight after a failed relock. The item is raised by a 10-second sweep, so the check recorded "not raised" for an item raised 9.4 seconds later. It now waits up to 15 seconds when a duty has ended relock-failed.
8. When a typed password got no answer the driver recognised, it recorded only "no-result-within-60s". It now also records what the page's status line said while it waited (`pageSaid`), so the row shows what a person would have seen.
9. Case 15.9 failed any run in which the half-typed-field marker was still set when the case ended. The spec says that marker outlives its request and is cleared by the next input helper before any password can be typed. The case now opens a next grant (`next-helper-clears-field`) and checks the marker goes there. Follow-on (`then`) steps are also kept in the evidence row.
10. Case 12.9 froze the typist and the first guard but left the owning server running. That server's sweep replaces a frozen guard within 10 seconds, so the replacement relocked at the deadline and the other agent's grant was rightly refused; the deadline-based recovery by another agent, which the case is about, was never reached. The case now also freezes the owning server (served under launchd), so nothing replaces the guard.
11. The driver did not know the page's wording for the helper's `shield-not-confirmed` refusal ("This Mac's lock screen is not ready for a password right now…"), so it recorded "no result". It is now mapped.
12. The deadline cases aimed from "the moment the driver saw the grant open, plus 10 minutes". Over 33 duties the server's own end time for a grant came a median 0.64 s earlier than that (range 0.44 to 2.9 s), so a password aimed half the typing time ahead still arrived after the grant had ended (15.3, rerun at 16:03 PST: no duty, page said "Desktop access ended"). The driver now reads the grant's `expiresAt` from the page's own responses and aims from it; the row records it as `grantExpiresAt`.
13. The new `next-helper-clears-field` step ended its extra grant with an ordinary click on Stop and did not notice when that did not go through, so the extra grant's helper was still running at the end and the case failed its leftover check (15.9, 16:42 PST; the field itself read cleared in 11 ms). The step now tries the click for 3 seconds, records the result as `stopClick`, stops the grant from script if the click did not go through, and records `helperGone`.
14. Aimed 0.6 s ahead of the server's expiry, 15.3 created its duty 0.21 s before the ceiling and the ceiling arrived before the first character (rerun 17:09 PST: duty `relocked`, Mac's own flag locked throughout, 0 submissions, verdict "the password was never typed"). The lead is now 0.8 s.
15. The "lock screen is not ready" refusal. Measured live with an observer that evaluates the helper's own two conditions five times a second: a few seconds after the Mac locks, or after its display wakes, loginwindow lets go of secure input for about half a second and takes it back (for example 5.1 and 5.6 s after two locks, for 0.66 and 0.59 s). A password arriving in that moment is refused before any attempt is spent, and the page tells the person to try again. The driver now does the same: at most two more tries, 1.5 s apart, each waiting for the page's answer, recorded as `notReadyRetries`. Deadline cases type once.
16. Two earlier attempts at this were wrong and are withdrawn: waking the display (`caffeinate -u`) at the start of each case, then right before the grant. With the first in place the refusal rose to 6 of 16 passwords in one run. The wake is kept only ahead of deadline typing, where ten idle minutes is also the Mac's display-sleep time.
17. The leftover-process rule counted any input helper. A helper that refused the password before reserving belongs to no duty; with its server frozen it stays up. The rule now looks only at the guard and typist the duty recorded.
18. The leftover-process rule counted zombies. In case 12.1 the proof server is frozen on purpose, so it cannot collect its exited children; the typist and the guard both lingered as Z after finishing and were matched by pid as "still running after the duty closed" (clean run 20:15 PST and two reruns). `processes()` now reads `stat` and drops zombies (`parseProcessList`), and the evidence records their pids as `zombies`.

Measurement history can retain the exact method and targets used by earlier evaluations. Original baselines stay available while their current contract still refers to them, with conflicting records preserved rather than hidden. Missing archives and storage limits remain visible evidence gaps; ordinary services continue.

The existing feature board now has a measurement coverage panel. It reads feature switches, decision points, jobs and work items independently of the review table, so missing measurements stay visible. It separates recorded comparisons, missing links, inactive evaluations and sources that cannot be read.

Whole efforts, jobs, decisions and capabilities can use optional measurement contracts on existing initiatives. Generic results have separate counts and cannot borrow feature proof. A decision-quality adapter keeps settled quality and unknown coverage separate, with explicit gaps when current evidence or evaluation capacity is missing. Ordinary services continue.

The existing coverage board can open one work item's recorded measurements. It shows baseline/current values, samples, current targets and numeric history, with outcome and quality measurements separate. Gaps and source/version changes stay visible rather than becoming a continuous progress line.

The iPhone app's session screen now has the dashboard's controls. A new menu shows the machine, door and model, switches door and model, moves the session to another machine, closes it, and shows its details. The screen gains a keys tray with Stop, photo and file attachments, a History tab, and a "+" on the sessions list for a new session with its default door and model. Sessions on other machines now open through the machine the phone reached. Every control runs the dashboard's own route, so existing rules and refusals stay in force, and ending, moving or starting a session takes Face ID for that exact action.

Recommended services gains its second setup recipe, for Tailscale (`tailscale-v1` in `src/recommended/recipes.ts`). It stays dark: like Jev's, it only runs on a throwaway or development agent that lists it under `recommendedServices.provingRecipes`, and offers stay off everywhere (`offersLive: false`).

The recipe's brief has the setup session check whether Tailscale is installed and install it without administrator rights where it can, take care of the Linux operator step, start Tailscale's sign-in and send the person its one-tap link, then call the check. It never uses an auth key, a stored credential or a browser login of its own, and never signs out or moves a machine that is already on a tailnet. If it can't finish, the agent stays reachable through its backup (Cloudflare, the local network or messaging).

The check reads `tailscale status --json` (the program on PATH first, then the Mac app and the usual install folders). It passes only when the machine is signed in, has a private address and is online, and its words never include an address, device or account name. A hung Tailscale answers "unknown", so a yes starts nothing until it can be read. A recipe can now declare that it keeps no secret, and the key route refuses one for it.

The outbound link check now lets Tailscale's sign-in host (`login.tailscale.com`, that exact host only) through. In the live run it refused the sign-in link, the recipe's one step for the person, even after the link came from tool output.

When a new agent pairs its second machine, takeover is now turned on for that pair. If the machine in charge goes down, the other one takes over. Pairing writes `multiMachine.leaseSelfHeal.soloCaptainHold.enabled` and `requireLastingLink` on both machines, plus each machine's role.

Safeguards:
- Pairing now swaps lasting addresses (LAN, Tailscale or a named tunnel, never a quick tunnel).
- The joining machine takes over only after it has a signed answer from its partner over one of those addresses, recorded in `state/lasting-link.json`. Until then the first machine serves alone, so two machines that cannot reach each other never both answer.
- LAN detection now recognises Linux interface names such as `enp7s0`, and cloud `/32` interfaces pass the LAN check.

Agents already paired are unchanged. To turn takeover off on a pair, set `soloCaptainHold.enabled:false` on both machines and restart each. Reverting the release alone is not enough.

Dashboard and app session lists now resolve titles from durable conversation records, retain meaningful saved/peer names when adapter caches are absent, and correctly distinguish app and Slack aliases from Telegram topics. Job runs use their job definition name. Pool reads can recover known Telegram titles without confusing machine-local aliases.

Private-memory sessions on macOS can send Slack replies without Bash trying to create a forbidden temporary file. Existing shipped reply helpers migrate to the corrected template; customized helpers remain preserved.

Replies on a busy machine no longer wait behind four separate faults in the Telegram outbox.

- The scan for late or out-of-order replies took 39 s on a real 652 MB store and blocked every send. It now reads a page in index order and looks only at replies written around the same time: under 100 ms a page on the same data (the first, cold page 419 ms), with identical answers on all 1117 rows.
- Node's 250 ms per-address connect window produced false `ETIMEDOUT` failures when the event loop paused. Bot API requests now get 5 s, through their own dispatcher.
- A config read that only ran out of time no longer refuses every send. Its budget is 10 s, and the last snapshot keeps its normal 30 s bound. A real refusal, or a change on disk, still revokes at once.
- Recovery runs every 30 s when the origin outbox owns it, and the wait between recovery starts for one message goes 30 s, 1 m, 2 m, 5 m, then 15 m. The legacy lane stays at 5 minutes.

No send path was added, and a message whose outcome is unknown still never retries by itself.

## What to Tell Your User

Nothing yet. This is switched on only for development agents, where it watches and records without refusing anything.

When the Instar iPhone app shows a dashboard page inside its own screen, you see just that page, without a second set of bars. The dashboard in a normal browser looks and works as before.

A model appearing in the inventory means it has a recorded definition. It does not mean it can run this task. Missing inventory sources remain visible.

On the remote desktop page, the Stop button now works while the Mac's password box is showing. Before, the password box covered it.

I can distinguish a written baseline from one backed by recorded data, and show the current comparison and its gaps. A numerical change alone is not a claim that something improved.

If I run on Linux, I can now restart myself when I get stuck, the way I already do on a Mac, and I pick up new versions after big updates without waiting for a reboot. This starts after my next restart. On any machine, if restarting myself doesn't fix a problem after a few tries in a day, I stop retrying and tell you instead of looping.

The board shows which work has a recorded baseline comparison and where evidence is missing. Coverage is not proof that outcomes improved. Expand a group to see the gaps.

Open Show measurements to see what changed and which evidence is missing. A numerical change is not automatically an improvement. The view says when a baseline, source or historical evaluation method cannot be checked.

From the session screen in the app you can now change the door or model, move the session to another machine, attach a photo or file, press keys like Enter and Stop, read its history, and close it. You can also start a new session from the sessions list, and open sessions running on your other machines. Anything that ends, moves or starts a session asks for Face ID each time. If a machine has typing from other machines switched off, the app says so and offers to move the session.

Nothing changes for you yet. Your agent is learning to set up Tailscale for you, so that later you can reach it from your own devices with one tap on a sign-in link. It only runs on test agents until it has been proven.

If you set me up on a second machine, the two now cover for each other. If the one in charge goes down, the other picks up your messages within a couple of minutes. That needs the two machines to be able to reach each other directly, on the same network or over Tailscale. If they can't, I'll tell you when you pair them, and the first machine keeps working on its own.

Your dashboard and app keep showing the conversation name when its session is replaced or an adapter's title cache is missing.

The owner repair link keeps privacy enabled, and the repaired agent can now send its answer back to the private Slack channel.

Your replies should stop getting stuck when this machine is busy. If a send does hit a brief problem, it's tried again within about a minute instead of up to 25 minutes later. You may see a few notices about older replies that arrived late, as those checks can now finish.
