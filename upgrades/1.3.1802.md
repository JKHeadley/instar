## What Changed

New read-only `GET /preferences` returns the learned preferences as structured entries (`dedupeKey`, `learning`, `recordedAt`, `confidence`, `dedupeCount`, optional `origin` and `textRedacted`) with `total`, `truncated` and `scope`. It uses the same gate (`monitoring.correctionLearning.enabled`, 503 when off) and the same source precedence as `GET /preferences/session-context`, never serves `violationPattern` or provenance, and scrubs credential-shaped text. The console's "What I've learned about you" page reads it to show when each preference was last seen, a "New this week" mark, and the machine that learned it; on an older server it falls back to the session-context block. CLAUDE.md gains one line about the route.

## What to Tell Your User

The "What I've learned about you" page now shows when I last picked up each preference, marks the ones that are new this week, and on several machines says which one learned it.

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| Dated list of learned preferences | `GET /preferences` (owner token; 503 when correction learning is off) |
| Dates and "New this week" on the Learned page | Automatic in the console |

## Evidence

Before: the Learned page parsed the session-context text block, which carries no dates, so it could not say when a preference was learned. After (tests/integration/preferences-list-route.test.ts, tests/e2e/preferences-list-alive.test.ts): `GET /preferences` answers 200 with dated entries newest first, 503 when correction learning is off, and a credential in a stored lesson comes back redacted; the jsdom page test shows "last seen" dates and the "New this week" pill, and the 404 fallback still renders the old list.
