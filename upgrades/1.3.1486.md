## What Changed

The feedback executor now records the changed relative paths and change types in its existing bounded audit when a drafted design fails the one-spec-file shape gate. This fixes the loss of diagnostic evidence when the rejected attempt workspace is removed. The same change set includes test repairs for Telegram cleanup timing and isolated HTTP route fixtures.

## What to Tell Your User

When a feedback design is rejected because extra files changed, the agent can now see which files caused the rejection and correct the next attempt. The safety rule that allows only one new design file remains in force.

## Summary of New Capabilities

- Rejected feedback design attempts leave a bounded audit of changed file paths and change types.
- The executor continues to reject drafts that change more than the permitted design file.

## Evidence

The October 26 attempt ended with “expected exactly one new file, found 7 changes,” but its deleted workspace left no list of those files. A unit test now creates a valid draft plus an extra source file, verifies that the attempt is rejected, and verifies that both changed paths and their types appear in the audit. The full unit, integration, and end-to-end suites passed with zero failures.
