## What Changed

SEC-147, step one of three. A signed request between an agent's machines names its sender but not the route or the machine it is for, so a copied request could be replayed to another machine of the same agent within its 30-second window. This release teaches every machine to check an optional second signature, `X-Signature-V2`, over the method, the request path and the receiving machine's id (`machineAuthV2Message` in `src/server/machineAuth.ts`). When it is present it must verify: otherwise the request is refused as `binding-mismatch`, before any replay state is claimed, without counting as evidence against the sender's key, and with a rejection the receiving machine signs (`X-Machine-Auth-Reject`, also carried on the WebSocket upgrade's 403). The rejection names that one delivery and is signed only for a request that could still have been admitted, so an old or already-run request gets the ordinary anti-replay answer. A request without it is accepted exactly as before, and no machine sends it yet: sending is step two, and refusing the old form is step three, each a later release. Each machine also counts, per sender, the requests it admitted with and without the new signature and those it refused, as evidence for the later steps.

## What to Tell Your User

- **Groundwork for safer machine-to-machine messages**: "My computers can now check a stronger signature on the messages they send each other, one that says which computer a message is for. Nothing changes yet; they start sending it in a later update."

## Evidence

- `tests/unit/machine-auth-binding.test.ts` (new, 14): accepted only over the same method, path and machine; each changed in turn is refused; the rejection verifies under the receiver's key and names the refused nonce; a refusal leaves replay state unchanged; an already-admitted request replayed with a bad binding gets no signed rejection; a v1 signature cannot pass as v2; the full mounted path is used; the original replay is refused at the other machine when bound.
- `tests/e2e/multi-machine-http.test.ts` (+2): on two real servers, a bound heartbeat is accepted and one bound to another route is refused with a signed rejection.
- `tests/unit/WebSocketManager.test.ts` (+3): the upgrade's 403 carries the rejection and drops a header that could split the response.
