## What Changed

- **⚗️ Experimental, and off unless you switch it on.** A paired agent can now get its own Telegram topic, named `"<peer> · Threadline · <id>"`, as the home for notices about that agent. It is created when a pairing becomes mutually verified. Nothing changes until `threadline.peerHomebase.enabled` is set, and this release ships only the first two parts — the topic and the record of who chose it.
- **Why it exists.** A request from a paired agent landed in an unrelated conversation the operator had no reason to look at, so he never saw it. One topic per paired agent means there is a place to look.
- **Your own choices are protected, deliberately.** Each conversation now records *who* chose the topic it posts into. A topic **you** chose is never overridden. A topic whose origin is unknown — anything bound before this shipped — is **left alone**, because it may well have been your deliberate choice. Only a conversation with no topic, or one that merely inherited whatever topic it happened to start in, is re-pointed. Moving an older conversation onto a peer's new topic stays something you ask for.
- **Creation can fail without breaking anything.** Only the machine currently serving creates the topic (so two machines cannot mint two), and if creation fails — no forum, Telegram unreachable — the pairing still succeeds and the agent simply has no homebase, which falls back to today's behaviour.

## What to Tell Your User

Nothing to do. If you run more than one paired agent and want each one's notices in its own place, this is the start of that; ask your agent to switch on the per-peer homebase topic. Existing conversations stay where they are until you ask for one to be moved.

## Summary of New Capabilities

- `threadline.peerHomebase.enabled` (default off): create a dedicated topic for a mutually-verified peer agent at pairing.
- Conversations record the provenance of their bound topic (`operator` | `origin-inherited` | `peer-homebase`), so a deliberate choice can be told apart from an accidental one.

## Evidence

- 45 tests across the four affected files: the naming rule (including two peers who share a display name), every row of the binding decision — notably that an unknown-origin binding is preserved, which an earlier draft got backwards and would have destroyed deliberate operator choices — the serving-machine-only and find-or-create-once guards, and the awareness card appearing for both a new agent and an upgrading one.
- A test pins the two awareness-card guards as independent, because nesting the new card under an existing card's marker would have meant an agent that already had the old card could never receive the new one.
