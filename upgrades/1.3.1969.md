## What Changed

SEC-137. A single-line inbound message is typed into the session with `tmux send-keys -l`, without the bracketed-paste wrapper, so a control byte inside it reached the terminal as a key press. `\r` submitted the tagged part early and sent the rest as a separate turn with no sender tag; `\x15` (Ctrl-U) erased the sender tag so a forged one could follow; `\x03` or ESC could interrupt the running turn. `rawInject`, the chokepoint every inbound message passes through, now turns `\r\n` and a lone `\r` into `\n` (so a multi-line message takes the bracketed-paste path) and drops every other C0 control except tab and newline, DEL, and every C1 control (`neutralizeTerminalControls`, `src/core/terminalControlBytes.ts`). The same cleaning (`sanitizeTypedText`) now also covers the peer-agent live-session typing path in the server and the pending first-message record, and a single-line message containing a tab goes through the bracketed paste. Ordinary text, including emoji, accents and every script, is unchanged.

## What to Tell Your User

- **Safer message delivery**: "Hidden control characters in a message can no longer press keys in my session, so nobody can cut off or fake the tag that says who sent it."

## Evidence

- `tests/unit/headless-spawn-reroute.test.ts`, "SEC-137 repro" (from the security-review job, fails on main): a message with `\r`, `\x15`, `\x03` and ESC reaches `send-keys` with no control byte.
- `tests/unit/terminal-control-bytes.test.ts` (new): CR and CRLF become newlines; keystroke bytes, DEL and C1 are dropped while tab and newline stay; ordinary text in several scripts and emoji is byte-for-byte unchanged.
