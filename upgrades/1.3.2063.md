## What Changed

Accounts now opens grouped by provider, with the soonest weekly reset first in each group. Use **Group by** to switch to machine groups or a single list, and **Sort by** to order by weekly reset, most used, or name. The dashboard remembers your choices in that browser.

Accounts now has a usage list and a separate sign-in repair section. The usage list shows each account and keeps the existing grouping and sorting controls. It uses the newest available reading for each quota window from any machine. The sign-in state sits on its own line and the row says when a reading is unavailable. Repair status starts with a summary per machine. Open it to see the affected accounts. Machines with every account signed in share one summary. Routine sign-in gaps stay with the agent.

Delayed Accounts sign-in steps and dialog timers now belong to the page and dialog that started them. A request already sent to a computer can still finish. Visible account buttons continue to work while the list refreshes. Sort and group choices remain available when the list refreshes. The weekly forecast remains on the page.

The native Accounts read now includes an opaque grouping key for each machine with an account slot, along with the existing sign-in status for that slot. This lets the Mac app group Accounts by machine even when two machines have the same name.

## What to Tell Your User

Choose how you want to see Accounts. The layout changes immediately, and your dashboard remembers it when you return.

The Accounts page shows usage and reset times first. A separate section shows which sign-ins the agent is checking or fixing on each machine.

If you leave Accounts while a computer is starting or repairing a sign-in, your new page keeps its own dialogs. You can return to Accounts to see the latest result.

An updated Mac app can group your accounts by the machines that actually have them. Existing app versions continue to show Accounts the same way.

## Summary of New Capabilities

The repair section can identify a machine that answered with no accounts. A machine that could not be checked is reported separately.

There is no new setting or action. This repairs the existing Accounts flow.
