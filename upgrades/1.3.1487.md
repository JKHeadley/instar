## What Changed

- `authMiddleware` no longer exempts every `/threadline/*` path from the bearer check. Only six peer-protocol routes (plus `GET /threadline/blobs/:id`) stay open, matched by exact method and path, because another agent must reach them and each enforces its own authentication: `GET /threadline/health`, `POST /threadline/handshake/hello`, `POST /threadline/handshake/confirm`, `POST /threadline/messages/receive`, `POST /threadline/threads/backfill`, `POST /threadline/secrets/request`. Everything else under `/threadline/` (relay-send, relay-discover, status, hub/bind, telegram-bridge/config, observability, conversations, peers health, negotiator, pairing, thread reads) now needs the agent bearer like any other route. (fb-829a7161-942: an unauthenticated POST over the public tunnel reached `/threadline/relay-send`'s field validation.)
- The Threadline MCP stdio helper sends the bearer on its relay-status read, and resolves the token from a third source when neither the session environment nor a plaintext config carries it: the encrypted vault (`resolveMcpAuthToken` in `src/threadline/mcpAuthToken.ts`). The `{ secret: true }` placeholder is never used as a token.
- The job-template auth lint mirrors the exact public list instead of treating `/threadline/` as a public prefix.

## What to Tell Your User

Nothing to do. One door that should have been locked now is: before this, anyone who knew your agent's public tunnel address could make it send agent-to-agent messages under its own name. Your own tools, dashboard and paired agents keep working as before.

## Summary of New Capabilities

- None; a security fix.

## Evidence

The new integration test replays the reported request (tunnel headers, no token, empty body) against the real middleware and routes: on the previous code it fails with "expected 400 to be 401" and a forged well-formed send reaches the send path (503 relay-not-connected); with the change both are refused with 401 and the tokened request reaches the handler. Unit tests cover all 25 own-surface routes (refused without a token, passed with it), the six public routes plus blob fetch (open by exact method+path, prefix/suffix look-alikes gated), the helper's token resolver (env → config → vault, placeholder never used, locked vault yields nothing), and the lint change. Real-server threadline e2e suites (local route, backup routes, signed envelope, pairing production path, stdio send) pass unchanged because every legitimate caller already sent the token.
