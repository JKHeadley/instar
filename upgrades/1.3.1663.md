## What Changed

A sender is no longer left guessing whether another agent saw its message. When a message reaches the other agent's server but no session can take it yet, that server now says so at once, and says again if the message is later lost, including to a restart. When a session does get it, the session is asked to acknowledge it with a one-line summary in its own words. If it says nothing, it gets one reminder at 5 minutes, and at 15 minutes the sender is told "a session has this and hasn't acknowledged it", which stays true if the session is simply busy.

These receipts go only to an agent that has said it understands them, and an older agent receives nothing new. A receipt never starts or wakes a session on either side, nothing is typed into the sender's session, and nothing blocks a session or a message. The sender finds them on its peer health read, in thread history and on a timed-out wait. This reverses an earlier decision against a "queued" receipt; the reasoning is at `describeUndeliveredRouterResult`. Separately, a message held behind a full session limit now starts within about a minute of a slot opening, rather than waiting the full 8 minutes.

Routine Agent Health reports now stay in the attention record without sending Telegram messages. A report explicitly marked as needing the person can still reach the Agent Health topic. HTML formatting now survives a standby machine's relay to the Telegram holder.

After a rejected Claude sign-in key is fixed, every conversation that was waiting now gets a real answer. Each restarted conversation is given the messages that arrived during the outage and the exact command to reply. When messages were held, a restart counts as done only once a reply shows up; if none does within 15 minutes, the person is asked to send again and the miss is reported. With nothing held, nobody is asked. The check is per conversation: it confirms a reply, not that each held message got its own answer. Telegram is covered by tests; only Slack has been proven live so far. `slack-reply.sh` in a bound Slack session now ignores a channel id passed out of habit. Before, it posted that id as the message and dropped the real reply. The operator warning counts as delivered only when a person can read it: if the Slack alert channel has none of the agent's people in it, each of them gets a direct message.

Feedback executor change sets may now contain up to 5 MiB of valid UTF-8 text, enough to modify the current `server.ts` and `routes.ts` pair with focused tests. Binary or invalid UTF-8 content keeps the former 4 MiB aggregate limit. The 200-file ceiling, credential scan, confined workspace, independent review, and test/CI gates remain.

The memory-privacy spec and the maturation board now say what has shipped since 1.3.1657: memory privacy is off by default and on only when an owner turns it on. The board gains a memory-privacy entry whose last rung is "off by owner preference", decided by Justin on 2026-11-04, with a development-agent rung that still has to earn its evidence. No runtime behaviour changes.

With memory privacy turned on, a Linux agent saved memory correctly but could not answer anyone: the sandboxed session has its own network, so its reply scripts could not reach the agent's server (curl exit 7). Each scoped session on Linux now gets a small curl setting in its own folder that sends requests for the agent's server through the sandbox's own proxy, which already allows it. The session reaches nothing it could not reach on macOS. macOS is unchanged, and so is every agent with memory privacy off (the default).

A session's tmux name is reused when a conversation returns to a machine, and lookups by name could pick an old finished record instead of the live session. When a conversation moved away, that could leave the live session running on the machine it had left. Every lookup by name now picks the live session.

## What to Tell Your User

When you ask me to reach out to another agent, I can now tell you what really happened instead of "they still haven't replied": whether their server is holding it, whether a session has read it and what that session understood, or that it was lost. This needs both agents to be on this version, so an older agent still shows as unknown.

Agent Health is quieter: I keep my own machine and session reports in the record, and message you only when I need you to act.

If my sign-in key stops working and you fix it, I'll answer what you sent while I was down. If no answer comes, I'll ask you to send it again. Warnings about my key now reach you directly, even if you never joined my alert channel.

The executor can now submit a small fix that touches two large Instar integration files for review. This removes one measured size blocker; a fresh fix still has to pass review and tests before it reaches users.

Nothing changes unless you turned on memory privacy on a Linux machine. If you did, people now get replies again; their facts stay as separate as before.

Nothing to do. On an agent with several machines, a conversation that moves back and forth no longer leaves a stray copy behind.
