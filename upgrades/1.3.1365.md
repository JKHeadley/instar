## What Changed

The dashboard New Session box could pick a topic's door and model but not the machine it runs on, so a dashboard topic always started on the lease holder. Spec: `docs/specs/dashboard-new-session-machine-choice.md`.

- **Machine select** in the New Session box: Automatic (default) plus every pool machine. Offline and clock-out-of-step machines are listed but cannot be picked. The serving machine is labelled "(this machine)". A remote pick lists THAT machine's doors and models (`GET /topic-profile/options?machine=`). The select is hidden on single-machine installs and for Slack/headless.
- **`POST /sessions/create` `machine`** (nickname or id; needs `X-Instar-Request: 1`).
  - This machine: the existing create saga runs, plus a pin.
  - Another machine:
    1. A signed mesh probe of the target (`session-status`, the plane the start rides), then a door/model pre-flight on it (`POST /topic-profile/validate-choice`).
    2. The topic is created.
    3. Ownership is placed on the target and ONE checked signed `deliverMessage` carries the door/model (`startTopicOnMachine`).
    4. Ownership settles by outcome: accepted → claim + pin, 201; unknown → claim + pin and keep, 202 `started: 'unknown'`; refused → claim + release, NO pin, 502 `start-remote-failed` (the topic is left for ordinary placement, never stranded on a machine that refused it).
    5. After an accepted or unknown start the creating machine posts one line in the topic: "This topic is assigned to <machine>; its session is starting there. Requested: <door · model>." (the unknown variant says no confirmation came back).

  Refused before anything is created: `unknown-machine`, `machine-offline`, `machine-clock-suspect` (only `suspect-clock-removed`, the status placement itself removes), `machine-needs-update`, `machine-choice-unavailable` (pool dark or pin replication dark), `machine-needs-telegram`, `machine-invalid`, `machine-unreachable` (`reason: 'mesh'` when the target does not answer the signed probe, `reason: 'peer-auth'` when it holds a different API token), and a target-refused explicit door/model. A claim lost to another placement generation during the start (another owner, or a newer placement on the same machine) answers 202 `ownership: 'superseded'` with no pin and nothing released.
- **Owner side:** a new first branch in the `deliverMessage` `onAccepted` (`createDashboardCreateStartRunner`) seeds the profile, re-validated on the target, then spawns silently under the spawning guard. A forwarded message that arrives mid-start waits up to 60 s for the binding instead of spawning a second session (at most 32 such waits on a machine; past that the message takes the inbound error path at once). Corrections (door refused, model not applied, spawn failed, session started but not bound) are posted by the owner.
- **Heartbeat** advertises `seamlessnessFlags.dashboardCreateReceive` (pool not dark, Telegram configured, topic-profile wired). `GET /pool` gains `selfMachineId`.
- **CLAUDE.md:** a "Dashboard machine choice" line after the door + model line. `migrateClaudeMd` inserts it idempotently and it is added to the shadow-slice markers.

## What to Tell Your User

When you start a new conversation from the dashboard, you can now choose which of your computers runs it. There is a new Machine choice under Door and Model. It starts on Automatic, which works just like before. Pick one of your machines and the conversation starts there straight away, on the door and model you chose; I check that machine can actually run them first, and the conversation gets one line saying which machine it is assigned to. A machine that is off, or out of step, is shown but can't be picked, so a conversation never quietly ends up somewhere else. If the machine you picked refuses the start, the box tells you and the conversation is left unassigned rather than stuck on it.

## Summary of New Capabilities

- Choose the machine a new dashboard conversation runs on.
- The door and model list follows the chosen machine.
- Machines that are offline, out of step, or not yet updated are shown but refused, with a plain reason.
