## What Changed

On a fresh Linux server the sandbox used for private memory needs two packages. The agent now installs them at startup if it has passwordless sudo, instead of only reporting that they are missing.

When an agent serves more than one person, one person's remembered facts could reach another. Each conversation now has an audience set by its place: a private chat serves one person, and a channel or group serves everyone who can read it.

Each audience has its own memory folder. Sessions outside the owner's private chats run in an operating system sandbox and hold a limited key that the server refuses everywhere except a short list. If the sandbox cannot start, the agent sends a fixed reply and does not run unprotected.

A Slack reply now goes to the thread its message came from.

The Instar iPhone app can now show the agent's accounts, spending and resource use natively. Three new read-only routes answer a paired owner phone (or the agent's token): `GET /mobile/accounts` (each subscription account once, with its login email as the console shows it, signed in or needing sign-in on each machine, usage windows highest first with reset times, and how old the reading is; accounts needing sign-in first), `GET /mobile/spend?window=today|week|month` (recorded pay-per-use cost with how each figure was worked out, added across the machines that answer with each machine's own state, this machine's paid routes with committed spend against their limits and whether limits enforce, conversation token totals, and exactly what period each figure covers) and `GET /mobile/resources` (CPU and memory for the agent, its server and each session on this machine over the last hour, with old readings marked by age). They are trimmed summaries of what the console's Accounts, What thinking costs and Resource usage views show: no login folders, machine or account ids, credential references or raw errors. Only owner phones may read them (an MSP phone gets 403 `owner-phone-required`); they share their own 20-per-minute allowance, and pool-wide answers are built at most once every 15 seconds. The raw `/subscription-pool`, `/routing-spend/*`, `/tokens/*` and `/resources/*` routes stay closed to phones. A failed read records a `MobileCapacityScreens.read` degradation. The console's pool account view now names a peer's accounts by the machine that was asked, never by a name the peer supplied.

The Instar iPhone app can now show the agent's schedule, promises and machines natively. Three new read-only routes answer a paired owner phone (or the agent's token): `GET /mobile/jobs` (every job with its schedule in plain words, last run and outcome, next run, and whether it is late or failing, late or failing first, merged across the machines that answer), `GET /mobile/commitments` (open promises first with their due dates and what they are waiting on, then those closed in the last week) and `GET /mobile/machines` (each machine by name with a plain status line, load and Instar version). They are trimmed summaries of what the console's Schedule, Promises and Machines pages show: no job instructions, scripts, file paths, hostnames, machine ids, tokens or settings, and free text is secret-scrubbed and shortened. An MSP phone gets 403 `owner-phone-required`. The raw `/jobs`, `/commitments` and `/pool` routes stay closed to phones. A failed read records a `MobileOpsScreens.read` degradation instead of failing silently.

Telegram approval buttons no longer accept anyone when no owner is known. Prompt-gate buttons and typed answers need the configured owner or the one verified operator. Tunnel consent needs the configured owner. Pairing taps refuse a tap with no chat id. A non-owner's typed reply is no longer taken as a prompt's answer, though the text can still reach the session as an ordinary message. An agent that has met someone but can't confirm a single owner records this at startup.

Groundwork for recommended services, with no offers sent. The door and Tailscale setup steps moved out of the install command so the server can run them later. New agents are marked ready for offers when created, and existing agents wait until their own first list ships. Agents also note the first reply Telegram or Slack accepted. The recommended services route reports both values.

## What to Tell Your User

Nothing to do. On a new Linux server, private memory now sets itself up when it can.

If you are the only person using me, nothing changes in our private chats. In a channel with other people, I now keep your private memory out, so I may know less there. If several people use me, each person's memory stays theirs.

Once the app update with these screens is on your phone, your agent's page in the app has a "Capacity" section: Accounts, What thinking costs, and Resource usage. Accounts that need signing in are at the top, each account shows how much of its 5-hour and weekly limits is used and when they reset, the cost screen adds up what AI use cost across your machines, and the resource screen shows what is using the computer. If a machine is offline or didn't answer, the screen says so. These screens only look: signing in and spending limits stay in the dashboard. Only the owner's phone sees them.

Once the app update with the new screens is on your phone, your agent's page in the app has an "Is everything up?" section: Schedule, Promises, and Machines and health. Late or failing jobs, overdue promises and machines that aren't answering are at the top, and you pull down to refresh. These screens only look; nothing on them changes anything. Only the owner's phone sees them.

Approval buttons in Telegram now only work for you, even if your owner was never set up explicitly. If a button ever says I can't confirm who my owner is, tell me. Usually your message settles it. If I still can't confirm, I'll say so.

Nothing changes for you yet. This prepares your agent to recommend helpful services later.

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| Sandbox tools installed at boot | Automatic on Linux with passwordless sudo |

| Capability | How to Use |
|-----------|-----------|
| Memory privacy status | `GET /memory-privacy` |
| Name people who share memory freely | `memoryPrivacy.sharedMemoryPeople` in `.instar/config.json` |
| Switch it off | `memoryPrivacy.enabled: false` in `.instar/config.json` |

- The owner's phone can see every subscription account, whether it is signed in on each machine, and its usage and reset times.
- The owner's phone can see what AI use cost across machines, how each figure was worked out, and whether spending limits are enforcing.
- The owner's phone can see CPU and memory use for the agent, its server and each session.

- The owner's phone can read the agent's schedule, with late or failing jobs first.
- The owner's phone can read the agent's promises, open ones first with due dates.
- The owner's phone can see each machine's status and version, alongside the agent's health.

No new capabilities. This closes a gap where an unset owner meant anyone in the chat could answer.

No new capabilities. `GET /recommended-services` now reports `migrationComplete` and `firstResult`.
