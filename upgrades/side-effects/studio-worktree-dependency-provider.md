# Studio worktree dependency provider

The normal CLI checks a disabled-by-default machine setting before its existing dependency preparation, SQLite smoke check and Husky setup. A verified seed produces a private copy-on-write graph. A clean miss uses checkout-private npm installation. An integrity failure or occupied target stops preparation visibly. Disabled and explicit no-share retain their former paths.

The helper and seed receipt are pinned in the authority of the agent's local configuration. The checkout only supplies its recipe data. The verified graph must be confined to the destination after copying. No seed, native ABI, executable path or credentials are replicated through the worktree ledger.

The new path is synchronous inside the CLI's existing worktree creation lock. The provider has a bounded timeout. A failed staging attempt may leave an inert private staging directory for inspection. It does not proceed to a writable link or remove an unrelated target. Worktree retirement and existing-checkout migration are separate scope.

Independent safety, integration and decision review findings are recorded in the convergence report. The separately invoked external reviewer failed to return findings. The Studio setting stays disabled during the candidate verification.

A disposable APFS volume reported 6,397,952 additional bytes for the verified clone while file-based checkout accounting reported 767,713,280 bytes. The scoped volume benchmark took 9.964 seconds. The normal Studio worktree counter still sums file allocation, so it cannot report these shared physical blocks as reclaimed. Native readiness and the real Git integration fixture passed.
