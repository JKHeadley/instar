# Local Source logical capacity ledger (component only)

New opt-in class GraphSourceCapacityLedger requires an explicit byte policy, actual canonical local state root, enrolled MachineIdentityManager, owned SingleInstanceLock and owner trust key. It is NOT wired into production Source, Runtime or W admission in this component checkpoint. Existing Source ACK semantics and defaults are unchanged.

reserve(original) verifies original owner-pinned control/packet and exact encrypted bundle, serializes actual local signed hash-only charge publication, fsyncs retained inode/directories and readbacks. Concurrent same-root instances share a serialization queue; cold reload revalidates actual signed rows. No plaintext application content, ciphertext or key envelope is written to ledger rows. Actual managed-store file sizes are conservatively charged in addition to logical reservations; already-promoted originals can therefore currently be double charged. No release/refund/promotion API exists. Unknown capacity files and uncertain scratch prevent new logical admission; errors and failed fsync return no token.

Required policy separates durable, transient and metadata byte limits and configured future sidecar/row overhead. There are NO new default byte limits. The transient estimate charges two copies of exact record+shared-context bytes plus configured overhead. Configured future overhead is not a demonstrated worst-case storage guarantee. Shared context logical bytes are charged once per actual context hash. Existing physical duplicates remain separately charged.

This ledger allocates no disk extents, blocks, preallocated files or filesystem quota. Both inspection and minted token always expose physicalHeadroomProven:false and readyForSourceAck:false. Logical credit alone must never authorize Source ACK, Native action, transfer receipt, Saved or Committed. Physical allocator/provisioning, actual-source integration, exact row promotion/reclamation and v2 large-state proof remain unfinished work requiring review. No awake peer is needed to create local owner Recorded/Pending; later each node must obtain its own real credit before its own Source ACK.

Files: state/conversation-graph-capacity/<SHA256 opaque event ID>.json, signed domain graph-source-local-capacity-v1. Rows have immutable original packet/record/context commitments and numeric charges, agent/self/policy hashes only. Changed policy is failclosed until an explicit reviewed migration exists. Counter rollback with all local authority copies restored remains outside this component's freshness guarantees.

## Later opt-in composer delta

Source now has an optional actual capacityLedger option, and Intake a once-only bindCapacityLedger(actual) port. These component ports are NOT wired by Runtime/default/W. Source uses actual original file fsync/reopen/decrypt plus fence/current Native context/generation checks before its own new positive Source receipt; Intake credit precedes reservation publication. Normal original receipt cold repair uses the same proof only when explicitly opted in; existing valid original receipts remain untouched. Immutable original credit excludes mutable proof sidecars. Source-private actual proof says readyForSourceAck only for local durable-original/internal-policy scope and always futureRecoveryReady:false/physicalHeadroomProven:false. Existing whole-stage cleanup-view limit remains a separate known blocker; do not enable this as full recovery admission. All three production component deltas require independent review before wiring. No transient release or new default was introduced.
