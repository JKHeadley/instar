# Side effects of fixed worker pilot permit reception

The fixed child accepts one scoped first-claim permit in an explicit pilot mode. It checks the actual registered run and canonical private state directory under the disposable test-deploy root. The built-in generated synthetic artifact is the only input that passes the owner, descriptor and digest checks. The stream still validates the exact body and final EOF before it announces the plan. The exact committed permit is verified by the planned store under the same writer lock before mutation.

The child refuses disconnect, wrong response, wrong permit identity and changed plans. Its registered allocator stays open through the operation and holds process custody until actual exit. A failure can leave an admitted claim in the disposable home and must be reported as uncertain by the future parent coordinator. The existing preview protocol only accepts discard.

The receipt is tested against the actual fixed child using a registered run, a real reservation and generated synthetic data. No server route or production apply authority is enabled. Reverting the fixed-child pilot mode restores the previous discard-only behavior. No storage-format migration is needed.

Independent rereview concurred. The bounded fixture rejects ordinary artifacts, outside and symlinked state directories, and executes only the exact committed synthetic first claim in the fixed child.
