# Side-effects: an account with no stored credential is noticed (every-poll engine login read)

Tier 2 (it changes when an account is marked needs-reauth, which starts the automatic repair). Built under the approved, converged spec docs/specs/never-silent-conversation.md §3.6 (CMT-1781 item 3); the spec section is amended to record the build and its keychain guard. 6 source/test files, about 200 lines. Effort: no new spec rounds (approved spec), one commit attempt so far.

What changed: `QuotaPoller` takes an optional `engineLoginSignedOut(account)`. When an account's stored credential cannot be read at all (`credential-absent-or-unreadable`), the poller asks it. `true` (a trusted NO) shows `loginCheck: signed-out` at once; two such answers at least 5 minutes apart move the account to `needs-reauth` with the new cause `cli-auth-status-signed-out`, which `ACTIONABLE_CAUSES` admits. The server wires it to `engineTrustedSignedOut(framework, home)` in `src/providers/adapters/engineSessionHooks.ts`: the engine's own login reader (`claude auth status`, canary-proven) must say NO **and** the engine's credential store must be open (`ENGINE_CREDENTIAL_STORE_OPEN`: macOS `security show-keychain-info` exit 0; non-macOS the store is a file, so open).

1. Over-block: none; this blocks nothing.
2. Under-block / false positive: the risk is marking a working account needs-reauth, which would start a needless repair. Guarded three ways: the credential must be unreadable (not merely expired), the engine's own check must say signed out with its empty-home canary proven, and the login keychain must read unlocked; and it must hold on two polls 5+ minutes apart. A locked keychain (the reason this case was excluded before) answers null and resets the streak. A swap or re-point that briefly empties a slot is shorter than the 5-minute gap.
3. Level of abstraction: engine specifics stay in the adapter table; `QuotaPoller` sees one boolean. No framework-id literals added to core.
4. Signal vs authority: the poller already had authority to mark needs-reauth from corroborated evidence; this adds one more corroborated source of the same transition, through the same `markNeedsReauth` + ledger observation path.
5. Interactions: the repair runtime admits the new cause like `cli-signed-out-auth-refused`; the phone/console show `signed-out` and then the repair state (PR 3201). An account already needs-reauth is left alone. Cost: one `claude auth status` + one `security` run per poll, only for accounts with no readable credential.
6. External surfaces: account status in `GET /subscription-pool`, the Accounts screen, and unattended repair starting for listed identities.
7. Multi-machine: each machine judges its own slots; the Mac Mini (no console session) will usually read its keychain as locked, so it stays `unavailable` there rather than starting repairs it cannot finish.
8. Rollback: remove the `engineLoginSignedOut` wiring line in server.ts (or revert); no state or config migration. Accounts it moved to needs-reauth return to active on the next successful sign-in, as today.
