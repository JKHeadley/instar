# Removal-aware exact App message context

The disposable server uses one prepared custodian snapshot to resolve the exact anchor and select bounded older rows. Removed occurrences cannot serve as an anchor or appear among the returned rows. A changed proof prevents the response. Owner authority and epoch are checked before and after preparation and after reading. The isolated response exposes the basic message fields; quote, reaction and attachment projections are outside this checkpoint. No deployed server has enrollment.

## 6b. Operator-surface quality

Opening a removed message on the isolated server reports that it is unavailable. Opening a surviving message still selects that exact row and can show older surviving messages.

## Framework generality

The signed read is independent of device platform and does not depend on a bridge.

## Independent review

Concur for isolated acceptance. Anchor and bounded tuple query share the store snapshot. The final signed scope and exact proof prevent stale output. Removed or ambiguous anchors cannot resolve to a different row.
