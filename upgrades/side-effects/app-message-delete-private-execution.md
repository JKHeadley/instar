# Private signed App Delete execution

The private executor rechecks current signed ownership, read and Delete grants, exact target access and serving custody. A fresh request requires verified absence of a removal before it durably reserves the exact intent. Only the corresponding indexed journal fact can confirm success. An identical request can recover the same receipt after a restart. A changed target conflicts, and an unresolved request never runs a second append.

The fixture exercises this executor under the production signing middleware. The production action remains unmounted. This checkpoint creates no provider mutation. Its synchronous absence check is limited to the private fixture. The future route must use the background proof path and coordinate removal-aware history and sync before activation.

## 6b. Operator-surface quality

A lost reply can be recovered without deleting a different message or repeating the original action. An unresolved result tells the client to retain its current row until it receives a confirmed removal.

## Framework generality

The request contract and durability checks are independent of the device client and agent harness.
