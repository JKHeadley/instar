# Removal-aware App downloads on the isolated server

An enrolled App download requires the current signed owner, the creation custodian and a surviving readable occurrence of the exact hash. Selection is rechecked after opening the blob and before writing HTTP response headers or bytes. The file size must match the selected attachment. Another readable occurrence can still authorize the same hash. If the exact proof changes while opening the file, the server closes it and returns the ordinary absent-file response. The acceptance path does not delete cached files or interrupt streams already admitted. Normal boot supplies no enrollment.

## 6b. Operator-surface quality

A shared file still opens if another readable message carries it. A file whose last readable message was deleted is unavailable on the isolated server.

## Framework generality

The protected download works with the same local file and byte-range response independent of device platform.

## Independent review

Concur for isolated acceptance. The final check runs after file open and stat, before headers or stream admission. Enrollment during open also prevents the legacy selection from returning bytes.
