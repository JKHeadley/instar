# App Delete read acceptance on the server router

An explicit in-process enrollment on a development server exercises the signed owner history and sync handlers on their usual HTTP URLs. A single codec binds both routes. Boot uses the actual machine trust capture for a synthetic single custodian, key ledger, Team Access log and journal index. Enrollment sticks until the isolated server exits. Enrolled reads use the owner-only contract and do not fall back when it refuses. Other conversations continue with the existing wire format. The normal CLI supplies no enrollment. No configuration option, write route, capability or front-door activation changes.

A separate temporary state directory with synthetic identities exercises the real AgentServer, routes and signatures. The signed target is seeded with a removal fact. The history page must omit the text and the sync page return its exact removal marker under the same epoch. This checkpoint supports the first history page and incremental sync only. It cannot be enabled for real histories until related reads, durable custody, downgrade fencing and the client change are verified.

## 6b. Operator-surface quality

The test verifies that the app can get a removal update and open the chat without seeing the old message. Ordinary app behavior stays as it is today.

## Framework generality

The isolated signed read check does not depend on a particular native operating system, agent harness or messaging bridge.
