# Removal-aware bound session copies

The disposable bound-session route requires the original bind token, current serving custody and the exact surviving attachment ID. Another attachment with the same hash does not substitute for a removed ID. The route checks again before copying, after staging, and before handing the session its path. Access loss during staging discards scratch data before publication. Existing retained copies are not erased by this read path. Default startup supplies no enrollment. This does not cover automatic dispatch file lines or historical copies already held by a session.

## 6b. Operator-surface quality

A session can still open a surviving attachment. Asking for a deleted message's exact attachment yields no path, even when another message holds the same file.

## Framework generality

The check applies to the bound App session route independently of session framework.

## Independent review

Concur for isolated acceptance. Exact attachment and current session proof are checked before publication and before confined-inbox handoff. The lifecycle injects a removal while staging and requires neither a destination file nor a returned path.
