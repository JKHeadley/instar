# Replies sent while the agent restarts are no longer lost

When the agent sends you a Telegram message, it hands the text to its own server, which checks it and sends it on. Every so often the server restarts, for example to install an update. For the first few minutes of a restart a small placeholder answers instead of the real server. It replies to every request with "I am still starting up" and does nothing else. It never looks at the message and never talks to Telegram.

The sending script handles this sensibly: when it gets that answer, it saves the message in a small local queue so it can be sent once the server is back. The bug was in what happens next. When the server comes back, it looks through that queue and asks of each message: "Can I be sure this was never sent?" It only said yes for two specific kinds of refusal. "I am still starting up" was not one of them, so every message queued during a restart was treated as "may already have been delivered", and those are deliberately never sent again, to avoid sending you something twice. The result was that anything the agent wrote during a restart quietly disappeared, even though the script had said it was queued.

This change teaches that check to recognise the placeholder's exact answer. Because the placeholder never sends anything, a message that got that answer certainly did not reach you, so it is now sent after the restart. The message still goes through all the usual checks on the way out (tone review, duplicate check, time limit), so nothing gets a shortcut. Anything that looks even slightly different from the placeholder's answer is still treated as uncertain and is not resent.
