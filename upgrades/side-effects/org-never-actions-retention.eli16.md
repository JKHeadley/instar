# Keeping the policy-check notes file small

When an organization's "never" rules are checked in observe mode, the agent writes a short note after any sent message that looked like a breach, and shows those notes at the next session start. If no session started for a long time, that notes file could keep growing forever. Instar has a rule that every file the agent keeps adding to must say how big it can get, and a test checks that the declared limit is real. This change makes the notes file roll over once it passes one megabyte, keeping only one older copy, and writes the limits for both files this feature keeps (the check log at five megabytes, the notes at one) into the list of stored files. Nothing the person sees changes: the session start already showed only the latest two hundred notes. The only thing lost is very old notes that nobody would have been shown anyway. Undoing it is a plain revert of one commit. This came from a test failure on the verify machine, not from a person, and it closes that failure at its cause rather than by changing the test.
