# Side-Effects Review — server-down remote recovery

**Date:** 2026-11-06. **Author:** Echo. **Tier:** 2 (credentials, process lifecycle, cross-machine repair). **Status:** independent implementation review complete; final repository checks below govern merge. Production enrollment is explicit, not asserted by this artifact.

## Summary of the change

Recovery has two target-server-independent carriers: a forced-command host SSH wrapper and an outbound HTTPS sidecar. Both use one durable target admission ledger and six bounded actions. Recovery code, native dependencies and Node are copied into a protected content-addressed runtime outside the mutable main installation. Setup, owner-phone controls, checkpoint carry, proof publication, pool health, source repair, trusted updates and rollback are integrated. Guided setup and missing-route visibility ship on the fleet; signed installation explicitly enables the active runtime. No constitution changes. The approved spec completed six review rounds; four implementation reviewers independently examined component boundaries and the final artifact, finding and correcting timing, ownership and crash-consistency defects. The implementation is approximately 125 files / 7.4k added lines; final staged size is reported in the PR. Initial source was fresh origin/main d1de939e5, refreshed onto 91b5bca55 (1.3.1694) before commit.

## 1. Over-block

Unknown owner authority, changed protected bindings, invalid boot/clock state, expired offline leases and exhausted budgets refuse mutations. These states remain inspectable where authentication permits. Authenticated health uncertainty, an intentional sleep request, or a malformed/wrong-agent health response suppress repair rather than authorize a restart. Valid bounded target clock skew is translated conservatively onto the source clock; it does not extend freshness. A dark or unpaired source cannot make a target green. This can leave a legitimate outage requiring explicit owner rearm/setup, which is preferable to silently widening machine-control authority.

## 2. Under-block

Recovery cannot survive a powered-off machine, unavailable host network, compromised OS account, or loss of both independent carrier infrastructures. It reports unavailable/unknown rather than promising access. Root certification keys and enrolled phone keys are separate authorities; possession of ordinary peer HTTP/SSH credentials does not grant recovery actions. A signed listener receipt is insufficient unless the actual source transport, target boot, route keys, installed endpoint and independent runtime agree. IPv4/Tailscale and public relay live paths were tested independently; physical shared-host reboot was not performed. Cold process/native-storage launch with the mutable package unavailable exercises the independent runtime without rebooting other users' machines.

## 3. Level-of-abstraction fit

Fixed machine actions and their admission live outside the main server. The relay distributes signed state and envelopes; it does not execute arbitrary commands. The main server owns setup and visibility, not the survival of installed recovery listeners. Existing router leases select a repairer; existing BlockerLedger records unmet setup. Owner setup remains explicit and target-bound. Test fixture authorities are rejected by the production authority loader.

## 4. Signal vs authority compliance

Reference: [signal vs authority](../../docs/signal-vs-authority.md). Cryptographic identity, finite verbs, exact owned service bindings, monotone revocation and finite side-effect budgets are deterministic safety floors. They are not brittle text-based judgments about user intent. Probe failures produce health/repair evidence; they cannot override the router lease, owner grant, intentional sleep or target admission. No new heuristic blocks ordinary user messages or tool work.

## 4b. Judgment-point check

No static heuristic arbitrates competing conversational signals. The enumerable six-action domain and irreversible process-control safety floors are declared in the driving spec. Readiness requires evidence and never infers authority from a hostname, live HTTP server, constructed subsystem or optimistic timeout.

## 5. Interactions

Recovery SSH grants have their own managed namespace and survive ordinary MutualSSH reconciliation. SSH, relay, watchdog and restore processes serialize against the same SQLite ledger. PID ownership includes birth identity. Main/fleet updates have a durable prepared/outcome protocol; protected rule guards are cleared only after every target's corresponding state is resolved. A hold is restored by its owned service or independent deadline, including after main/sidecar failure. The existing global watchdog retains unrelated agents' rules. Recovery-specific stop decisions are bounded and use the typed helper under the shared ledger. Repeated failures terminate in cooldown/exhaustion rather than an unbounded loop. Routine checkpoint/grant renewal cannot reset repair budgets; explicit owner-signed rearm advances an epoch.

## 6. External surfaces

Adds operator-authenticated setup and mobile enrollment/control pages, dedicated relay recovery endpoints, source-aware machine/session health and recovery notices. Browser signing keys are nonexportable; host enrollment capabilities are short-lived and one-use. A dedicated recovery certification root was provisioned into the existing main-only protected release environment; source contains only its public pin. The legacy release root was not replaced. Issuance consumes an explicitly reviewed public request from main and publishes only a public certificate. No production owner-phone key or agent recovery enrollment is silently created. The real setup path handles their absence.

## 7. Multi-machine posture

Private keys, service bindings, durable admission/fences/budgets and runtime slots are machine-local by design. Signed relay checkpoints carry owner intent; SSH can independently carry a fresh checkpoint and return the exact target acknowledgement. Signed route evidence is published through authenticated session status and merged by source/target/boot/key/epoch, never stitched across unrelated sources. Dark sources and conflicting boots remain unknown. Repair notices reserve a durable origin operation and retain their original sender/topic/idempotency key across retries and lease expiry. An ambiguous enqueue remains pending on that original sender; a partition can delay delivery beyond five minutes. Another machine cannot spend a second origin budget to hide that uncertainty, and status does not report pending delivery as accepted.

## 8. Rollback cost

Owned uninstall first deactivates admission durably, restores an outstanding owned hold, removes only its managed recovery keys/services and retains audit state. Cached SSH connections cannot revive admission. Trusted updates retain the prior immutable runtime and exact binding snapshots; interrupted writes reconcile or roll back before mutation authority returns. A public root pin can remain installed without enrolling any agent. Removing it is a normal release change; the private protected release secret is not part of repository rollback.
