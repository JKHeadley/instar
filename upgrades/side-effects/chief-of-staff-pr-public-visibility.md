# Side-effects review for public pull request visibility

The shared Chief of Staff PR transport requests GitHub's repository visibility field and serves rows only on explicit public evidence. A previously public result can become unavailable after the next refresh observes private or uncertain visibility. The existing authorization-loss path clears both the live and fallback observations in either PR stream. Authentication failures disclose only unavailable coverage. Public rows retain their existing response shape and retention. The production HTTPS fixture now carries visibility. The old captured fixture remains unchanged and demonstrates the refusal without the new field.

The two-hour investigation of the permanent-links incident uses one public repo. This guard prevents credentials that can see a newly private repository from widening that public search scope. Tests cover private and missing visibility after a warm cache, the existing complete public response, and the real production server route against a mock of GitHub transport.

Independent review rechecked public-only scope, mixed-stream authorization denial and warm-cache eviction. Twelve focused HTTP tests passed against the new raw public response. Two production-boot cases passed against the controlled transport.
