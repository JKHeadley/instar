# Side-Effects Review — Project rows that say something, on the dashboard

**Date:** 2026-11-17
**Author:** Echo
**Independent reviewer:** fresh general-purpose reviewer against the spec and the server code at this base. Four findings fixed: the latest report is shown in the opened row whenever it is not the folded line (a waiting reason built from item counts is not the report, so nothing the server said is lost); the phone line names an item check only when an item has `canMark` and is unchecked (a duplicate-id item cannot be checked on its own; an agent-may-certify item can); the Finished fold keeps its open state across the refresh after Ask for an update; the answer to Ask for an update is kept for a minute across that refresh. Left as is: the server's waiting reason can say "Tap Finish to close it.", and the opened row's phone line says Finish is on the phone.
**Tier:** 1, console client for docs/specs/work-door-project-rows.md §3.1–3.2 (server side PR #3396, which this branch builds on together with #3361).

## Decision-point inventory
What a project row shows and one button. The folded row adds one server-written line: why it waits on you, else why it stopped, else the latest report. The opened row adds when it was and will be checked, each done item's server words, **Ask for an update** (`POST /work/projects/check {key}`), and a plain line naming what the owner can do on their phone. Pause, Mark checked and Finish are not offered on the console: they are owner Face ID taps, and the spec (decisions 6 and 8) keeps the console PIN from standing in for them.

## Over-block and under-block
Ask for an update needs no PIN: the server allows the console's bearer because it approves nothing and runs within the Chief of Staff's own cadence and brakes (spec §3.2). Its answers (checked now, queued with the server's words, or a refusal with the server's `detail`) are shown in words. Nothing is offered that the server would refuse: the button appears only when `actions.checkNow.allowed`, and the phone line names only actions the row says apply.

## Level of abstraction
All words are the server's; the console only chooses which line goes where. A row from an older server (no `actions`) shows none of the new parts and keeps its old shape.

## Signal versus authority and judgment
No authority change and no new gate. docs/signal-vs-authority.md applies unchanged.

## Interactions and external surfaces
Web console Work page, Projects section only. The iPhone, Mac and Android rows are built by the app sessions. Builds on #3361's projects-model.js changes (names, history folds).

## Multi-machine posture
Whichever machine serves the console answers the read and the check request; a machine that does not run checks queues it (server behaviour, §3.2), and the row's `checks` says so.
