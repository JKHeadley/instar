# Side-effects review for the first private work lookup

**Scope and tier.** Tier 2, because a new endpoint can read private evidence. The A1 spec governs this increment. Its initial runtime seed covers local native-app user-side conversation messages and the shared public Instar pull request cache. Work UI, peer search, grouped artifacts, continuation pages, and broader providers follow separately. The endpoint marks the other sources unsearched and its results partial.

**Authorization and destination.** Auth middleware must verify an existing owner-private console session before the endpoint can query anything. A bare PIN cannot authorize the endpoint. The actual session is verified again after the public provider wait. Local authorization, native source lookup and response serialization are synchronous after that wait. The route refuses the server's unscoped master credential, shared agent scope, device principals, and caller-supplied destination. The endpoint uses a small body budget and no-store responses. The user query is a JSON body field. The PR provider uses a fixed public GitHub request and matches candidates locally. A separately reviewed dependent patch verifies public visibility on every network refresh and clears previously usable cached observations if the provider denies it.

**Evidence.** Public PR records expose their observed state with source identity. Local conversation candidates include the original message position and are labeled as leads. Generated agent replies are excluded before result selection, before choosing native-app results. This avoids reusing a copied approval as if it were current original proof. The user-side role is a search filter rather than an attestation of human identity. Local source coverage distinguishes present, unknown and unsearched App, Telegram and Slack lanes. App tombstones and revoked source permission cannot yield excerpts. Configured Telegram and Slack remain unknown until their current source authorization and erasure boundaries are proven. Other operator-written transcripts retain lead status even if they mention an approval. The existing mobile conversation search retains its own default scope.

**Operational impact.** The same server-owned pull request provider instance serves both production entry points. The lookup wait uses the existing five-second interactive conversation search budget. The shared PR refresh may finish in its own existing bounded lane and can be reused later. A provider error or timeout contributes unavailable coverage without returning its error text. A disabled or expired dashboard session cannot receive results after a provider call. There is no write admission, action dispatch, or persistent search log in this increment.

**Rollback.** Removing the new route leaves the canonical stores and their history in their own owners. The Chief of Staff PR route can again own its default provider instance. No source data conversion is involved.

**Verification.** Targeted unit, HTTP and production-boot tests. Separate evidence is recorded for the dependent public-visibility patch. The route is development-only and requires the existing scoped dashboard credential. The original unprompted Chief of Staff outcome, Work UI and fleet maturation are later acceptance items.
