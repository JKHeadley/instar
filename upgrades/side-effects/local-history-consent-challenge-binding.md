# Side effects of binding owner approval to the private preview

The dormant preview, challenge, and confirmation share one server-built disclosure. The disclosure hash covers the exact operation, card revision, selected source rows, pinned target and expiry. Challenge issuance and confirmation each re-read the sealed preview, active card, and current signed source ownership evidence.

- Changed disclosure, destination, card, apply request, or unavailable current ownership fails closed. Reopening the current preview is the recovery for stale display data.
- The existing Work Board presence message and one-use challenge store prove the enrolled phone's signature. A successful confirmation returns only the existing proof reference.
- Preview reads remain private and machine-local to the staged operation and target boot. No added storage, outside request, browser route, copy authority or runtime enablement.
- The future native caller must pass its admitted device and verified Host. A copy caller must recheck current ownership before any durable permit.
- Reverting removes the optional challenge adapter and the dormant preview hash field. No data migration is needed.

Independent review concurred with the shared disclosure and current ownership checks.
