# Dashboard browser credential grant integration

The Dashboard discovers grants with the browser's existing non-exportable key. The standard Needs You read advertises availability under the existing server switch. It grants no consent authority. Signed discovery and writes use only the grant service's exact routes. The service revalidates the native owner, browser key, assignment and disclosure on every action. A PIN session by itself never signs.

The credential section is independent of the Home and front-door owner count. A storage error clears the input and requires a fresh disclosure and submission. A stale grant refreshes its own list. Leaving the page aborts pending client reads and closes the sheet.

The server switch remains off by default. The branch does not change durable storage, browser key enrollment, grant issuance or trust approval. Roll back by leaving the switch off or reverting this follow-up. Preserve the two server release fragments in upgrades/next when stacking the branches.

## 6b. Operator-surface quality

- The credential request leads with Enter credential. The form gives the source's reviewed title and purpose above the masked input and Submit credential.
- The form keeps request IDs, browser device IDs, signature details and storage details out of its text.
- Cancel dismisses the form and clears the input. The form offers no destructive action.
- Chromium exercised the full Dashboard at 390 and 1280 pixels. At both widths it showed the same short prompts, reported a changed request in plain language, and reopened with an empty field after a storage failure.
