# Feedback Entry Rule Links: Side Effects

## Summary

Pure component under approved design-standard-enforcement section5. It reads supplied Markdown and parsed standard structure, emits typed shape/link observations and does not activate the complete entry lint. This is not a card writer or an authority to publish, waive or merge.

## 1. Over-block

No application block/allow surface. The entry format is deliberately canonical: the metadata table, diagnosis and added/sharpened table must have their documented headings. A differently formatted entry yields a structural finding for review rather than an invented approval.

## 2. Under-block

No source-authentication or publication clearance. Changelog exactness, base-entry history, gate-miss fix links, owner quote redaction review and actual server-feedback family binding are explicitly listed as unevaluated. Complete activation remains on the approved design project's existing carrier. Metadata text cannot authenticate a sender or card approval.

## 3. Level-of-abstraction fit

Pure structural signal over explicit document inputs. Uses the already-shipped Markdown lexer and recursive token children; no separate fence grammar or candidate code execution. Existing server sender/card verification remains the authority for live source facts.

## 4. Signal vs authority compliance

Complies with docs/signal-vs-authority.md. mergeAuthority:false, sourceVerification:false and publicationPrivacyReview:false are constants. Matching an email shape or rule identifier never grants a waiver or blocks a user action.

## 4b. Judgment-point check

No new heuristic at a competing-signals decision point. Filename/entry numbers, required metadata, known rule IDs, reciprocal provenance and exact numbered-problem links are structural invariants. Semantic diagnosis correctness and quote redaction still need review.

## 5. Interactions

No I/O, timer, mutable state or installed CLI path. The existing manual command still honestly excludes feedback-entry lint. Code and HTML examples are removed recursively; inline rule citations and original written problem numbers are preserved.

## 6. External surfaces

No new endpoint, command, messaging or external call. Results do not echo arbitrary source-header prose or matched non-synthetic email addresses. Filenames and identifiers remain diagnostic inputs, not a guarantee that the document is safe to publish.

## 7. Multi-machine posture

Pure function by design; equal standard/documents produce equal observations. Markdown options are pinned explicitly. No machine-local authority or state can strand on transfer.

## 8. Rollback cost

Revert the component and tests. No data migration or agent configuration needs repair.
