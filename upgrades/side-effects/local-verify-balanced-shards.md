## Summary of the change

Amendment to `docs/specs/local-verify-merge-authority.md` ("Balanced shards", built 2026-10-27). Operator request (Telegram topic 130715, 2026-10-26 17:51): merge throughput is top priority. Stacked on PR #2392 (fail-fast).

- `src/localVerify/policy.ts`: `e2eShards` 2 → 3; new `integrationShards: 2`, in the policy hash.
- New `src/localVerify/shardPlan.ts` (pure): `filterOverlapGroups` (files whose paths contain one another — vitest's case-insensitive substring filter — are planned as one unit), `planShards` (longest-processing-time-first onto the least-loaded shard; null below 50% duration coverage or if a shard would be empty), `mergeDurations` (50/50 blend, bounded at 20,000 files, invalid input ignored).
- `src/localVerify/laneReport.ts`: `parseVitestJson` keeps each file's wall time (`ms`) when the report carries `startTime`/`endTime`.
- `src/localVerify/orchestrator.ts`: the integration lane runs as `integrationShards` processes (or `VerifyRunInput.laneShards`, from the live setting `monitoring.localVerify.laneShards`, 1..`MAX_LANE_SHARDS`=4); shards of a lane get explicit file lists from `planShards` (fallback `--shard=k/n`); a `shard-plan` audit line per sharded lane; integration/e2e per-file durations are written to `<verifyRoot>/file-durations.json` after the lanes (never read for a verdict).

## Decision-point inventory

- `planShards` — add — which process runs each lane file. Deterministic over the inventory and the duration history.
- Lane verdict, record, merge predicate — pass-through, unchanged.

## 1. Over-block

- A test that only passes when it shares a process with a particular earlier file (order dependence) may fail when the plan moves it. Same exposure as any vitest shard change; the isolation re-run (now also for flaky-on-main files) absorbs a one-off, and a real order dependence is a test defect worth surfacing.
- Policy-hash change: every existing record re-verifies on next use (one-time cost).

## 2. Under-block

- The history file is writable by the lanes' test code (same user): it is read only below 2 MB and can only move files between shards (a hostile history unbalances a run, never changes which tests run).

- None: every inventoried lane file is assigned exactly once; a duplicate or a missing file still fails the lane through the unchanged join and inventory rules. A bad history only unbalances the shards.

## 3. Level-of-abstraction fit

Lives in the verifier child where the shard arguments are built; the history file sits in the verifier's own `verifyRoot`, beside the bare clone and the kept-failed list.

## 4. Signal vs authority compliance

The duration history is a performance hint with no authority over any verdict. It cannot add, drop or skip a test.

## 4b. Judgment-point check

None added.

## 5. Interactions

- **Host load:** 9 lane workers instead of 7 (4 unit + 2 integration + 3 e2e), all inside the single held suite slot; measured on the Studio before shipping (see Evidence in the PR).
- **Generated assets:** the build step regenerates `dist` and the standards-registry asset before any lane starts, so each process's `globalSetup` finds them fresh and writes nothing (no concurrent-write race).
- **Fail-fast (PR #2392):** stopping a lane stops all of its shards (each shard's exec carries the same signal).
- **Isolation re-run:** unchanged; still one file at a time, after its lane.
- **Step names:** `integration` steps are now `integration-1`, `integration-2` in run logs and deadline error steps (`deadline:integration-1`), as `e2e-1`… already were.

## 6. External surfaces

No route or record-schema change. New audit line `shard-plan`. New state file `<agentHome>/.worktrees/.verify/file-durations.json` (machine-local, regenerated by use).

## 6b. Operator-surface quality

Nothing new for the operator to read or tap.

## 7. Multi-machine posture

Machine-local; each machine's history reflects its own speed.

## 8. Rollback cost

No restart: `monitoring.localVerify.laneShards: {"integration": 1, "e2e": 2}` restores the old process counts at the next start (the balanced plan still applies to the e2e pair). Full rollback: revert the change; the history file is ignored by the old code. One more policy-hash change on revert (records re-verify once).

## Conclusion

Shortens every verify by balancing the slow lanes across more processes, with no effect on which tests run or how a verdict is reached.

## Class-Closure Declaration (display-only mirror)

## Second-pass review

Concurred. Independent cross-model reviewer (Codex, read-only), two rounds:
- Round 1 BLOCKED: (1) vitest positional filters are case-insensitive substrings, so a file whose path contains another's could run in two shards (an otherwise passing PR fails) — fixed with `filterOverlapGroups` (overlapping files planned as one unit); (2) the history file is writable by the lanes' test code and was read whole — now read only at ≤ 2 MB; (3) the test fake used exact matching — now uses vitest's rule, with overlap, size-cap and grouping tests.
- Round 2 **CLEAN** ("No remaining defects found in this change"; its in-memory check ran 294 shard-coverage, substring-overlap and determinism cases).
