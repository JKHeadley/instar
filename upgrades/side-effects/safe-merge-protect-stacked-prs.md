# Preserve pull requests that depend on a merging branch

Just before the merge command, safe-merge reads the pinned, open parent and enumerates its head branch's open dependent pull requests through GitHub pagination. It retargets same-repository dependents to main, confirms head, draft status and new base, and lists the old base again. GitHub records each change on the child's timeline. Safe merge also attempts an explanatory comment and prints a warning if it cannot confirm that comment. Unreadable state, an unconfirmed move or a cross-repository dependent stops the parent merge. The tool keeps draft state and does not carry over a verification verdict. Explicit CLI branch deletion is skipped when dependents moved. GitHub can still apply its own repository preference once no open dependents use the branch.

The API is the source of branch and PR state and the existing merge authorization remains the authority. Retargeting can trigger checks. If a later merge step fails, already moved children stay on main. The subsequent retry can proceed after GitHub confirms the remaining state. Revert this commit to remove the rule and leave any previously retargeted PRs intact.
