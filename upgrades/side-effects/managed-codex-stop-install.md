# Side-effects review for the packaged managed Stop hook update

Tier 1 for the exact-stock dark transport update. It uses the existing executable hook upgrade path. It updates known packaged program bytes while keeping data, configuration and locally edited programs in place. No production launch is enrolled or tagged by this change.

## Decision-point inventory

Update only a recognized previous stock hash. Preserve unrecognized bytes. In a preserved hook, report once if the known static legacy authentication reference lacks its dependency.

## Over-block

An unfamiliar stock-derived version is treated as a customization and preserved. The known reference check is limited to the former Studio form. A present helper suppresses the warning.

## Under-block

Static detection covers the one known resolver call, not arbitrary shell dependencies. The warning is advisory. No repaired or missing file can authorize a managed continuation without a verified enrollment.

## Level of abstraction and signal versus authority

The updater owns distribution of known built-in hook bytes. It reports a missing dependency without changing the operator's authority over a customized hook.

## Tests, impact and rollback

Migration tests cover the exact predecessor, executable update, idempotency, preserved custom bytes, duplicate references and a present resolver. Roll back an installed stock update by restoring the previous packaged hook. The explicit test switch stays off throughout.
