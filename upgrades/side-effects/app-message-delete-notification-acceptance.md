# Removal-aware notification previews

On the disposable server, an enrolled conversation returns notification text only to the current signed owner device after rechecking the exact agent message against the custodian journal. Removed and absent messages share an unavailable response. Legacy bearer and notification credentials cannot use the protected preview. The client can keep the generic notification in that case. Normal startup does not supply enrollment and retains the current preview path.

## 6b. Operator-surface quality

An enrolled preview no longer shows deleted text. The acceptance contract uses the signed owner device; notifier credential support would need separate verification before production enrollment.

## Framework generality

The protected read does not depend on a messaging bridge or client operating system.

## Independent review

Concur for isolated acceptance. The protected path validates the current signed owner and exact message ID before building the preview. Unenrolled previews retain their existing credential behavior.
