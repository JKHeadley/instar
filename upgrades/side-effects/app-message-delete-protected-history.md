# Protected first page for App message deletion

The unmounted owner history executor applies the current signed owner, conversation access, creation custody and complete removal proof. History and sync share the same view epoch. A removal committed during selection invalidates the page even if the epoch itself is stable. Unavailable row access evidence refuses the whole page. Only the existing sanitized message fields and a boolean indicating older rows leave the fixture. No cache lease or cursor is issued by history. The test route marks responses no-store.

## 6b. Operator-surface quality

When a message is removed, a fresh protected history page leaves it out. A page made stale by a concurrent removal waits for a new request. The fixture does not change the normal history screen.

## Framework generality

The reader is independent of native platform and agent harness. Team access, older pages, exact context, links, quote previews, search and other dependent projections are still production integration work.

## Independent review

Concur with the unmounted first-page checkpoint. Revalidation rejects a stale page even when the visibility epoch survives an append. Uncertain row authorization releases neither messages nor a continuation.
