# Three owner reports become lasting design rules

This update puts three new reports from the owner into the shared design register. The first asks for one clearly identifiable Chief of Staff conversation above project containers. The second asks for native context actions where the person actually right-clicks a chat or message. The third asks that helper conversations appear under their real parent, or remain in a readable recovery location when parentage cannot yet be established.

Each record explains the failure, maps the existing rules, names the missing rule and lists the evidence still needed. It keeps the Chief of Staff's relay clearly labeled instead of inventing a direct quote from the owner. Original screenshots and private conversation contents remain in the private archive. Proposed server field names remain proposals, not shipped capabilities.

The standard gains permanent rules for the main conversation's fixed place, actual native context targets and authenticated creation provenance. Those rules describe the expected result and the regression checks. They do not claim that code or a release has completed. The Apple app owner reports that the Mac navigation update is released, and the matching iPhone placement is available in TestFlight according to the app owner. Store approval, complete native menu actions and production-owner server parentage proof stay open. This commit changes documents only; it moves or deletes no existing conversation.

The rules also retain the standard’s simple metadata format: surface values come from its declared list, and every machine rule appears in the summary table. These bookkeeping corrections do not weaken the requirements.


The register also catches up its progress notes. The first server usage-data change has already merged, so the Accounts diagnosis now says what it delivered and what remains. Later phone and Mac releases are attributed to the app owner's actual reports. A reviewed synthetic Windows view is distinguished from a shipped update. These are status corrections, not a new application release or a declaration that the original feedback is closed. Readers can see the remaining checks without being told completed work has never started.
