# relay-send falls back to the undici package's own fetch when Node's fetch rejects the package Agent

Tier 1. One call site gets a rejection-only retry. Rollback is a revert.

- What changed. `sendMessageViaHttp` (src/threadline/mcp-http-client.ts) now calls `fetchRelaySend`, which passes the 325s `undici` Agent as before. If Node's fetch throws a `TypeError` whose cause code is `UND_ERR_INVALID_ARG`, it resends the same request once through the `undici` package's own `fetch` with the same 325s Agent (package fetch and package Agent always agree), and records, for the process, to go there directly. Same shape as `fetchWithTelegramDispatcher` in src/messaging/telegram-egress.ts, except that one drops to Node's default dispatcher; that would break this route's deadline ordering (next bullet but two).
- Evidence. On Node 26.13.0 (bundled undici 8.12.2) with the `undici` 6.27.0 package, `tests/e2e/threadline/send-honest-error-e2e.test.ts` failed on unmodified main with `Failed to reach agent server on port N: fetch failed`; the fetch error's cause was `UND_ERR_INVALID_ARG invalid onError method`. A plain fetch to a 127.0.0.1 server in the same Node succeeds. CI runs Node 20/22, where the two undici versions agree, so CI never saw it. `package.json` engines allow `>=20.12.0`, so Node 26 users hit it in production: every MCP `threadline_send` failed.
- Duplicate delivery. None possible from the retry: the rejection is raised inside `Agent.dispatch` before a connection opens, and only that exact error is retried. Any other error (ECONNREFUSED, abort, timeout) is handled exactly as before, with no retry.
- Deadline ordering. docs/specs/threadline-mcp-local-http.md (Bounds) requires the inner fetch (325s) to outlast the route's own answer (320s) so the route always speaks first. Falling back to Node's default dispatcher would cap the inner fetch at 300s and invert that. The fallback keeps the 325s Agent, so the ordering holds on every Node. A mutant that falls back to Node's default fetch fails the unit test's 325s assertion.
- Under-block. None. The fallback request is identical, with the same timeouts.
- Over-block. None. No check is added or weakened.
- External surfaces and multi-machine posture. None. No persisted format, config or route change.
- Rollback. Revert the commit.

Verification: new `tests/unit/mcp-http-client-dispatcher-rejection.test.ts` (resend once through the package fetch carrying the 325s Agent, then remembered; a real ECONNREFUSED is not retried). The e2e `send-honest-error-e2e.test.ts` now passes on Node 26. Mutants: retry removed, the unit test fails 1/2 and the e2e fails with the original "Failed to reach agent server"; fallback to Node's default fetch, the unit test fails on the 325s assertion. A plain probe on Node 26.13.0 confirmed the package fetch plus package Agent returns 200 where Node's fetch plus package Agent throws UND_ERR_INVALID_ARG. The three existing unit files for this helper pass (39/39 with the new file). `tsc --noEmit` exit 0.
