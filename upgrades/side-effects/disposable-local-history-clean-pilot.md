# Side effects of the clean disposable local history pilot

The pilot mounts the reviewed native owner intake only when localHistoryDisposablePilot.enabled is explicitly true, the listener is loopback, a machine signer is present and the private state belongs to the canonical disposable test home. It will stage only the generated fixture for the synthetic owner. The signed route passes exact request bytes through a sealed pinned channel. It uses the existing state-scoped SQLite exchange lease and the staging worker's distinct child custody.

The server chooses the copy budget, samples the live filesystem and verifies consent inside the write-permit transaction. An aborted request cannot issue an approval after cancellation is visible to staging. An issued claim remains charged through delivery, settlement and recovery. The fixture applies its first claim only. The remainder is interrupted. No replay or later permission is inferred.

The pilot keeps one selection in memory and waits up to ten seconds for the tiny generated fixture's verification before returning from complete. It is intentionally narrower than the future general native intake and status contract. Shutdown fences lazy construction before awaiting existing work. Real history remains held and the route does not advertise general import availability.

The normal AgentServer signed HTTP test verifies default darkness, an exact generated snapshot, changed-byte refusal, live floor refusal with a synthetic unwritten reserve, one successful first claim after pressure release, and replay refusal. Staging tests cover committed reservation recovery. No private overlay runtime or test sources were brought into this stack.

Independent rereview verified that shutdown prevents a first pilot request from constructing the service while the listener is still closing. The gate is checked by both the mount and the live owner resolver.
