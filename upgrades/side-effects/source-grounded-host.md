# Side-effects review for the source-grounded real-conversation host

A manual tool plans, answers, judges and totals the private source-grounded case pack. It runs only when an operator-directed session invokes it on the machine that holds the pack and the subscription. No endpoint, job, hook or startup path calls it.

1. **Over-block.** A pack whose files do not match their manifest, a plan whose bytes changed, a failed confinement probe, an unconfined Claude stream and any tool activity all halt the step. This is a manual evaluation and can be rerun on a known good route.
2. **Under-block.** The answering and Claude judging turns use the same confined settings as the public capture: no tools, empty MCP, no settings or hooks, one turn, no session persistence and no API key. Each Claude turn's stream is checked: confined start, no tool events, one turn. The Codex judge uses instar's own tool-free profile, a read-only sandbox, an empty scratch directory and an ephemeral session. It runs with --json, and every turn's event stream is checked against a fixed list of allowed item kinds: the model's messages and reasoning, its plan list, and notice items. A top-level error event is a notice. Only a failed turn, or no completed turn, fails the call. Any other item, such as a command, a file change, an MCP call or a web search, fails the turn as tool activity. A unit test keeps that profile identical to src/core/codexToolFreeProfile.ts. The reducer and the answerer never receive a question, label or rubric. The judges receive no arm label and no trial id, and submission ids are seeded hashes. The arm can still be inferred from what an answer cites: the reduced record, many messages, or none. totals.json carries that limit in its limits field (arm-inferable-from-citations), along with the fact that the answer model and judge A are from the same family.
3. **Abstraction.** The frozen offline modules still do all scoring: evaluateJudgeFlow, the retry policy, slot binding, the independence check and consensus. The host only produces their inputs. Models quote evidence, and the host turns each exact quote into code-point offsets. A quote that is not found verbatim stays an invalid span and fails the record, never a fuzzy match.
4. **Signal and authority.** Totals are exploratory. They cannot qualify, activate or tune a reduction. The status field says so.
5. **Interactions.** Every step writes into a caller-chosen run directory, with owner-only permissions, and skips trials already recorded. Only real model outcomes are recorded. A route failure (a lost login, an unconfined start, tool activity, an unreadable stream) halts the step with a dash code and saves nothing for that trial. An answer timeout is not saved either, so a rerun retries both. Judge timeouts follow the frozen retry policy and are kept in the ledger. The totals count a valid answer still waiting for a judge as notJudged, and a trial with no answer recorded as notRun rather than as failed criteria, so no trial drops out silently or turns into a wrong answer. Each trial in totals.json says whether it has a real result (scored). Paired arm comparisons use only pairs where both trials are scored. Each trial also records whether both judges finished every criterion (complete) and its verdict counts. Each paired comparison carries a completeOnly version over pairs where both trials are complete, so a judging gap is not read as a worse answer. Run 1 showed why: the full arm had the most incomplete criteria. When a route failure halts a judge slot on its retry, the earlier timeout in that slot is dropped with it, and the rerun starts the slot from a fresh ledger. Each model turn runs in its own empty folder under the run's scratch folder. The folders are kept, not deleted, and a turn that leaves any file there fails as tool activity. One ordinal counter orders model completions against the first combining of judge outputs, which is what the independence check needs.
6. **External surfaces.** An invocation uses Anthropic inference on the selected authorized subscription and OpenAI inference through the selected Codex login, and may consume quota on both. Private source, question, label, answer and judge text stays in the run directory. The totals file carries identifiers and counts only, and a test asserts that no case text reaches it.
7. **Multiple machines.** The pack and the logins live on one machine, and the run happens there. Nothing replicates.
8. **Rollback.** Remove the script or revert the commit. There is no activation, state migration or runtime caller.

## Diagnose step

A diagnose command reads the run folder and returns counts only: answer outcomes by arm and reason code, and judge attempts by arm, judge family, state and error code. Anything that is not a plain dash code is reported as "other", so no model or private text can appear. For each rejected answer or grading, it also reruns the frozen schema with Ajv and counts where the shape broke: Ajv's rule and the location in schema terms, with array positions as N. A property name the model chose is kept only when it is a plain code. It also classifies each quote that failed to resolve, as unknown record, empty, typography-only (it matches after normalising Unicode form, curly quotes, dashes and spacing), case-only, elision, or not found. For a quote whose record id is unknown, it also reports the id's pattern class (for example a source id under the answer collection, a claims path without /text, or a bare claim id), never the id itself. That is for diagnosis only: resolution itself stays exact.

Judge record-id rules. Run 1 showed the OpenAI judge naming answer records in a form the host does not resolve. The old template listed the answer ids as one slash-separated hint that reads like a path. The judge instructions now state each id form exactly, with a neutral example, and forbid prefixes, array positions and combined ids. Gradings made before and after this change used different wording for that one rule, and a rerun says which slots were regraded. It makes no model calls and writes nothing. Run 1 needs it to find why judges left points unfinished, without anyone reading private content.

## Scoring rule for the case decision

 Two criteria come from it. "decision" passes only when the answer reaches the reference decision and is never critical. "no-wrong-decision" is an absence criterion that fails only when the answer asserts a different decision, and it is critical when the case is. A justified refusal in the no-context arm therefore loses the decision point without being counted as a critical failure, which is what the totals are meant to show. The judge instructions say the same: decision and convey-N need an evidence quote, while no-wrong-decision and avoid-N need none, which matches the validator.

## Confinement probe

Before the reduce turn, before any answer turn, and before judging for each judge route (Claude and Codex), the host runs a capability probe instead of an exact-text check. Run 1 showed that a tool-free Sonnet writes pretend tool calls as plain text, so wording proves nothing. A canary file with a fresh random code sits beside the turn's empty folder. The model is asked to read it back and to create a file. The probe passes only when the turn came back ok (for Claude this includes the confined-start and no-tool-event stream check), the folder stayed empty, and the code is absent from the reply. Afterwards the canary is kept, like the turn folders, but its code is overwritten. Each probe reply is kept in the run's probes.json as evidence only. The probe prompt holds no private text, but a reply is model output, so probes.json stays in the owner-only run directory with the rest. A probe gets the same 240-second limit as a judge turn and, like a judge turn, one retry only after a timeout, because a timeout says nothing about confinement. Any other probe failure halts at once, with a dash-only code (for example confinement-probe-failed-anthropic-tool-activity) so the command line shows the reason instead of a generic host error. Any other error text, which can quote model output, becomes the fixed code unparseable-stream.

## Named context arms

`plan --contexts <spec.json>` replaces the single reduced arm with up to four named context arms, each with one text for every repeat or one text per repeat. Arms run in the order none, the named arms, then full. A context record gets a neutral id (`context-` plus 10 hex characters from the seed, arm and repeat), so a judge can't read an arm name from a record id. Each trial in such a plan lists only the original messages and its own context record. The answer prompt and the judge prompt therefore never carry another arm's text. Run-1 plans list every record, and the filter in `trialContext` keeps them as they were. `contexts.json` holds the texts. totals.json lists each context by id, arm, repeat, sha256, length and builtBy (a checked plain label), never its text. Paired comparisons cover every pair of arms, with run 1's three keys and order unchanged. diagnose takes the arm from the plan file. The old `--reduced` path and `reduced.json` behave exactly as before. Three new tests cover validation and neutral ids, per-trial source isolation (no other arm's text and no arm name in the judge prompt), and totals and diagnose over a four-arm run. 25 of 25 host tests pass. Signal only: this changes the benchmark tool and no runtime behaviour.
