# The "In the way" list shows what was said, not the command that said it

When the agent sends a message that sounds like it is stuck ("I can't…", "blocker"), a small checker writes it down as a possible blocker, so a real wall does not get forgotten. The trouble was what it wrote down. The agent sends messages by running a short shell command that wraps the text, and the checker saved that entire command: the wrapping, the topic number, and sometimes a private link with its secret signature still attached. The dashboard's Plans page then showed those lines exactly as saved, so the operator saw fifty rows of shell commands instead of readable sentences, and one of them exposed a signed link.

Now the checker saves only the message itself, and any part of a link that looks like a signature or token is replaced with "…". The dashboard also tidies the rows already saved the old way: it shows the first line of the message, masks the same link parts, and if there was no message at all it says that a command was flagged instead of printing the command. The checker also stops mistaking the agent's own code-writing for messages: before, a command that merely saved a file mentioning the message script was treated as a message and could create a bogus entry. Only commands that actually send a message are checked now.
