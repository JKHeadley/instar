# Spec experience review — side effects

## Behavior and authority
The existing required lessons-aware reviewer receives an experience-fit question. Its report records the user's outcome, journey, contrasting permission cases and evidence limits. No constitution text, approval API or trust decision changes.

## Installed agents
PostUpdateMigrator adds a marked instruction at a unique anchor in recognized spec-converge SKILL.md copies in canonical, Claude and Codex roots. Surrounding prose remains. Missing or ambiguous anchors and incomplete local blocks are reported without replacement. Shipped-owned reviewer templates continue their established refresh policy, now including existing canonical and Codex copies, with backups retained. Unrelated custom skills are untouched. Existing stamped user-edit conflicts hold the entire SKILL body/stamp migration before canonical changes; shipped templates still refresh. Stock rendering stamps advance with canonical content. Canonical write failure stops rendering mutation. Existing Codex metadata changes only its recognized stamp.

## Verification and limits
Focused tests exercise the public migration ordering, actual framework rendering/parity, retry, missing files, custom prose and external symlink boundaries. Full unit/integration/e2e verification is owned by the merge line. This is delivery of a review instruction, not proof that future reviewers will always reach the right judgment.

## Rollback
Revert this source change. For an already migrated home, remove the marked experience block and restore affected shipped templates from their retained backups or the prior release, then reconcile framework renderings through the normal parity path. A code revert alone does not erase installed content.

## Decision-point inventory
Reviewer Q5 adds contextual assessment within the existing review process. Migration uses fixed file identity, unique insertion anchors and parity provenance to decide whether a safe content update is possible.

## 1. Over-block
A locally edited stamped rendering holds body migration for all copies. This deliberately preserves its conflict; shipped reviewer templates still update. Ambiguous anchors report a skip instead of guessing.

## 2. Under-block
A review instruction cannot guarantee a correct judgment. Customization that removed provenance predates this migration and cannot be reconstructed from a missing stamp. Existing framework parity remains responsible for reporting drift.

## 3. Level-of-abstraction fit
Experience-fit belongs in the existing contextual LLM review. File migration checks enumerable content invariants; it does not judge user intent.

## 4. Signal vs authority compliance
No new authority to approve work or grant permission. Q5 feeds the existing reviewer. See docs/signal-vs-authority.md.

## 4b. Judgment-point check
No new static heuristic at a competing-signals judgment point. Anchor and stamp comparisons protect installed-file integrity, not conversational decisions.

## 5. Interactions
Owned template refresh runs before the additive body migration. Repeated runs do not duplicate the marked block. Real parity verification covers stamp consistency and protected local edits. Atomic writes protect individual files; this is not a multi-file transaction. A canonical write failure stops rendering writes; existing user-edit conflicts hold the body migration before any canonical change. Concurrent operator edits during migration remain an existing update-path limitation.

## 6. External surfaces
Existing installations receive changed skill files; no network service, user-facing API or operator action is added. Other skills are not targeted. No production restart is performed by this PR author.

## 7. Rollback and observability
Migration reports upgraded, skipped and failed paths through MigrationResult. Owned-template backups remain. Use the rollback procedure above; already installed content requires explicit restoration.
