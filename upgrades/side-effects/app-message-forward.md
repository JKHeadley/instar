# Default-off App message forwarding

## Admission and authority

A device-signed intent binds the actor, selected occurrence, destination and original custodian. The existing People policy decides destination send access and source conversation and row visibility. Signed destination readers may receive metadata-only receipts for their accepted attempts. Unknown, ambiguous and unreadable source occurrences share a response. There is no asynchronous preflight between authorization and append.

The first slice accepts plain text and refuses attachments, system notes, and cross-custodian writes. These are intentional limits on the dark contract. The existing inbound masking and authority-token projection run without invoking the pairing scanner. Recipients may read the deliberately copied text through destination access. Raw source identities stay in the private request ledger, and the stored binding is removed from mobile projections.

## Side effects and interactions

Only the destination history changes on acceptance. The route bypasses dispatch, Stop, pause, semantic classification and bridge paths. Ordinary sends and direct commands keep their existing handling. Session bootstrap, attribution recap, work timing and context-budget writing exclude forwarded rows. The derived index adds a default-zero column for earlier rows and uses it before history limits are applied.

One immutable custodian coordinates retries. Exact persisted evidence can recover an interrupted receipt. Unknown pre-append reservations cannot authorize a second append. Store failures return an unknown outcome where acceptance cannot be proved. The dedicated wire kind keeps older peers from treating a forward as a direct message, and supported peers can replicate the destination copy through App history. All participating readers need compatible versions before activation.

## Rollback and verification

The feature flag starts off. Disabling it stops writes and receipt recovery, and accepted copies remain in destination history on compatible readers. Restore the flag on the original custodian to recover a receipt after an outage. No live configuration or client activation is part of this change. Verify signed route admission, restart recovery, no agent side effects, replication validation and subsequent session history through targeted tests.

## 6b. Operator-surface quality

The native app can keep the composer untouched and show a stable result for the selected source and destination. The client must preserve the original machine and exact signed intent for retry. Native UI and provider verification are required for their respective capabilities before activation.

## Framework generality

The route does not dispatch a model, select a harness or depend on a messaging provider.
