## Decision points and authority

This change records an authenticated owner's exact sealed intent before canonical writer admission. Current owner authentication/revocation, device identity/dashboard grant lookup, project scope and observed-head/header-CAS decisions remain with the actual owner service and its existing graph policy. The signed installed membership/profile pins recording identity. Global sequence allocation, source receipts, native fencing, custody verification and all-member final certificates remain with the existing Source/WriteAdmission/native/custody engine. Structural parsers and signature checks refuse invalid records; no heuristic content detector becomes a new policy authority. See `docs/signal-vs-authority.md`.

## Behavior and validation

Intake gains a machine-local, sequence-free spool with Ed25519 admission control and X25519/AES sealed private body. The body contains immutable request identity, owner admission locator, grant snapshot, exact change/observed heads/version, and stable provisional create identity. PINs, bearer tokens and content keys are not persisted. Titles and admission locators have no plaintext or deterministic private-title digest in public control. Recording returns `recorded-local`, never a Source ACK or remotely recoverable Saved promise.

The real writer's promoter runs inside the same runtime mutation token as current head validation and original Source allocation. A duplicate logical key consults existing frozen Source/Intake first. Local cancellation is distinct from witnessed cancellation; it refuses if the request is already globally admitted. Local refusal/cancellation and accepted private intent survive process restart. Priority logical erasure applies to queued body/hardlink/scratch copies, including writes racing erase.

Initial proofs: six local spool unit cases passed; four actual-runtime integration cases passed with real identities, leases, lifetime locks, peer transport, filesystem source and witness. The latter include closed custody service + standby recording/reopen, genuine all-member promotion, promotion-marker failure and exact retry, no-allocation refusal, and physical queued-title erasure. These are targeted results, not complete owned-default boot/release acceptance. Subsequent changes require their own rerun.

## Review

1. **Over-block:** missing/corrupt attribution, absent decryption key, mismatched body reuse, erased targets and bounded disk/item capacity refuse acknowledgment rather than create unverifiable local continuity. Membership-change rewrap and offline forwarding must be explicitly proven; no blank fallback or cloud purchase is a remedy assumed by this module.
2. **Under-block:** recording itself does not prove that the owner remains authorized at eventual promotion. The actual root owner adapter must re-resolve its sealed device/dashboard admission locator and current grant, then check heads/scope/fences immediately before submission. A callback's claimed outcome alone cannot mark a Source operation durable: runtime verifies the actual existing Source binding.
3. **Layer:** this extends existing Intake, not a second graph event store. Local overlays are separate from the canonical reducer and journal. Device/dashboard authority stays outside the disk spool; actual native authority stays in the existing writer engine.
4. **Signal vs authority:** no content heuristics grant or deny owner policy. Machine signatures and strict schema preserve accepted evidence, while actual owner and native-write authorities make their existing decisions.
5. **Interactions/races:** source/intake lookup prevents local cancel from replacing an admitted operation. Control is durable before private body publication; fences are rechecked after awaited publication. Priority purge is independent of the ordinary mutation queue. Promotion-marker failure cannot create a second canonical packet. Shutdown drains spool writes before lifetime lock release.
6. **External surfaces:** new versioned local Pending/status/overlay semantics require matching native/dashboard handling and actual authorization on every status/list/cancel call. No status404 is converted into permission to regenerate an unresolved operation. External custody configuration is not required for local recording.
7. **Multi-machine:** recorded-local is intentionally machine-local custody until a verified owned-machine copy exists. The logical idempotency identity is machine-independent; original signed sealed intent must be forwarded with registered recorder binding and current owner revalidation. Neither a same-disk custody signature nor a different machine ID alone proves physical disaster independence. Canonical publication still follows all-installed-member proofs.
8. **Rollback:** keep existing source/certificate/erasure ledgers intact. Disable new admissions while preserving queued files and explicit unresolved status; never silently discard or regenerate already recorded local requests. Do not resequence frozen canonical packets or relax restore/erasure quarantine.
