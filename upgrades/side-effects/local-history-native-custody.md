## 1. Over-block

Special/symlink/changing files, invalid UTF-8, unsupported session kinds, source identity mismatch, oversized supported files, wire/sequence/scope mismatch and expired work refuse. A selected live file being appended needs a stable snapshot. The existing source-byte ceiling is a conservative support policy, distinct from the character guard; it can reject a large file mostly made of excluded records. An ambiguous network outcome requires a fresh channel, not replayed ciphertext.

## 2. Under-block

These are internal supporting modules, not an HTTP admission service. Cryptographic validity alone does not prove an owner action, independent target-key enrollment, private parent-directory custody, capacity reservation or permission to copy. No server constructor or native caller is enabled here. Actual writer and private-owner prerequisites remain separate unmerged work; no no-op substitute is introduced. A callback that never settles despite cancellation can retain its lease; it is not declared exited or released by a timer. Sampled RSS can overshoot and does not prove survival under host-wide exhaustion.

## 3. Level-of-abstraction fit

The crypto primitive authenticates records without interpreting history or granting rights. Manifest parsing owns structural data only. The shared descriptor reader remains the single leaf identity/UTF-8/hash implementation; it is not directory ancestry proof. The fixed child parses inert bytes, while the parent retains current permission and output custody. Higher-level server code must own real native admission, private upload reservations, publication and durable store writes.
