# What The Quoted-Reply Foundation Check Establishes

This is a record of tests and source checks, not a new reply feature. Choosing Reply in a chat will not start working because of this documentation change.

The check establishes which existing building blocks the future quoted-reply work can reuse. Request records already survive a server restart without allowing the same uncertain operation to run again. Existing receipt checks preserve verification when a machine rotates its signing key. Those existing tests passed. The check also used the actual older message codec and store to show why an older installation can lose the connection between a reply and its original. A later duplicate does not repair the already stored message. That compatibility limit is accepted for this first version; we are not adding a separate system to preserve or rebuild quote evidence.

The report identifies the exact source-reader and navigation functions being built in the separate message-link change. Those functions are not installed in this branch, and the report does not copy or pretend to verify that other work. The quoted-reply implementation must use the real verified foundation when it becomes available.

Four remaining obligations stay explicit: connect the signature to the exact reply and original, hide protected source details, let genuine stop requests reach the existing authority, and retain safe crash outcomes without sending an uncertain message twice. These are implementation requirements, not checks this report claims have passed for a new quote route.

No new server route, browser control, database, permission, provider send or installed setting is added. No operator decision is needed for this record. The card remains open for the quoted feature, its real tests, the app owner's proof and later message actions.
