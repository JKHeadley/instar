# Side-effects review for managed retirement after a host reboot

A replacement admission can retire an unresolved managed claim only after a different valid OS boot on the same machine and the same current custody epoch. The immediate transaction retains the old launch and native identities as non-actuating, frees the canonical round scope, and applies the old remaining budget to the replacement. The indexed budget record survives an unstarted retry. A conflicting exact task key prevents retirement and replacement.

Paused, completed, legacy, foreign, and same-boot claims stay held. The caller must supply trusted local OS identity and current custody. The packaged fixture supplies the host ID. Its native cases exercise ordinary continuation and refusal with the additional evidence, while store tests simulate the boot transition and late callbacks. No global default, live launcher, or automatic recovery action changes.
