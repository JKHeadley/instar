## What Changed

The watcher that posts status lines when a message goes unanswered now follows the session that is actually answering. A message sent to a Slack channel or Telegram topic whose old session had died used to arm the watcher with the old session's name. The server then started a replacement, but the watcher kept checking the dead name. About half a minute in, it posted "5-minute check — The session appears to have stopped" while the new session was working. Now the watcher looks the session up again before every check. It holds the alarm while a session is starting, and a single dead reading at the first check gets until the 2-minute mark for a replacement to appear. "5-minute check" is printed only once about 5 minutes have passed. A session that is really dead with nothing replacing it is still reported, with wording that makes no time claim.

## What to Tell Your User

If you message me after my previous session ended, you won't get a false "the session appears to have stopped" a minute later while I'm already working on your message. If a session really does stop, I still tell you.

## Summary of New Capabilities

- No false "session stopped" alarm while a replacement session starts or is already working.
- "5-minute check" appears only after about 5 minutes.

## Evidence

Reproduced in `tests/unit/presence-proxy-replacement-session.test.ts`: all four scenario tests fail on the previous code and pass after. They cover a live replacement (no alarm, watcher switches name), a spawn in progress (no alarm until it lands), really dead with no replacement (still reported, no "5-minute" label at the 2-minute mark), and a spawn that never lands (reported at the real 5-minute mark). Two more tests check that the server wires the spawn-in-progress signal for Slack and Telegram. Incident: indra on Slack, 2026-11-03 11:46–11:47 PST.
