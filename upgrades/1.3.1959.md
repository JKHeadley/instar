## What Changed

SEC-153. The dispatch channel fetched unsigned JSON and, on its own, executed action and configuration dispatches, auto-applied lessons, and spawned an agentic session with prose content as the prompt. Now nothing is applied or executed unless it verifies under a key pinned in `dispatches.trustedKeys` (config file only), and stored dispatches keep their signature fields so that check can run. Prose, and any `agentic` step, is held for review even when signed. Configuration and action text, and unsigned automatic applies, never enter `dispatch-context.md`. `PATCH /config` and the bearer config-write guard refuse `dispatches.dispatchUrl`, `dispatchFile` and `trustedKeys`. A config migration turns off polling of the address agents were given at init, and records it under `legacyDispatchUrlRemoved`. New agents are created with no dispatch server. Held dispatches stay in the record, pending approval.

## What to Tell Your User

- **No more unchecked remote instructions**: "I used to follow update instructions from a web address without checking who sent them. Now I only act on ones signed with a key I trust, and none is set up yet, so anything that arrives waits for you to look at it. I have stopped asking the old address."

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| Dispatches executed or auto-applied only when signed by a pinned key | Pin the server's key under `dispatches.trustedKeys` in the config file |
| Remote prose never becomes a session prompt; held for review instead | Automatic |
| Dispatch origin (address, record file, keys) fenced from the API | Automatic |
| Old unsigned dispatch address migrated off | Automatic on update |

## Evidence

- `tests/unit/sec153-dispatch-origin.test.ts`: unsigned, tampered, unknown-key and prose dispatches are never executed and stay pending. A structured dispatch signed by the pinned key runs. The context file drops configuration and unsigned automatic text. The origin keys are refused for the API key. The migration removes exactly the old address.
- Before this change the fields a signature needs were dropped on storage, so a verifier could never have passed anything.
