## What Changed

- Possible blockers that the deferral checker records now hold the message text, not the whole command that sent it, and link signatures or tokens are masked. A command that only writes text mentioning the reply script (code, docs) is no longer mistaken for a message. The dashboard's Plans page shows older entries the same tidy way.

- Home: "What needs you" rows no longer repeat the machine name or show the priority word, and empty card footers are hidden.
- Work: the Pace card keeps each dot beside its line on a phone and leaves out queues with nothing open, and a stalled pile now reads "nothing came in or got done this week; N still open" instead of "holding steady".
- Promises: the empty "Waiting on you" card no longer repeats the headline.
- Messages: the page leads with "Messages to you" instead of "No messages are held" when nothing is held.
- Menus: removed the outdated "opens in the dashboard, works exactly as before" line; the footer now just links the older dashboard.

- The dashboard's Secrets page shows saved Secret Drop submissions as one counted line instead of a long code per submission.

- The automatic merger only considers a pull request whose full test run passed. A failed run used to count as "verified", so a failed PR at the front of the line was attempted, refused and retried while ready PRs behind it waited.

- The automatic merger no longer skips a ready pull request just because GitHub's list says its mergeability is "unknown" (which happens after every merge). It reads that PR directly, which makes GitHub compute it, so the next round merges it.

- When the dashboard combines information from several machines, each machine is named from the list on the machine you are viewing, so the same machine no longer appears under two names (for example in the Machines page and in alerts).

- Topics you create or rename in Telegram now get their real name on the agent's server even when its lifeline does the Telegram polling. Before, the lifeline dropped the text-less "topic created/renamed" message, so those conversations showed as "Conversation name unavailable".

## What to Tell Your User

The "In the way" list on Plans now reads as plain sentences instead of shell commands, and it no longer shows private link signatures.

Small clean-ups on the home screen and menus, mostly visible on a phone.

The secrets list is easier to read: submissions you sent through a secure link appear as one line with a count.

Changes that passed their tests no longer wait behind one that failed.

Finished changes merge without someone having to open them first.

Each of your machines now shows under one name across the dashboard. A rename changes the name on the dashboard of the machine where you rename it.

New topics show their real names on the dashboard. Topics created recently pick up their name the next time a message is sent in them.

## Evidence

- On a live agent all 50 stored entries were whole reply commands, one with a signed private link, printed verbatim on the Plans page. Unit tests run the real rendered hook against a local server and check the posted text, and check the dashboard's cleanup of stored rows.

- Found on phone-width screenshots of the dashboard; rechecked after the change. A unit test covers the row sub-line.

- On a live agent the page listed several 64-character codes; a scan of every dashboard page flagged them. Unit test covers the grouping and that the codes are not shown.

- On a live agent the merger picked a PR whose test run had failed as the oldest ready one; it was refused, and the pass ended. Unit tests cover the passing-only rule and its wiring.

- On a live agent a verified PR was absent from every merge round until it was opened directly, and merged on the next round after that. Unit test covers the direct read for "unknown" and none for a real conflict.

- On a live agent one Mac appeared as "Mac M5 Pro" on the Machines page and as "Mac Lan" in its alerts. Integration test: a peer that calls itself differently is shown under this machine's name, including the alert title.

- On a live agent, four topics created that day showed as "Conversation name unavailable"; no machine had their names. Unit tests cover the lifeline forwarding a created/renamed name; route tests cover recording it and refusing an empty message that is not a name-only update.
