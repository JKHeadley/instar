## What Changed

The top of the Accounts screen, on the phone and on the dashboard, now shows a notice only when something needs the person or changes what they can do. It used to always show a summary line, such as "SageMind - Adriana is nearly out; others have room.", which was routine and could be wrong: in the reported case two accounts were at 100%, not one "nearly out".

The phone read (`GET /mobile/accounts`) now carries `notices`, each with its action. A notice appears when a machine has no signed-in account and a sign-in would fix it, when accounts need signing in that no machine notice covers, when every usable account, or every usable account of one kind (Claude, Codex), is at or over 90% (with when room returns), or when this machine's own account list can't be read. One account full while others have room is on its row and is no longer a message. The dashboard's Accounts page uses the same rules: its title is "Accounts" unless a sign-in needs you, notices sit under it with a Sign in link or "Ask the agent about this", and the routine "at 90% or more" line and the "nothing for you to do yet" line are gone; a waiting sign-in shows on its row. The `headline` field stays for app builds that already show it, and no longer names one account as nearly out.

A test for the failed-file diagnosis peer always used the same temp folder name. An empty leftover folder owned by another user made it fail on every run on that machine, which held every PR in the merge queue. It now picks a fresh name each run. Test-only: nothing that runs on an agent changed.

The test used a fixed attempt id, so its temp folder was always the same path in `/tmp`. A folder left there by another account made five of its eight tests fail for everyone on that machine. It now uses a unique id per run.

When a feedback worker's check stopped at its time or output limit, the record held only the limit's name, so nobody could tell whether the base, head, lint or related-tests run was responsible, and the check folders are deleted with the attempt. The latest check failure now also names the check and keeps the end of its output. The failure reason itself is unchanged.

When the feedback executor could not reach GitHub, its status said github-unavailable, but nothing told anyone, and fixes stopped for more than a day without a notice. After two hours in that state it now raises one high-priority attention item per outage, and the outage record clears as soon as access returns. Behaviour during an outage is otherwise unchanged.

Serious agent-failure callouts now become evidence-backed investigation cases, separate from routine preferences. The shared correction ledger retains scrubbed failing replies, instructions, decisions, severity, diagnosis, class repair and verification receipts. Cases reopen on recurrence and cannot be verified without complete evidence, a repair reference and passing repeat/allowed-case checks.

The investigator reserves durable attempts before starting, backs off, and pauses after three attempts on unchanged evidence. Cases remain open during that pause. Evidence and immutable history replicate through the existing authenticated journal, with current origin-routed writes and clearly stale read-only copies when a holder is unavailable. Ordinary preference learning remains opt-in; failure capture is default-on with an explicit opt-out.

A Needs-you notice on the iPhone app (an attention item, such as "Something other than the lifeline called my Telegram intake") can now be settled from the owner's phone: `POST /mobile/attention/:id/choice` with `done` or `ignore` runs the dashboard's own close route. The app shows which machine raised each notice, read from what the agent already sends.

The owner's paired iPhone can open Remote Desktop with Face ID instead of the dashboard PIN, and has a Dashboard PIN page.
- `POST /mobile/desktop-unlock` takes a fresh Face ID (presence-key) signature over a single-use, purpose-bound challenge, and returns a desktop-only session. That session is tied to the phone, lasts 15 minutes, is accepted only by the Remote Desktop routes, and ends when the phone is removed, the PIN changes or the switch is turned off.
- The phone's desktop calls are signed by the phone; it never receives the API token.
- `POST /mobile/dashboard-pin/reveal` returns the exact PIN this machine's dashboard checks. Where the owner has a private chat, it first tells them there, without the PIN. Every reveal is audited.
- The browser dashboard keeps its PIN unchanged.
- The switch is `mobilePairing.ownerPresence.enabled`: live on development agents, off on the fleet.

The Accounts page's "Needs you" card now shows its whole explanation on a phone instead of cutting it off with dots. Every other card marked as needing the operator gets the same treatment.

The approved Skill Learning Sentinel spec (`docs/specs/skill-learning-sentinel.md`) lands with its maturation-ladder
entry `monitoring.skillLearning` registered in `src/data/feature-ladders.json`, so the ladder names a real feature
switch with dated rungs (dev-agent-live → fleet) from day one. No runtime behavior changes in this release; the
feature itself ships switched off until slice 0 arrives.

After a server restart, the machine's ownership number moved ahead of the copy saved with the feedback queue. Sorting refused every model call until another job updated that copy, and it reported the refusal as "call-cap-reached" even with most of the daily limit unused. The pace tuner then slowed sorting because of that false limit. A current owner with unbroken tenure now carries the saved number forward when it reserves a call, as starting a drain run already does. Stale owners and other machines are still refused. "call-cap-reached" now appears only when a daily counter is really at its limit; any other refusal reads "authority-admission-refused".

## What to Tell Your User

The top of your Accounts screen is now only for things that matter: a machine with nothing signed in, or all your accounts (or all of one kind) running out, with when room comes back. Each one has a button to fix it or ask me about it. When nothing needs you, it stays empty, and the account list shows how full each one is.

Nothing to tell. This keeps pending fixes moving and changes nothing you can see.

When a feedback fix attempt runs out of time, I can now see which check was slow and fix the real cause.

If feedback fixes stop because GitHub can't be reached for more than two hours, you'll get one notice instead of nothing. It clears up by itself when access returns.

When you point out a serious failure, your agent records what happened and investigates whether a rule is missing or an existing rule was not followed. It keeps the case open until it has evidence that the repair prevents a repeat. If an investigation gets stuck, it tells you and stops repeating the same attempt indefinitely.

Every item on the app's Needs-you list now says which of your machines it came from, and notices have Done and Ignore buttons, so you can settle them from your phone instead of only asking about them.

On your phone, Remote Desktop now opens with Face ID instead of your dashboard PIN. If a browser asks you for the PIN, the app has a Dashboard PIN page that shows it after Face ID. I'll message you privately whenever it's shown.

On a phone, the Accounts page now shows the full reason an account needs signing in. Nothing else about signing in changed.

Nothing to do. This is the design for a feature that will learn reusable skills from your repeated requests, plus
its maturation plan, registered ahead of the code so the plan cannot be forgotten.

Feedback sorting keeps moving after a restart instead of pausing and wrongly saying it hit its daily limit. No limits changed.
