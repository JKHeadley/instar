## What Changed

> **Catch-up note.** This change merged and shipped on 2026-10-21 with no release note of its own, so it reached users unannounced. Its presence in the published 1.3.1374 and 1.3.1375 packages was confirmed by reading the package contents, not by their version numbers.

- **Notices about interrupted work no longer need a Telegram topic (#2254 — merged and shipped 2026-10-21, unannounced).** `ReapNotifier` resolved its lifeline-bound notices — unbound sessions and the cross-topic index — solely through `lifelineTopic()`, which is Telegram-shaped. On an agent that talks on Slack that is always null, so every such notice was recorded `no-topic` ("lifeline topic not configured") and dropped: the layer whose whole job is to prevent silence was itself silent. Three honest outcomes now replace the single drop — a lifeline topic is used exactly as before; without one the notice goes through the server's notification gateway, which already reaches whichever platforms the agent actually has; and with no destination at all the notice is logged unconditionally and raises one `reap-notice-no-destination` item rather than disappearing.
- **The unanswered-message watcher is built on a Slack-only agent.** `PresenceProxy` and its siblings sat inside `if (sharedIntelligence && telegram)`, so on an agent with no Telegram adapter the whole block — including the watcher that notices an operator message going unanswered — was never constructed. Measured, not assumed: `grep -c 'Presence Proxy wired to Slack'` over the indra agent's entire server log returned **0**. The gate is now `if (sharedIntelligence && (telegram || _slackAdapter))`, with the Telegram-specific hooks inside it individually guarded.

- **The feedback executor's confinement rehearsal no longer fails on a cache location, which would have stopped the pipeline for a day.** `runRunnerCanary` ran every confined probe with `confinedEnv(process.env, { TMPDIR })`. vitest and esbuild write their caches next to the nearest package root, which from an attempt workspace resolves ABOVE the workspace into the agent home — a `denyRead` path — so the `base-unit-smoke` must-succeed probe died with `EPERM: operation not permitted, open '<agentHome>/package.json'`. Any canary probe failure calls `profileUnenforceable()`, which writes a `DAY_MS` latch that **no route can clear**, so a cache-location accident would have taken the executor offline for 24 hours. The canary env now also carries `VITEST_CACHE_DIR` and `ESBUILD_CACHE_DIR` under `paths.tmpDir`, exactly as `FeedbackExecutorService` already passes them to its own check runs. The sandbox settings are untouched: the agent home stays denied, and all 14 must-fail probes (including `bash-read-agent-config`, `bash-read-secret` and `bash-read-home`) are unchanged, so this cannot mask a real confinement break.

- **A pool login now records folder trust for the agent's own directory, not just the top-level first-launch flags (#2251 — merged and shipped 2026-10-21, unannounced).** Claude Code gates a session on `projects[<agent dir>].hasTrustDialogAccepted`, which is a different question stored in a different place from the three top-level flags the readiness seed already wrote. A login that had the top-level flags but not the per-folder entry therefore reported "ready" while every session launched under it hit "Do you trust the files in this folder?" — whose default option is **No, exit** — and died in about 16 seconds. Two of the Mac Mini's pool logins were in exactly that state on 2026-10-20, which is why a conversation placed there spawned three times in 35 minutes and never answered. `ensureInteractiveReady` now takes the agent directory and treats a missing per-folder trust entry as reason enough to patch, instead of early-returning on the top-level flags alone.
- **A missing agent-directory accessor degrades loudly instead of throwing.** The first version of this change called `sessionManager.agentProjectDir()` directly, and CI caught it: the account-swap refresh path injects a narrow stub for that dependency, so a direct call took the whole refresh down with `TypeError: agentProjectDir is not a function` — a worse failure than the bug being fixed. The call is now optional and, when the accessor is absent, logs a named warning saying folder trust was **not** seeded for that config home and a respawn there may still die at the dialog. Two regression tests pin both halves.

- **A conversation is no longer placed on a machine that cannot start a session (#2252 — merged and shipped 2026-10-21, unannounced).** Placement already avoided a machine whose account quota was exhausted or whose LLM circuit was open, because routing a conversation there is silence the user has to discover. A machine that cannot start a session **at all** was not covered — and it is the one cause that makes a machine look *best* rather than worst: no load, no sessions, untouched quota. On the Mac Mini (2026-10-20) two pool logins had never recorded folder trust, so every Claude session launched under them died in 16 seconds at a dialog whose default option is "No, exit"; the operator's conversation had been placed there, spawned three times in 35 minutes, died three times, and placement kept it there throughout. A new `SessionStartFailureTracker` counts consecutive startup deaths inside a 15-minute window (default threshold 3) and reports the machine as unable to start work; a single successful start clears it completely, so a machine that recovers is re-admitted with no operator action. The signal is fed from the existing `sessionExited` path (`reason: 'process-exited-during-startup'`) and the new `sessionStartSucceeded` event, rides the existing capacity heartbeat, and joins the existing placement-eligibility signal rather than adding new plumbing. The transition into the blocked state raises one attention item.

- **A message pasted into a session is recovered or announced, never silently abandoned (#2250 — merged and shipped 2026-10-21, unannounced).** Stage B fences a recovery keypress behind the durable delivery row that authorized the original injection, but those rows are prepared for `codex-cli` only — so on every other framework `fireStuckInputRecovery` returned `refused` / `missing-durable-delivery-evidence` without pressing anything. One agent's event log carried **75,001 consecutive such refusals, every one at attempt 0**: the ladder never advanced, never exhausted, and never escalated, re-asking the same impossible keypress every ten seconds while the logs recorded that recovery had happened. The fence now applies where its evidence can exist and falls through to the pre-Stage-B best-effort keypress where it structurally cannot — the same untracked path the session's own injection already takes. `verifyInjection` consumes the recovery result instead of discarding it, ends on a verify-only pass, and reports `Recovery keypress sent; outcome reported by the verification pass that follows` rather than the previous `Recovered without user intervention`, which was asserted before anything had been checked. `StuckInputSentinel` now carries a refusal budget: after `maxAttempts` consecutive refusals it raises one `undeliverable` alarm (attention item plus a line in the topic) and marks the draft exhausted, so an impossible recovery becomes an honest terminal state instead of an infinite retry.

- **The merge hot-spot in `PostUpdateMigrator` is gone.** The file imported 26 symbols from `../scaffold/templates.js` on one line, and every PR adding a CLAUDE.md awareness marker appends a symbol to it — so two concurrent PRs always conflicted on that exact line (hand-resolved five times on 2026-10-21 alone). The import is now one symbol per line, sorted, so two unrelated additions land on different lines and git merges them without help. Formatting only: `tsc --noEmit` confirms all 26 symbols still resolve, and import order carries no meaning here. A new ratchet (`tests/unit/PostUpdateMigrator-templates-import-shape.test.ts`) keeps the shape and also asserts every imported symbol is still used, so a future tidy-up cannot collapse it back or silently drop one. Honest scope: this reduces collisions sharply rather than abolishing them — two symbols that sort adjacently can still need a hand.

## Summary of New Capabilities

- `ReapNotifier` `fallbackNotify` / `raiseNoDestination`; honest `sent` / `no-topic` outcome recording.
- The shared-intelligence block is constructed for Telegram **or** Slack; seven `onMessageLogged` hooks and three `getSessionForTopic` lookups individually guarded.

- No new surface. Two additional environment values inside `runRunnerCanary`.

- `ensureInteractiveReady(configHome, { projectDir })` — patches a missing `projects[<dir>].hasTrustDialogAccepted` and seeds `allowedTools`.
- `SessionManager.agentProjectDir()`; `SessionRefresh` calls it optionally with a named warning on absence.

- `src/core/startFailureTracker.ts` — `SessionStartFailureTracker`, `DEFAULT_START_FAILURE_WINDOW_MS` (15 min), `DEFAULT_START_FAILURE_THRESHOLD` (3).
- `computeSelfQuotaState(..., startFailure?)` carries the cause; `MachinePoolRegistry.recordHeartbeat` replicates it; `PlacementExecutor.decide()` consumes it.
- `SessionManager` emits `sessionStartSucceeded`; one `machine-cannot-start-sessions` attention item per transition.

- `fireStuckInputRecovery` returns `{status: 'attempted' | 'effect-unknown' | 'refused'}`, and the Stage B fence is scoped to frameworks whose delivery rows exist.
- `StuckInputSentinel` refusal budget → one `undeliverable` escalation; `SessionManager.markStrandedDraftExhausted`.
- `onUndeliverable` wired in `server.ts` to the attention queue and the bound topic.

- No new capability. One ratchet test.
