## What Changed

- **Spec review converges on fractal 80/20.** `/spec-converge` stops when a round raises no finding that changes what gets built; wording and long-tail findings go to a `## Left behind` list instead of another round. Round cap 3 for Tier 1, 6 for Tier 2+. The "a smaller finding count is NOT convergence" rule is removed, and the report gains a `## Proportion` line.
- **Plain size tiers** in `/instar-dev` and `/build`: small and reversible → short spec, one review round, targeted tests; the full chain for large, irreversible or security-sensitive changes.
- **Found-problem triage** in `/instar-dev`, `/build` and `/autonomous`: blocks the current work → fix now; major → new topic + session that starts its own `/autonomous` run to completion; otherwise → the feedback queue (`/feedback`) or the evolution queue (`/commit-action`). Found problems no longer accrete into the run.
- **Proportion signal**: convergence reports, build summaries and autonomous final reports state effort (rounds, gate attempts) beside change size and flag a mismatch. Signal only.
- Existing agents receive the updated skills through a new update migration (stock copies only; customized skills are left alone).

- **safe-merge judges the latest run of each check, the way GitHub does.** When a check failed and a rerun on the same commit passed, safe-merge still read the old failed run and refused with `refused:red-checks` (PR 2289, 2026-10-22), although GitHub showed the required check green. It now keeps only the latest run of each check within its own workflow (a pass in one workflow never hides a failure of the same-named check in another), using the same rule the green-PR watcher uses (one shared module, `scripts/latest-run-per-check.mjs`). A rerun that is queued or still running keeps safe-merge waiting instead of being judged on the old failure.
- **A brief empty or garbled checks answer from GitHub no longer refuses the merge at once.** safe-merge reads the checks up to two more times (5 s, then 10 s later) before refusing `contexts-unverifiable`, and never retries past the merge deadline.
- **The green-PR watcher runs the safe-merge that ships with the running server**, not the copy in the agent's home checkout. That checkout can sit on any branch with uncommitted edits; on 2026-10-22 it held an old safe-merge from before local-verify, and that was what the watcher ran. The watcher still needs the instar source checkout for its git reads.
- **safe-merge finds its agent home from its installed location.** Run from `<agent home>/.instar/shadow-install/node_modules/instar/scripts/`, it now resolves the agent home from that path (only when that home has `.instar/config.json`). Before, it found the right home only because the agent home happened to be a git checkout; on an agent home that is not one, it resolved to `…/node_modules/instar` and found no config.
- local-verify's status loop also loads safe-merge from the installed package (the same helper, `src/core/installedSafeMerge.ts`).

- **A pull request with no GitHub Actions checks no longer counts as green.** When the test workflows never start (PR #2302: a conflict with main stopped `pull_request` from firing, and only Vercel reported), the green-PR watcher used to read the empty result as "settled green", and `safe-merge --auto` would arm GitHub auto-merge. With no required checks on the repository, GitHub then merges at once. Now the watcher skips the PR with the reason `no-checks-ran` (written to its audit log), and `safe-merge` refuses with `refused:no-checks-ran` and a plain message that the PR is NOT green and its CI never started. The local-verify floor is unchanged.

## What to Tell Your User

Nothing to do. My reviews of my own changes now stop once they stop changing what I build, and problems I spot along the way get sorted instead of piling onto the current job, so small requests finish much faster.

Nothing changes for you unless you run the automatic merging of your agent's own pull requests. If you do: a pull request whose tests failed once and then passed on a rerun now merges instead of being refused, and the merge always uses the checked version that came with your installed Instar.

Nothing changes for you day to day. If your agent merges its own pull requests, it will no longer treat one where the automated tests never started as ready to merge. It waits instead and says why: "no checks ran".

## Summary of New Capabilities

- None (process change to built-in skills).

- None. Two fixes to the existing merge path.

- No new capability. The merge path refuses a pull request where no GitHub Actions check ran, and names the reason (`no-checks-ran`).

## Evidence

- Before: `skills/spec-converge/SKILL.md` said "A smaller finding count is NOT convergence" with a 10-round cap; a single requested feature (topic 127831) ran 18 rounds and 9 commit attempts and absorbed 13 found problems, still unbuilt after 14 hours.
- After: the bundled skills carry the 80/20 criterion, size tiers, triage rule and proportion line; `tests/unit/PostUpdateMigrator-fractalEightyTwentyTriage.test.ts` proves the content and that a stock installed copy (including one carrying the previous criterion's marker, and the prior autonomous skill from main) is upgraded once, idempotently, while a customized copy is left untouched.

- `tests/unit/safe-merge-latest-run.test.ts` — the PR 2289 shape (fail then pass) passes; pass then fail stays red; queued and running reruns keep waiting; safe-merge and the watcher pick the same run on the same history; empty/unparseable reads retried then refused; installed-location agent home, including a home that is not a git checkout.
- `tests/unit/green-pr-automerge-wiring.test.ts` — the constructed MergeRunner gets the installed safe-merge path; the source-checkout requirement still holds.
- `tests/e2e/local-verify-lifecycle.test.ts` — the status loop loads the installed safe-merge, not a stale checkout copy.

- `tests/integration/safe-merge-no-checks-ran.test.ts` runs the real script with a fake `gh`: `--auto` with only a Vercel check refuses and never calls `gh pr merge`, and with one Actions check it proceeds to arm.
- Unit cases in `green-pr-red-watchdog`, `green-pr-logic` and `safe-merge-hardening` cover an empty rollup, Vercel only, Actions plus Vercel, and a failing/pending status still winning.
- Side-effects review: `upgrades/side-effects/zero-checks-not-green.md`.
