## What Changed

When an update check finds a new version and auto-updates are on, the agent waits five minutes (in case a newer release follows) and then installs. Before this fix, setting `updates.autoApply` to false during that wait did not stop the install: the waiting timer was never cancelled and the install step never re-read the setting, so the update landed anyway. Now turning auto-updates off, through the config file (picked up by LiveConfig) or `PATCH /updates/config`, cancels the waiting install at once; the install step re-reads the setting just before installing and refuses when it is off; and a check that finds the setting off cancels any waiting install. `PATCH /updates/config` now also returns `cancelledQueuedUpdate: true|false`. A manual apply (`POST /updates/apply`) is unchanged and still works with auto-updates off.

Fifth piece of the context budget's Phase 2 (shadow folding, still switched off): the cost-versus-savings check, in `src/monitoring/foldBenefit.ts`.

- **`estimateFoldBenefit`** works out whether shrinking a conversation now would save more than it costs. That covers the handoff turn, any re-asks, writing the bundle and the checks, set against the context no longer re-read each turn, priced with the same cost weights the context-budget metrics use. It only recommends asking when the expected remaining turns clear break-even by 1.5×. It prices conservatively on engines that don't report caching.
- **`capOne`** works out how many turns are left before the engine's own automatic compaction. It flags when only one handoff's worth of room remains.

Nothing calls it yet.

The console's Settings → Context page now has a "Practice folds" section. It shows how many practice runs have been graded of the 40 needed, what share of quiz answers would have been lost, whether any run would have lost the operator's own words or a decision, and why other attempts didn't run, all in plain words. Switched off, it says so in one line.

First piece of the context budget's Phase 2 (shadow folding, still switched off). Two new internal modules hold the deterministic half of a fold:

- **The handoff check** (`src/monitoring/foldHandoff.ts`): a strict parser for the note a session writes before a fold ("what I finished, what to keep word for word, what's open"). A verifier checks it without a model:
  - the finished stretches fall inside the conversation and don't overlap;
  - anything labelled as the operator's words is exactly one of the operator's messages, and otherwise it is relabelled as the session's own;
  - tool output points at a real transcript entry;
  - "no background work" doesn't contradict the evidence;
  - every message is accounted for exactly once.
- **The resume packet** (`src/monitoring/foldPacket.ts`): builds the restore bundle stable-first (purpose, the operator's recent words, the long view, decisions, phase, current work, the session's handoff, the verbatim tail, pointers). It opens with a marker saying this is restored context, not a new request. A verifier refuses a packet if:
  - an operator quote differs from its message;
  - tool output sits in a protected section;
  - derived text looks like an operator quote;
  - a kept item is missing;
  - the packet is too large.
  Only a verified packet is staged (private, single-use). A new `staged-fold-packet` fold carrier releases it when the fold ends, and the boot sweep releases it after a crash.

No route, config key or live behaviour changes. Nothing calls these modules yet except the boot sweep's carrier pass.

The context budget's running summary of a conversation no longer picks up the practice-fold handoff note. The layer ticker now skips the transcript range a fold's internal turns occupy, the lock window recorded by the fold coordinator. That way a conversation's "current work" never reads "writing a handoff note".

Second piece of the context budget's Phase 2 (shadow folding, still switched off): the quiz questions a practice fold is graded by (`src/monitoring/foldProbe.ts`).

- **Material.** The folded stretches go through the existing span sampler. Every decision and every "keep word for word" item is always included. An extra independent sample, stratified across the stretch, comes from what the sampler left out, so the quiz can catch losses nobody named.
- **Generation.** One model call (`FoldProbe`, with all inputs fenced as data), and at most one re-ask naming what is missing.
- **Validation in code.** Questions are typed. A question about a decision, a kept item or the next step is never treated as a lookup-able detail. A question citing material the generator wasn't shown is dropped. The floor of one question per finished stretch and per open thread is checked. The question ceiling comes from the `FoldProbe` budget.

No route, config key or live behaviour. Nothing calls it yet.

Third piece of the context budget's Phase 2 (shadow folding, still switched off): grading the practice quiz (`src/monitoring/foldGrade.ts`).

- **One model grade per answer** (`retained`, `retrievable` or `lost`), with the inputs fenced as data.
- **Fixed rules in code, above the model:**
  - "found it by looking it up" counts only for lookup-able details, and only when a lookup really happened;
  - a lookup on a constraint or an open thread counts as lost;
  - an ungradeable answer is never a pass;
  - a text search of the restore bundle corrects a wrong "it wasn't there" diagnosis, but never turns a wrong answer into a pass.
- **The roll-up.** Losing the operator's own words or a decision means roll back. A second loss after one correction means roll back. Other losses get one correction and a re-quiz. The would-be loss rate is the Phase 2 exit measure.

No route, config key or live behaviour. Nothing calls it yet.

Three corrections to the context budget's practice folds, which remain off by default. A quiz that could not cover every required item no longer counts as a graded run. An item the restore bundle carried in its safe form is no longer marked missing. The handoff request no longer asks a session for a transcript id it cannot know. The design's Phase 1 freshness window is now three days instead of a week.

The building blocks for the context budget's practice folds (Phase 2), and the record they will fill:

- **The switch.** `contextBudget.fold.shadow` is registered as dev-gated: live on development agents, dark on the fleet. Nothing runs yet.
- **`GET /context-budget/fold-shadow`.** Graded practice folds toward the 40-fold exit, the would-be loss rate, folds that would roll back, and why others were skipped. Counts only; 503 while off.
- **Clean stop and ask brakes** (`foldCleanStop.ts`). The checks that a conversation is at a safe stopping point (any unknown counts as not safe), including unfinished background tasks. The brakes cap asks at 2 per hour, back off for 30 minutes, and sample 1 in 3 stops.
- **The handoff audit** (`foldAudit.ts`). Checks the session's handoff note against open PRs and red tests in both directions, plus a fenced model check against the topic's purpose and decisions. One re-ask, a second only for a lost decision.
- **The handoff request turn**, with a message index the session can name stretches by.
- **Fold coordinator.** It can renew its lock and record the lock window. One session's tool-policy marker can now be removed on its own.
- **Per-prompt hook.** A conversation is no longer muted while its practice quiz is graded off to the side.
- An awareness note tells agents how to read the record.

Fourth piece of the context budget's Phase 2 (shadow folding, still switched off): the throwaway session that takes the practice quiz, and the narrow access it needs.

- **`runShadowAnswerer`** (`src/monitoring/foldShadowAnswerer.ts`):
  - starts a one-shot Claude Code session seeded with the restore bundle, under the live session's model;
  - the session has none of the agent's credentials and only the Bash tool, and is bounded in time;
  - its tool-policy marker is written before it starts;
  - it collects the answers, and counts a lookup only when the session's own transcript shows it happened.
- **Spawn options.** `SessionManager.spawnSession` accepts `instarSessionId` (a caller-chosen session id) and `memorySessionToken` (a narrow token, only with `omitAuthEnv`, set after credentials are blanked).
- **Probe token.** `MemoryPrivacy.issueFoldProbeToken` binds the token to a new synthetic place, `fold-probe:<topic>`.
- **Session guard.** That place can reach only its own topic's chunk lookups (`GET /topic/:id/chunks`, `/topic/:id/chunks/:key`), and the chunk handlers re-check it. It is refused everywhere else.
- **Fold-marker hook.** It now allows those two exact lookup paths, for marked sessions only. It reaches existing agents on update.

Nothing starts the answerer yet. Existing spawns are unchanged.

The context budget's practice folds now run (Phase 2, shadow folding). This is on development agents only, behind `contextBudget.fold.shadow` (dev-gated); it is dark on the fleet.

When a conversation's session finishes a turn, the runner checks three things in order:
- the brakes: at most 2 asks per hour per conversation, a 30-minute backoff, and only 1 in 3 stops;
- whether shrinking would save more than it costs;
- whether this is a calm stopping point.

Only then does it ask the session, once, for a short handoff. The conversation's sends and incoming messages wait for that one turn, at most 5 minutes. The session is released straight away. Then, off to the side:
1. a restore bundle is built and checked;
2. quiz questions are written;
3. a throwaway session with no credentials of its own answers them;
4. the answers are graded;
5. one row goes into the record at `GET /context-budget/fold-shadow`.

The live conversation is never shrunk.

Also fixed: on a machine whose session pool is live, folds could never start, because ownership read as unknown for every conversation. Ownership now follows the topic's active ownership record (§9.3). An ownership change fences the fold.

The context budget's practice folds are now listed in the project's feature ladder, LLM component registry and reviewed hook wiring. The summary layers' first soak is three days rather than seven.

The context budget's watcher (ContextBudgetSentinel) could only watch, never act, on an agent whose session pool is live. Every conversation counted as "observed only", because ownership read as unknown. It now uses the same ownership rule as the fold coordinator: a conversation is owned by the machine its active ownership record names. On that machine the watcher can request a stale summary's rebuild, clear an orphaned hold, and reconcile a stuck fold. Other machines still only watch.

SEC-118-R2, the follow-up from the independent review of #3513. The error answer to a request whose body was never read now carries `Connection: close` in its headers, as well as closing the socket after the answer. Proxies that reuse connections, such as the tunnel, then close cleanly and pass the real answer through, instead of seeing an abrupt cut.

- Closing, delivering or editing a promise by id (`POST /commitments/:id/deliver` and the other id-addressed commitment routes) no longer answers "ambiguous across machines" when the matches are copies of ONE promise. A rebuilt or restored machine can hold its own copy of a promise that started on another machine while that machine's replica holds the same record; before, the route refused even with `?origin=`, so a finished promise could not be closed at all and would later be reported as late. Now, when every match names the same origin, the copy published by that origin wins: the local record when the origin is this machine, otherwise the origin's replica, and the change is forwarded to the origin machine. Different machines that happen to reuse one id still answer 409 and still need `?origin=`. Merged rows from a replica now carry `replicaOwnerMachineId` (which machine's replica held the row). Fixes feedback `fb-6a8328a1-e98`.

- The Instar phone app can now list conversation grouping suggestions, accept one, or reject one (owner phone only, device-signed). Accepting is one request: the agent creates the group, names it and moves the conversations in, continuing on the next call if another machine is slow to confirm. Every step uses a request id derived from the suggestion, so accepting the same suggestion from two places makes one group. The dashboard uses the same single request.
- A group can become a Chief of Staff project from the phone: the agent drafts the binding (a goal from the group's name, a done checklist, the bound conversation; the owner can use their own words and repos) and the owner confirms it with Face ID. Only that confirmation creates the project, and it first re-checks that the group still matches the draft and that the conversation is not already a project.

Two silent-loss paths found in the 2026-11-20/21 Mac Studio outage review are closed.

**Replies parked while the server was starting.** When the reply script posts while the boot beacon answers ("the server is starting"), it queues the reply. Since the beacon's answer changed shape on 2026-11-16, the outbox no longer recognised that answer as proof the reply never left, labelled every such row "may have arrived" and never sent it. The proof now recognises the beacon's current body exactly (`OriginLegacy.isBootBeaconBody`), and the beacon exports its body builder (`bootBeaconResponseBody`) so a contract test pins the two together. A parked reply is now sent by the next recovery pass. An identical reply already resent by hand is suppressed by the existing content check. An unproved 503 row is counted (`legacy-503-unproved`), and an `outcome-unknown` imported row now reads `unknown` on the outcome route instead of falsely "pending, the server retries".

**Replies held because this machine did not hold the lease.** A held or parked reply is now checked against a 30-minute bound (from when it was first written) at every automatic release point: the startup-queue import, the direct send site in `recoverHeld`, and forwarded-hold recovery (`recoverForwardedHold`, shared by the quick ladder and the recovery pass). Past the bound it is never sent automatically: it is retired (`suppressed`, reason `stale-hold-handed-back`, text kept) and handed back to the session that wrote it as one line, or, when no session is running, raised as one plain hub attention item per conversation that ends "If it should still go out, tell me and I will send it." A forward whose last attempt may have reached Telegram is never retired; its receipt is still resolved first. A retired row can never be held again (no resurrection).

**Retire one held reply by id.** New `POST /telegram/origins/operations/:operationId/retire` (agent token; a phone token gets 403) stops one held or startup-parked reply on this machine with an optional note. It refuses a reply that is not held (409 `not-held`), may be mid-send (409 `in-flight`) or may already have arrived (409 `uncertain`). Every retirement, automatic or by request, writes a row to the new `telegram_origin_retirements` table (who, why, prior state, age), and the outcome route reports it. Per-operation routes now accept imported ids (`legacy:<delivery id>`).

The Instar app can now open a single work card by itself, and turn a message into a work card with Face ID, the same "Make a card" the dashboard offers with its PIN. The card remembers the conversation and message it came from. Only the owner's own paired phone can do either; the agent cannot make a card in the owner's name this way. A retry of the same request gives back the same card instead of a second one. The app's own button and card screen come in an app release; until then, "Make a card" on the dashboard works on a phone.

The worktree reaper's proof that `src/data/standards-registry.md` is an unmodified generated copy used `git hash-object`, which the source-tree guard refuses inside every agent worktree. The proof always failed, so every worktree holding that copy was kept as "uncommitted changes". The copy's git blob id is now computed directly and compared with the committed id; anything that is not an exact copy is still kept.

SEC-133. The relay and registry login signed the relay's challenge raw with the agent identity key, the same key that signs pair-verify receipts and handshake answers, so a relay that chose the challenge bytes could get those signed. The agent now signs a challenge only when it has the shape the real relay sends: 32 random bytes as base64, exactly 44 characters ending in one `=` (`src/threadline/client/relayChallenge.ts`). Any other challenge is refused without a signature: `RelayClient` emits an error with code `challenge-refused` and closes, and `RegistryRestClient.authenticate` rejects. Each refusal is reported as a health degradation that names the relay host. Real relays already send this shape, so no relay change is needed. Binding the signature to the relay itself is step 2 (commitment CMT-025).

The worktree monitor reuses each worktree's unmerged-work answer while neither its head nor the default branch has moved, and caches commit times. A quiet 5-minute scan now starts about 3 git processes instead of over 850 on a machine with about 430 worktrees.

At boot, the worktree monitor no longer parses a saved report over 16 MB. Older versions could leave a report of hundreds of MB, and parsing one at boot ran the Studio server out of memory (2026-11-19). The first scan replaces the file.
