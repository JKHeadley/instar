## What Changed

- **The operator approves constitution changes only.** Directive (2026-10-22): "Why am I having to approve these? I should ONLY have to approve constitution changes." The local-verify merge floor no longer asks for the operator's approval of a harness-changing, protected-path, skips-added or tests-removed PR, and no longer reads the feedback executor's approver acceptance. Such a record is admitted only when the verifier finds an **independent second-pass review** of that exact head: an instar-dev trace the PR adds or changes, read from the head's tree, whose second pass concurred, whose `coveredFiles` include every flagged path, and whose side-effects artifact is in the same tree. The trace must pin its artifact's sha, the artifact's second-pass section must name its reviewer, and the review is bound to the head: if a flagged file changes after the trace's last commit, a new review is needed. The record stores `independentReview: { trace, concurred: true }`. safe-merge also honours the ruleset's `require_code_owner_review`: a constitution PR that is not approved is refused with the review link instead of attempting a merge GitHub would refuse. Without it, safe-merge refuses `refused:needs-independent-review` and the `instar/local-verify` status stays pending (`awaiting-independent-review`).
- **One trace judge.** `scripts/lib/instar-dev-trace.mjs` is shared by the instar-dev pre-commit gate (its existing coverage and artifact checks, unchanged in behaviour), the verifier and the green-PR watcher.
- **Green-PR watcher.** Protected-path PRs are no longer routed to the operator. Only a PR touching a file `.github/CODEOWNERS` owns (read at runtime from the base branch on GitHub; today the constitution) waits, until GitHub reports the code-owner review approved. On the local floor a protected-path PR is judged by its record; on the actions floor the watcher checks the same independent review at the PR head itself. A `needs-independent-review` refusal is terminal for that head: no ladder attempt, no attention item, no retry until the head moves.
- **safe-merge right after a push.** When `gh pr checks` answers "no checks reported" (GitHub has not registered any check run yet), safe-merge now keeps waiting within its deadline instead of refusing `contexts-unverifiable`; zero checks never count as green, and a head that never gets checks ends `refused:checks-timeout`. Other unreadable answers still refuse, now quoting gh's error text.
- The Green-PR section of existing agents' CLAUDE.md is re-synced by the update migration.

## What to Tell Your User

You now only get asked to approve changes to the constitution, and GitHub asks you for those directly. Other risky changes, like edits to the merge tool or the test setup, get a second independent review that is written into the change, and then merge without you.

## Summary of New Capabilities

- `refused:needs-independent-review` (safe-merge local floor) and the `awaiting-independent-review` status reason.
- `record.independentReview` on local-verify records.
- The watcher waits on GitHub's code-owner review for CODEOWNERS-owned PRs instead of routing protected-path PRs to the operator.

## Evidence

- Before: safe-merge's local predicate refused a flagged record with `refused:needs-operator-approval` / `refused:approver-dependent` unless the operator had approved its exact head, and the watcher raised "touches protected paths — it needs your manual review and merge".
- Before (checks): PRs 2296 and 2314 were refused `contexts-unverifiable` ("returned unparseable JSON: ") seconds after a push. After: `tests/unit/safe-merge-latest-run.test.ts` shows "no checks reported" parsed as zero rows that do not settle, and every other empty/unparseable answer still throwing with stderr.
- After: `tests/unit/safe-merge-local-floor.test.ts`, `tests/unit/localVerify/statusProjection.test.ts` and `tests/integration/safe-merge-local-floor.test.ts` show a flagged record refused without a recorded review (even with an operator approval) and admitted with one; `tests/unit/localVerify/orchestrator.test.ts` covers a covering vs non-covering trace, a non-concurring second pass, a trace added after the head, a trace already on main, and a missing or sha-mismatched artifact; `tests/unit/green-pr-automerger.test.ts` and `tests/unit/green-pr-automerge-wiring.test.ts` show a CODEOWNERS-owned PR waiting until approved and a protected non-constitution PR merging without any operator line.
