## What Changed

One read-only route for the Instar iPhone app, for an owner phone or the agent's token: `GET /mobile/secrets`. It answers what's waiting on each machine that replies, plus this machine's key names, vault state and sync state. It never carries a value, a length, a token or a Secret Drop link.

The move check for sharing could never pass when the machine receiving the conversation was also the machine in charge of routing. Its test message was handed back to be delivered on that machine, and nothing delivered it, so the check always reported no reply. It now delivers the test message there, and says so plainly if that fails. Real messages were never affected: they have their own delivery step.

The check also credited a reply to the machine that logged it. A machine without the lease sends through the lease holder, so a correct reply read as coming from the wrong machine. It now reads the signed record of who wrote the reply.

Saved Telegram replies are retired before recovery delivery when a newer user or agent message has reached the same topic in local or pooled history. Incomplete pooled history holds the draft for later review. Automated notices and uncertain or partly delivered replies keep their existing recovery behavior. Topic-name lookup no longer sends a visible dot probe; unknown older names retain a fallback label.

## What to Tell Your User

Your iPhone app can now show which passwords or keys I'm waiting for and which ones I already hold, by name only. Handing one over still happens on the web page I send you.

Nothing to tell them. This fixes a test tool, not how conversations move.

An older saved reply will not appear after the conversation has moved on. The temporary dot used to look up a topic name is gone.

## Summary of New Capabilities

- **Passwords & keys in the app.** What's waiting on each machine, the names of what I hold, and whether my vault opens and syncs, without opening the dashboard.
- **Right now in the app.** A one-screen glance at what needs you, what's running, promises, machines and health, built from reads the phone already has.

Queued reply recovery checks topic chronology across known machines before it sends.
