## What Changed

The coherence journal's tail reader (used by the ownership applier on every tick, and by the journal read routes) now reads its window backwards in 64 KiB steps and stops once it has the entries it needs. It no longer reads and splits up to 4 MiB synchronously each time. Results are identical: the same entries, order, corrupt count and truncation flag. On a loaded Laptop, the old read held the server thread for 11.6 seconds inside the ownership tick.

## What to Tell Your User

My server should stop freezing for seconds at a time on a busy machine. One routine check was reading far more of a log file than it needed, all at once, and now it reads only the newest part it actually uses. Nothing about how messages are routed changes.

## Summary of New Capabilities

Faster, bounded reads of the coherence journal on the server's hot path (no visible change).

## Evidence

tests/unit/coherence-journal-tail-equivalence.test.ts compares the new reader with the previous body over 392 generated cases (identical results) and shows a 50-entry read of a 3.6 MB file reads at most one 64 KiB chunk. The existing CoherenceJournal*, OwnershipApplier* and JournalSyncApplier tests pass (131).
