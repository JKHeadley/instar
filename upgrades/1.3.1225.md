## What Changed

- Existing-agent framework shadows now retain the W32 preparation-carrier, liveness-authority, and cadence-executor awareness sections with exact nested-bullet boundaries, avoiding malformed markdown or unrelated over-copy.
- Every W32 liveness and preparation mutation route now has an explicit machine-local, single-executor write-domain declaration used by conformance and write-admission observability.
- Intentional fail-closed preparation and executor-rebind outcomes are distinguished from silent degradation without raising the repository ratchet baseline.
- Autonomous-stop-hook migration tests now label synthetic anchor-compatible layouts honestly and keep exact historical stock-byte coverage separate.

- Added an exact-identity W32 duty profile instead of forcing W31-only semantics onto the approved W32 charter.
- Added exact live TENETS and approved W32 charter fixtures with fixed SHA-256 assertions.
- Made recurrence due-time/ceiling bounded and frozen after close or expiry.
- Added ordered multipart reaffirmation authority for the real seven-message W32 start recitation.
- Added fresh-source machine evidence for compiler-discovered `source.*` rows.
- Bound W32 opening evidence to Lane A's server-owned liveness status; dry-run status cannot admit.

- Exact-profile W32 now enters a terminal `closed_failed` ledger state at its 24-hour ceiling, but only when its matching run-liveness authority is enabled and enforcing.
- Successful W32 close now preflights every other duty before revoking active, freezes the liveness snapshot, mints the source-bound freeze/census receipt, and closes without a separate soak.
- Liveness projection is revoked before terminal ledger persistence, so a projection error leaves a safe nonterminal ledger for retry rather than recording a false close.
- Failed/stalled terminal liveness ticks persist one notification intent, requery its deterministic live-history marker before retry, and preserve the delivery receipt across restart. Delivery is at-least-once because the external send and local receipt cannot be committed transactionally.
- Hashed per-window terminal tombstones prevent reopening a finished W32 with replacement run identities while allowing a genuinely new window to register.
- A terminal run binding cannot be registered again, and terminal lifecycle ticks cannot create additional cadence instances.

## What to Tell Your User

Window 32's supporting infrastructure now survives existing-agent migration and repository-wide ownership/audit checks without weakening any safety ratchet. Its live behavior is unchanged; this closes the integration gaps around it before rollout.

Window 32 can no longer remain visibly active after it closes or reaches its ceiling. Its last liveness snapshot and duty census are frozen, and a failed ceiling exit is durably retried across restart, with history-marker reconciliation to suppress ordinary duplicates.
