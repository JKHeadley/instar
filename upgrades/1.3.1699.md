## What Changed

An agent that sets up another agent for its owner can now make the new agent trust it as an "introducer" (`instar mobile introducer show` on the creator, `instar mobile introducer add` on the new agent). The owner's phone, which already has the creator, can then add the new agent with one Face ID tap. The phone asks the creator to vouch, with a short signed note, for that phone's own waiting key on that exact agent. The new agent checks the creator's signature and finishes the pairing. No code, no PIN, no chat round-trip. The creator signs with a key derived from its identity and used for nothing else. The list of introducers is copied to a machine that joins the new agent later.

The phone's waiting screen is now told only about ways that can work right now, easiest first. The dashboard is named only while its pairing page is actually open. A code that is held on the pairing page comes with that page's link.

An agent with no Telegram and phone pairing without Telegram turned off no longer hands out a pairing link that could never finish (fb-cceb7986-efa). It refuses with a plain reason.

## What to Tell Your User

When I set up a new agent for you, your phone can add it with one Face ID tap. Your phone already has me, so I vouch for it, and you don't need a code, a PIN or a chat with me. While a phone is waiting to pair, it only shows ways to approve that actually work, starting with the easiest.

## Summary of New Capabilities

- `instar mobile introducer show|add|remove|list`: make a new agent trust its creator's owner phones
- `GET /mobile/introducer`, `POST /mobile/introductions/challenge`, `POST /mobile/introductions` (owner phone, Face ID) and `POST /mobile/device/introduction` (the waiting phone)
- The waiting phone's status lists `paired-agent`, and `codePageUrl` when the code is on the pairing page

## Evidence

Unit, integration and E2E tests: two real `AgentServer` boots, where an owner phone on one agent activates its own waiting key on the other. Refusals are covered for the bearer token, another waiting phone, a wrong audience, the identity key, replay and expiry. The live proof ran on a cloud VM agent from the simulator; it is described in the PR.
