## What Changed

- The executor's change-set byte limit is 4 MiB, up from 2 MiB. A modification to `src/commands/server.ts` alone carries about 1.9 MB of file bytes, so a normal accompanying test could exceed the old limit. The 200-file cap, sandbox, secret scan, and protected-path gate remain in force. Independent review still refuses diffs over 192 KiB; the separate owner-approval route has its own gate.

## What to Tell Your User

Feedback fixes that touch a large source file and a test can now reach review instead of failing the size check. Oversized changes are still refused.

## Summary of New Capabilities

Feedback executor attempts may modify up to 4 MiB of whole-file bytes before review. This covers a change to the current large server source file plus a companion test.

## Evidence

- Unit boundary tests cover a large modified file with a companion test and a payload one byte over the new cap. The focused suite passed 50 tests; the full unit stage passed 52,800 tests with zero failures. Integration and E2E remain in progress.
- The live attempt failed `changeset-too-large` after touching `server.ts` and a test. Its exact byte total cannot be recovered because the workspace was removed.
