## What Changed

Pushing the secret set to another machine (`POST /secrets/sync-now`, and the boot-time push) now waits up to 30 seconds for each machine's answer instead of the general 5-second mesh limit. A WSL machine was storing every push while the sender reported it as aborted.

The Windows desktop companion now declares itself DPI-aware (per-monitor v2, with the older system-aware call as fallback) before it reads any screen size. On a display scaled above 100%, Windows had been reporting a smaller, scaled-down screen to it. The companion then captured only the top-left part of the screen, while mouse input covered the whole real screen. Now capture, cursor position and input all use real screen pixels.

## What to Tell Your User

Nothing to do. If a secret seemed not to reach one of your machines, it may have arrived anyway; the status now says so correctly.

When you control a Windows machine whose display is scaled (for example 150%), the viewer now shows the whole screen instead of a zoomed-in, cut-off corner. A tap or click lands where the cursor is drawn, not below and to the right of it.

## Summary of New Capabilities

None; a correctness fix.

Correct full-screen capture and pointer alignment on scaled Windows displays.

## Evidence

The receiving machine's log showed every push stored while the sender reported "aborted"; one call site now passes a 30-second timeout.

Live on Mama PC (1920x1200 at 150%): before the fix the viewer reported 1280x800 and showed only the top-left two thirds of the screen. After installing this build the viewer reported 1920x1200 with the taskbar visible. A low-level mouse hook in the interactive session logged the injected press and release at the exact physical pixel the viewer targeted. One click each opened and closed a Windows Terminal tab and opened the Start menu.
