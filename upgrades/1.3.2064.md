## What Changed

Web chat saves outgoing text and selected file bytes in encrypted browser storage before clearing your draft. Reopening the browser can continue the original send, and a lost response does not create a second message. Pending messages show what needs attention. You can save a local copy of an attachment or remove a saved message. Removing a local copy cannot recall a message already accepted by the server.

The connection line keeps showing Updating until the conversation's actual reads finish. A healthy connection check alone no longer hides unfinished catch-up.

## What to Tell Your User

Your browser keeps unsent text and files when the connection drops. When you return, it continues the original request or explains what needs your attention. Keep the browser profile: deleting its data also deletes its saved messages. Recovery runs while the console is open.

## Summary of New Capabilities

| Capability | How to Use |
|---|---|
| Saved outgoing text and files | Send from web chat; inspect the pending panel when a send needs attention. |
| Local file recovery | Choose Save file copies on a pending message. |
| Explicit recovery decisions | Continue the original request after reviewing the displayed reason; no replacement request is silently created. |

Existing browser pairing and channel access remain required. Browsers without Web Locks retain content and require an explicit recovery action. Configuration changes preserve existing false values and custom recovery generations.

## Evidence

The change has unit and signed HTTP coverage, six passing real IndexedDB cases and six passing production-initialization Chrome cases, including a measured phone layout. Exact-head complete verification and live release acceptance remain required; local evidence is not a claim that the update is already installed.

## Rollback

Disable browser outbox recovery and advance its recovery generation before deploying a corrective version. Keep encrypted-storage cleanup and logout guards. Restoring support requires local review in each browser profile. A historical binary predating these guards is not a supported privacy-safe rollback.
