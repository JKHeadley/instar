## What Changed

Fleet reports (about 125 between Nov 19 and Nov 26) showed `PromptGate` and `UnjustifiedStopGate` failing on every call on several agents, with `/health` reporting a 100% error rate and no cause anywhere. Bob's metrics showed all 51 failing stop-gate calls ran on `gemini-cli` with no Gemini sign-in on that machine. The cause: the provider-fallback default policy (`src/core/internalFrameworkDefault.ts`) routes the internal `gate` category to the fastest "active" framework (pi → gemini → codex → claude), and "active" meant only that the framework's provider built, which for `gemini-cli` is "the binary is on PATH". Neither gate is a safety-gating call, so a failure never swapped to another framework.

- **Routing fix.** The server's active-set filter is now the pure `selectActiveInternalFrameworks()` and also requires a usable sign-in (`hasUsableInternalLogin()` in the new `src/core/frameworkLoginPresence.ts`). For `gemini-cli` that is the CLI's own cached OAuth credentials at `~/.gemini/oauth_creds.json` with a non-empty access or refresh token (the check `crossModelReviewer` already used, now shared). Without it Gemini is not active, so the gate falls through to the next framework and finally the agent default. Agents with a signed-in Gemini keep today's routing. An operator's explicit `componentFrameworks` is untouched.
- **Error classes.** Every failed provider call now records one fixed label in the feature-metrics ledger (`error_class` column, added idempotently at open): `rate-limit`, `capacity`, `auth`, `timeout`, `max-turns`, `spawn-error`, `no-route`, `parse`, `cli-exit` or `other` (`src/core/llmErrorClass.ts`). Message and stderr text are never stored. `/metrics/features` rows and the `llmReliability` components on `/metrics/features` and `/health` carry an `errorClasses` breakdown; older rows read `unrecorded`.
- **PromptGate backoff.** After a failed detection call the same unchanged pane is not asked again until a backoff expires (30 seconds, doubling to 5 minutes; at most 1 minute for a rate limit, full capacity or a timeout). A changed pane, sent input, a successful call or session cleanup clears it at once, and pattern-based detection keeps running. The failure is reported to `DegradationReporter` with its class only, at most once per class every 30 minutes, instead of being silently swallowed.

## What to Tell Your User

If one of my automatic checks was failing every time on this machine because it was being sent to an AI service I'm not signed in to, that stops: those checks now use a service I am signed in to. And when one of my checks fails, I can now see what kind of failure it was, so I can fix it instead of guessing.

## Summary of New Capabilities

| Capability | How to Use |
|-----------|------------|
| Internal checks never route to an installed but signed-out Gemini CLI | Automatic at server start |
| Failed AI calls record a fixed error class | `errorClasses` on `GET /metrics/features` and on `llmReliability` in `/health` |
| PromptGate backs off a failing screen and reports the failure class | Automatic; `PromptGate.llmDetect` degradation |

## Evidence

- Root cause traced on main: `LATENCY_SENSITIVE_FRAMEWORK_PREFERENCE` (pi → gemini → codex → claude) in `src/core/internalFrameworkDefault.ts`, applied to an active set built from `buildProvider(fw) !== null` only in `src/commands/server.ts`; the gemini provider builds whenever the binary is detected (`src/core/intelligenceProviderFactory.ts`). Live evidence from Bob: UnjustifiedStopGate 51/51 errors in 24 h, all on `gemini-cli`, no Gemini account on that machine.
- A hand run of the plain Claude gate call on the Studio succeeded (exit 0, 7 s), consistent with its 1.4% stop-gate error rate; the failure is machine-dependent, which the routing cause explains.
- Tests: `tests/unit/llmErrorClass.test.ts`, `tests/unit/frameworkLoginPresence.test.ts` (including Bob's shape: gemini installed but signed out → gate goes to codex), `tests/unit/FeatureMetricsLedger-errorClass.test.ts` (class recorded, clamped, no text in the DB, old DB gains the column), `tests/unit/PromptGate-failureBackoff.test.ts`, new cases in `tests/unit/CircuitBreaking-feature-metrics-tap.test.ts`, `tests/integration/metrics-features-routes.test.ts` (route and `/health` carry `errorClasses`), and `tests/e2e/provider-fallback-default-policy-lifecycle.test.ts` (real server: gates route to codex, never the signed-out gemini).
