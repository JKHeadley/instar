## What Changed

On macOS, a server started in the background (a LaunchAgent, or anything that outlives its ssh or terminal session) needs the Local Network privacy permission for its own node program file before it can reach home-network addresses. macOS cannot show that prompt to a background program, so an unapproved node gets EHOSTUNREACH on every LAN peer call, which reads as a dead peer. A new process-wide listener on undici's `undici:client:connectError` channel (`src/core/MacLocalNetworkAccess.ts`, wired once in `startServer`, no-op off macOS) confirms such a failure with Apple's `/usr/bin/curl`. If curl connects where node was refused, it raises the `MacLocalNetwork` degradation, which names the node path and the System Settings fix. It re-reports every 25 minutes while the problem persists, and a later home-network connect clears it. Signal only: no routing, retry or refusal changes. Awareness entry: `mac-local-network-access`.

An organization's published AI policy is now accepted only in one standard form: the headings Purpose, Never, Ask first and Normally, in that order, with each rule on its own `- ` line. `POST /org/draft` rewrites a loose draft into that form and returns it as `policyMarkdown`, or refuses with `policy-not-standard` and a plain reason (a line outside the four sections, a character nobody can see, a comment marker or code fence). The agent, the instar.sh/join page and the Mac app read the policy with the same strict reader (`src/core/OrgPolicyGrammar.ts`), refuse anything else, and refuse names with hidden characters. The join page and the Mac app also check the policy against its signed fingerprint before showing it. This closes SEC-078 (the join screen and the agent could read the same policy differently) and SEC-077 (invisible characters could ride into the rules file).

The agent can now write a small app for one project, such as a sales pipeline or a course tracker, and attach it the same way as part 1's built-in pages. Each version needs the owner's Approve on a Work Board card from their phone; the desktop console cannot approve it. The app runs in a sealed frame: it cannot see the dashboard, its sign-in or anything outside its own data, and it only talks to `/project-apps/<appId>/api/data` and `/api/summary` with a short-lived key the wrapper hands it. Everything it stores is encrypted, and erasing destroys the keys. New routes: `GET/POST /project-apps`, `PUT /project-apps/:appId/source`, ticket/key/frame/api routes under `/project-apps/:appId/`. New replicated kind `project-app-blob` (older machines skip it). Switch: `projectApps.custom.enabled` (development agents only). For now apps are served only from the machine holding the lease; other machines show "still copying".

npm can hold a freshly published version as "staged" for close to an hour before it shows up. A release run that started in that window picked the same version number again and npm refused it (E409, then 403). This happened twice in a day (1.3.1868 and 1.3.1873): three runs failed and merged work waited 60 to 150 minutes for the next release. Both publishers (`publish.yml` and `npm run release:local`) now push a `published/vX.Y.Z` tag the moment `npm publish` succeeds, before the smoke wait. The version resolver counts the highest `vX.Y.Z` or `published/vX.Y.Z` tag as already used, so the next run picks the next number.

## What to Tell Your User

If one of your Macs quietly loses touch with your other machines over your home network, I will now tell you why and how to fix it. Usually that means turning on "node" under System Settings, Privacy & Security, Local Network on that Mac. Before this, it just looked like the other machine was off.

If you set up your organization's AI policy, the agent now writes it in one standard layout before you read it back, so what you approve, what colleagues see when they join, and what their agents follow are always exactly the same text. If a line doesn't fit under Purpose, Never, Ask first or Normally, the agent asks where it belongs instead of guessing.

When a project would be easier to run from its own little app, such as a pipeline you can drag deals through, I can build one for it. You approve each version from your phone before it runs, and it lives in a locked box: it can't see your dashboard or anything else, only its own data.

## Summary of New Capabilities

- A Mac agent server names a macOS Local Network permission refusal instead of reporting the peer as unreachable, with the exact fix.

- `/org/draft` returns the standard policy text (`policyMarkdown`) and refuses non-standard drafts with `policy-not-standard`.
- One strict policy reader shared by the agent, the join page and the Mac app; 51 shared test cases (`tests/fixtures/org-policy-vectors.json`).
- Hidden characters, comment markers and code fences are refused in policies, and hidden characters and comment markers in organization names.

- Agent-written project apps, approved version by version from the owner's phone.
- A sealed frame with a narrow per-app key.
- Encrypted app storage with erase by key destruction.
- An example sales-pipeline app.
