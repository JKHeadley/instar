## What Changed

`ConversationGraphReplicationRuntime.reconcilePending` (the background pass that finishes changes still waiting for confirmation) walked every uncertified record each pass, re-validating it and submitting it to the peers, while holding the graph's mutation lane. Peer requests (including the other machine's `observe` calls) wait behind that lane. On the accept-all rig, a backlog of 50 uncertified source-observation records made every pass long enough that every observe from the M5 timed out on both addresses, so the observations that would have certified those records never landed: a self-feeding stall. Uncertified continuations are now bounded the same way resumed deliveries already were: after one continuation does not finish (held, or not committed/canceled), no other is tried in that pass, and a record that keeps not finishing is tried less and less often (doubling, capped at 40 passes), never dropped. Both this bound and the existing delivery bound now take records least-recently-tried first, so a backlog larger than the cap still cycles through every record.

The readiness pass no longer re-runs the runtime's liveness check (`alive()`: instance lock, machine registry, identity files, signed membership) for a manifest entry when the previous entry finished without awaiting anything; after any await it checks again, as before.

When an agent runs on more than one machine, each change to the shared conversation history is confirmed by the other machines. A machine can be reached at several addresses (home network, Tailscale, tunnel). When the other machine took more than 5 seconds to answer, the sender tried the next address with the very same request. The receiver refused that repeat as a possible replay, so the answer was lost. On the page this looked like "Saved here. Waiting for <machine> to confirm." and then "changes are not being confirmed right now." Now an exact repeat of a request gets the same answer as the first copy, waiting for it to finish if needed. The work still runs only once, and a request with changed contents is still refused.

`OrphanProcessReaper.classifyProcesses` looked up each candidate process's parent pid and parent command with two synchronous `ps -p` spawns per process. On a loaded host that held the server's event loop for 3-4 seconds per poll (CPU profile of an agent server during graph work, 2026-11-18: two of the four longest uninterrupted stalls were this alone). It now reads one `ps -A -o pid=,ppid=,command=` listing per classify pass and answers both lookups from it; a pid missing from the listing (it exited, or the listing failed) falls back to the per-pid query, so classifications are unchanged.

`GraphWitnessService.recoveryManifest` (the source manifest inside every witness inventory, built on each readiness pass and on peer inventory requests) loaded each stored operation through `operation()`, which signs a witness state proof for the operation — about ten canonical hashes and an Ed25519 signature — and then threw the proof away. At ~565 operations that held the event loop 1-4 s per inventory on the accept-all rig (2026-11-18). `operation()` is now split into a private `operationState()` (the same reads and the same verification, each failure throwing as before) and the signed proof on top; the manifest uses `operationState()`. `operation()`'s output is unchanged.

## What to Tell Your User

- **Machines stay in touch under a backlog**: "If a lot of changes are waiting for my other machine to confirm, I now retry them a few at a time instead of all at once, so the other machine can still get through to me and the backlog clears."

- **Accept all with several machines**: "Accepting changes no longer stalls at 'waiting for your other machine to confirm' when that machine is busy. The confirmation comes through even if the first way of reaching it is slow."

- **Fewer pauses**: "A background check that looks for leftover processes used to freeze me for a few seconds at a time on a busy machine; it now does its work in one quick step."

- **Faster record checks**: "A check I run on my records of saved changes no longer signs a receipt for every change just to throw it away, so it finishes much faster."
