## What Changed

- `dashboard/console/home-model.js`: Home stops showing counts that ask nothing of the operator (routine notices, promises carried or untouched for weeks); a missed promise untouched for 14+ days is no longer a red row; a promise waiting on the operator is listed once (in What needs you, not again under What I've promised); when every machine is answering, Where I'm running shows that one line instead of a row per machine; the headline names the areas it can't fully see ("can't fully see promises") instead of counting them. Spec `docs/specs/console-makeover.md` §1 updated to match.

Local Verify's coordinator now offers an eligible queued PR to an idle peer even when an unrelated full test suite occupies its own slot. Its normal pump gets the first chance to start local work. Main-branch checks stay local, and the existing lease, update pause, peer version, eligibility, and durable reservation rules still govern dispatch.

- The event reporter is no longer registered on Claude Code's WorktreeCreate and WorktreeRemove hooks. A hook on those events replaces Claude Code's own worktree creation and must print the worktree path; the reporter printed nothing, so creating a worktree failed in every Instar session. A settings migration removes the entries from existing agents and keeps any other hook on those events.

## What to Tell Your User

The console's home screen is quieter. It shows what needs you and little else: no counts of routine notices or old promises, no red rows for things that went stale weeks ago, no list of machines when they are all fine, and the same item is never shown twice. Everything is still there one tap away under "See all" or the tab links.

The Mac Mini no longer needs the Studio to start a merge check before it can take a waiting PR. When another full suite has the Studio's only test slot, the Mini can still work on an eligible PR. The Studio remains in charge of merging and keeps main-branch checks.

If you or I ever tried to start work in a separate working copy and it failed, that is fixed after this update. Nothing to do.

## Summary of New Capabilities

- Calmer console Home: only actionable items on the front page.

- An idle peer can verify an eligible queued PR while an unrelated suite occupies Studio's local slot.
- Studio releases its next-slot priority claim as soon as no locally runnable verification remains.

- None; a fix for a broken Claude Code feature.

## Evidence

Console unit tests 86/86 (new: all-healthy machines collapse, stale misses aren't red, waiting promise listed once, headline names unseen areas); e2e `console-home-lifecycle` 20/20. Rendered at 390px on a live five-machine snapshot from the Mac Studio.

Two regression tests reproduced the idle-peer gap before the code change and passed after it. Focused integration, production lifecycle, full-suite, and CI results are release gates.

Reproduced on Claude Code 2.1.310: with a silent hook on WorktreeCreate, worktree creation failed with "hook succeeded but returned no worktree path"; without it, it succeeded. New migration tests run the real settings chain.
