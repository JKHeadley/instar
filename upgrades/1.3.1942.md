## What Changed

- The Windows normal-Chrome driver now always starts Chrome with `--disable-features=CalculateNativeWinOcclusion`. Without it, Chrome stops drawing a page whose window other windows cover, and stops publishing the page to the accessibility tree the driver reads. The extra-flags allowlist is unchanged and still cannot add or replace `--disable-features`.
- When a page read finds no page document but the window title names a site, the driver looks again after a second; still missing, `text`, `find`/`click`/`invoke` and `editfields`/`typeedit`/`typesecretedit` answer `ERR page-not-rendering` (exit 2) with what it observed and the remedy, instead of returning Chrome's own toolbar strings as page text with exit 0. Blank and new tabs keep their exit codes; `text` there adds a note that only Chrome's own UI was read.
- `attach` warns when the Chrome it binds was started without the fix (binding still succeeds).
- The `/normal-chrome-browser` skill gains a short Windows table (symptom, meaning, what to do), a Recovery quick list row and the flag in the `launch` row. Installed skills receive the same text on update, local edits kept.
- Corrects feedback `fb-0cecd448-dfe`: its "disconnected display" reading came from a Windows session-0 query that cannot see the desktop; the real cause was occlusion.

## What to Tell Your User

If I drive a browser on your Windows machine, pages no longer come up blank just because another window is in front of Chrome. If one ever does, I now get a clear reason and fix it myself by restarting that browser window rather than reporting the page as empty.

## Summary of New Capabilities

- Windows browser pages keep drawing while covered by other windows.
- A named `ERR page-not-rendering` when a page cannot be read, with the remedy.

## Evidence

Live on the Mama PC (Windows 11) on 2026-11-19 with a desktop app window covering the screen, throwaway profiles only: the old driver's launch showed a blank page and `text` returned only Chrome UI strings; the new driver against that same Chrome answered `ERR page-not-rendering` and warned on `attach`; the new driver's own launch read "This domain is for use in documentation examples..." and the screenshot showed the page. Unit tests pin the new driver bytes, the fixed flag, the unchanged allowlist, the named read paths and the skill-note migration.
