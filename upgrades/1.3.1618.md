## What Changed

- Slack files in the Instar iPhone app (docs/specs/mobile-native-chat-media.md §4.9, Slack half). When files in app conversations are on, every photo, document and transcribed voice note the Slack adapter downloads for an inbound Slack message (or a standalone shared file) is also copied into the app's file store and recorded as a durable `platform-media` event under the Slack conversation's canonical key — the same key app-sent Slack messages use, taken from the conversation registry's mint for the message's routing key. Each file of a message gets its own record (`<ts>`, `<ts>:1`, …), so a re-delivered message records nothing twice.
- The app's view of a Slack conversation now shows those files: a phone reading `GET /mobile/chat/slack/:id/messages` gets each recorded file as an `attachments` entry, in the message's file order. The read also returns `conversationKey`, which the phone passes as `ref` to `GET /mobile/media/<hash>`. A download is served only when this machine's own registry minted that conversation (its current key) and the file is recorded in it.
- A phone never sees a server file path in a Slack conversation: history rows and the list preview show `[photo]` and `[file: <name>]`, and the notes the adapter writes for a shared text file say "on the agent's machine" instead of the path.
- A shared text file whose content is put straight into the message is not copied (its text is already in the message).
- The copy reuses the Telegram half's checks (store size limit, disk floor, 50 MiB, hash, type from the bytes). It runs beside delivery and is waited on for at most 30 s; a failure is reported as an `AppMedia.slackInbound` degradation and the session still gets the Slack message exactly as before.
- The platform-media key check (and the purge route's) now accepts the registry's `_` unknown-workspace placeholder, which is what a Slack conversation's key carries until its workspace is known. Files recorded under the placeholder key still show after the key gains the workspace id.
- Bearer reads of Slack history, the session's Slack messages, and app conversations are unchanged.

- A promise waiting on you shows on the dashboard's home page only when it is due within a day or overdue; the rest stay on the Promises page.
- Promises no longer show Approve / Decline buttons; you reply in the conversation, mark it handled, or drop it.

- A native Linux machine (not WSL) can now be a remote desktop target. It shares the agent user's own X11 session, either a desktop login or a virtual one such as TigerVNC or Xvfb, through ImageMagick `import`, `xdotool` and `xrandr`. No VNC or other port is opened: the picture and the input travel on the same signed, encrypted desktop stream as Mac and Windows, behind the same PIN, grant, Stop and audit.
- Guided setup no longer says "Linux is not supported". A Linux server with no X display, a Wayland login, a locked screen, a missing capture tool or a display that stopped each reports not ready with a plain reason.
- Optional `remoteDesktop.linuxDisplay` (e.g. `":1"`) picks the display when there are several. WSL machines keep using the Windows companion.
- The CLAUDE.md remote-desktop section says what Linux supports; existing agents get it through the existing migration.

`POST /mobile/pairing-codes` no longer requires a running Cloudflare named tunnel when multi-route is on. A machine without one mints a link over its own Tailscale HTTPS name (a proven own name that its local `tailscale status` + `tailscale serve` still name). The Cloudflare tunnel stays preferred while it runs. Each code is bound to the host and kind it was minted for, and redeem accepts only that host. Mint refuses `409 approval-unavailable` on a machine that cannot deliver the confirmation code, and a Tailscale link waits (`409 address-unverified`) while a backup relay may carry traffic. The mint response gains `originKind`. Pairing links and waiting devices now last 30 minutes (were 10 and 15). The CLAUDE.md pairing section is updated, and existing agents receive the rewrite.

- A network-security test that could fail by coincidence for an hour at a time now uses a harder puzzle, so it no longer blocks merges. No product code changed.

## What to Tell Your User

Photos and documents you send to me in Slack now show up in that Slack conversation in the Instar app, and you can open them there. They download from the machine that lists the conversation. This only works while files in app conversations are switched on, and the app needs its next update to display them.

Promises only interrupt you when they're nearly due, and they no longer ask you to "approve" things that aren't approvals.

Your Linux machines can now show up in Remote Desktop, like your Macs and Mama PC. A Linux machine needs a desktop running as the agent's user. A cloud server can use a virtual desktop such as TigerVNC. Turn it on from the Desktop page, the same way as the other machines. If a machine has no desktop, or uses the newer Wayland desktop, the page says so instead of showing a blank screen.

Adding an agent to the Instar iPhone app no longer needs a Cloudflare address: if the agent's machine is on your Tailscale network, the link can use that. If so, I'll tell you the link only opens on a phone with Tailscale switched on. Pairing links and the wait for the confirmation code now last 30 minutes instead of 10 and 15.

Nothing visible changed; this only keeps the automated checks reliable.

## Evidence

- Unit tests (`tests/unit/app-platform-media-slack.test.ts`): Slack keys in the event validator (placeholder workspace, concrete workspace, thread; malformed keys refused), per-file ids, the conversation key from a real ConversationRegistry mint matching `resolve(id).key`, "held locally" (unknown, replicated and stale-placeholder keys refused), every file of a message found in order and under the earlier placeholder key, a duplicate, the device text, and the SlackAdapter hook (one call per file under the tag the session got, inlined text files skipped, a throwing or never-settling hook never stops delivery, no hook when off, standalone `file_shared` files handed over).
- Integration tests (`tests/integration/slack-platform-media.test.ts`) through the real device authenticator and a real registry: attachments in file order, no path in the text or the list preview, `conversationKey` returned; Bearer read unchanged; a download with `ref=<conversationKey>` serves the bytes; another conversation's file, a conversation this machine never minted, a wrong-workspace key and a junk ref answer 404; a Bearer token cannot download; media off answers 503.
- End-to-end test (`tests/e2e/mobile-native-media-alive.test.ts`): an AgentServer on a development agent with a real SlackAdapter and ConversationRegistry wires the hook; a Slack photo message is recorded on the production path, and a phone paired through the production path sees it in the conversation's history and downloads it. A fleet agent sets no Slack hook.

- On a live agent a dateless promise appeared in "what needs you" with an Approve button that had no defined meaning; on the preview with this change it is no longer on Home. Unit tests cover no date, a date days away, a date within a day, and an overdue date.

- Unit tests: headless refusal, Wayland refusal, locked screen (screen lockers and logind's lock hint), input mapping on one screen and on a chosen screen, scroll conversion, Stop releasing held keys and buttons, no input sent after Stop, and a vanished display ending the session.
- Live on Cirrus (Ubuntu 24.04, TigerVNC display :1), standalone: probe ready, about 15 frames a second at about 150 KB each, cursor placed correctly, capture refused after Stop. The full path through the app is verified on Cirrus after release.

On 2026-11-02 a fresh cloud agent with a verified Tailscale own name was refused `409 stable-address-required`, and two links expired before the operator opened them. Integration tests cover Tailscale-only mint+redeem, Cloudflare preference, the down-tunnel fallback, the relay wait at mint and redeem, binding (a Tailscale link survives Cloudflare returning; an altered host is refused), and the standby refusal.

- The test failed 4 of 4 runs on main at the time; with the change it passed 3 of 3 runs, 16 of 16 tests.
