## What Changed

Threadline pairing invites now require owner info. An agent that does not know its owner's name cannot make or approve an invite, and an invite or accept that names no owner is refused before any prompt appears. The owner name now resolves from `threadline.ownerName`, then registered users, then the one verified Telegram operator.

The agent instruction template and the in-place instruction migration now explain the usage-limit scheduler pause status. Both point to the existing migration-status endpoint, describe the conditional pause field, and distinguish a deadline release from permission to run AI jobs before a fresh healthy usage reading. The migration adds the section once to existing agents, while new agents receive the same guidance at initialization.

Instar keeps the Windows desktop unavailable if its already running companion cannot return a signed update token. Mama PC showed this failure after the first diagnostic release. The installer now records a fixed reason for that handoff: a connection refusal, an unreachable address, a timeout, an HTTP refusal, or an invalid reply. The diagnostic contains no network address, Windows path, request body, or secret. The companion still must return its update token and stop before Instar replaces its executable.

## What to Tell Your User

Pairing invites now always say who the agent belongs to. An invite from an agent that doesn't say is refused, and that agent needs updating before it can pair with me.

- **Clearer usage-limit updates:** “I can tell you whether my scheduled work is paused and whether a fresh usage reading is still needed before AI jobs resume.”

Mama PC's Instar agent remains reachable while its Windows desktop helper is off. The new diagnostic narrows down the repair, but this release alone does not make the Windows desktop ready. The normal desktop flow still asks for only the dashboard PIN.

## Summary of New Capabilities

Owner info is required for pairing. New optional setting: `threadline.ownerName`.

No new setting or user action is required. Agents can explain the bounded pause and fresh-reading state from the status endpoint when those fields are present.

The authenticated `/desktop/diagnostics` maintenance endpoint gives a fixed code for a failed Windows companion update handoff. It grants no screen or input access.

## Evidence

Justin saw "echo (unknown owner's agent)" on a live invite on 2026-10-30. Unit tests run the refusals against both handshake copies and the owner lookup against the real file layout; an end-to-end test refuses both cases through the production bootstrap.

Before this change, neither the fresh instruction template nor the update migration had the quota-pause section, so an agent could infer that a deadline alone made AI jobs safe to run. The new focused test checks both instruction paths, conditional wording for an absent field, and byte-idempotent migration: 230/230 focused tests passed. The runtime pause fix remains in a separately reviewed executor PR and is not claimed as part of this guidance change.

Focused unit tests cover the update transport failure classes and the redacted status. The existing HTTP route and production-boot tests cover the diagnostic provider path. Live Mama PC screen, input, and Stop proof remain required after the repair.
