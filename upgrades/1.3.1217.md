# Upgrade Guide — vNEXT

## What Changed

Paired machines can now recover from lost or regenerated signing/encryption
files without silently becoming a different machine. A separate Ed25519
recovery key is escrowed only when the OS keychain is genuinely available; its
public root is established during explicit pairing. After sustained typed
signature refusals, the claimant performs a bounded challenge/claim exchange
that proves possession of the new signing key and recovery-root continuity.

Peers accept only an exact next epoch with corroborating evidence. Conflicts,
missing proofs, weak replicated anchors, governor refusal, and ambiguity enter
a claim-hash-bound quarantine for phone/PIN review. Revocation remains sticky.

The same release can retain private VM/WSL/LAN/Tailscale source observations,
but address shape alone is never identity authority. Promotion remains disabled
until a listener can bind the connection to the paired Tailscale node; proxy,
public/shared-egress, and unbound CGNAT traffic cannot satisfy recovery evidence.

## What to Tell Your User

If one paired computer loses its local identity files, the other computers no
longer need a blind re-pair or a manual file edit. When the cryptographic and
network evidence is strong enough, the pairing heals under the same machine
identity. When it is not, the change waits visibly in the Machines dashboard
for approval or denial. The dashboard also shows whether this machine's
recovery key is actually available and which accepted key changes still need
acknowledgement.

## Summary of New Capabilities

- Keychain-only machine recovery keys with destructive-loss recovery rehearsal.
- One-use, exact-epoch signing-key re-announcement with possession and continuity proofs.
- Durable typed-refusal episodes, bounded retries/backoff, and SelfActionGovernor admission.
- First-hand vs replicated recovery-anchor provenance and live-peer fingerprint agreement.
- Claim-hash-bound quarantine with PIN-gated approve, deny, and rotation acknowledgement.
- Root-signed, recipient/action/content-bound operator grants for remote root rotation and acknowledgement; ordinary machine auth is insufficient.
- Root-signed, nonce-bound recovery-bearer and bulk-projection responses; stale or substituted responses are rejected.
- Sticky revocation, independent signing/recovery epochs, tombstones, and attributable audit.
- Non-authoritative endpoint observation with shared-egress/proxy defenses; promotion waits for cryptographic node provenance.
- Registry First status at `GET /identity-recovery` and `GET /identity-changes`.
- Mobile Machines-dashboard review card; fleet-dark, development dry-run-first rollout.
