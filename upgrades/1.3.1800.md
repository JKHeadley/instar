## What Changed

A pairing link can now name the conversation that asked for it (`topicId` on `POST /mobile/pairing-codes`). When the phone pairs, or does not, one plain line is posted there, for example: A phone named "Justin's iPhone" was paired with Echo (key ABCD-…). A line that cannot be posted ends in one attention item for that conversation. The phone list (`GET /mobile/devices`) also reports each recent link's outcome, and every agent's instructions now say the phone list is the answer to "did it pair?", never a delayed-message log line. Links are never refused because of `topicId`; in app or Slack conversations the link is made as before and no line follows. A new notification category, "Phone pairing results", delivers the line only when it answers the person's own recent message in that conversation; otherwise it goes to the quiet feed. Off switch: `mobilePairing.outcomeNotice.enabled: false`.

## What to Tell Your User

When I send you a link to add me to your phone, I'll now post one line in this conversation once it's done, saying whether the phone paired, and if not, why. I also check the phone list before telling you how a pairing went, instead of guessing from a delayed message.

## Summary of New Capabilities

| Capability | How to Use |
|-----------|-----------|
| Pairing result posted in the asking conversation | Automatic when the agent mints a link with `topicId` (its instructions fill it in) |
| Recent pairing outcomes in the phone list | `pairingOutcomes` on `GET /mobile/devices` |

## Evidence

On 2026-11-14 an agent told the operator his phone pairing had failed because it read a held owner-message log line, while `GET /mobile/devices` already showed the phone `active`. After: unit tests cover every outcome, the send-answer table, restart replay, outbox hand-off and the name filter; the integration test drives mint with `topicId` → redeem → confirm and sees exactly one paired line sent to that topic as a system template; the e2e test boots `AgentServer` and sees the same through its production wiring.
