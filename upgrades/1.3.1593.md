## What Changed

Promise actions in the console (Approve, Decline, Mark as done, Drop, Resume) always name the machine that holds the promise. Promise ids are numbered per machine, so a bare id could be refused as ambiguous when another machine had a promise with the same number.

The remote desktop viewer can now list a machine's screens and switch between them during a session, without reconnecting. `GET /desktop/requests/:id/displays` reports each screen's name, resolution and whether it is the main one, plus the machine's platform. Switching is a new `selectDisplay` action on the encrypted stream, sent only after the machine reports support, because an older host ends the session on a command it does not know. The macOS helper captures and maps the pointer on the chosen screen. The Windows companion can show one screen, and all screens in one picture stays the default.

Three-finger swipes send the machine's standard shortcuts through the existing input path: Mission Control, App Exposé and Spaces on a Mac, Task View and Ctrl+Win+arrows on Windows. The same actions are buttons in the tools panel. Arrow keys posted on a Mac now carry the Fn and NumericPad flags a physical keyboard sends, because macOS registers these shortcuts with Fn set.

The Windows "Instar remote control active" banner no longer sits over window buttons. It is a small always-on-top strip at the bottom right that either person can drag, and it cannot leave the screen.

On a phone, double-tap and hold now drags with no click pair, so dragging a window by its title bar no longer maximizes it. A lone tap's click waits about 300 ms to tell it apart from a double tap.

When a remote desktop stream closes, the machine being viewed logs one line of counts for that session: how many times it tried to grab the screen, how many grabs were unchanged, sent, dropped (and why: bandwidth allowance, a full send buffer, or an out-of-range size), how many grabs failed, how long a grab took on average and at most, pictures sent per second and the bit rate. Counts only; no screen content, grant or operator.

The window-run liveness authority kept a single binding for the whole agent (`window-run-liveness/state.json`), so a live run in one topic refused every other topic's registration with `window-run-liveness-active-binding-exists` and left that topic's run in `preparing` (topic 131439, 2026-11-01, while the quota topic held the slot). It now keeps one binding per topic under `window-run-liveness/topics/<topicId>/`, each with its own lock and tick serializer, and the W32 cadence clock is split the same way under `window-run-cadence/topics/<topicId>/`. The old single file moves into its topic's directory on first read. `GET /window-run-liveness` adds `states` (every topic) and both it and `POST /window-run-liveness/tick` (and the cadence routes) accept `?topicId=N`. Start admission and the preparing-run watchdog read each topic's own binding. One window id can no longer be live in two topics (`window-run-liveness-window-bound-elsewhere`). The CLAUDE.md register line (and existing agents' copy, via migration) now says one binding per topic.

## What to Tell Your User

Approve and Decline now work on every promise; before, some failed with an "ambiguous across machines" error.

Remote desktop now handles more than one screen. A Screens button lists them by name and size, and tapping one switches to it without reconnecting. Three-finger swipes work like a Mac trackpad: up shows everything, down shows the app's windows or goes back, and left and right change desktops. If a swipe does nothing on a Mac, those shortcuts are turned off in its Keyboard settings. On Windows the "remote control active" banner has moved to the bottom right, and you can drag it. On a phone, double-tap and hold now drags instead of maximizing a window, so a single tap clicks a moment later than before.

Nothing visible changes. This lets the agent find where a choppy remote desktop picture is losing frames.

If I'm running a long piece of work in one conversation, I can now start another one in a different conversation at the same time, instead of the second one quietly never starting.

## Summary of New Capabilities

No new capability; a fix.

Screen list and switching during a remote desktop session; three-finger desktop gestures and matching buttons; a movable Windows indicator.

Per-session picture counts in the server log (`[DesktopStream] frames:`).

- Autonomous runs in different topics are watched independently, so one no longer blocks another.
- The liveness status can be read for one topic (`?topicId=`) or for all of them.
