## What Changed

The first Mac remote desktop target now captures its screen through one persistent ScreenCaptureKit helper per grant. It keeps the newest frame, sends bounded JPEGs, and skips unchanged images. The sender retries a changed frame dropped for bandwidth and stops native capture immediately when access ends. PIN-only entry, one controller, ten-minute grant, and Stop remain the operator flow.

An explicitly enabled development Mac can now offer its logged-in desktop through an Instar dashboard viewer. A local ScreenCaptureKit and CGEvent helper provides display and human input. Every session requires the dashboard PIN, browser key proof, target identity pinning and a scoped ten-minute grant. One controller at a time; Stop, expiry and server restart close display and input. The phone viewer fills the screen, keeps gestures on the remote surface, and offers trackpad and direct modes. Continuous native capture uses hardware H.264 when the browser can decode it, with a JPEG fallback. The stream tolerates dropped frames and short capture failures, while persistent native helpers avoid per-action process startup. The npm release builds and includes one universal Mac helper for Apple silicon and Intel. The feature is dark by default and returns 503 on unsupported hosts.

The viewer pointer now has a black outline on white backgrounds. Laptop trackpad two-finger scrolling is sent to the remote Mac through the existing bounded input path. The Trackpad / Direct switch is hidden on devices without touch input; on touchscreens it labels the difference between relative pointer movement and touching a position directly.

The live remote desktop uses the full browser viewport, with Stop and a compact control dock over the image. Two-finger pinch zooms up to 4× and a Fit button restores the whole screen. The keyboard button focuses a typing field in the same tap so mobile browsers can open their software keyboard. The shortcut controls remain available from the dock.

The Mac remote desktop now captures up to 1920 × 1080 pixels instead of shrinking a 1080p desktop to 960 × 540. Hardware H.264 uses AVC Baseline level 4.0 and a 5 Mbps encoder target. The JPEG fallback also keeps the full pixel dimensions and uses higher quality when the bounded frame fits. The sender remains capped at 15 requests per second with a 10 Mbps byte budget and bounded frame and queue sizes.

- The event reporter is no longer registered on Claude Code's WorktreeCreate and WorktreeRemove hooks. A hook on those events replaces Claude Code's own worktree creation and must print the worktree path; the reporter printed nothing, so creating a worktree failed in every Instar session. A settings migration removes the entries from existing agents and keeps any other hook on those events.

## What to Tell Your User

Open the same Remote desktop page and enter the dashboard PIN. The Mac should update more often during motion while Stop remains immediate. This is a Mac quality pass; Windows and Linux host support and measured AnyDesk-level smoothness are still acceptance work.

On an enabled Mac, open its Instar dashboard Machines page and choose “Open this machine.” Enter the dashboard PIN. Use one finger to move and tap, two fingers to scroll, or switch to Direct mode; choose Stop when finished. The first test covers the Mac where Echo is installed. Mama PC's Windows desktop and other machines require their own host adapters and live tests before their buttons can appear. This is an initial quality pass; physical phone checks and measured latency are still needed before claiming AnyDesk-level smoothness.

On your MacBook, move and click normally, and scroll with two fingers over the remote desktop. The touch-mode switch no longer appears on a mouse-only device. The pointer stays visible on white windows.

Open the same desktop link and enter the same dashboard PIN. Rotate your phone to landscape for the widest view. Pinch to zoom, tap **Fit** to see the whole desktop, and tap the keyboard icon to type. **Stop** ends access immediately.

The Echo Mac desktop should look sharper on a laptop. Open the same desktop link with the same dashboard PIN; no new setup is needed. The browser still scales the full image to fit its window.

If you or I ever tried to start work in a separate working copy and it failed, that is fixed after this update. Nothing to do.

## Summary of New Capabilities

- Continuous native Mac screen capture with bounded frame and bandwidth use.
- Dropped changed frames are offered again without requiring another screen change.
- Wake recovery checks the current public tunnel before restarting it, preserving reachable desktop sessions.
- A viewer whose connection is lost can resume the same logical access session with fresh keys when the target authorizes it. The current browser can also replace a half-open old stream with a signed proof bound to that stream. Stop, expiry, and revocation never resume.

- Native, browser-based operator remote desktop on an explicitly enabled development Mac.
- PIN-only operator entry, target identity pinning, single controller, bounded display/input and immediate local revocation.

- A visible pointer on light backgrounds.
- Laptop wheel and trackpad scrolling through the remote desktop input path.
- Touch-mode labels and visibility that match the input device.

- Full viewport remote desktop with floating controls.
- Pinch zoom, local pan, and one-tap mobile keyboard focus.

- Full HD Mac screen streaming when the display is 1080p or larger.
- Higher-resolution JPEG compatibility when the browser cannot decode the H.264 profile.

- None; a fix for a broken Claude Code feature.

A current 12.5-second public phone-emulated motion check loaded 211 images, about 16.9 per second. A fresh public phone-emulated browser stayed live for eight active minutes with changed images at all sixteen checks, touch input, and immediate Stop. The full suite and physical phone checks remain release work, tracked in `upgrades/side-effects/native-remote-desktop-continuous-capture.md`.

Unit, HTTP integration, production-boot E2E and live macOS capture/input/revoke checks are recorded in the feature tests and the side-effects artifact. Full-suite completion is required before release.

The browser unit test checks wheel-event normalization and batching and verifies that browser pinch events are not sent as remote scroll. The public laptop browser check confirms the live viewer receives a full-resolution stream and Stop revokes access.

Focused gesture tests cover zoom, scroll, keyboard input, and cleanup. A public HTTPS browser check received a live 1920 × 1080 H.264 frame in portrait and landscape emulation, verified viewport fill, pinch zoom, keyboard focus, and Stop/revocation. Physical iOS keyboard appearance remains a device check.

Echo's 1920 × 1080 Mac display returned a full-resolution H.264 keyframe that ffmpeg decoded and a complete full-resolution JPEG. Focused protocol, stream, native host, grant, and browser viewer tests passed. The full test tiers remain release checks.
