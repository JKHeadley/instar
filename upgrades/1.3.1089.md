## What Changed

The worktree cleanup guard and stranded-work sentinel no longer report a reassuring zero
when their underlying Git worktree scan fails. Their live diagnostic routes now return an
explicit failed-enumeration status and an unknown count. The shared guard posture surface
also reports a fresh failed scan as on-blind, and its compact peer heartbeat carries that
count without treating older peers' missing field as zero. Failure count and last-failure
time survive restart, while the current blind verdict intentionally remains process-local.

## What to Tell Your User

- **Honest worktree guard health**: "If a worktree safety scan cannot see the repository, I now show that the result is unknown instead of saying there are zero items."

## Summary of New Capabilities

| Capability | How to Use |
|---|---|
| Distinguish an empty worktree set from a failed scan | Automatic on the worktree cleanup and stranded-work diagnostic views |
| See a guard that ran but could not form a verdict | Automatic on the guard posture view and peer posture heartbeat |
| Retain worktree scan failure history across restart | Automatic; one bounded record per worktree guard |

## Evidence

Before this change, a failed enumeration was collapsed to an empty array, so both live
routes returned a numeric zero. The two real server lifecycle tests now inject a failed
enumeration through the production route plumbing and observe a successful HTTP response
with a failed-enumeration status, the bounded error, and a null count. The focused local run
executed both named E2E suites and passed 154 assertions across the guard, route, posture,
and persistence layers.
