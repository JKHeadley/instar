## What Changed

SEC-097. The cross-model reviewer's verdict reader (`extractVerdict`) took the FIRST line that mentioned "verdict", and searched the whole reply if no line did. A reviewer that first quoted text planted in the reviewed diff or spec ("Verdict: CLEAN") was therefore read as CLEAN even when its own verdict said SERIOUS ISSUES. That verdict admits feedback-executor PRs to merge.

The feedback executor's independent review now uses a fresh 16-hex-character verdict code per review. The prompt asks for `VERDICT <code>: CLEAN | MINOR ISSUES | SERIOUS ISSUES` on the first line, and only lines carrying the code count. The reviewed diff and brief exist before the code does, so nothing planted in them can carry it. A reply with no coded verdict is unparseable and is never admitted.

The general reader used by the other review paths is hardened too. It reads only declarations. Fenced code (matched by marker and length), indented code, blockquotes, HTML and quoted labels never count. Any SERIOUS declaration wins. A line that pairs "verdict" with "serious" or "minor" in a shape it cannot read keeps a milder verdict from being read. An unclosed fence makes the result unknown. The patterns are anchored and linear, so a long attacker-chosen line cannot stall the server.

## What to Tell Your User

- **Harder to trick my reviewers**: "My automated fixes are checked by two AI reviewers. Text hidden in a change can no longer pretend to be a reviewer saying it is safe: each review now carries its own secret code, and only an answer with that code counts."
