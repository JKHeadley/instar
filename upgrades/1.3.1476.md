## What Changed

User corrections encountered while immediate class-review work is load-shed now enter a bounded, scrubbed capture backlog. A periodic prune removes expired entries even when the LLM circuit is open. Class review counts distinct open linked Actions and Initiatives against the work cap, admits work into remaining slots, and sends a coalesced Attention item when the cap is full. The production server now wires that attention route to Telegram.

- Generated Codex instructions now ask agents to give a direct answer, explain what they found and what they are doing next, and state whether they need input from the user.
- Existing generated Codex instruction files receive this section when a session starts. Hand-authored files are preserved.

On the default one-suite host, Local Verify now keeps its short priority claim while one verifier holds the slot if another local check is runnable. The claim uses the same queue admission decision as a normal start, so a pause, hold, remote reservation, or empty queue releases it. Hosts where both the server and verifier child can run more than one suite still leave spare capacity to other full suites. Production wiring reads both effective caps.

## What to Tell Your User

Instar is less likely to lose a correction just because review is busy. It keeps a bounded, scrubbed record for later review and alerts the agent when the review queue is full. This repairs the existing capture path; the broader automatic local and shared improvement pipeline is still being designed separately.

Codex replies should now say plainly what the agent found, what it is doing, and whether it needs your input.

When several changes are waiting for merge checks on a one-slot machine, a regular full test run can no longer slip between two checks. The merge line keeps its place while the current check finishes. Small targeted tests remain available, and a machine with extra full-test slots can still use them.

## Summary of New Capabilities

- Bounded correction capture during review load shedding, with expiry pruning.
- Review capacity based on actual open work and a coalesced full-cap alert.

Codex agents get clearer guidance for explaining progress and next steps.

- The next queued merge check keeps the one-slot machine's priority reservation through the current check.
- The reservation follows the live queue decision and the machine's actual suite capacity.
