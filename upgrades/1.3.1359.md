## What Changed

Approving a Threadline pairing invite in Telegram is allowed only for the agent's owner. Until now the agent found its owner only in the Telegram settings (`ownerUserId`, or `promptGate.ownerId` in the same block). Many agents were set up without either, so when their real owner forwarded an invite from his own Telegram account, the agent answered "Only the agent's owner can do this." and sent him to the dashboard.

Now, when no owner id is set, the agent uses the operator it has already verified: the person whose own messages reached it through its Telegram listener and were recorded as its operator. This counts only when exactly one person has ever been verified as an operator on this machine. The agent now keeps a short list of everyone it has verified, because its per-topic record only remembers whoever spoke there last. If two different people have ever been verified, or nobody has, the agent refuses. On upgrade the list starts from the operators recorded at that moment, so someone who was already overwritten before the upgrade can't be seen. Setting `ownerUserId` is still the recommended explicit choice. Records typed in by hand through the operator API, and records copied from another machine, never count. An owner id that is set still wins, so agents that have one see no change. `monitoring.promptGate.ownerId` now also counts as a set owner for pairing, and an owner id written as text ("7812716706") is read as a number.

When the agent cannot name its owner at all, it now says so: "I can't approve this here because this agent hasn't been told who its owner is." followed by the dashboard pointer. "Only the agent's owner can do this." is kept for someone who genuinely isn't the owner.

The rest of the agent's owner handling (private messages to the owner, tunnel consent prompts) is unchanged.

## What to Tell Your User

If you forward a pairing invite to me in Telegram and you're the person I already know as my operator, I can now show you the Approve button even if nobody ever typed your Telegram id into my settings. If I don't know who my owner is, I'll tell you that plainly and point you to the dashboard instead of saying you're not my owner. If anyone else has ever written to me in my Telegram group, I'll refuse instead of guessing; setting your Telegram id as my owner fixes that for good.

## Summary of New Capabilities

- Telegram invite approval works for the verified operator when no owner id is configured.
- A clear refusal when the agent has no owner it can name.

## Evidence

- `tests/unit/threadline/PairingInviteTelegram.test.ts` (42 pass) and `tests/integration/pairing-invite-telegram-routes.test.ts` (14 pass, through the real forward and callback routes with a real operator store): set owner wins; one verified operator approves; another person is refused as not the owner; a second group member who spoke last in the owner's topic makes the agent refuse both of them; two operators, none, a hand-typed record, or a sender whose message was not verified all get the "hasn't been told who its owner is" refusal.
- Breakage: each guard disabled in turn made a test fail (9 of 9 for the new history guards).
