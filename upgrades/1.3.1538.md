## What Changed

The feedback executor now excludes six exact untracked files created by this repository's build, lint, and safe-operation checks when it compares a sandboxed builder's workspace with the trusted publish clone. A file already present in the clone remains a real change. Symlinks and unrelated files remain subject to the existing gates.

## What to Tell Your User

Feedback design drafts can now pass the file-shape check after repository checks generate their normal output. The executor still refuses unrelated changes and protected tooling paths.

## Summary of New Capabilities

- The feedback executor recognizes six exact generated output paths and excludes them only when they are absent from the trusted publish clone.

## Evidence

Live attempt `feedback-d2bf749f-6792-4477-846f-f2d023888597:a1` was rejected at 2026-10-28 12:46 UTC with the exact six generated paths in `execute:spec-shape-rejected`. A regression test reproduces the seven-file workspace, verifies the draft is the sole publishable change, and checks that a tracked generated path and unrelated source file remain visible. ## Why

A live executor builder wrote the requested single design draft, but its spec publication gate saw seven changes: the draft and six files generated by the repository checks. The gate correctly refused that shape. Its own prerequisite checks had contaminated the workspace, so the draft could not reach review.

## User-facing result

Feedback builders can run repository checks without their generated files blocking a valid design draft. Only the requested draft goes to review.
