## What Changed

A headless one-shot session (`claude -p` jobs and spawns, `launchLane: 'headless'`, `completionMode: 'exit'`) that finishes inside the 120-second startup window is now recorded as `process-exited` with outcome `completed`, not `process-exited-during-startup`. The evidence is the existing `remain-on-exit failed` setting: a failed exit keeps its pane and status, so a pane that vanished after the option was set exited 0. Before this, every short job on a fast machine was logged "Died DURING STARTUP", and after three of them the start-failure tracker dropped the machine from placement and raised "This machine cannot start sessions". Interactive sessions, headless sessions that exit non-zero, and sessions whose option could not be set are classified as before.

## What to Tell Your User

If you saw a warning that this machine cannot start sessions while everything seemed to work, that was a false alarm caused by quick scheduled jobs. It no longer happens.

## Summary of New Capabilities

- Quick scheduled jobs are recorded as finished, not as failed starts.
- No false placement drop or "cannot start sessions" alert from them.

## Evidence

Four new unit cases cover both sides (clean headless finish counts as completed; headless failure, unretained pane and interactive clean exit still count as failed starts). Seen live on a fresh Ubuntu server (agent nimbus, 2026-11-03): jobs that finished in 18 to 36 seconds were logged as startup deaths and the machine dropped itself from placement.
