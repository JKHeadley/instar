## What Changed

`GET /context-budget/delta-shadow` now reports a real rework baseline (`reworkBaseline`). It used to say the rework rate "is not built yet", even though the measurement backend (`GET /context-budget/metrics`, Phase 1 S13) shipped. The baseline sums that backend's per-session rework (repeated tool inputs within the 30-turn window) over the same 24-hour window and sessions. Its status is `ok`, `pending` (a transcript has not been read yet) or `partial-before-upgrade`. `partial` is set when the backend's bounded session list left some sessions out. With no token ledger on the machine it reads `unknown` with the reason, never zero. The result is reused for 5 minutes. Read-only, no new switch.

## What to Tell Your User

Nothing to do. The context-budget check that compares shorter prompts with full ones now shows whether sessions are redoing work, instead of saying that number doesn't exist yet.

## Summary of New Capabilities

- `reworkBaseline` on `GET /context-budget/delta-shadow` carries the measured rework rate (source `GET /context-budget/metrics`). No new routes.

## Evidence

- Unit: `tests/unit/context-budget-delta-hook.test.ts`. The summed rate, a lagging session making the baseline `pending`, a truncated list setting `partial`, a null rate with no tool inputs, and `unknown` with no sessions. 78/78 with `console-context`.
- E2E: `tests/e2e/context-budget-delta-hook-alive.test.ts`. On the production path the route returns a wired baseline (sourced from the metrics route, or `unknown` with a reason), never the old text. 3/3.
