# Console names cannot be routing IDs

The console has several places where it tells a person who or what they are looking at: an agent, a machine, a Telegram conversation, a session binding, a feature, or an account. Some older pages used a routing number or a slice of an agent fingerprint when the real name was missing. That looked like a name, but it was not one. It also gave the operator no useful way to understand the row.

This change gives the console one shared display-name check. A name must be distinct from the matching ID and must not be a generated topic label, machine ID, agent fingerprint, UUID, or similar placeholder. If the source has a usable name, the console shows it. If it does not, the console says the name is unavailable in ordinary words. IDs remain available for routing and in clearly labelled technical details where an advanced action needs them. For example, the permission-slip form still submits a fingerprint as its value, but the picker describes the agent by name or says the name is unavailable.

The same check now covers Home, machines, sessions, other agents, permission slips, held messages, subscriptions, plans, promises, queue pace, jobs, secrets, feature cards, the older dashboard views, and server notices about machines. Pickers for pairing, permission slips, people, conversation settings, and secret requests omit destinations without a verified name or with a name shared by another destination. Subscription approvals, repair buttons, sign-in cards, and account-by-machine cells also withhold actions when the visible target is missing or ambiguous. This prevents an ambiguous label from selecting the wrong target. A Telegram topic called only “topic 127504” or “Telegram topic 127504” is no longer accepted as a verified title by Instar’s shared server rule either. This avoids a split where the API rejects one placeholder spelling but the console accepts another.

A missing name is a data gap, not an invitation to invent one. The user can still open the relevant row, and a future verified name from the platform or pairing record can fill the label. The fix does not rename Telegram topics or overwrite records. It changes what the console is willing to present as a name.
