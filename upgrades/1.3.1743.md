## What Changed

- **The feedback drain must earn its move to every agent on real numbers.** Its readiness bar used to pass with one good run read from the last run alone. It now needs at least 200 finished runs in the last 7 days with at least 97% of them succeeded (read from the drain's own run database, so restarts do not reset it), at least 3 feedback PRs merged at their approved head in the last 30 days, and the existing readiness error-rate check.
- **A busy server no longer makes the feedback drain job fail.** The job's first status read now waits up to 10, 20 and 30 seconds. If all three time out, the run is recorded as skipped ("server too busy"), not failed. A server that is down, a wrong answer or a broken drain still fail as before.
- **Session-run jobs can record a skipped run.** A job can write a reason to `$INSTAR_JOB_SKIP_FILE`; the run is recorded `skipped`, counts as neither success nor failure, and leaves the failure streak, the last error and the failure and silence alerts unchanged. A declared failure wins.

## What to Tell Your User

The feedback pipeline now has to show a week of steady runs and real merged fixes before it is turned on more widely, and it no longer reports a failure just because the machine was busy for a moment.

## Summary of New Capabilities

- Durable 7-day success-share and merged-PR bars for the feedback drain on the maturation ladder.
- `$INSTAR_JOB_SKIP_FILE`: a session-run job can record its run as skipped.
