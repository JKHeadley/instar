## What Changed

Two read-only routes for the Instar iPhone app, for an owner phone or the agent's token: `GET /mobile/proposals` and `GET /mobile/inside`. Each answers a trimmed summary across the machines that reply. Nothing is written.

On multi-machine agents with the session pool active, a conversation already running on a machine now stays there instead of being placed elsewhere on its next message, unless it is pinned elsewhere or this machine can no longer serve it. A moved conversation now fetches its recent messages over the signed mesh, so it no longer needs a bearer token shared between machines. The older call remains as a fallback and now has a 5 second deadline.

Every place the server hands a session or a notice a Telegram topic id now carries the topic's verified name beside it — `topic 11882 "🤝 echo"` — read from the existing topic registry, or says `(name unresolved)` plainly when no trusted name exists. This covers the `[telegram:N …]` message prefix (which now always includes the name or the unresolved marker), the agent-to-agent reply notices and spawn-prompt topic hints, and attention items and notices that mention a topic. One shared formatter renders them, and a ratchet test fails when new code renders a bare topic id.

## What to Tell Your User

Your iPhone app can now show proposed fixes and how I'm doing inside, without opening the dashboard. Dismissing a proposal is still done in the dashboard.

Nothing changes for you unless your agent shares work across machines. If it does, a running conversation won't jump to another machine by itself, and a moved one gets its recent messages back.

When I mention one of your topics, I can now always tell you its name, not just its number — or I'll say the name isn't known yet.

## Summary of New Capabilities

- **Proposals in the app.** Fixes I suggest after a new kind of failure, how often it happened and on which machine.
- **How I'm doing inside in the app.** Recent records, repeating problems, checks on my own claims and correction reviews, for each machine that answers.

| Capability | How to Use |
|---|---|
| Running conversations stay on their machine | Automatic when the session pool is active |
| Moved conversations get recent messages without a shared token | Automatic; uses the `topic-history-pull` mesh verb |

No new capability; topic names now travel with topic ids in everything the server tells a session or a notice.

## Evidence

Live, 2026-11-02: a peer's session was told "the server sent it to topic 11882, the topic for echo" and told its user it could not see the topic name, though the registry held "🤝 echo". Unit tests cover the formatter and the prefix; an integration test drives a real ThreadlineRouter + TopicLinkageHandler with names from a real TelegramAdapter registry; an e2e test checks the boot wiring and the adapter-to-prefix path.
