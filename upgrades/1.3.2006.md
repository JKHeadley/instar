## What Changed

The development Chief of Staff can search open Instar pull requests and recent merged work through the local server. It searches descriptions and branch names as well as titles. The lookup returns evidence links and shows which parts of GitHub it could read. Existing and new agents receive instructions to use the lookup before answering whether work exists or assigning a new design.

The Chief of Staff pull request lookup now requires GitHub to confirm the repository is public. When GitHub reports private or unverified visibility, the service clears both cached views before serving another result.

Purely internal agent cards no longer populate the owner's ordinary work board, Projects, Conversations, pins, search, unread or Needs-you counts. A deliberate agent-only board view retains access. Internal history is created when execution or an allowed note needs it; existing history is preserved. Status wording describes agent execution without inventing an owner approval request. Genuine person-facing requests remain visible. Enabled hierarchy reads apply the same presentation boundary without removing graph records or owner authority.

## What to Tell Your User

When you ask me whether something was already planned, I can look for the work where it actually lives, including an open pull request. I can point you to the original work and say if I could only check part of the record.

The public work lookup now checks that its source is still public. It reports missing coverage when it cannot verify that.

Routine work the agent manages stays out of your conversations and Needs you. You can inspect it through “View the agent’s internal cards.” Real questions and approvals still appear where you expect them.

## Summary of New Capabilities

| Capability | How to Use |
|---|---|
| Prior pull request lookup in the development Chief of Staff | Ask whether an Instar change already exists or bring up a proposed new design. The Chief of Staff can look up the public repository and cite what it finds. |

Public source coverage uses verified GitHub repository visibility.

The board's explicit agent view and additive classification fields let clients distinguish internal work without guessing from titles. Ordinary reads remain the owner projection.
