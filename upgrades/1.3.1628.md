## What Changed

The direct destructive-operation lint now reports files and directories it could not inspect. Temporary read errors are retried briefly; an unreadable or unparseable path produces a nonzero result instead of being silently skipped.

## What to Tell Your User

The source safety check now tells you when it could not inspect an enumerated source file. A clean result means it read the paths it selected to inspect.

## Summary of New Capabilities

- Names unreadable or unparseable selected files and unlistable existing directories, with the reason inspection failed.
- Retries short-lived file read errors before reporting that the scan was incomplete.

## Evidence

The focused lint tests cover read and parse failures, transient retries, unreadable directories, and a clean tree. The exact PR head also passed the local unit, integration, and end-to-end verification before this release-note-only follow-up; the new head still requires its own verification.
