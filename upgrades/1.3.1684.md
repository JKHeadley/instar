## What Changed

The lifecycle end-to-end test no longer fails under load at its final "saved to disk" check. Before running a job by hand, it now ends its own leftover sessions instead of waiting for them to finish. It then checks right away that the job really started. Test-only; no runtime change.

A machine that took over an agent after a network split could stay silent on Telegram. Its lifeline remembered the "someone else is polling" (409) errors from the split and, since #2759, refuses to start polling while that count is above zero. Only a successful poll reset the count, so it never polled again. Now a 409 counts as evidence for two minutes only (twice the longest backoff), so an old count lapses. A standby also stops reporting itself as stuck in a 409 fight to the watchdog. The rule against a second poller is unchanged.

Six more faults in the locked-screen proof driver (`scripts/locked-proof/`), found in the live run on the Mac Mini on 2026-11-05 after the viewer-wait fix let it start. Proof tooling only; no runtime code changes.

1. Cases 12.1 and 12.6 freeze the server with SIGSTOP, but the server ran as a tmux pane process and tmux resumes a stopped pane process at once, so the server never froze and the case judged a running server. Both cases now serve the agent under launchd first and put it back in tmux afterwards, and `stop-server` throws unless `ps` shows the process stopped.
2. After `start-server` or `serve-under-launchd` the driver went straight on while the new server still read the lock state as "unknown", so the final sample read "unknown" and the next case's viewer had no machine to open. Both now wait up to 120 seconds for a known lock state.
3. `readLockState` returned agent A's "unknown" without asking agent B. An agent that does not know yet is now skipped like one that is down.
4. The driver took a proof server's `/desktop/locked/status` as the lock state. That value is a cache which only refreshes while a viewer is connected, so it read "unlocked" for a locked Mac and "unknown" after a start, and verdicts could be wrong in both directions. The driver now reads the Mac's own flag from IORegistry (`IOConsoleUsers`, `CGSSessionScreenIsLocked` for the proof user) and asks a server only when the proof user has no console session. Every sample records the servers' reading beside it as `serverLockState`.
5. Case 12.3 kills the proof user's tmux server, which takes agent B down with agent A, and the driver restarted only A. `start-server` now always starts agent A, as before, and also starts agent B when it is not listening.
6. `recover()` failed a case when it tried to resume a process that had already exited. Resuming a process that is gone is now skipped; stopping or killing one that is gone still throws.

The maturation ladder's crash-loop pauser and unknown-agent trust entries now carry a graded-wrong quality bar: at most 5% of reviewer-graded decisions may be wrong, with at least 5 graded. A feature that runs often but does the wrong thing can no longer read ready-to-advance. A new registry marker, `shippedOn`, records that the code switches a feature on for every machine regardless of its setting. Such a feature reads as fleet. The autonomous heartbeat uses it, so the ladder stops reporting it as dark.

Adding a phone no longer needs a code to be read and retyped. The owner's private Telegram message now has an Approve button beside Decline, and the pairing page and the legacy dashboard's Phones tab have Approve on each waiting phone, behind the same unlock that shows the code. An already paired owner phone on the same machine can list and approve a waiting phone with Face ID (`GET /mobile/pairing-requests`, then challenge, approve or decline). Each approval is bound to one waiting phone, works once, ends when that pairing ends, and a late, repeated or wrong answer refuses with a plain reason. The redeem answer and `GET /mobile/device` now tell a waiting phone `confirmWith`, `fingerprint` and `expiresAt`, so the app can wait instead of asking for a code. If a link is used by two phones, or two phones wait at once, Approve is refused and the code or Decline remains. A phone paired for someone other than the owner stays code-only. The code keeps working for older apps, and stays readable after Approve because an older app finishes on its code box. Off switch: `mobilePairing.approve.enabled: false`.

Remote Slack history now binds its owner check to the key and person that actually signed the request. It rereads live device, revocation, named-owner and pairing/native authority before each holder dial and after formatting, using the exported mobileOwnerDeviceAdmission helper.

The worktree reaper no longer counts the commit gate's own untracked or ignored decision records and traces as uncommitted work. Before it removes a checkout it copies those records to `.instar/instar-dev-decisions-archive/<worktree>/`, checks each copy byte for byte, and keeps the checkout if the copy fails. Only files named the way the gate names them qualify; staged records, locally edited tracked records, nested files and symlinks still keep the checkout. The reaper's off-by-default switch is unchanged.

When `instar worktree create` refuses because `.worktrees/` holds 500 directories, the message now says how many are git checkouts, how many are other folders, and what those folders are by name. The limit and what counts toward it are unchanged.

## What to Tell Your User

If your agent runs on two machines and the connection between them drops, the machine that takes over now answers your messages. Before, it could stay quiet until it was restarted.

My feature-promotion scoreboard got stricter. A feature now has to make good decisions to move up, not just run often. The progress-heartbeat feature, which is already on everywhere, now shows as on.

- **Adding a phone**: "When a phone asks to pair, you can tap Approve in your private Telegram message or on the pairing page instead of typing a code. Only approve if you are pairing a phone right now and the key shown matches the app. The code still works if the app asks for it."

If you remove a phone's access while it is waiting for Slack history from another machine, the waiting read now checks that change before showing the history. It also stops if the phone's key or person changes, its owner loses that role, or pairing is turned off.

Nothing changes in day-to-day use. If I ever run out of room for new working copies, my report of what is filling that folder is now specific. Cleanup of old working copies also keeps a copy of their review records.

## Summary of New Capabilities

None. This is a bug fix.

- Maturation ladder bars can now hold a feature back when reviewers have graded its decisions as wrong.
- The ladder recognizes features that are on in code for every machine.

- Approve or decline a waiting phone from the owner's private Telegram chat, the pairing page, the legacy Phones tab, or an owner phone with Face ID.
- A waiting phone can read where its approval is waiting and move on by itself when it is approved.

No new route. Remote history checks the actual signed phone identity, current owner profile and recorded revocation before each holder connection and before returning content. The shared admission helper is available to other private phone-read routes. Sends and remote attachment downloads are unchanged.

- The worktree reaper archives commit-gate records before removing a checkout, so no audit record is lost with the checkout.
- The worktree capacity refusal names what is filling the folder.
