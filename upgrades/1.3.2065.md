## What Changed

- **Stop-check decisions can now be replayed (development agents only).** The UnjustifiedStopGate's prompt is now built by one pure function (`buildStopGatePrompt`) from the system template, the trusted evidence and the guard-filtered untrusted content. On a development agent each stop-check decision row in the local judgment provenance log keeps the credential-scrubbed (`scrub-secrets-v1`) stop reason and recent turns plus the trusted evidence under the machine-local `_contentFull` field, and the served context gains `promptSha256` (the prompt the model saw), `replayPromptSha256` (the prompt rebuilt from the stored copy), `scrubChanged`, `scrubVersion` and `captureVersion: stop-replay-input-v1`.
- **The replay check is explicit.** `rebuildStopGatePromptFromCapture` and `assessStopGateReplayEligibility` rebuild the prompt from a stored row and compare it with `replayPromptSha256`; `exact` is true only when the scrub changed nothing. Truncated, missing, malformed, unknown-version and tampered captures are reported as not replay-eligible with a fixed reason.
- **Nothing the stop check decides changes.** Prompt text, model, timeouts, parsing and the continue/allow/escalate verdict are unchanged; the scrub applies to the stored copy only.
- **Switch.** `monitoring.stopGateReplayInput` (dev-gated: on for development agents, off on the fleet, where rows stay byte-identical), resolved through `resolveStopGateReplayInput`. Registered in the dev-gated feature list, as a composed ladder entry, and as an awareness entry.

## What to Tell Your User

Nothing changes in how I decide whether I may stop. On development agents I now keep a scrubbed copy of what each stop check judged, on this machine only, so we can test whether a cheaper model could make the easy calls.

## Summary of New Capabilities

- Replay input for stop-check decisions, kept machine-local and never served.
- A prompt-fingerprint check that marks rows that cannot be replayed, and says whether a replay is byte-exact.

## Evidence

- `tests/unit/stop-gate-replay-input-capture.test.ts`: with capture on, the stored copy rebuilds the exact prompt for both guard settings (guard off stores the user-stripped turns the model saw); a token in the reason is scrubbed from the row while the model still sees it, and the row is marked not exact; a real JudgmentProvenanceLog serves no captured text while the local row passes the check; capture off leaves the context keys and the prompt unchanged; the verdict is identical with the switch on and off; every unreplayable row shape is refused.
- `tests/integration/stop-gate-replay-input-provenance.test.ts`: a real gate call through a real IntelligenceRouter and decision-quality recorder; `GET /judgment-provenance` never returns the captured text or `_contentFull`, the local row passes the check, and its `rawResponseHead` carries the verdict.
- `tests/e2e/stop-gate-replay-input-lifecycle.test.ts`: the server's construction site uses `resolveStopGateReplayInput`; a development config writes an eligible, exact row, a fleet config writes a row with no capture, with the same verdict.
