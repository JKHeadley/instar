# Two machines without a git remote no longer restart each other

## What Changed
On a two-machine agent with no shared git remote, a machine that restarted could claim the lease from its own old copy without asking the other machine. That made both machines hold the lease at once, the tie-break made one of them restart, and that restart set up the next tie, about every 15 minutes with no end. A machine that keeps only its own copy of the lease now asks the other machine first, for up to 10 seconds. A peer's lease at the same number now replaces its own expired copy, so it names the right holder and stops handing the old copy to the holder. An expired peer lease no longer counts as a tie. If nobody answers it claims as before, so takeover of a machine that is really down still works. Such a machine now also always renews the lease it holds. Before, only agents with Telegram or app conversations did, so on other agents, Slack ones included, the lease ran out between checks, the other machine took it, and each swap restarted a machine. An explicit setting that turns renewal off still wins. A signed request from the other machine for the lease now also extends the holder's lease, because a machine that is restarting asks for it long before it can receive anything, and the holder's lease used to run out in that window. A machine whose identity is not set up now also gives up a lease it holds while renewal is running.

## What to Tell Your User
If your agent runs on two machines without a shared git remote, those machines could have been restarting every 15 minutes, dropping connections each time. After this update they should settle down on their own. Tell me if you still see it.

## Summary of New Capabilities
- A machine that has just restarted checks with the other machine before taking charge, on pairs with no shared git remote.

## Evidence
Unit: tests/unit/lease-restart-no-tie.test.ts covers both sides of both decisions. Coordinator: tests/unit/lease-restart-no-tie-coordinator.test.ts runs the real pull loop, tie-break and restart decision: five restarts on each side, a return at the holder's number, and 15 simulated minutes with no holder change (the same rig with renewal switched off changes holder repeatedly; measured at 15 changes). Integration: tests/integration/lease-restart-no-tie.test.ts replays the restart over the real lease transport with real lease files, including ten restarts behind a live holder, a restart longer than the lease, and a takeover with the holder down; tests/integration/lease-contested-resolution.test.ts covers the expired-lease rule. Wiring: tests/e2e/lease-takeover-wiring.test.ts. Found live on the test pair nimbus and proof-2 (fb-c51067c6-148): 58 restarts in about 15 hours. A simulation of the real coordinator over 2 to 3 hours: up to about 30 seconds fully down, a single restart settles at once; from about 35 to 60 seconds it can take a few extra restarts and then settles; past the 60-second lease on every restart it still loops. One long outage followed by short restarts settles. Echo's one measured restart was 14 seconds; Luna's three auto-update restarts were about 61 seconds, for a reason not yet known, with one role restart and no loop in its current log on this machine. Not yet proved live on the pair.
