## What Changed

- **The `/normal-chrome-browser` skill now covers Windows as well as macOS, as one method with one set of rules.** The Windows driver, `native-drive.ps1`, was written by PP (an Instar agent) and ships exactly as reviewed and live-tested: it drives a normally launched Chrome with real mouse and keyboard input and reads the page through Windows' accessibility tree, with no debugging port. Its wrapper, `ndrive.sh`, is how an Instar agent calls it from WSL and is where Instar's rules are enforced: it refuses the operator's own Chrome profile folder and any non-local or malformed profile path, refuses anything flag-shaped or quote-smuggled in a URL slot, a URL carrying a credential-shaped parameter (a one-time code or token never goes on a command line), an outfile that is not a local Windows path, and anything but a real `chrome.exe` as the browser to start, keeps each agent's "which Chrome am I driving" record separate, honors the "take focus anyway" override only against a recorded operator declaration (`normalChromeBrowser.unattendedMachine`, written by the agent when the operator says the machine is unattended), asks the driver whether anyone is using the machine before `invoke`, runs one driver at a time per agent (a second call waits, then answers `ERR busy`, so two sessions do not interleave keystrokes on one Chrome within the windows the skill states; a driver that outlived an interrupted call is waited for too), sweeps the leftovers of an interrupted earlier call, can check the page's host before every click or keystroke (`ND_EXPECT_HOST`), refuses further input after a timeout or crash until the agent has looked at the page, and writes one content-free line per call to `.instar/logs/normal-chrome-browser.jsonl`.
- **An Instar agent inside WSL can reach the desktop.** On the operator's Windows machine Instar runs in a background Windows session that cannot see the desktop (found by the live test). The wrapper detects that and runs the driver through a one-shot Windows scheduled task on the desktop session, with no password, no install and no admin rights.
- **Each side's lessons now protect the other.** The macOS launcher refuses a launch flag in its URL slot (before, `chrome-launch.sh prof --remote-debugging-port=9222` would have reached Chrome), refuses a URL carrying a credential-shaped parameter without echoing it, and opens Chrome in the background so it never takes focus from whoever is at the keyboard. The Windows section carries the macOS lessons (read why a page refuses before guessing, verify by reload, scheduling, the stale API-token trap) and PP's Windows lessons (fill fields by index, disable extensions for a scripted sign-in, run `canfocus` before a live test, the PowerShell 5.1 traps, `WSLENV`).
- **Three platform cases, stated plainly:** macOS; Windows reached from WSL (the shell an Instar agent on Windows runs in; other Windows shells are refused, not guessed at); Linux with no Windows underneath, which is not built (tracked as ACT-138).
- **Existing agents get the new text on their next update.** An untouched copy of the skill is replaced whole; an edited copy keeps every edit and gains the shared rules and the Windows section at the end, with the full shipped text beside it as `SKILL.shipped.md`. The CLAUDE.md card now says macOS + Windows; the old macOS-only card is replaced in place only when it is the exact shipped text (an edited one is kept), in CLAUDE.md and in the AGENTS.md/GEMINI.md mirrors, and a stale copy left by a release revert is removed.
- **The decision-surface lint now watches PowerShell files** (`.ps1` joined its population), and all five browser scripts are declared and content-pinned.

## What to Tell Your User

Your agent can now do web tasks in a normal Chrome window as one of its signed-in accounts on Windows too, not only on a Mac: things like reading a usage page, changing an account setting, or finishing a sign-in that an automated browser gets blocked on. On Windows it clicks and types for real, so a sign-in popup that only opens for a person's own click now opens. It only does what you ask. It never touches your own Chrome, never takes the keyboard while you are using the machine, and never prints a password. If a page asks for a CAPTCHA or a phone confirmation, it stops and tells you. The one new setting is a record that a machine is unattended; your agent writes it only when you say so, and it is what allows the driver to take focus on a machine nobody is using. Linux without Windows underneath is not covered yet, and your agent will say so rather than improvise.
