## What Changed
- **Reading another machine's session no longer needs a shared API token.** Machines of one agent that were joined with different tokens could not read each other's session transcripts or pool history ("token refused"), and the credential URL guard refused others ("peer URL refused"), F4 in `docs/specs/native-conversation-any-machine-access.md`. A new signed mesh verb, `session-transcript-pull`, serves one page of a session's record (or the machine's own session list), and `topic-history-pull` gains a `shape: 'pool'` with whole rows, `before` / `beforeMessageId`, up to 100 rows and a 512 KiB cap. `GET /sessions/NAME/transcript?machineId=`, `GET /sessions?scope=pool` and `GET /telegram/topics/N/messages?scope=pool` ask over the signed verb first and say how each machine was read (`via`).
- **The bearer hop is a narrow fallback.** It is used only when a machine says definitely that it cannot serve that kind of read: `no-handler`, `claim-unauthorized` from a machine whose version advert is absent or older than this release, or a history answer without the `shape: 'pool'` echo. A timeout never falls back to sending the token; the machine is listed in `asleepOrUnreachable` with its name and last-seen time. What each machine has answered in signed form is remembered per machine, per kind of read and per version: `GET /pool/signed-reads` (`signedCapable`, `bearerFallbackNeededBy`, counts).
- **Nothing is cut silently.** Each transcript entry carries `index` (its place within its record) and `clipped: true` when the 4,000-character cut applied; `full=1` returns it whole. A page that stops inside one record continues with `nextBeforeIndex`. A row larger than the cap comes cut on a character boundary with `rowTruncated: { row, totalBytes, from, to }`, read on with `rowOffset` / `rowIndex` / `byteFrom` (history: `row` + `byteFrom`). The machine's own API token and dashboard PIN are removed before any clip or cut.
- **Who may read a transcript.** The owner only, and only where the owner may see every conversation the session served, resolved at read time from this machine's team record. While the team log has a gap or the team puller is refusing, the read is refused ("This machine cannot confirm who may see this session right now."). A session of someone else's private conversation is refused ("This session serves a conversation that is private to someone else."). Phones, members and guests never read a transcript; no device route is added. On an agent with a team, an older machine's answer (no conversation list) is refused.
- **CLAUDE.md** gains "Reading another machine's sessions (signed pool reads)" for new and existing agents.

## What to Tell Your User
I can now read any of my sessions and conversation history on any of my machines, even when those machines were set up with different keys. If a machine is asleep, I say which one and when it was last seen instead of saying there is no history. A session's working record is shown only to you, and never for a conversation that is private to someone else.

## Summary of New Capabilities
- `session-transcript-pull` mesh verb (transcript and list modes); `topic-history-pull` `shape: 'pool'`.
- Signed-first pool reads on the transcript, session-list and topic-history routes, with `via` and `asleepOrUnreachable`.
- `GET /pool/signed-reads`: per-machine, per-kind signed capability and the bearer fallback still needed.
- Transcript paging by offset plus entry index, `clipped` marks, `full`, and the oversized-row continuation.

## Evidence
- `tests/unit/sessionTranscriptPull.test.ts`: unknown session, no path, token and PIN removed, `clipped` and `full`, truncation keeps the newest entries, offset+index paging returns every entry exactly once across a cut inside a record, the oversized row (alone, continuation byte for byte, UTF-8 boundaries, a token across the cut in neither piece, the cursor reaches the older entry), and every audience boundary (no conversation, device refusal, gap, refusing puller, confined to another person, two conversations, unreadable, grant then revocation, missing field on never-team vs team).
- `tests/unit/topicHistoryPull.test.ts`: pool shape fields, cursor pass-through, `truncated` + `oldest`, the oversized row, the older-peer echo rule.
- `tests/integration/pool-reads-signed.test.ts`: two servers with different API tokens; transcript and pool history `via: 'signed'`; an unregistered machine refused without a bearer hop; an older peer reached by bearer once and remembered; a peer advertising the new version that answers `claim-unauthorized` is not downgraded; history-without-transcript capability tracked per kind; a timeout does not fall back and names the machine; the asking machine and the serving machine both refuse a transcript of someone else's private conversation; a missing `conversations` field served on a never-team agent and refused with a team.
- `tests/e2e/session-transcript-pull-alive.test.ts`: two AgentServers on the production init path with different tokens; the route returns 200 with `via: 'signed'` for a remote session, and server.ts registers the verb and hands the signed sender to AgentServer.
