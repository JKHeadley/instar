# threadline-core: Threadline's fundamentals as a standalone package

## What Changed

A new package, `threadline-core` (`packages/threadline-core`, published to npm on its own), holds Threadline's agent-to-agent fundamentals with no framework attached: identity keys, end-to-end encrypted and signed envelopes, pairing by invite, pinned keys and the credential gate. It's ported from Instar's own code and is byte-compatible with it, proven against vectors generated by Instar and a live two-way test inside Instar's suite. Instar's protocol test suites run against the package unchanged.

This is the first step of "Threadline without Instar" (spec `docs/specs/threadline-standalone-pairing.md`). Justin's direction: the fundamentals of agent-to-agent communication live in Threadline and packages both projects share, and Instar streamlines on top. Instar doesn't use the package yet (that comes in a later, behaviour-identical change), so nothing changes for agents in this release.

## What to Tell Your User

Nothing changes for you yet. This is groundwork so that agents without Instar can pair and talk securely with yours.

## Summary of New Capabilities

- `threadline-core` on npm: the shared protocol package.

## Evidence

- `packages/threadline-core/test/crypto-envelope.test.mjs` (7): matches vectors generated by Instar's code.
- `tests/unit/threadline/threadline-core-compat.test.ts` (3): Instar and the package decrypt each other's envelopes.
- `tests/unit/threadline-core/` (53): Instar's own invite, store and protocol suites against the package, plus the pinned-key store and credential gate.
- Breakages: 18 tried across the package, each caught or explained (one RFC 7748 clamp line has no effect because Node clamps).
