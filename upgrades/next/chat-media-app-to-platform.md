## What Changed

- Files from the Instar iPhone app into Telegram topics and Slack conversations (docs/specs/mobile-native-chat-media.md §4.9, increment 3). With files in app conversations on (`mobilePairing.native.media.enabled`), `POST /mobile/chat/:topicId` and `POST /mobile/chat/slack/:conversationId` accept the same signed `attachments` an app conversation send takes (§4.3). They used to refuse any body with files (400 `media-target-unsupported`); with media off they still do.
- An upload can now name the conversation it will be sent into: `telegram:<topicId>` (a topic this machine knows) or a Slack conversation's canonical key (the `conversationKey` the Slack history read returns, held by this machine). The send checks that every upload belongs to this device and this exact conversation, with exactly the signed hash, size, kind, type and filename (409 `attachment-mismatch` otherwise).
- The message is stored as a `media-message` under `telegram:<topicId>` or the Slack key, with the phone's signature (covering every file's hash) and this machine's receipt, before it is dispatched. The session receives one line per file before the caption, in Telegram's forms (`[image:<path>]`, `[document:<path>] (…)`, `[video:<path>]`, `[voice:<path>] <transcript>`), each a private copy.
- Telegram mirror: the files go into the topic through a new `TelegramAdapter.sendMediaToTopic`, as `sendPhoto` / `sendVideo` / `sendVoice` / `sendDocument`, or one `sendMediaGroup` for several, captioned "📱 <owner> (from the app): <caption>". The request is multipart through the same egress door as every Telegram send, so with the origin outbox active its bytes are captured, sealed and recorded before dispatch. A file above 50,000,000 bytes is mirrored as the line "📱 <owner> sent <name> (too large for Telegram; open it in the app)". A caption too long to sit under the files goes as its own message.
- Slack mirror: each file is uploaded into the channel or thread through Slack's v2 upload (`FileHandler.uploadFile`, which now takes an optional thread, a message beside the file, and a file name), the first carrying "📱 <owner> (from the app): <caption>".
- A failed mirror never fails or repeats the dispatch: the answer says `mirror: "failed"` (Telegram also keeps `mirrored: false`).
- History: a device reading a Telegram topic gets the app-sent message with its stored caption (never a server path), its `attachments` and `originVerified`; the Slack history read already returned stored rows with attachments. Both download through `GET /mobile/media/:sha256` with `ref=telegram:<topicId>` or the Slack `conversationKey`.
- A retried request answers its recorded result (one dispatch, one mirror); the same request id with different files is refused as reused. If the Telegram inbound core refuses a send early (its id is released after the message and files were saved), the retry reuses the saved message and its files instead of claiming them again.
- The upload, preflight, claim, publish and record-size steps of the app conversation send moved into one shared module (`src/server/mobileMediaSend.ts`) that all three routes use; the app conversation send behaves as before.

## What to Tell Your User

You can now send photos and files from the Instar app into a Telegram topic or a Slack conversation, not only into the app's own conversations. I get them with the message, and a copy appears in the topic or channel marked as coming from the app. A file bigger than Telegram allows (about 50 MB) shows up there as a short note saying to open it in the app. The app needs its next update to offer this.

## Evidence

- Unit tests (`tests/unit/mobile-media-to-platform.test.ts`): the mirror plan (a file at exactly 50,000,000 bytes uploads, one at 51,000,000 becomes the too-large line, a file with no local copy becomes a line, an over-long caption goes as its own message, display names cannot forge a tag), the method per kind, media-group typing, multipart-safe names and types, the send-body checks, the idempotency hash parts changing with every signed field, both mirror functions, and `TelegramAdapter.sendMediaToTopic` (one file per kind, a media group, the multipart body accepted by the origin outbox's own `captureOriginAttachments`, no token in an error, no relay when tokenless).
- Migration test (`tests/unit/PostUpdateMigrator-appMedia.test.ts`): the template carries the new line; an installed section without it gains it once, right after "Reply with files".
- Integration tests (`tests/integration/mobile-media-to-platform.test.ts`) through the production device authenticator: a Telegram photo stored under `telegram:<id>`, delivered as a readable path, mirrored as `sendPhoto` by a real TelegramAdapter (fetch stubbed), shown in device history with `originVerified: "verified"` and downloaded by the topic ref; two files as one `sendMediaGroup`; a 51,000,000-byte file mirrored as the text line; retry idempotency; a retry after an early inbound refusal reusing the saved message and files (delivered once); a failed mirror; an upload for another conversation refused; a Slack send with a file stored under the canonical key, dispatched with its path, uploaded into Slack and downloadable; Slack retry idempotency; media off refuses as before.
- End-to-end test (`tests/e2e/mobile-native-media-alive.test.ts`): an AgentServer on a development agent with a real TelegramAdapter; a phone paired through the production path uploads a photo for `telegram:42`, sends it, and the message is stored, delivered, mirrored as `sendPhoto`, and shown and downloadable in the topic's history.

## Summary of New Capabilities

- The app can send files into Telegram topics and Slack conversations (`attachments` on `POST /mobile/chat/:topicId` and `POST /mobile/chat/slack/:conversationId`; uploads named `telegram:<topicId>` or the Slack `conversationKey`). Behind `mobilePairing.native.media.enabled` (development-agent gated).
