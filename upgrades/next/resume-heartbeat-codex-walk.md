## What Changed

The 60-second topic resume heartbeat (`commands/server.ts` → `TopicResumeMap.refreshResumeMappings`) checked each live session's recorded transcript id in EVERY framework layout — Claude, then the Codex rollout archive, then Gemini. The Codex branch (`findRolloutFileSync` in `providers/adapters/openai-codex/observability/sessionPaths.ts`) `statSync`ed every entry under `~/.codex/sessions` before testing its name, so a MISSING Claude id (two live Claude sessions on the Mac Studio had stale ids) walked 286,984 files on the main thread once a minute: ~25 s of frozen event loop per minute, `/health` timeouts, and three supervisor restarts of a healthy server on 2026-10-13.

- **A session is checked in its own framework's layout.** `TopicResumeMap.jsonlExists(uuid, framework)` and `ThreadResumeMap.jsonlExists(uuid, framework)`: `claude-code` → Claude transcripts only (this project's `~/.claude` dir and every pooled `~/.claude-*` home); `codex-cli` → the Codex archive only; `gemini-cli` → Gemini only. Only an untagged session keeps the legacy every-layout order. A missing transcript is an honest miss: the existing mapping is kept, nothing is deleted, and no newer transcript is substituted.
- **The framework travels with the id.** The heartbeat tick now lives in `src/core/ResumeHeartbeat.ts` (`runResumeHeartbeatTick`) and pairs each session's `claudeSessionId` with its `framework` from the session registry; every save-before-kill `findUuidForSession` call passes the framework; the thread resume map resolves a thread session's framework from `state.listSessions()`; `TopicResumeMap.get()` checks a stored entry in the layout of its own `framework` tag (untagged → `claude-code`).
- **The Codex lookup can no longer block the loop**, for every caller: (1) a remembered exact path, validated with one stat; (2) a remembered miss (60 s TTL after a cheap-path miss, 5 min after a full enumeration; dropped when the newest day partition's mtime changes, or explicitly by `invalidateRolloutLookup` — `CodexResumeMap.save` calls it); (3) a UUIDv7 partition hint — Codex ids embed their creation time, so the lookup reads that local-date partition and its two neighbours by NAME only; (4) sync callers only: a readdir-only scan newest-first capped at 20,000 names; (5) beyond that, an async enumeration that tests names before any stat, yields the event loop per directory and every 5,000 names, is bounded at 2,000,000 names, and is single-flight per id. A sync caller whose id needed the async path answers an honest null now and reads the settled answer on its next call; an async caller joins an enumeration already in flight. `rolloutLookupStats()` exposes the counters.
- `walkForUuidSync` / `walkForUuid` are gone. `listAllRollouts` and `findNewestRolloutSync` are unchanged.
- Not in this change: `ProjectMapper`'s synchronous per-worktree Git scan at boot (a separate boot-delay amplifier named in the same report) — tracked as ACT-109. <!-- tracked: ACT-109 -->

## What to Tell Your User

Once a minute I run a small bookkeeping check so that, if a conversation's session is ever restarted, it can pick up where it left off. For a Claude session whose record pointed at a transcript that was no longer on the machine, that check used to go looking for it through every one of my Codex session files as well — hundreds of thousands of them — and while it did, I could not answer anything for about 25 seconds. On a busy machine that made my own supervisor think I had hung and restart me. Now each session is checked only in its own framework's files, and the Codex lookup itself is built so it can never freeze me again. Nothing changes in what you see, except that I stop going quiet for no reason. If a transcript really is missing, I keep the old note rather than guessing a different one, exactly as before.

## Summary of New Capabilities

- The server no longer freezes once a minute when a live Claude session's recorded transcript is missing.
- A Claude session's resume check never reads the Codex or Gemini archives; a Codex session's never reads Claude homes.
- Looking up a Codex session file by id is bounded and yields the event loop; a present file is still found on the first call through its date partition.
