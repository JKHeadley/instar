## What Changed
- **A new headless Codex session no longer launches on a Codex account the pool reads at its usage limit.** Before, `POST /sessions/spawn` with `framework: codex-cli` (and every other headless Codex spawn) never asked the subscription pool which account to use: the headless lane consulted the pool only for `claude-code`, and the wall rescue's spawn resolver only handled Claude accounts. A Codex session therefore rode whatever login the default `CODEX_HOME` held, untagged. On 2026-11-12 on the Mama PC that login read 100% weekly (resets 2026-11-14), and three builders and two probes each died at their first turn with "You've hit your usage limit" while other Codex accounts in the same pool read 30, 34 and 62% (feedback fb-39e55b95-f00, fb-fb4d0e68-3a2). The pool's `status: active` on that account was not the cause; nothing on the spawn path read the quota.
- **Placement.** A headless `codex-cli` spawn now uses the same rule as Claude spawns: it launches under a pool Codex account that is not walled and has a fresh reading under the soft threshold (coolest first), and is tagged with it (`subscriptionAccountId`, `CODEX_HOME`). All spawns are tagged when the pool has 2+ usable Codex accounts; otherwise the pool steps in only when some Codex account is walled. An account is walled while its weekly or five-hour window reads 100% or more, until that window's reset time: the same check the wall rescue already uses. Unread or stale accounts (possibly an expired login) are never picked; with no qualifying account the default login is used as before.
- **Refusal.** When every usable Codex account is at its limit, the spawn is refused before any tmux session exists: `409` with `code: codex-accounts-walled` and a plain reason naming the soonest reset.
- **Unchanged.** No Codex accounts in the pool → the default login, as before. `subscriptionPool.wallRescue.enabled: false` or `autoSwapOnRateLimit: false` turns this off. `pinSessionsToPool: false` keeps the default login unless some Codex account is walled. An explicit account pin always wins. Claude spawns and the interactive lane are untouched.
- **Reap log.** Exited rows now carry `subscriptionAccountId` when the session was tagged, so a death at a usage wall names its account.

## What to Tell Your User
If I start a background Codex task and one of my Codex accounts is out of its usage allowance, I now start it on an account that still has room instead of one that will fail at once. If every Codex account is out, I say so plainly instead of starting work that dies immediately.

## Summary of New Capabilities
- Headless Codex spawns are placed on a pool Codex account with room and tagged with it.
- `codex-accounts-walled` spawn refusal (409) when every Codex account is at its limit.
- Reap-log exited rows include the launch account.
