## What Changed

The completion-claim verifier's 41% failure rate came from the shared LLM spend cap, not from bad model output. Each call was charged an estimated 0.25 cents against the shared queue's background share, which ran out each day at about 06:00 UTC; later calls were refused before reaching a model and were counted as invalid output. The verifier now has its own queue, bounded by its existing component budget. Refusals are typed, every failed turn is recorded with a reason code, failed branch and model (never claim text) at `GET /completion-claim/failures`, and the verifier stays observe-only until failures are under 5% on each of the last 7 complete days, even with `dryRun: false`.

The feedback executor now tells its independent safety reviewers whether a PR contains an implemented fix or a design draft. A design draft is reviewed for safe scope and a concrete regression-test plan only while its current head is exactly the expected newly added draft file. The fix path continues to require an executable test that would fail without the change.

A running scheduler now checks its durable supervision hold before each script admission, including after an asynchronous gate. A certificate revocation or other hold written after scheduler startup therefore closes the next script route without requiring a restart. A joined test-agent lifecycle test exercises mocked provider decisions, timeout, a late answer, planted-secret redaction, a synthetic certificate revocation hold, and a hold arriving during the gate.

## What to Tell Your User

Instar's checker that compares what an agent said it did against what it actually did was being cut off for much of each day because it shared a small spending allowance with other background features. It now has its own allowance, so it no longer uses up theirs, and it keeps a record of why any check fails, without storing what the message said. It stays in watch-only mode until it has run reliably for a week.

Feedback design drafts are reviewed as designs only when the current pull request contains exactly the expected new draft. Implemented fixes still need an executable regression test before merge.

The running scheduler now notices a newly recorded safety hold before it starts another script. The test agent uses synthetic results and mocked model replies, so this is safety evidence, not permission to turn on production decisions.

## Summary of New Capabilities

| Capability | How to use it |
|---|---|
| Per-turn failure record for the completion-claim checker | Ask your agent why the checker failed |
| Feedback draft review by current head shape | The executor checks the current pull request's files and diff before applying design-stage safety criteria |

Durable supervision holds take effect on the running scheduler's next script admission. The joined lifecycle test checks the scheduler and server path under synthetic inputs and records exactly which rollout gates it does and does not cover.

## Evidence

Reproduced in `tests/unit/completion-claim-failure-ledger.test.ts`: 300 turns on a shared-cap queue reach the model 240 times and record 60 `lane-reserve` failures; the same 300 turns on a dedicated queue all reach the model. In production, 1,094 admitted turns minus 447 invalid equals the 647 model calls for that period, and calls stop around 06:00 UTC each day until a restart.

The feedback reviewer-shape tests cover both sides of the boundary: a valid one-file new draft receives design criteria, while a code fix or malformed design head retains the implementation-test requirement. The merged reviewer change does not prove that an executor-produced fix has reached merge.

See `docs/specs/job-result-supervision-v2-joined-test-agent-evidence.md`. The live provider, pool certificate registry, and development shadow gates remain open. Production model decisions remain off.

## Why

Live evidence: executor-produced PR #2439 was a one-file design draft, but its reviewer rejected it solely because it had no implementation or executable test. The corrected prompt distinguishes that expected design stage from a code fix. The review verdict gate, two-family requirement, protected-path rule, and exact-head merge requirement are unchanged.
