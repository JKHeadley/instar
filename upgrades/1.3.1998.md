## What Changed

Permanent agent links (spec `docs/specs/permanent-agent-links.md`). This adds an optional link that names an agent by its identity, not by one machine's address: `https://instar.sh/a#v=1&i=<agent id>&t=home|doc|conversation[&r=…]`. Everything after `#` stays on the device, so instar.sh stores nothing and never learns which agent or page.

- New setting `agentLinks.enabled` (default off, read live). Off or absent, nothing changes.
- `GET /mobile/agent-link/identity?nonce=…` (device-signed). It returns the agent's id and public key, plus a signature over a fixed transcript that binds the id to this device, the host the device signed for, and its nonce. With that, the app can prove a paired agent really holds the id before it opens links for it. The route never creates, repairs or rewrites an identity, and refuses `identity-split`, `identity-key-locked`, `identity-unreadable` and `no-agent-identity`.
- `POST /agent-links` (Bearer) builds a link from `{target, ref?, comment?}`. It adds `warning: split-identity` when one of the agent's machines publishes a different identity.
- instar.sh: a static `/a` page with an "Open in Instar" button. It makes no network request and never redirects. Apple's link file now lists `/a` for the iPhone app and adds the Mac app.
- One `agentLinks` evidence row per outcome in `logs/feature-evidence.jsonl`. Ladder entry `agentLinks`, set to default-off-by-preference.

## What to Tell Your User

If you'd like, your agent can now hand out links that always open the right place in the Instar app on your iPhone or Mac, even when its machines change addresses. Just ask it to turn on permanent links. The links hold no password or access: opening one still needs your own paired app.

## Summary of New Capabilities

- `agentLinks.enabled` (default off).
- `POST /agent-links`: build a permanent link to home, a document or a conversation.
- `GET /mobile/agent-link/identity`: the app's identity proof.
